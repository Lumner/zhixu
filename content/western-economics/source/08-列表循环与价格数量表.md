# 08 列表、循环与价格数量表

## 学习目标与先修

先完成07章。约3—4小时，学会列表、索引、for循环、range和累计；用一组价格生成数量表。经济意义先沿用第04章的假设，不把程序表格当作真实调查。

## 为什么需要列表

若要计算8个价格，不必复制8次公式。**列表**`list`能按顺序保存多项内容，用方括号表示：

```python
prices = [0, 10, 20, 30, 40, 50, 60, 70]
```

这是[demand_table.py](示例代码/demand_table.py)的第一段数据。**索引**表示位置，从0开始，所以`prices[0]`是0，`prices[2]`是20。`len(prices)`是项数8，最后一项索引为7，也可写`prices[-1]`。访问`prices[8]`超出范围，会触发`IndexError`。

## for循环怎样逐项执行

```python
for price in prices:
    quantity = max(0, 120 - 2 * price)
    print(price, quantity)
```

这是可用于已有prices列表的片段。`for`每次从列表取一项，赋给price，再执行缩进的内容，直到所有项处理完。第一次price为0，算出quantity为120；第二次price为10，算出100。`max(0, x)`返回0与x中较大者，用于避免负购买量。

循环不会同时计算所有行。手写追踪表“第几轮、price、quantity”可以检查自己的理解。完整文件的`{price:2d}`表示整数至少占两列，`{quantity:3d}`表示至少三列，便于对齐。它们只影响显示。

## 累计变量与经济解释

完整程序循环前写 `total_quantity = 0`，循环内写 `total_quantity += quantity`，是 `total_quantity = total_quantity + quantity`的简写。如果把归零放进循环，每一轮都会忘掉前面的累计。

但这里的每个价格是互斥的假想情景，不同情景的需求数相加**不是某一天市场总需求**。程序输出特意称为“Sum across hypothetical scenarios”。累计只是语言练习。只有同一时期、同一价格下不重叠消费者的购买量，才可按适当定义加成市场需求。

## 运行与输出解释

在示例目录的PowerShell执行 `python demand_table.py`。主要输出：

```text
P= 0, Qd=120
P=10, Qd=100
P=20, Qd= 80
P=30, Qd= 60
P=40, Qd= 40
P=50, Qd= 20
P=60, Qd=  0
P=70, Qd=  0
Sum across hypothetical scenarios: 420
```

前6行数量每次减少20，因为价格每次增加10，系数为-2。到价格60数量为0；再提价时截断规则使数量仍为0，因此最后一段不再维持原直线的斜率。

## range、追加与另一种循环

`range(0, 71, 10)`生成0、10、…、70，结束值71本身不包含；`range(0, 70, 10)`最后只到60。需要实际列表可写 `prices = list(range(0, 71, 10))`。

`results = []`创建空列表，`results.append(quantity)`可逐次加一项。`while`则在条件持续成立时重复，例如每轮更新计数器；忘记更新可能无限循环。本课固定情景优先用for，避免初学阶段增加不必要的停止条件。

## 常见错误

- 从1开始索引导致第一项漏掉、最后越界。
- print没有缩进，结果只显示循环结束时的最后一个值。
- 在遍历时随意删除列表项，造成跳项。先建立新列表更清楚。
- 以为数量表中的每一行属于同一天可相加的观察。先问各行代表什么。

## 练习与参考答案

1. 价格改成 `[5, 15, 25]`，数量是多少？答：110、90、70。
2. `list(range(5, 26, 10))`是什么？答：`[5, 15, 25]`。
3. 用空列表记录数量，应把`results=[]`放哪里？答：循环前，循环内append；否则每轮重建只剩最后一项。
4. 怎样解释420？答：本例跨假想价格情景的算术和，没有自动对应实际日销量的经济含义。
