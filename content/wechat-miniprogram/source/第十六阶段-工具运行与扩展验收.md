## 2. 本次实际工具链

Node24.15.0、npm11.12.1、TypeScript5.9.3。已实际运行npm install生成锁文件，再npm ci重建依赖，均使用ignore-scripts/no-audit/no-fund；没有全局升级。

在第17组目录：

```powershell
npm ci --ignore-scripts --no-audit --no-fund
npm run check
npm run build
npm test
```

check真实检查正例及四个预期错误注释；build生成dist；test重新检查/构建，执行50项并拒绝四个单独类型负例。类型错误后停止，不用旧dist继续验收。

npm ci需要依赖来源可访问或缓存可用。未安装时不能把交付dist等同自己完成了编译验证。node_modules未放进ZIP。

## 5. 手动HTTP实验

构建后运行npm start，使用输出的实际127.0.0.1临时端口。GET /healthz返回fixture-only/persistent=false/wechatIdentity=false。

用固定X-Course-Actor=A创建一条任务，读取并用相同opId重放，记录数不增加；改内容重用原编号得到409；正确version更新成功、旧版409；B列表看不到A记录。

重启服务后数据消失。A/B是可伪造夹具，不能当真正身份。不要将此服务开放到网络或填入正式后端配置。
