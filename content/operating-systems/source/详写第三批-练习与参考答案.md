## 一、题目：对象、箭头与生命期

题1：x=10，p指向x，q复制p。执行*q=30后，x和*p分别是多少？再把q改指向y，p是否跟随？

题2：函数参数int* p接收main中current的值；函数内p=&other为何不能重绑main的current？如果参数改为int** slot并传&current，哪个表达式访问current对象？

题3：动态对象由两个指针引用，free后只把一个设NULL，另一个为何仍不能访问？扩容成功后保存的旧元素指针又该怎样处理？

题4：结构体赋值中的普通int字段与指针字段分别复制什么？为什么不能按“几个字段”手算永久通用的结构体文件布局？

题6：输入文件成功打开、输出打开失败，应清理哪些资源？如果输出写入或关闭失败，可否仅凭文件存在宣布成功？

题7：fread第二个参数为1时返回n意味着什么？若为4，n还是字节数吗？复制最后短块时应该写多少？

题8：已经读到一行12abc，strtol可得到12就能算合法分钟吗？EOF、空行、业务数值0有什么区别？

## 四、提示与简答

题1：两个路径访问同一x，均读30；只重绑q不改p。题2：普通参数改副本，*slot访问调用者current对象。题3：对象生命期已结束，清空一个名字不改变事实；成功扩容后根据新结果重建内部位置。

题4：int复制值，指针复制访问关系，不自动深拷贝目标；填充、类型表示与端序等使原始结构体布局不适合作通用持久格式。题5：旧owner仍负责释放，覆盖成NULL可能丢失地址。题6：关闭输入并释放已拥有动态对象；文件可能只是部分结果。

题7：size=1时n是字节数，size=4时是完整项数；复制只写本次读到的有效字节。题8：还需检查尾随内容与范围；EOF可能是无记录，空行是取得了换行但无数字，0则是可合法的数值。

题9：初始10和20，第一次next后saved=10，再一次后*left=20，最终a20/b10。题10：Make依据规则与时间等判断目标；未改变不需重做，改选项可用make -B等明确强制构建，不能假设所有配置变化都自动被编码进依赖。

## 五、综合项目：学习记录文件整理器

在Ubuntu建立 `~/os-lab/batch03-review`，保存record-tool.c。输入是普通文本，每行一个十进制分钟值，允许周边空白和正负号，但最终数值必须0—1440；最多32条；每行正文最多62字节且必须换行。空文件允许表示0条，空白行不是一条有效数值。

程序读取全部输入并验证，再导出到尚不存在的新文件。导出格式仍为每行一个规范整数，便于再次作为输入；结构体id按读入次序产生，不把结构体原始内存直接写成文件。

先自己画流程：检查参数 → 打开输入 → 按行读入 → 转换与追加 → 检查读取和关闭 → 创建新输出 → 导出与关闭 → 汇总 → 释放。输入失败不创建新输出；导出中途失败可能留下部分新文件，不能把本工具称为原子保存协议。

## 六、完整参考程序

**完整程序：record-tool.c**

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <ctype.h>
#include <errno.h>

struct Record {
    int id;
    int minutes;
};

int parse_minutes(const char *text, int *result) {
    char *end = NULL;
    errno = 0;
    long value = strtol(text, &end, 10);
    if (end == text || errno == ERANGE) {
        return 0;
    }
    while (isspace((unsigned char)*end)) {
        end++;
    }
    if (*end != '\0' || value < 0 || value > 1440) {
        return 0;
    }
    *result = (int)value;
    return 1;
}

int append_record(struct Record **items, size_t *count, size_t *capacity, int minutes) {
    if (*count >= 32) {
        return 0;
    }
    if (*count == *capacity) {
        size_t next = *capacity == 0 ? 2 : *capacity * 2;
        if (next > 32 || next > SIZE_MAX / sizeof **items) {
            return 0;
        }
        struct Record *grown = realloc(*items, next * sizeof **items);
        if (grown == NULL) {
            return 0;
        }
        *items = grown;
        *capacity = next;
    }
    (*items)[*count].id = (int)*count + 1;
    (*items)[*count].minutes = minutes;
    (*count)++;
    return 1;
}

int main(int argc, char *argv[]) {
    if (argc != 3) {
        fprintf(stderr, "usage: record-tool INPUT NEW_OUTPUT\n");
        return 2;
    }
    FILE *in = fopen(argv[1], "r");
    if (in == NULL) {
        perror("open input");
        return 1;
    }
    struct Record *items = NULL;
    size_t count = 0;
    size_t capacity = 0;
    size_t row = 0;
    int failed = 0;
    char line[64];
    while (fgets(line, sizeof line, in) != NULL) {
        row++;
        int minutes;
        if (strchr(line, '\n') == NULL || !parse_minutes(line, &minutes)) {
            fprintf(stderr, "Invalid or incomplete line %zu\n", row);
            failed = 1;
            break;
        }
        if (!append_record(&items, &count, &capacity, minutes)) {
            fprintf(stderr, "Cannot append: record limit or allocation failure\n");
            failed = 1;
            break;
        }
    }
    if (ferror(in)) {
        failed = 1;
    }
    if (fclose(in) == EOF) {
        failed = 1;
    }
    if (failed) {
        fprintf(stderr, "Input did not complete\n");
        free(items);
        return 1;
    }
    FILE *out = fopen(argv[2], "wx");
    if (out == NULL) {
        perror("open new output");
        free(items);
        return 1;
    }
    long total = 0;
    for (size_t i = 0; i < count; i++) {
        total += items[i].minutes;
        if (fprintf(out, "%d\n", items[i].minutes) < 0) {
            failed = 1;
            break;
        }
    }
    if (fclose(out) == EOF) {
        failed = 1;
    }
    if (!failed && printf("records=%zu total=%ld\n", count, total) < 0) {
        failed = 1;
    }
    if (fflush(stdout) == EOF) {
        failed = 1;
    }
    free(items);
    if (failed) {
        fprintf(stderr, "Export or summary failed\n");
    }
    return failed;
}
```

## 七、按函数责任解释，而不是从头背代码

parse_minutes借用文本并通过int*交回结果；只在转换、尾随内容、范围都通过后写结果。调用者保证result是有效可写整数地址，text是有效C字符串。

append_record接收owner槽、有效数量与容量槽。初始状态为NULL/0/0；容量用2、4、8、16、32增长；只有新项已写入后才增加count。失败时原owner与数量仍可由main处理，函数不会偷偷释放调用者已有对象。

`sizeof **items` 对本例普通类型给出Record大小，不实际读取未分配对象。`(*items)[*count]`先取得数组指针，再访问待添加位置；不把items这个二级指针自身当作业务数组。

main负责资源协调。输入流关闭且验证成功后才创建输出；所有失败出口都释放已拥有items。total用long，32条×1440至多46080，不让一个可能较小的int承担这份总和口径。

## 八、实际运行与可预期结果

在batch03-review目录的Bash执行：

```bash

printf '30\n 45 \n0\n+60\n' > raw-minutes.txt
./record-tool raw-minutes.txt clean-minutes.txt

```

运行汇总应为records=4 total=135，输出文件为30、45、0、60四行。再次用clean-minutes.txt作为输入并指定另一个新输出，应得到相同规范内容。这比只看终端总数更能检查持久格式是否可复用。

## 九、边界与失败验收

空输入文件导出空文件并汇总0条；32条1440可以处理，总和46080；33条应拒绝且不创建新输出。负数、1441、12abc、空行、过长行、缺换行的最后一行都应拒绝。

源不存在应非零退出；目标已存在应保持其原内容；源目标相同也不能截断原输入。分配调用失败时不创建输出，释放先前已取得的数组。导出或关闭失败则可能已经产生部分新文件，要报告失败而不是假装回滚。

参考验证脚本会定点模拟分配失败、读取失败与写入/关闭失败，不通过耗尽内存或破坏磁盘制造故障。诊断工具结果独立记录；没有报告不等于证明所有未来输入正确。
