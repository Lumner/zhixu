# 09 结构体与动态内存

> **零基础详细版 · 已重写。** 先完成第08章，能分清指针对象与被指向对象。本章建议分三至四次学习，连同所有权图、扩容与错误处理约7—10小时。每份动态对象都要说明由谁释放。

## 9.1 为什么同时需要“记录”和“动态空间”

一条学习记录可能包含编号、分钟数和完成状态。这些字段属于同一件事，若分散在互不相关的数组里，很容易让第3个编号与第4个分钟误配。

结构体把有关联的字段组合成记录。动态内存则解决另一问题：某些对象需要在运行时确定容量，或者需要跨越创建它的函数调用继续存在。

两者可以独立使用：结构体可以放在普通局部变量里，动态空间也可以只放int。先分别理解，再把它们组合，不把“出现struct就一定需要malloc”当规则。

**完整程序：struct-value.c**

```c
#include <stdio.h>

struct Task {
    int id;
    int minutes;
    int done;
};

int main(void) {
    struct Task task = {1, 30, 0};
    printf("id=%d minutes=%d done=%d\n", task.id, task.minutes, task.done);
    task.minutes = 45;
    task.done = 1;
    printf("updated=%d done=%d\n", task.minutes, task.done);

```

保存后用C17与常用警告选项编译struct-value.c，运行应先显示id=1 minutes=30 done=0，再显示updated=45 done=1。这里done使用本例约定0/1，不是系统替你保存的一项业务状态。

## 9.3 类型定义与创建对象是两件事

`struct Task { ... };` 描述一种记录类型：有哪些字段、分别是什么类型。结束大括号之后的分号不能漏。

`struct Task task = {1,30,0};` 才创建名为task的对象，并按字段顺序初始化。类型名Task不是当前对象名task，大小写也有区别。

`.`访问一个结构体对象的字段。字段既可以读取，也可以在允许写的对象上赋值。若修改字段顺序，依赖位置的初始化也要核对；更明确的指定初始化如 `{.id=1, .minutes=30, .done=0}` 可减少顺序依赖，但仍需匹配实际字段名。

## 9.4 结构体指针与箭头符号

若有 `struct Task *p = &task;`，`p->minutes` 等价于 `(*p).minutes`。先通过指针访问那个结构体对象，再选其中字段。

`p.minutes` 不对，因为p本身是指针，不是结构体对象；`*p.minutes` 又受运算优先级影响，不等价于想表达的那一步。箭头符号帮助把这类访问写清楚。

还可以建立结构体数组，tasks[i].minutes表示第i个记录的分钟字段。下标边界仍由真实数量约束，使用struct不会自动检查i是否越界。

## 9.5 结构体赋值复制什么

同类型结构体可以赋值。对于本节只含int字段的Task，复制会给新对象相应字段值；后来修改新对象的minutes不会自动改旧对象。

如果某个结构体字段本身是指针，普通结构体赋值复制的是指针值，不会自动复制它指向的整个动态对象。这可能形成两个记录指向同一底层数据的关系，释放责任必须另外安排。

结构体大小也不一定恰好等于所有字段大小相加，编译实现可能为对齐插入填充。因此分配与步长使用sizeof实际类型，不手算“3个int就永远12字节”。后续也不能把结构体原始字节直接当成跨平台文件格式。

## 9.6 自动局部对象为什么有生命期限制

函数中普通自动局部对象在相应执行期间存在。函数返回后，不能靠保留它的地址让原对象继续作为那个对象使用。

如果一个辅助函数需要创建一组数据并交给外部稍后使用，必须选择合适的存储与所有权方案，例如由调用者提供缓冲区，或分配动态对象并明确转交释放责任。不能简单返回局部数组地址。

“栈”“堆”是常见实现语境。本章首先以语言对象的生命期与分配接口为准，不用某台机器地址高低推断释放规则。第24章再把分配器与内核区域联系起来。

## 9.7 第一个动态对象：先申请，再初始化

**完整程序：heap-value.c**

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *value = malloc(sizeof *value);
    if (value == NULL) {
        fprintf(stderr, "Allocation failed\n");
        return 1;
    }
    *value = 42;
    printf("value=%d\n", *value);
    free(value);
    value = NULL;
    return 0;
}
```

输出value=42。malloc请求一块指定字节数的空间，成功返回指向该空间的指针，失败返回NULL。它不负责把所有字节初始化为你想要的数，所以赋42发生在读取之前。

在本例普通int类型中，sizeof *value只按类型计算大小，不会真的通过尚未初始化的value读一个int。这样写也避免以后修改所指类型，却忘记同步分配大小。

C17中malloc返回的void*可按相应规则转为对象指针，不需要在本例加一层强制转换。要包含stdlib.h，让编译器看到正确函数声明，不能靠强转遮住漏头文件。

## 9.8 free结束什么，NULL赋值又改变什么

free(value)归还所拥有的动态对象，结束其生命期。此后不能继续读取*value、再次free同一份对象，也不能使用指向它内部的旧指针。

`value = NULL` 只更新这个指针变量，方便后面不再把它当作当前有效目标。若还有另一个alias保存旧地址，不会自动被清空。把一个变量改成NULL并不是全程序悬空指针扫描。

free要求传原分配接口返回并仍由你管理的合适指针，不能给局部对象地址，也不能给动态数组中间某个元素地址。free(NULL)无操作，可以帮助统一清理，但不代表free任意坏地址也没关系。

## 9.9 calloc：数量与单元素大小分开给

**完整程序：calloc-array.c**

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    size_t count = 3;
    int *values = calloc(count, sizeof *values);
    if (values == NULL) {
        fprintf(stderr, "Allocation failed\n");
        return 1;
    }
    printf("initial=%d,%d,%d\n", values[0], values[1], values[2]);
    int total = 0;
    for (size_t i = 0; i < count; i++) {
        values[i] = ((int)i + 1) * 10;
        total += values[i];
    }
    printf("count=%zu total=%d\n", count, total);
    free(values);
    return 0;
}
```

先输出initial=0,0,0，再count=3 total=60。calloc按元素数量和大小请求空间，将分配字节清零；对本例int对象，这提供零初值。

不要把“字节全零”推广成所有类型都具有你想要的语义初值，例如所有实现中的指针空值或任意复合资源状态。需要怎样的对象值，仍应按类型和接口建立。

本例count固定3，循环中的窄化转换在该范围内安全。外部数量输入需要先检查范围与总大小，不能直接把一个负整数转换为size_t后当大数组数量。

## 9.10 数量计算也需要边界

如果用malloc(count * sizeof *values)，乘法发生在调用之前。若乘法溢出，传进去的可能已经是错误小数值，之后按原count写入就会越界。

通用检查形状是：请求非零数量，并确认count不大于SIZE_MAX除以单元素大小，再进行乘法。SIZE_MAX可由适当标准头提供，下面扩容程序使用stdint.h。

calloc分开接收两项并按其接口处理大小问题，但业务上限、循环次数和总资源预算仍由调用者控制。本课不通过尝试耗尽真实内存来演示失败；验证脚本会在指定分配调用处模拟失败。

## 9.11 结构体与动态数组组合

[完整源码：records.c](示例代码/records.c)

```c
#include <stdio.h>
#include <stdlib.h>

struct Task { int id; int minutes; };

int main(void) {
    size_t count = 3;
    struct Task *tasks = calloc(count, sizeof *tasks);
    if (tasks == NULL) { perror("calloc"); return 1; }
    int total = 0;
    for (size_t i = 0; i < count; i++) {
        tasks[i].id = (int)i + 1;
        tasks[i].minutes = ((int)i + 1) * 10;
        total += tasks[i].minutes;
    }
    printf("records=%zu total=%d\n", count, total);
    free(tasks);
    tasks = NULL;
    return 0;
}
```

编译records.c，预期records=3 total=60。tasks指向第一个Task，tasks[i]访问第i个完整结构体，随后.minutes访问字段。所需大小用sizeof *tasks，让结构体实际布局参与计算。

拥有者为main：它接收分配结果、负责检查、使用、最后释放一次。若以后把这份地址交给辅助统计函数借用，默认不会因此自动把释放责任也交过去，必须在接口里另行约定。

## 9.12 容量与有效数量如何一起变化

一个动态列表可以有容量capacity=4，而实际只存count=3项。第4格有空间，不表示里面已经有一个可读取的有效业务记录。

| 动作 | 有效数量count | 容量capacity | 允许读取的记录区间 |
| --- | --- | --- | --- |
| 预留2格 | 0 | 2 | 暂无有效记录 |
| 加入第一项 | 1 | 2 | 下标0 |
| 加入第二项 | 2 | 2 | 下标0、1 |
| 扩容后加入第三项 | 3 | 4 | 下标0、1、2 |

扩容负责获得更多空间，添加操作负责初始化新记录，再更新有效数量。不能在分配出4格后就直接把count设成4，宣称已读取到4条用户记录。

## 9.13 realloc的关键：失败时保留原所有者

realloc尝试调整已分配对象大小，成功可能换位置，也可能仍用原位置；保留范围内的原有内容，新增加空间不自动有业务初值。[分配接口说明](https://man7.org/linux/man-pages/man3/malloc.3.html)

非零新大小的请求失败时，旧对象仍由原拥有者管理。若直接 `values = realloc(values, bytes)`，失败NULL会覆盖原地址，原对象可能失去可释放路径。使用临时指针先接收，成功后再更新owner。

成功之后，不继续使用旧对象地址或由它产生的旧内部指针；即使返回地址数字恰好一样，也按新的有效结果和当前对象范围重新建立访问关系。

## 9.14 完整扩容程序：保留旧值、初始化新项

**完整程序：realloc-grow.c**

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>

int main(void) {
    size_t count = 2;
    size_t new_count = 4;
    int *values = calloc(count, sizeof *values);
    if (values == NULL) {
        fprintf(stderr, "Initial allocation failed\n");
        return 1;
    }
    values[0] = 10;
    values[1] = 20;
    if (new_count <= count || new_count > 32 || new_count > SIZE_MAX / sizeof *values) {
        fprintf(stderr, "Invalid new count\n");
        free(values);
        return 2;
    }
    int *grown = realloc(values, new_count * sizeof *values);
    if (grown == NULL) {
        fprintf(stderr, "Resize failed\n");
        free(values);
        return 1;
    }
    values = grown;
    for (size_t i = count; i < new_count; i++) {
        values[i] = ((int)i + 1) * 10;
    }
    count = new_count;
    int total = 0;
    for (size_t i = 0; i < count; i++) {
        total += values[i];
    }
    printf("count=%zu first=%d last=%d total=%d\n",
           count, values[0], values[count - 1], total);
    free(values);
    return 0;
}
```

预期count=4 first=10 last=40 total=100。旧10、20保留，新增两项由循环写成30、40。业务上限32使这份教学序列的数值计算保持很小，不借由任意巨大数量测试机器极限。

失败分支中free(values)释放旧对象；成功分支更新values后只释放当前结果一次。grown作为临时接收者，不再另行free，避免两个别名对同一份对象重复释放。

本例始终拒绝new_count为0，不把不同标准/实现对零大小realloc的特殊行为混入第一次扩容教学。

## 9.15 用二级指针转交分配结果

**完整程序：owned-output.c**

```c
#include <stdio.h>
#include <stdlib.h>

int make_pair(int **out, size_t *count) {
    if (out == NULL || count == NULL) {
        return 0;
    }
    *out = NULL;
    *count = 0;
    int *values = calloc(2, sizeof *values);
    if (values == NULL) {
        return 0;
    }
    values[0] = 10;
    values[1] = 20;
    *out = values;
    *count = 2;
    return 1;
}

int main(void) {
    int *values = NULL;
    size_t count = 0;
    if (!make_pair(&values, &count)) {
        fprintf(stderr, "Could not create pair\n");
        return 1;
    }
    printf("count=%zu total=%d\n", count, values[0] + values[1]);
    free(values);
    return 0;
}
```

输出count=2 total=30。调用前的输出槽必须为空，不把它当成覆盖任意既有owner的通用接口。make_pair成功时把分配结果转交main，main成为释放责任方；失败时输出保持NULL和0。

借用与转交要区分：普通统计函数只读values，不应擅自释放它；创建函数返回新对象时则需要明确谁接手。二级指针只是表达结果的一种手段，本身不会自动追踪所有权。

## 9.16 常见错误按“对象是否仍有效”排查

| 情况 | 为什么不成立 | 应检查的责任 |
| --- | --- | --- |
| 分配失败后直接访问 | 没有获得所需对象 | 检查返回值与失败路径 |
| 先free再读取旧地址 | 对象生命期已结束 | 最后一次使用与释放顺序 |
| 两个别名各free一次 | 同一对象被重复释放 | 唯一释放责任方 |
| 只释放外层结构但漏掉独立成员 | 独立分配对象仍未处理 | 每次分配对应的清理协议 |
| 扩容后用旧内部指针 | 原访问关系可能失效 | 依据新结果重建位置 |

本课不通过随机解引用旧指针来证明“确实会坏”。规则上错误已经成立，诊断工具能发现部分实际表现，但一次没有报告也不推翻语言约束。

## 9.17 怎样检查清理路径

为每次成功分配画一条线：谁接收→谁借用→是否转交→最后谁释放。再在每个可能失败的步骤画出口，确认已经获得的资源仍有清理路径。

例如realloc-grow先获得values，参数不合法、扩容失败、正常结束三条路径都应释放现有对象；第一次分配失败则没有那份对象要释放。不能不分前提在所有出口反复free同一个地址。

测试脚本会在初次calloc或后续realloc处定点返回失败，用来检查退出状态和已有资源处理。它测试这次明确失败分支，不模拟操作系统所有内存策略。

## 9.18 练习与提示

题一：struct Task有id、minutes、done三个字段，更新done会自动修改minutes吗？

题二：有两个指针指向同一动态数组，free其中一个后把它设NULL，另一个还能解引用吗？

题三：realloc-grow的new_count改成3、5、2，分别应走什么路径？只对允许增长的情况计算结果。

题四：为什么新增空间必须初始化，为什么容量4而有效数量2时不能把后两格当作已有记录？

题五：make_pair返回成功后谁负责free？如果统计函数只借用这份地址，它能未经约定把对象释放吗？

提示：用对象身份和生命期解释，不靠地址数字相同与否做判断。每条错误路径单独列出已获得哪些对象。

## 9.19 参考答案与完成条件

题一：不会，它们是独立字段，业务同步需要代码明确实现。题二：不能，目标对象已释放，改一个指针不恢复其他别名。题三：3项为10、20、30，总60；5项总150；2被本例“必须增长”规则拒绝。题四：新空间不是已有业务数据，realloc也不自动初始化新增部分。题五：main拥有释放责任，借用者不能擅自释放。

完成条件：能为结构体字段、数组元素和指针访问分别写正确表达式；画出一次分配、扩容、失败和转交的责任线；区分有效数量与容量；说明free后为什么不能靠非NULL判断对象继续可用。
