## 25.1 文件系统提供命名空间

文件系统把路径、目录、元数据与数据关联起来。Linux 以 `/` 为路径根，不同文件系统可以挂载到目录树的不同位置；设备上的分区与目录树中的位置不是同一概念。相对路径从当前工作目录开始，改变 cwd 会影响之后的相对路径解析。

`.`、`..`、重复分隔符、软链接等会影响解析。用户输入路径不能只凭字符串前缀判断真实访问范围，实际安全路径处理还涉及链接、并发修改等问题。本课练习使用自己控制的目录。

## 25.2 权限位怎么读

`ls -l` 中常见 `-rw-r-----`：首位是文件类型，后面三组分别是所有者、所属组、其他人的 rwx。r=读、w=写、x=执行/搜索，数值分别 4/2/1。`640` 表示所有者读写，组只读，其他无权限。

目录的 r 是列出名字，x 是搜索/穿越，w 通常配合 x 用于创建或删除目录项。删除一个文件主要由父目录权限等决定，不只是看文件自己的 w。ACL、sticky bit、挂载选项、特权与其他安全机制还可能改变结果。

## 25.3 在自己的目录做实验

在 Ubuntu Bash 执行，每次可选新目录名：

```bash
mkdir -p ~/os-lab/permissions-demo
cd ~/os-lab/permissions-demo
printf 'private note\n' > note.txt
chmod 600 note.txt
ls -l note.txt
stat note.txt
umask
```

当前用户仍能读写自己的文件；`600` 不等于“连所有者都不能访问”。不要为了实验去改系统目录权限，也不要用 root 运行后再判断普通用户权限是否有效。

umask 限制创建时的权限位。例如请求 0666、umask 0022，通常得到 0644；一般表达为 requested & ~umask，不是通用十进制减法。默认 ACL 等仍可参与最终结果。

## 25.4 文件扩展名与可执行权限

Linux 不只按 `.exe` 判断能否运行。可执行权限、文件格式、解释器、挂载限制等共同作用。给 `.c` 加 x 不能把源码变成机器程序；C 必须先编译。脚本还涉及首行解释器约定，本课不要求学习新的脚本语言。

## 25.5 练习与答案

①`chmod 640 file` 中其他人能读吗？②只有文件可写、父目录不可写，必定能删除吗？③cwd 改变会改变已经打开的 fd 指向吗？答案：①不能；②不能据此保证；③不会，已有 fd 已引用打开对象，后续相对路径查找会变化。

完成条件：能从一行 ls 权限给出有前提的判断，区分目录权限与文件权限，不把错误都用 sudo 绕过。
