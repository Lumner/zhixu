# 25 路径、目录与权限：系统怎样找到并允许你访问文件

> **零基础详细版 · 已重写。** 从逐段查找路径开始，分别理解文件与目录的rwx，再运行普通用户权限和目录描述符实验。建议7—10小时。

## 1. 目标和先修

第10章会读文件，第14章会使用描述符，但文件名为什么能指向内容？为什么文件只读也可能被删除？本章把这些问题拆开。

学完能沿路径说明查找起点，读懂基本权限位，解释目录r/w/x，正确计算umask，并说明cwd变化不会让已有引用自动换目标。先复习终端路径、字符串、open和错误返回；inode的细节留到下一章。

## 2. 文件系统提供命名空间

**文件系统**把名字、目录、文件对象和数据联系起来。**目录**保存名字到对象的关联，是查找路径的一部分，不是普通用户应该当文本逐行解析的清单。

Linux常见路径以`/`组织成树，不同文件系统可以**挂载**到树中的不同位置。挂载是把一个文件系统接入某个目录位置；磁盘分区是存储划分，两者不是同一个概念。一个进程所见的根与挂载也可能受环境隔离影响，本课使用当前普通Linux环境。

## 3. 绝对路径与相对路径

以`/`开头的路径从进程所见的根开始；其他路径通常从当前工作目录**cwd**开始。`notes/day.txt`需要先在起点找notes，再在其中找day.txt。

`.`指当前目录，`..`表达向上查找；符号链接可能改变中间实际走向，下一章展开。不能只删除字符串中的`../`或检查文字前缀，就宣称把访问限制在安全目录内；并发改名、链接和实际解析规则都需要考虑。

本课所有会创建、修改或删除名字的实验，只用于自己刚建立的专用目录，不拿系统路径做练习。

## 4. 建立独立课堂目录

Linux/WSL Ubuntu的Bash终端执行，不在Windows PowerShell执行：

```bash
mkdir -p ~/os-lab/files
cd ~/os-lab/files
practice_dir=$(mktemp -d "$PWD/permissions-XXXXXX")
cd "$practice_dir"
pwd
id -u
```

practice_dir是这次专用变量，不是系统变量。mktemp按模板建立一个新目录，避免覆盖上次实验。若id输出0，先切换正常Linux用户，不用sudo执行权限判断；root的能力会绕过某些普通权限限制。

实验放在Linux家目录，不用/mnt/c上的Windows文件夹推断原生Linux权限。WSL挂载选项、ACL等会影响结果。本批实际在UID1000和Linux临时文件系统验证。

## 5. ls权限列怎样拆

`-rw-r-----`第一位`-`表示普通文件，后面每组三位分别属于所有者、所属组、其他人。r读，w写，x执行；短横表示该位未设置。

| 组 | 三位 | 本例含义 |
| --- | --- | --- |
| 所有者 | rw- | 可读写，未设置执行位 |
| 所属组 | r-- | 可读 |
| 其他人 | --- | 没有这三项基本许可 |

普通判断通常按身份选择相应权限组，不是“所有者那组不允许，就再去其他人组借权限”。ACL、能力、安全模块、只读挂载等还会参与访问判断，本章先在无额外ACL的自建目录理解基本位。

## 6. 八进制640是什么意思

每组三个位权重r=4、w=2、x=1：rw-=6，r--=4，---=0，因此为640。C源码中的`0640`开头0表示八进制，不是十进制640；Shell的chmod也接受这种权限数字约定。

常用600表示所有者读写，700表示所有者读写执行/搜索，644表示所有者读写、其他基本身份可读。数字不是安全等级排名，选什么取决于对象用途和访问者。

给C源码加执行位不会把它编译为机器程序。Linux执行还要考虑格式、解释器和挂载等限制；之前gcc得到的可执行程序与源文本不是一回事。

## 7. 文件的r/w/x与目录的r/w/x不同

| 位 | 普通文件 | 目录 |
| --- | --- | --- |
| r | 读取内容 | 列出其中名字 |
| w | 修改内容 | 通常配合x增删或改名目录项 |
| x | 按执行协议运行 | 搜索/穿越，按名字访问内部对象 |

读取`box/note.txt`需要沿途目录可搜索，并且最终文件允许读取。目录能列名字，不等于能查询每个内部对象的元数据；反过来，知道精确名字且目录可搜索时，可能无需列目录就访问文件。

## 8. 先验证文件只读

在刚创建的practice_dir中执行：

```bash
mkdir box
printf 'abc\n' > box/note.txt
chmod 700 box
chmod 400 box/note.txt
cat box/note.txt
printf 'extra\n' >> box/note.txt
echo $?
```

cat应读到abc，追加应被拒并非零退出。`>>`由Shell请求以追加方式打开，失败发生在启动printf写入以前。不要把失败归为C语言不会输出，更不要用sudo绕过以后再说权限无效。

这里只改自己创建的文件。400不代表“谁都不能读”，所有者仍有r。

## 9. 目录只有搜索位时

继续在同目录执行：

```bash
chmod 100 box
cat box/note.txt
ls --color=never box
echo $?
```

普通用户预期仍能按已知名字读到abc，但不能列出box的名字。目录x允许查找note.txt，文件400允许读；目录没有r，列举失败。

`--color=never`让这里的GNU ls不为颜色额外查询类型；它是Ubuntu工具选项，不是C语法。不同系统工具诊断文字可能不同，验收的是成功/失败和内容，而非某一句英文。

## 10. 目录只有读取位时

继续执行：

```bash
chmod 400 box
ls --color=never box
cat box/note.txt
echo $?
chmod 700 box
```

可以列名字，但按路径打开内部文件缺少搜索权限而失败。`ls -l`还需要查询内部对象信息，不能拿它代替这里的纯名字列举。最后恢复700，方便后续操作。

若现象不同，先核对UID、文件系统位置、是否存在默认ACL及实际mode；不要把环境差异隐去后宣称所有系统都如此。

## 11. 删除主要改变父目录的名字

box已经恢复700，note.txt仍为400。在这个专用实验目录可执行：

```bash
rm -f -- box/note.txt
ls --color=never box
```

这一步仅移除本次创建的note.txt。普通所有者对父目录有写与搜索权限，因而能够删除这个目录项；最终文件自身没有w不直接禁止移除名字。

sticky bit、ACL等会补充限制，例如共享临时目录里的规则不能只按这个小例推广。删除名字与修改内容是不同操作，下章还会看到名字消失以后已打开引用仍可存在。

## 12. umask怎样限制新建权限

程序创建文件时提出mode请求，umask在基本无默认ACL情形下屏蔽其中一些位。通常表达为`requested & ~mask`，不是普通十进制减法。

请求0666、mask0022得到0644；请求0666、mask0077得到0600。若mask0111，请求本来没有执行位，屏蔽这些位仍是0666；用0666减0111却得到0555，显然不对。

umask不主动给不存在的位加权限，也不自动修改已经存在文件。目录继承默认ACL时还要按相应规则分析。

## 13. 完整程序：观察创建掩码

完整程序保存到`~/os-lab/files`，lab.h也放在那里；运行时传自己选择的一个新文件名。

**完整程序：mode-create.c**

```c
#include "lab.h"
#include <fcntl.h>
#include <sys/stat.h>

int main(int argc, char *argv[]) {
    if (argc != 2) { fputs("usage: mode-create NEW_FILE\n", stderr); return 2; }
    mode_t old = umask(0077);
    int fd = open(argv[1], O_WRONLY | O_CREAT | O_EXCL, 0666);
    int saved = errno;
    umask(old);
    if (fd < 0) { errno = saved; perror("create new file"); return 1; }
    struct stat info;
    int failed = 0;
    if (fstat(fd, &info) < 0) { perror("fstat"); failed = 1; }
    else { printf("requested=0666 mask=0077 actual=%04o\n", (unsigned)(info.st_mode & 0777)); }
    if (close(fd) < 0) { perror("close"); failed = 1; }
    return failed;
}
```

编译：

```bash
cd ~/os-lab/files
gcc -std=c17 -D_POSIX_C_SOURCE=200809L -Wall -Wextra -Wpedantic -Werror -g mode-create.c -o mode-create
./mode-create mask-new.txt
```

在本课无默认ACL环境预期actual=0600。再次同名运行拒绝覆盖；换新名字重做。umask只改变这个进程的创建规则，并恢复旧值，不修改你的Shell或全系统设置。fstat字段下章细讲。

## 14. cwd改变与已取得的引用

cwd影响之后相对路径的查找起点，不会把已经打开的文件描述符换成另一个文件。还可以先取得目录描述符，再用openat相对于它查找固定名字。

这能避免每次依赖进程的cwd，但不是自动安全沙箱：带`..`、绝对路径或链接的参数仍有自己的规则。本节只使用自己目录中固定的note.txt。

## 15. 完整程序：用目录描述符锚定查找

**完整程序：cwd-anchor.c**

```c
#include "lab.h"
#include <fcntl.h>

int main(int argc, char *argv[]) {
    if (argc != 2) { fputs("usage: cwd-anchor DIRECTORY_WITH_NOTE\n", stderr); return 2; }
    int base = open(argv[1], O_RDONLY | O_DIRECTORY);
    if (base < 0) { die("open directory"); }
    int fd = -1, failed = 1;
    if (chdir("/") < 0) { perror("chdir"); goto cleanup; }
    fd = openat(base, "note.txt", O_RDONLY);
    if (fd < 0) { perror("openat note"); goto cleanup; }
    char byte;
    ssize_t n;
    do { n = read(fd, &byte, 1); } while (n < 0 && errno == EINTR);
    if (n < 0) { perror("read"); goto cleanup; }
    if (n != 1) { fputs("note must contain at least one byte\n", stderr); goto cleanup; }
    printf("byte_after_chdir=%c\n", byte);
    failed = 0;
cleanup:
    if (fd >= 0 && close(fd) < 0) { perror("close note"); failed = 1; }
    if (close(base) < 0) { perror("close directory"); failed = 1; }
    return failed;
}
```

用相同编译选项生成cwd-anchor。先在一个新目录准备note.txt首字节h，再运行`./cwd-anchor 那个目录`，预期byte_after_chdir=h。程序只改变自身cwd，不会改变启动它的Bash工作目录。O_DIRECTORY在本课Linux接口中要求打开目标为目录。

## 16. 为什么不先access再open

先access确认“似乎可读”，再open，中间对象或权限可能变化；access还涉及与有效身份不同的检查语义。实际要读时应直接尝试open并处理结果，不把预检查当作成功保证。

同理，先确认文件不存在再普通创建有时间窗口。本课新输出使用O_CREAT|O_EXCL把“不应已存在”交给一次打开操作，重复运行不会悄悄覆盖旧结果。

## 17. 错误原因不全是权限位

ENOENT可能是中间名字不存在或链接目标不存在；ENOTDIR表示某个应作目录的部分不是目录；EACCES可能是沿途搜索或最终访问被拒。只读挂载、ACL、安全机制还可能限制操作。

先保留接口和错误位置，再检查路径起点与每级目录，最后看最终对象。不要用chmod777处理所有问题，也不要为了课程实验改系统目录或其他课程文件。

## 18. 常见误解

“文件600只有root能读”：所有者有读写，root是另一套特权语境。

“目录r就一定能打开内部任意文件”：还需搜索位和最终对象权限。

“文件没有w就无法删除”：删除目录项主要看父目录及额外规则。

“路径字符串前缀正确就安全”：解析、链接、并发变化都要考虑。

“openat自动限制不许出目录”：本节固定名字可预测，通用不可信路径要另作设计。

## 19. 练习、提示与参考答案

1. 750逐组是什么？所有者rwx、组r-x、其他---。
2. 请求0666、mask0027，结果？0640，按位屏蔽计算。
3. cwd改变后已打开fd是否重新解析原路径？不会，它已引用打开对象。
4. 目录100和已知文件400，为什么可能可读却不能列目录？x负责搜索，r负责列名，最终文件有r。
5. mode-create第二次运行为什么失败？O_EXCL拒绝已有名字，不是第一次保存没完成。

动手题：换一个新的权限实验目录，先预测400/100两种目录状态，再操作并记录UID、pwd、mode与结果。只恢复自己对象的权限，不通过特权让结果“看起来通过”。
