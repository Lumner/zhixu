## 19.1 从互斥到等待条件

先理解锁。消费者发现队列空，不应持锁忙循环，否则生产者无法取得锁放入数据。它需要“释放锁并睡眠，条件可能改变后重新拿锁检查”。条件变量正用于协调这种等待，真正条件保存在共享状态里。

本章使用容量为 1 的通道：slot 存放值，full 表示是否有值，done 表示生产者不会再产生新值。所有访问在同一把锁下。单槽是有界队列的最小模型，不是无限消息队列。

## 19.2 完整例程 queue.c

[完整源码：queue.c](示例代码/queue.c)

```c
#include "lab.h"
#include <pthread.h>

static pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
static pthread_cond_t changed = PTHREAD_COND_INITIALIZER;
static int slot = 0, full = 0, done = 0, total = 0;

static void *producer(void *unused) {
    (void)unused;
    for (int value = 1; value <= 5; value++) {
        thread_check(pthread_mutex_lock(&lock), "lock");
        while (full) { thread_check(pthread_cond_wait(&changed, &lock), "wait"); }
        slot = value;
        full = 1;
        thread_check(pthread_cond_broadcast(&changed), "broadcast");
        thread_check(pthread_mutex_unlock(&lock), "unlock");
    }
    thread_check(pthread_mutex_lock(&lock), "lock");
    done = 1;
    thread_check(pthread_cond_broadcast(&changed), "broadcast");
    thread_check(pthread_mutex_unlock(&lock), "unlock");
    return NULL;
}

static void *consumer(void *unused) {
    (void)unused;
    thread_check(pthread_mutex_lock(&lock), "lock");
    for (;;) {
        while (!full && !done) {
            thread_check(pthread_cond_wait(&changed, &lock), "wait");
        }
        if (!full && done) { break; }
        total += slot;
        full = 0;
        thread_check(pthread_cond_broadcast(&changed), "broadcast");
    }
    thread_check(pthread_mutex_unlock(&lock), "unlock");
    return NULL;
}

int main(void) {
    pthread_t p, c;
    thread_check(pthread_create(&p, NULL, producer, NULL), "create producer");
    thread_check(pthread_create(&c, NULL, consumer, NULL), "create consumer");
    thread_check(pthread_join(p, NULL), "join producer");
    thread_check(pthread_join(c, NULL), "join consumer");
    printf("sum=%d\n", total);
    thread_check(pthread_cond_destroy(&changed), "destroy condition");
    thread_check(pthread_mutex_destroy(&lock), "destroy mutex");
    return 0;
}
```

运行 `make queue`、`./queue`，应输出 `sum=15`，来自 1+2+3+4+5。运行先后可不同，但每个值被消费一次，程序最终结束。

## 19.3 三个关键时刻

生产者满时用 while(full) 等待；消费者空且未结束时用 while(!full && !done) 等待。pthread_cond_wait 会原子地释放互斥锁并进入等待，返回前重新取得锁。状态改变后广播，等待者恢复后再检查谓词。

为什么用 while 而不是 if？可能发生虚假唤醒，也可能其他线程先消耗了资源；被唤醒只说明“值得重新检查”，不保证条件已经属于你。先在同一锁内修改状态，再通知，可以避免检查与睡眠之间丢失通知。

done=1 时也可能 full=1；消费者要先取走最后一个值，只有 !full && done 才退出。把“看到 done 立即退出”写在前面会丢掉最后一项。join 完所有线程后，才销毁条件变量与锁。

## 19.4 信号量的另一种表达

信号量维护计数，wait 在没有可用额度时等待，post 归还/增加额度。有界队列可设 empty=N、full=0，再配一把锁保护队列结构。生产者先 wait(empty)，再锁队列、入队、解锁、post(full)；消费者反向使用。

不能先锁队列再等 empty/full，否则另一方可能需要同一把锁才能创造额度。POSIX sem_wait 失败可能因 EINTR，需要按返回值和 errno 处理；pthread 的错误码规则不同。信号量计数可以保存“可用额度”，条件变量的 signal 本身不是可累计的消息。

## 19.5 练习、答案与完成条件

①消费者为何要同时观察 full 与 done？②生产者发完五个值，为何还要通知？③把容量扩成 4，还要新增哪些状态？

答案：①区分暂时没数据与永久结束，且保留最后待取值；②唤醒可能正在等数据的消费者，让它确认结束；③数组、读写位置、当前数量，等待条件分别是 count==0 与 count==capacity，并保持循环索引正确。

完成条件：无需照抄代码也能说出两个等待谓词、唤醒时机、最后一条数据的处理顺序。接口说明见 [pthread_cond_wait](https://man7.org/linux/man-pages/man3/pthread_cond_wait.3.html)。
