# 11 系统调用：程序怎样请内核帮忙

> **零基础详细版 · 已重写。** 本章从普通函数走到系统调用，解释参数、返回值、错误和公共辅助函数。建议用5—7小时完成阅读、输入代码与排错。

## 1. 学完要能做什么

你已经会用C变量、数组、指针和文件流。本章要回答一个新问题：程序能计算两个数的和，为什么不能自己决定把字符送到任何设备？

学完后，你应能画出“应用代码 → C库接口 → 内核 → 返回”的路径，使用`write`发送明确数量的字节，分清失败、部分完成与全部完成，并解释后续例程依赖的`write_all`。先复习第08章指针与`sizeof`、第10章`errno`与标准错误流。遇到地址仍然不清楚时，先画数组格子，不要把系统调用当咒语背。

## 2. 两种工作怎样分工

假设程序计算`3 + 4`，它通常只需执行CPU指令，不必让内核批准每一次加法。假设程序要写一个文件，内核就需要检查描述符是否有效、权限是否允许、目标是否还能接收数据。

**内核**是操作系统中管理核心资源与保护边界的部分。**用户态**和**内核态**是处理器执行代码时的不同权限状态。普通应用通常在用户态执行；内核在受保护的权限下处理请求。这里的“用户”不是登录账号，“态”也不是窗口有没有显示。

可以把系统调用理解为有明确规则的服务入口：请求必须带上约定好的参数，内核检查后返回结果。这个类比只说明权限边界；实际过程是机器指令、寄存器、内存和内核代码共同完成的，不是另开一个聊天窗口。

## 3. 函数调用不一定进入内核

**函数调用**是把控制转到某个函数，再按接口返回。第06章自己写的`add`是函数，C库的`strlen`也是函数。计算一个已有字符串的长度，一般不需要系统调用。

**系统调用**是应用请求内核服务的机制。Linux上的`write`接口通常由C库提供包装，再进入内核。教材写`write(...)`时，讨论的是这个接口及其行为，不要求你现在手写汇编指令。

`printf`负责格式化，还可能先把数据放到C库缓冲区；需要真正送出数据时才使用较低层的写入接口。因此“一次printf等于一次系统调用”不是可靠规则。`malloc`也可能复用库已经取得的内存，不保证每次调用都进入内核。

## 4. 进入内核和换进程是两件事

应用调用`write`后，内核可能很快完成请求，再回到同一个进程的下一条指令。这发生了权限边界转换，不表示一定换成另一个进程运行。

如果写入需要等待，当前任务可能进入等待状态，调度器才有机会让别的就绪任务使用CPU。**上下文切换**是保存一个任务的执行现场、恢复另一个任务现场的过程。系统调用、阻塞和上下文切换有关联，但不是同义词。第16章再计算调度结果。

## 5. C语言和POSIX接口分别是什么

C17规定C语言及其标准库；`printf`、`fopen`属于这条学习线。**POSIX**是一组操作系统接口规范，`fork`、`pipe`、`write`属于本课使用的POSIX接口。它们不是所有C环境都自动提供的能力。

## 6. 第一份直接写入程序

**完整程序：fd-write.c**

```c
#include <stdio.h>
#include <unistd.h>

int main(void) {
    const char text[] = "OS\n";
    size_t wanted = sizeof text - 1;
    ssize_t written = write(STDOUT_FILENO, text, wanted);
    if (written < 0) {
        perror("write");
        return 1;
    }
    if ((size_t)written != wanted) {
        fputs("write: only part of the data was sent\n", stderr);
        return 1;
    }
    return 0;
}
```

在Linux终端、本批练习目录执行：

```bash
gcc -std=c17 -D_POSIX_C_SOURCE=200809L -Wall -Wextra -Wpedantic -Werror -g fd-write.c -o fd-write
./fd-write
echo $?
```

正常输出为一行`OS`，然后退出状态`0`。`-D_POSIX_C_SOURCE=200809L`在编译前定义一个宏，让头文件按对应的POSIX接口集暴露声明。它不会给不支持POSIX的平台安装内核能力。`-Werror`把警告作为错误，帮助我们尽早发现类型和接口问题。

## 7. 把这一行拆成三个问题

`write(STDOUT_FILENO, text, wanted)`依次表达：写到哪里、从哪里取字节、最多写多少字节。

**文件描述符**是当前进程使用的一个非负整数，用来引用已打开的输入输出对象。常见约定是0为标准输入、1为标准输出、2为标准错误。宏`STDOUT_FILENO`表示1，它不保证目标永远是屏幕；Shell可以把标准输出接到文件或管道。

`text`在传参时变成指向首元素的指针。`write`只接收地址和数量，不会替你寻找字符串末尾。`"OS\n"`实际数组中有`O`、`S`、换行和终止字符`\0`，共4个字节。`sizeof text - 1`得到3，故不发送终止字符。

如果改成`sizeof text`，输出目标会多收到一个零字节；它可能在终端上看不见，不能据此说它不存在。如果只请求2字节，结果是`OS`没有换行。这一实验把第07章的字符串规则和实际I/O连接起来了。

## 8. size_t和ssize_t为什么不同

`size_t`适合表达对象大小和非负字节数量；`ssize_t`是POSIX定义的有符号整数类型，既要容纳成功传输的数量，也要表达`-1`失败。

因此不要写`size_t n = write(...)`再判断`n < 0`：无符号类型不能按这个方式保存负错误值。正确顺序是先用`ssize_t`接收，判断小于0，然后在确认非负后转换为`size_t`进行数量比较。

本课程序只处理远小于接口上限的缓冲区，不用一个请求发送超大对象。类型转换只是在已经满足范围前提时表达意图，不会自动修正越界或坏指针。

## 9. 一个合法的错误实验

**完整程序：fd-error.c**

```c
#include <errno.h>
#include <stdio.h>
#include <unistd.h>

int main(void) {
    const char text[] = "x";
    ssize_t n = write(-1, text, sizeof text - 1);
    if (n < 0) {
        int saved = errno;
        perror("write(-1)");
        printf("is_EBADF=%d\n", saved == EBADF);
        return 1;
    }
    fputs("unexpected success\n", stderr);
    return 2;
}
```

用与上一节相同的编译选项编译为`fd-error`，执行`./fd-error`后再执行`echo $?`。预期错误说明中出现无效描述符的含义，标准输出为`is_EBADF=1`，退出1。不同语言环境的错误文字可能不同。

`-1`不是有效描述符，内核拒绝这个请求；本例没有故意传入越界地址。先保存`errno`，是为了后面的库调用不影响我们要检查的错误值。只有接口已经表明失败时，才按其约定检查`errno`；成功后它可能仍保留旧值。

## 10. 成功不等于一次发送完

请求100字节，`write`可能返回100，也可能返回一个小于100的正数。后者叫**短写**：已经完成一部分，你需要从尚未完成的位置继续。不能从头重发全部内容，否则会重复。

这是算法演算，不是独立程序：

```text
初始地址p，剩余10
第一次返回4：下次地址p+4，剩余6
第二次返回2：下次地址p+6，剩余4
第三次返回4：剩余0，结束
```

`-1`且`errno == EINTR`表示这一次调用在成功写入前被信号中断，可以重试；若已经写入部分数据，接口可用正数报告进展。其他错误不能都无限重试，否则例如无效描述符会造成永不结束的循环。

## 12. 公共头文件里的写入循环

下面是需要`lab.h`其他声明配合的**函数片段**，完整头文件见[示例说明](示例代码/README.md)。

```c
static inline void write_all(int fd, const void *data, size_t length) {
    const unsigned char *p = data;
    while (length > 0) {
        ssize_t n = write(fd, p, length);
        if (n < 0 && errno == EINTR) { continue; }
        if (n < 0) { die("write"); }
        if (n == 0) { fputs("write: no progress\n", stderr); exit(EXIT_FAILURE); }
        p += n;
        length -= (size_t)n;
    }
}
```

`void *`表示暂不限定对象类型的地址；这里转为`unsigned char *`，是为了按字节移动。`const`承诺函数不通过这个指针修改待发送数据。`p += n`前进已完成的字节数，`length -= n`减少相同数量。

`continue`回到循环条件，再次尝试未完成部分。`die`调用`perror`并退出失败。对非零请求若意外返回0，这个辅助函数选择直接报告“没有进展”并失败，防止死循环；此时没有负返回值保证的`errno`，所以不拿可能陈旧的`errno`输出误导性说明。

## 13. 辅助函数的边界也要写清

`write_all`用于本课阻塞描述符上的有限、有效缓冲区。它遇到错误会终止整个进程，适合小实验；通用库往往应该返回错误，让调用者决定清理和重试策略。

它不是“任何目标都永远写完”的承诺：目标关闭、空间耗尽、信号策略等仍可能让程序失败。非阻塞描述符出现`EAGAIN`时，它也直接失败，不负责等待可写。管道另一端关闭还可能产生`SIGPIPE`，第14、15章再展开。

`static inline`用于让这类小辅助函数能够定义在多个源文件都包含的头文件中，每个编译单元有自己的定义；`inline`并不保证编译器一定把调用展开。头文件的防重复包含宏避免在同一个编译单元反复定义。`lab.h`中的线程辅助函数暂时不用，第17章再讲。

## 14. 再看C库缓冲

**完整程序：stdio-three.c**

```c
#include <stdio.h>

int main(void) {
    if (puts("one") == EOF || puts("two") == EOF || puts("three") == EOF) {
        perror("puts");
        return 1;
    }
    if (fflush(stdout) == EOF) {
        perror("fflush");
        return 1;
    }
    return 0;
}
```

编译为`stdio-three`。先直接运行，再在本批目录执行`./stdio-three > stdio-result.txt`，最后`cat stdio-result.txt`。两次应有相同的三行内容，但输出目标不同，C库的缓冲策略也可能不同。

`fflush`把库缓冲区中的内容提交给底层写入接口；它不等于文件已经能承受断电。这里单独使用标准I/O，不随意把同一目标上的`printf`和`write`交错使用。缓冲和底层偏移的协调需要额外规则，后面遇到时再明确处理。

## 15. 怎样观察系统调用

若Linux已安装`strace`，可在本批目录执行：

```bash

```

`strace`是跟踪Linux系统调用的工具。跟踪信息默认到标准错误，所以第二条仍可能在终端看到跟踪记录，程序正文进入文件。观察`write`的描述符、长度与返回数量，而不是只数`printf`行数。

本次验证环境没有`strace`，因此此节是可选观察步骤，未宣称已运行；核心C程序已另行编译运行。不要为了继续主线先折腾安装；第99篇列出官方说明。即使安装可用，运行时、库版本和缓冲设置也可能影响调用数量，不把某一次记录推广为固定规律。

## 16. 常见错误与检查顺序

| 现象 | 先检查 | 原因 |
| --- | --- | --- |
| 找不到`unistd.h`或`fork` | 是否真的进入Linux工具链 | 把POSIX实验放到了不匹配的平台 |
| `implicit declaration` | 是否包含头文件、编译宏是否一致 | 接口声明未正确提供 |
| 输出混入奇怪字符 | 地址、长度、终止字符是否区分 | `write`不会自动按字符串截断 |
| 程序永不结束 | 是否把所有错误都重试 | 永久错误不因重复调用而消失 |
| 错误说明出现`Success` | 是否在非错误路径读旧`errno` | 错误文字和真实返回值脱节 |

先核对终端和目录，再核对保存的源码、第一条编译错误、执行文件名，最后检查接口契约。不要用删掉错误检查的方法“修好”程序。

## 17. 自测、提示与参考答案

1. `const char s[] = "AB";`为什么通常只发送`sizeof s - 1`？提示：逐格写数组。
2. 请求8字节，依次返回3、2、3，三次地址和剩余数量是什么？
3. `write`返回2而`errno`恰好等于`EINTR`，应该当作失败吗？
4. 进入内核后立刻返回，是否一定发生了进程切换？
5. 把`stdio-three`的内容重定向后没有出现在屏幕上，如何判断成功？

参考答案：第一题数组有A、B、零字节，共3格，只发送前2格；第二题调用地址依次为p、p+3、p+5，调用前剩余8、5、3；第三题以正返回值报告的进展为准，不能用旧`errno`推翻成功；第四题不一定，同一进程可以继续；第五题检查退出状态和输出文件内容，而不是把“屏幕安静”当错误。

改造练习：把`fd-write`改为发送`"kernel boundary\n"`，仍用`sizeof`计算长度；再只发送前6字节，预测有没有换行。参考结果分别为完整一行，以及`kernel`无换行。两个版本都要重新编译并记录返回状态。
