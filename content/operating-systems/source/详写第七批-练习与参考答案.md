# 详写第七批：练习、参考答案与分阶段报告的笔记保存器

对应第25—29章。先把名字、对象、权限和输出协议解释清楚，再组合“新对象准备 → 发布名字 → 同步目录”的保存流程。项目不模拟真实断电恢复。

## 1. 学习安排与使用范围

五章建议38—53小时，本练习再预留5—7小时，合计43—60小时。先做追踪题，再输入程序，最后做失败阶段表。所有命令在Linux/WSL Ubuntu的Bash、`~/os-lab/files`执行，lab.h在同目录。

项目只用于自己新建、没有其他写者并发改名的**专用本地目录**，目标固定为note.txt。它会替换该名字，所以不把已有文档目录拿来试验；它不做安全沙箱、版本历史、远端文件系统恢复或旧权限/ACL继承。

## 3. 参考答案

第一题不能，父目录的写/搜索及额外机制决定删除名字；本课无额外限制小例可以删除。第二题不同：前者是目录项到对象，后者是fd到打开状态。

第三题每次调用前errno=0，NULL后立刻判断；第四题换行也可属于名字，NUL分隔可消除这一类歧义，前提仍要检查工具完整成功。

第五题分别是库输出到下层、指定文件同步、名字关联发布、相关目录项同步。第六题不能，新对象已经可见，应报告发布后错误。第七题不能，生命期和完成同步仍需协议。第八题130与120，不包含旋转、传输或真实设备基准。

## 4. 项目接口与明确结果

```text
./atomic-note OWN_DIRECTORY TEXT
```

TEXT为一个参数，最多1024字节，允许空文本，保存时再加换行。Shell引号负责保留空格。这个字节上限不是1024个中文字符；参数本身不能包含NUL。

返回0：要求的发布与同步调用成功；1：发布以前失败，按本地受控环境协议保留旧目标；2：参数错误，尚未打开目录；3：发布以后又出现错误，具体诊断说明阶段，不假称旧版本未变。

临时对象与目标都在同一个已打开目录下；新对象请求0600，实际还受umask等影响。不保留旧inode、硬链接关联、ACL或历史版本；这是发布新对象，不是原地修改所有名字引用的旧对象。

## 5. 状态与资源归属

main持有目录fd；临时文件创建成功以后持有temp fd与临时名字。文件同步和关闭完成后，renameat发布；成功后临时名字不再需要清理，目标note.txt成为新对象名字。

清理只移除自己本次成功建立的临时名，绝不在发布后随手unlink note.txt“回滚”。目录同步或关闭出错时新目标可能已可见，返回3。只检查旧/新内容的正常可见性，不把它当掉电证明。

## 6. 完整参考实现

**完整程序：atomic-note.c**

```c
#include "lab.h"
#include <fcntl.h>

static int write_complete(int fd, const char *data, size_t length) {
    while (length > 0) {
        ssize_t n = write(fd, data, length);
        if (n < 0 && errno == EINTR) { continue; }
        if (n < 0) { return -1; }
        if (n == 0) { errno = EIO; return -1; }
        data += n;
        length -= (size_t)n;
    }
    return 0;
}
static int sync_retry(int fd) {
    while (fsync(fd) < 0) {
        if (errno != EINTR) { return -1; }
    }
    return 0;
}
int main(int argc, char *argv[]) {
    if (argc != 3 || strlen(argv[2]) > 1024) {
        fputs("usage: atomic-note OWN_DIRECTORY TEXT (max 1024 bytes)\n", stderr);
        return 2;
    }
    int directory = open(argv[1], O_RDONLY | O_DIRECTORY | O_CLOEXEC);
    if (directory < 0) { die("open own directory"); }
    int file = -1, temporary_exists = 0, published = 0, status = 1;
    char temporary[80];
    for (unsigned attempt = 0; attempt < 64; attempt++) {
        int length = snprintf(temporary, sizeof temporary, ".note.tmp.%ld.%u", (long)getpid(), attempt);
        if (length < 0 || (size_t)length >= sizeof temporary) {
            fputs("temporary name too long\n", stderr); goto cleanup;
        }
        file = openat(directory, temporary, O_WRONLY | O_CREAT | O_EXCL | O_CLOEXEC, 0600);
        if (file >= 0) { temporary_exists = 1; break; }
        if (errno != EEXIST) { perror("create temporary"); goto cleanup; }
    }
    if (file < 0) { fputs("could not reserve a temporary name\n", stderr); goto cleanup; }
    if (write_complete(file, argv[2], strlen(argv[2])) < 0 || write_complete(file, "\n", 1) < 0) {
        perror("write temporary"); goto cleanup;
    }
    if (sync_retry(file) < 0) { perror("sync temporary"); goto cleanup; }
    int close_result = close(file);
    file = -1;
    if (close_result < 0) { perror("close temporary"); goto cleanup; }
    if (renameat(directory, temporary, directory, "note.txt") < 0) {
        perror("publish rename"); goto cleanup;
    }
    temporary_exists = 0;
    published = 1;
    if (sync_retry(directory) < 0) {
        perror("published; directory sync failed"); status = 3; goto cleanup;
    }
    status = 0;
cleanup:
    if (file >= 0 && close(file) < 0) {
        perror("cleanup temporary descriptor"); status = published ? 3 : 1;
    }
    if (temporary_exists && unlinkat(directory, temporary, 0) < 0) {
        perror("cleanup temporary name"); status = published ? 3 : 1;
    }
    if (close(directory) < 0) { perror("close directory"); status = published ? 3 : 1; }
    if (status == 0) { puts("published_and_synced"); }
    return status;
}
```

这是一份Linux本地课堂实现。close报告错误时不盲目重试旧fd，避免编号已释放后误关别的对象；测试专门覆盖“实际关闭后报告错误”的路径。遇到真实平台不同语义时，应依据平台说明调整，不能把此模板当全平台库。

## 7. 按阶段读代码

write_complete循环处理短写和EINTR，零进展主动设EIO再返回，调用者负责清理，不像lab.h的write_all直接退出。sync_retry只重试中断，其他同步失败保留错误。

临时名由PID和有限尝试序号组成，但**唯一性由O_EXCL决定**，不是相信PID绝不重复。已有临时名不会被打开覆盖；64次碰撞后失败，不无限重试。

文件同步成功以后才关闭并发布。发布标志单独保存，后续错误的状态取决于是否越过这条边界。只有全部清理与关闭也成功，才打印正常成功消息。

## 8. 第一次运行只用新目录

在本批Bash目录编译并建立新项目目录：

```bash
gcc -std=c17 -D_POSIX_C_SOURCE=200809L -Wall -Wextra -Wpedantic -Werror -g atomic-note.c -o atomic-note
note_dir=$(mktemp -d "$PWD/note-project-XXXXXX")
./atomic-note "$note_dir" 'first version'
cat "$note_dir/note.txt"
./atomic-note "$note_dir" 'second version'
cat "$note_dir/note.txt"
```

两次应报告published_and_synced，最终内容second version加换行。这个专用目录就是允许替换的范围。不要改成自己的笔记、系统配置或其他教程目录再“随便试一下”。

目录fsync若不受当前文件系统支持，程序可能在新版本已发布后返回3；请读错误记录，不删检查也不把失败重标成成功。本批实际在Linux文件系统验证。

## 9. 老fd、硬链接与新名字

保存新版本是创建新对象并替换一个名字。若原note.txt还有另一个硬链接，那个名字仍引用旧对象；若有人已经打开旧fd，也仍可读取旧内容。

这不是项目漏改一个路径，而是协议定义。若产品需求是编辑同一对象、保持所有硬链接看到同样变化，或保留权限/扩展属性，就要另做设计。这里以新对象发布换取较清楚的准备与可见边界。

## 10. 错误阶段验收表

| 注入位置 | 退出 | 目标的正常可见状态 | 本次临时名 |
| --- | --- | --- | --- |
| 临时创建/写入失败 | 1 | 旧目标保留 | 尽力清理自己的名字 |
| 文件fsync或关闭失败 | 1 | 旧目标保留 | 尽力清理 |
| rename失败 | 1 | 未由本次发布替换 | 尽力清理 |
| rename成功、目录fsync失败 | 3 | 新版本已可见 | 临时名已发布消失 |
| 发布后目录close失败 | 3 | 新版本已可见，读具体错误 | 不删除目标 |
| 全部成功 | 0 | 新版本完整 | 无本次临时名残留 |

配套包装器会定点模拟这些失败，并记录文件同步→关闭→rename→目录同步的顺序。它不等于真实断电模型，旧目标前提也依赖受控目录中没有其他写者干预。

## 11. 跨章验收与限制

路径权限：以普通用户验证文件/目录各权限，现有文件不被排他创建覆盖。链接与偏移：检查dev/ino关系、dup与独立open、unlink后fd。目录：空、正常、错误、特殊名字和1000项边界。设备模型：就绪后读尾部、FCFS/SSTF/LOOK有限路径。

保存器要覆盖空文本、1024字节、超限、原目标已有硬链接或打开fd、发布前失败和发布后错误；输出或错误状态与实际文件状态一起看。清理失败可能残留临时名，必须报告，不能称为所有故障都自动恢复。

没有并发写者冲突解决、完整ACL继承、加密擦除、递归安全扫描、远端NFS提交判定、真实断电恢复、驱动或硬件性能验收。这些限制分别对应明确未实现的需求，不妨碍本批有限协议的学习。
