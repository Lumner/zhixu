## 3. 概念题参考答案

第一题第一次从p发送12，第二次从p+5发送7，完成后剩余0。不是从头再发7。

第二题不能。普通私有变量分开变化；父亲从等待接口得到退出信息，不是自动读取孩子内存。第三题PID保持，旧printf只会在exec失败后才有机会执行。

第四题不一定，另一个进程仍有写端引用。第五题避免在异步处理上下文调用不安全的stdio操作；同时让收尾顺序更清楚。第六题依次为检查0、通知到达并设1、处理函数返回、调用pause、此后没有新通知。

第七题FCFS等待0/4/6，平均10/3≈3.333；SJF按B/C/A运行，按A/B/C列等待4/0/2，平均2。第八题可以，响应只统计第一次运行以前，等待累计全部就绪间隔。

## 4. 项目需求先写清

作品名`pipeline-run`，命令格式：

```text
./pipeline-run LEFT_PROGRAM [LEFT_ARG ...] -- RIGHT_PROGRAM [RIGHT_ARG ...]
```

以一个独立参数`--`作为分隔，左程序的标准输出连到右程序的标准输入；两边标准错误仍用于诊断。父进程启动两边后关闭自己的管道引用，再回收两边，在标准错误报告两个退出结果。

为保持参数协议简单，**恰好一个**参数可以等于`--`；本版不能把独立`--`再作为目标程序自己的参数。两边不能为空。不解析一整行文本，不支持Shell内建、引号语法解释、重定向符或作业控制。命令行中的引号已由外层Bash处理完毕。

本版选择返回右程序的状态，类似一种常见管道约定；它没有实现pipefail。左边失败、右边读取空输入后正常结束时，整个命令器仍可能返回0，必须结合两边状态解释。

## 5. 先把接线和关闭责任画出来

```text
左孩子：stdout(1) → 管道写端
                       ↓ 字节流
右孩子：stdin(0)  ← 管道读端
父进程：两边创建完后不保留任一管道端点，只负责等待
```

左孩子只保留写入所需引用，右孩子只保留读取所需引用。dup2完成后关闭多余原编号，避免exec后目标程序继承不需要的端点。父亲也必须关掉两端，尤其不能握着写端等待右程序EOF。

先创建左，再创建右，然后等待。若第二次fork失败，已经存在的左孩子可能阻塞写管道；父亲关闭端点并终止自己记录的左孩子，随后回收，避免留下未受管理的实验进程。只针对成功记录的正PID，不对0、-1或外部PID发信号。

## 6. 完整项目参考实现

**完整程序：pipeline-run.c**

```c
#include "lab.h"
#include <signal.h>

static int connect_pipe(int source, int target, const int fd[2]) {
    if (dup2(source, target) < 0) {
        perror("dup2");
        return -1;
    }
    for (int i = 0; i < 2; i++) {
        if (fd[i] != target && close(fd[i]) < 0) {
            perror("close pipe in child");
            return -1;
        }
    }
    return 0;
}

static void stop_and_reap(pid_t child) {
    if (kill(child, SIGKILL) < 0 && errno != ESRCH) { perror("kill cleanup"); }
    (void)wait_child(child);
}

int main(int argc, char *argv[]) {
    int split = -1;
    for (int i = 1; i < argc; i++) {
        if (strcmp(argv[i], "--") == 0) {
            if (split != -1) {
                fputs("exactly one -- separator is allowed\n", stderr);
                return 2;
            }
            split = i;
        }
    }
    if (split <= 1 || split >= argc - 1) {
        fprintf(stderr, "usage: %s LEFT [ARG ...] -- RIGHT [ARG ...]\n", argv[0]);
        return 2;
    }
    argv[split] = NULL;
    char **left_args = &argv[1];
    char **right_args = &argv[split + 1];
    int fd[2];
    if (pipe(fd) < 0) { die("pipe"); }
    if (fflush(NULL) == EOF) { die("fflush"); }
    pid_t left = fork();
    if (left < 0) {
        perror("fork left");
        close(fd[0]);
        close(fd[1]);
        return 1;
    }
    if (left == 0) {
        if (connect_pipe(fd[1], STDOUT_FILENO, fd) < 0) { _exit(1); }
        execvp(left_args[0], left_args);
        perror("exec left");
        _exit(127);
    }
    pid_t right = fork();
    if (right < 0) {
        perror("fork right");
        close(fd[0]);
        close(fd[1]);
        stop_and_reap(left);
        return 1;
    }
    if (right == 0) {
        if (connect_pipe(fd[0], STDIN_FILENO, fd) < 0) { _exit(1); }
        execvp(right_args[0], right_args);
        perror("exec right");
        _exit(127);
    }
    int close_failed = 0;
    if (close(fd[0]) < 0) { perror("close parent read"); close_failed = 1; }
    if (close(fd[1]) < 0) { perror("close parent write"); close_failed = 1; }
    if (close_failed) {
        stop_and_reap(left);
        stop_and_reap(right);
        return 1;
    }
    int left_code = wait_child(left);
    int right_code = wait_child(right);
    fprintf(stderr, "left_exit=%d right_exit=%d\n", left_code, right_code);
    return right_code;
}
```

本版是单线程实验程序；第12章关于多线程fork后调用限制仍适用。常规错误路径会回收已创建孩子；外部强行终止父进程、输出设备故障以及任意目标程序不自行结束等情形，不在这个小命令器的完整管理承诺内。

## 7. 分四段读代码，不要逐符号硬背

第一段找分隔符并校验。`argv[split] = NULL`把左参数向量截断；右边从下一格开始，仍使用原末尾NULL。没有创建悬空字符串，也没有让左程序收到`--`。

第二段创建pipe和左孩子。`connect_pipe`先dup2，再关闭非目标的原管道编号；源编号恰好等于目标时也不误关。孩子exec失败就127退出，不回到父亲逻辑。

第三段创建右孩子。失败时先关闭父亲端点，终止并回收已创建的左孩子；成功时两个程序可以同时推进。不要把等待左孩子移到第二次fork以前。

第四段父亲关端点并等待两边。虽然先wait左边，右边早已运行，不存在“还没启动消费者”的问题。孩子可能以任意顺序结束，两个状态分别保存；管理输出到stderr，数据输出留给右程序。

## 8. 第一次运行：六个字节

在本批Bash目录编译：

```bash
gcc -std=c17 -D_POSIX_C_SOURCE=200809L -Wall -Wextra -Wpedantic -Werror -g pipeline-run.c -o pipeline-run
./pipeline-run printf '%s\n' hello -- wc -c
echo $?
```

左侧外部printf输出`hello`加换行，共6字节；右侧wc统计字节数，标准输出应代表整数6，格式可能带空格。父亲在stderr报告`left_exit=0 right_exit=0`，整个命令退出0。

`'%s\n'`先由Bash保持为一个参数，再由printf按自己的格式规则解释；不是pipeline-run解析转义。如果环境找不到对应外部程序，先用自己编译的`argv-view`做参数检查，或核对系统中实际安装路径。

## 9. 大数据为什么必须测

在本批目录执行，使用环境已有的外部`seq`和`wc`：

```bash
./pipeline-run seq 1 100000 -- wc -l
```

应统计100000行，双方退出0。数据总量超过本环境管道容量，所以能检验“生产者和消费者都已启动再等待”的关键设计；不依赖容量具体是多少。若本机缺seq，不必为主线卡住，验证脚本还使用自编译的有限字节生产者和计数器完成同类检查。

大数据成功不证明所有资源与信号组合都无错；它验证的是有限输入下接线、并行推进、EOF与回收这条路径。测试时设置超时，若失败要清理该次测试自己创建的进程，不向任意系统进程发终止信号。

## 10. 错误路径逐项验收

| 输入或情形 | 应有行为 | 要观察什么 |
| --- | --- | --- |
| 没有--、左空、右空、多个-- | 用法错误，退出2 | 不启动目标程序 |
| 左程序不存在，右为wc -c | 左127，右可能0，整体按右返回 | 诊断和双边状态，不只看整体0 |
| 右程序不存在 | 右127，整体127 | 左边可能正常或因无读者收到SIGPIPE |
| pipe失败 | 报错，退出1 | 尚未创建孩子 |
| 第一次fork失败 | 关父亲两端，退出1 | 没有孩子需要回收 |
| 第二次fork失败 | 关端点、终止并回收左孩子，退出1 | 不遗留左孩子 |

不要人为耗尽系统资源来触发pipe/fork失败。配套脚本用链接包装器定点模拟这些失败，且只跟踪自己创建的孩子；真实正常进程实验与注入路径分别记录。

## 11. 调度题的完整演算

仍用A/B/C在0到达、工作量4/2/2，时间片1。时间线：

```text
0..1 A，1..2 B，2..3 C，3..4 A，4..5 B，5..6 C，6..7 A，7..8 A
```

| 任务 | 完成 | 周转 | 等待 | 响应 |
| --- | --- | --- | --- | --- |
| A | 8 | 8 | 4 | 0 |
| B | 5 | 5 | 3 | 1 |
| C | 6 | 6 | 4 | 2 |

平均等待11/3≈3.667，平均响应1。最后两段都由A运行，是因为其他任务已经完成；是否真的发生上下文切换取决于实现，不能仅凭时间片边界就断言换成了另一个任务。本题依然假设零切换开销。
