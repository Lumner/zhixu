# 最终综合实践：系统实验台

## 作品与输入范围

建立一个保留源码、运行说明与验证记录的个人系统实验台，核心工具为第 35 章 mini-shell。课程提供基线代码，毕业实践要求自己解释并完成一个小改造。依赖 Linux/POSIX 与 GCC，非完整 POSIX Shell，不用于替换系统登录 Shell。

## 最小完成清单

| 能力 | 验收输入/操作 | 预期 |
| --- | --- | --- |
| 编译 | `make all` | 全部教学例程编译成功 |
| 外部程序 | Shell 中 `echo hello` | 输出 hello |
| 内置目录 | `pwd`、`cd ..`、`pwd` | Shell 自己的目录变化 |
| 管道 | `printf abc | wc -c` | 结果 3，正常结束 |
| 输出文件 | `echo saved > result.txt` | 新文件内容 saved 加换行 |
| 管道重定向 | `printf abc | wc -c > count.txt` | 文件中为 3 |
| 错误程序 | 不存在的命令后 exit | 错误信息，退出 127 |
| 无效语法 | `echo a |` | 拒绝，状态 2 |
| 输入上限 | 超过一行容量 | 拒绝并清掉本行剩余输入 |
| 并发计数 | 运行 mutex | counter=20000 |
| 条件终止 | 运行 queue | sum=15，结束无挂起 |
| 概念模型 | paging/replacement | 地址翻译和手算结果一致 |

重定向会覆盖指定目标，只使用本次练习目录内可覆盖的测试文件。完整自动脚本在 [验证脚本](验证/verify.py)，运行方式与真实结果见 [验证记录](验证/验证记录.md)。

## 自己补充的改造

从 help、追加输出、三段管道中选一项。先写输入与预期，再设计解析状态和 fd 关系。每个新增路径包含正常、缺失参数、资源打开失败和不支持组合；不要一次同时扩展五种语法而失去排错线索。

## 交付说明模板

写下你的 Linux、GCC 版本，编译与运行命令，支持语法、失败输入与结果、描述符关闭设计、改造点、已验证范围与限制。附一次真实观察记录，不放包含私人路径或文件内容的无关输出。

能讲清“输入一行后发生什么”比把工具做得像完整 Bash 更重要。若继续扩展到完整作业控制、引号解析或不可信服务，需要单独设计和验证。
