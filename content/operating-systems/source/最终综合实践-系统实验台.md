# 最终综合实践：系统实验台毕业验收

36章详细主线完成后，用自己的运行记录完成本页验收。核心作品是第35章mini-shell和第九批的help改造，配套一份第34章观察报告与第36章闭卷复盘。平台为Linux/POSIX；程序是教学工具，不替换系统登录Shell。

## 一、先准备可复现目录

保留原下载包，自己的源码副本和编译产物分别整理。按照 [第35章](35-综合项目小型Shell.md)准备mini-shell.c与lab.h，按 [第九批练习](详写第九批-练习与参考答案.md)生成mini-shell-help.c。在Ubuntu/WSL的Bash中编译，再进入仅含本次测试文件的graduation-box运行。

报告写清每组命令属于Bash还是mini-shell。mini-shell里的`exit`回到Bash后，立即运行`echo $?`查看本次状态；如果先执行成功命令，旧状态就会被更新。只在自己的测试目录使用`>`，它会创建或覆盖目标。

## 二、功能验收矩阵

| 能力 | 输入/操作 | 通过证据 |
| --- | --- | --- |
| 编译基线与改造 | 按正文C17和警告命令编译 | 无诊断，运行的是新二进制 |
| 外部命令 | `echo hello` | hello加换行 |
| 内置目录 | `pwd`、`cd ..`、`pwd` | 父Shell目录确实变化 |
| 两段管道 | `printf abc | wc -c` | 数值3，能够结束 |
| 较大管道 | `seq 1 50000 | wc -l` | 数值50000，能够结束 |
| 输出文件 | `echo saved > result.txt` | 指定字节内容正确 |
| 管道加输出 | `printf abc | wc -c > count.txt` | 文件数值3 |
| 找不到程序 | 不存在命令后立即exit | 状态127与诊断 |
| 不可执行对象 | 自己的无执行权限文件 | 状态126 |
| 无效语法 | `echo a |` | 状态2，无执行副作用 |
| 失败恢复 | 失败后`echo recovered` | 主循环继续，后一次状态0 |
| 容量 | 63/64个token，1023/1024字节 | 前者边界与拒绝符合约定 |
| 非文本记录 | 含NUL的二进制测试输入 | 拒绝整行，不执行前缀 |
| help改造 | help、额外参数、管道/输出组合 | 成功或拒绝符合统一规则 |

手工终端不用输入NUL，自动脚本会在自己的临时目录构造。你的报告可记录自动验证结果并解释为何需要该边界；若修改输入实现，必须重新验证相关行为。

## 三、跨阶段能力验收

任选一个早期C程序不看答案重写，解释类型、容量和错误返回；任选一个进程或线程实验画执行与等待关系；手算一次分页与置换；画文件名字、打开引用与保存阶段；最后为本机请求项目说明协议和半关闭。这五项至少各留一份自己完成的证据。

不要求再造全部章节程序，也不把课程提供的历史日志当作自己的作业。若某部分说不清，回相应详细批次重做小实验，再回到毕业项目组合。

## 四、观察报告与闭卷复盘

第34章报告应有同一二进制的重复结果、checksum、wall与cpu解释、一个待验证假设。未安装strace就写未执行，不用伪造跟踪输出。

第36章十二题先闭卷答，再核对参考答案。每题结论后补最小条件、对象关系或一个反例。错题复盘写“我混淆了什么”“哪个实验能区分”，不要只把答案全文抄一遍。

## 五、失败与资源设计审查

独立画一条管道加重定向的fd矩阵，写出每个分支需要关闭什么、谁回收child。说明第二次fork失败时为什么不能无条件等待正在长时间运行的左侧；同时注明本实现只终止自己的直接child，没有完整后代和作业控制设计。

写出四种不同失败：输入语法错误、外部程序不存在、输出文件打不开、资源创建失败。它们发生位置与状态约定不同，不能一律归为“系统错误”。错误注入验证用户态分支，不证明真实设备、内核和所有环境都已覆盖。
