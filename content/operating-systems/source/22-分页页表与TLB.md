## 22.1 固定大小的映射单位

分页把虚拟地址空间切成页，把物理内存切成同样大小的页框。页表记录虚拟页映射到哪个页框以及存在、权限等状态。一个虚拟页不要求与相邻页在物理内存中连续。

简化公式：页号=虚拟地址整除页大小；页内偏移=虚拟地址对页大小取余；物理地址=页框号×页大小+偏移。页大小为 2 的幂时，可把地址位拆成高位页号和低位偏移。

## 22.2 先用微型数字手算

设页大小 4 字节，虚拟地址 13；页号 3，偏移 1。页表为 0→5、1→2、2→7、3→1，则物理地址为 1×4+1=5。这里故意用很小页方便演算，真实系统通常使用大得多的页面，并可能支持多种页大小。

[完整源码：paging.c](示例代码/paging.c)

```c
/* Model only: not a real page table. */
#include <stdio.h>

int main(void) {
    unsigned address = 13;
    unsigned page_size = 4;
    unsigned frames[] = {5, 2, 7, 1};
    unsigned page = address / page_size;
    unsigned offset = address % page_size;
    printf("page=%u offset=%u physical=%u\n",
           page, offset, frames[page] * page_size + offset);
    return 0;
}
```

`make paging`、`./paging`，输出 `page=3 offset=1 physical=5`。frames 数组是教材页表模型，不是程序在修改真实硬件页表。address 固定在合法范围；改成任意输入前需要检查页号是否落入数组，并处理不存在或无权限的项。

## 22.3 多级页表为何存在

若虚拟地址空间很大，单级表即使只使用少量区域也可能很大。多级页表把映射结构分层，未使用的范围可以不分配下级表，以额外访问层次换取稀疏空间效率。访问过程中既要定位映射，也要检查权限。

举例：32 位虚拟地址、4 KiB 页面，偏移占 12 位，页号占 20 位；若每项 4 字节，完整单级表需 2^20×4=4 MiB。数字是假设配置下的算例，不是每个系统真实页表大小。

## 22.4 TLB 缓存地址翻译

TLB 缓存近期的地址翻译，使多数访问不必走完整页表。TLB miss 表示需要寻找映射，映射本身可能有效；page fault 表示翻译/权限等检查需要异常处理。两者不能互换。

简化性能模型：TLB 查询 1ns，内存访问 100ns，单级页表查询额外一次内存访问，命中率 90%，不考虑重叠与缺页。命中耗时 101ns，未命中 201ns，期望 0.9×101+0.1×201=111ns。现实 CPU 的并行、缓存和多级遍历复杂得多，此算例只展示命中率的影响。
