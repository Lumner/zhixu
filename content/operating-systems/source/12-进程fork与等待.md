# 12 进程、fork与等待：一份代码怎样走出两条路

> **零基础详细版 · 已重写。** 本章使用有限数量的子进程观察创建、独立变量和退出回收，不靠延时猜测运行顺序。建议6—8小时。

## 1. 目标与先修

先完成第11章，知道描述符、返回值和系统调用；复习第05章条件分支、第08章地址和第10章输出缓冲。本章要做到：读懂`fork`的三种返回、解释父子变量为什么分开变化、用`waitpid`取得退出结果，并写出只创建两个孩子的程序。

先不要把“多进程”理解成“屏幕同时打印两行”。进程既有自己的执行位置和地址空间，也引用文件等资源。打印顺序只是其中一个观察窗口。

## 2. 程序和进程有什么不同

**程序**是保存在文件中的指令与数据，例如编译得到的`./process`。**进程**是操作系统管理的一次程序执行实例。同一程序可以启动多次，形成不同进程；一个进程后来也可以装入另一份程序，第13章讨论。

可以把程序比作菜谱，进程比作正在进行的一次做菜过程。菜谱不变，两次做菜却可以有不同进度和材料。这个类比不能解释内存保护，只帮助区分“静态文件”和“正在执行的状态”。

进程的状态包括：下一步要执行哪里、寄存器与栈、可访问的虚拟内存、打开的描述符，以及身份和管理信息。**PID**是系统分配的进程标识，存活期间用于指代该进程；它不是永久不变的身份证，进程结束并回收后数值可能被重用。

## 3. fork的接口约定

`fork()`尝试创建调用进程的一个子进程。原来的叫**父进程**，新建的叫**子进程**。成功后，两者都从`fork`返回处继续，但返回值不同。

| 在哪里观察 | 返回值 | 应走的分支 |
| --- | --- | --- |
| 创建失败，只有原进程 | -1 | 报告错误，不存在这个新孩子 |
| 子进程 | 0 | 执行子分支 |
| 父进程 | 子进程的正PID | 保存PID，以便等待或发送信号 |

返回类型是`pid_t`，由系统头文件定义。不要写`if (fork())`把成功父分支和失败混在一起。先保存，再先判负、后判零，可以把三条契约清楚表达出来。

## 4. 它不会让main从头重跑

以下是**概念模型，不是完整程序**：

```text
父进程：准备变量 → fork → 得到正PID → 父分支
                         ↘ 得到0     → 子分支
```

子进程不会重新执行`fork`以前的C语句。不过父进程当时尚未刷出的C库缓冲可能被复制，之后由两边各自刷出，看起来像“以前的printf执行了两次”。第8节专门处理这个问题。

两条分支的先后由调度决定。父进程没有天然优先权，代码写在文件中的上下顺序也不能对两个进程建立先后关系。要让某一步一定晚于子进程结束，需要等待接口，而不是“机器通常够快”。

## 5. 第一份主线例程

Linux/WSL Ubuntu的Bash终端，目录`~/os-lab/processes`。确保第11章的`lab.h`已复制到此目录。

[完整源码：process.c](示例代码/process.c)

```c
#include "lab.h"

int main(void) {
    int value = 10;
    fflush(NULL);
    pid_t pid = fork();
    if (pid < 0) { die("fork"); }
    if (pid == 0) {
        value = 99;
        printf("child value=%d\n", value);
        fflush(stdout);
        _exit(7);
    }
    int code = wait_child(pid);
    printf("parent value=%d child_exit=%d\n", value, code);
    return 0;
}
```

保存为`process.c`，编译运行：

```bash
gcc -std=c17 -D_POSIX_C_SOURCE=200809L -Wall -Wextra -Wpedantic -Werror -g process.c -o process
./process
echo $?
```

正常输出：

```text
child value=99
parent value=10 child_exit=7
0
```

最后的0属于Shell的`echo $?`，不是`process`自己打印。父进程在`main`返回0；子进程退出7。两个进程有各自的退出状态，不能因为孩子失败就认为父进程一定自动返回相同状态。

## 6. 逐步跟踪两份value

| 步骤 | 父进程value | 子进程value | 发生什么 |
| --- | --- | --- | --- |
| fork以前 | 10 | 尚不存在 | 只有一个变量实例 |
| fork成功后 | 10 | 10 | 两边看到各自地址空间里的初始值 |
| 子分支赋值 | 10 | 99 | 改的是子进程那一份 |
| 子进程退出 | 10 | 不再执行 | 父进程等待结果 |
| 父进程输出 | 10 | 已结束 | 变量值和退出码来自不同渠道 |

父进程知道7，是因为操作系统保存了孩子的退出信息，`wait_child`读取后返回；不是因为父进程看到了孩子的栈变量。

Linux可以用**写时复制**优化地址空间复制：起初某些物理页可以暂时共用，发生写入时再分离。但程序应依赖“普通私有内存的修改互不直接可见”这个语义，不从某一次地址打印推断物理页是否共用。共享内存映射另有明确接口，第24章再学。

## 7. 打印PID观察fork返回

**完整程序：fork-return.c**

```c
#include "lab.h"

int main(void) {
    if (fflush(NULL) == EOF) { die("fflush"); }
    pid_t child = fork();
    if (child < 0) { die("fork"); }
    if (child == 0) {
        printf("child pid=%ld fork_result=0\n", (long)getpid());
        if (fflush(stdout) == EOF) { _exit(1); }
        _exit(0);
    }
    int code = wait_child(child);
    printf("parent pid=%ld child_pid=%ld child_exit=%d\n",
           (long)getpid(), (long)child, code);
    return code;
}
```

使用前面的编译选项编译为`fork-return`。`getpid()`取得调用者自己的PID；`(long)`配合`%ld`用于本课POSIX平台的打印。运行两次，PID通常会变化，不能把教材里的某个数字写死为预期。

第一行的孩子PID应等于第二行的`child_pid`，并与父PID不同。这些关系比具体数字更有验证价值。第二行晚于第一行，是因为孩子先刷出输出并退出，父进程等待完才打印。

## 8. fork以前为什么先fflush

`fflush(NULL)`请求刷出所有打开的输出流。假设fork以前`printf("ready")`没有换行，文字还在C库缓冲中；复制地址空间也复制了这份未刷出的缓冲状态。若父子后来都用普通退出路径刷出缓冲，就可能出现两份`ready`。

稳妥的教学顺序是：在创建子进程前刷出已有输出；子进程需要打印时，检查刷新；用`_exit`结束子分支。`_exit`直接结束进程，不执行普通C退出清理，也不会替你刷新stdio，所以不能打印后就假定它会帮你送出。

原主线例程为了简洁省略了`fflush`返回检查；扩展实验展示了检查版本。输出设备失败时，原例不保证把打印失败转换成非零退出，这是例程限制，不把正常输出测试说成完整的I/O故障证明。

## 9. waitpid到底在等什么

`waitpid(child, &status, 0)`等待这个指定孩子发生终止，并取得编码后的状态。第三个参数0表示这里使用阻塞等待。**阻塞**表示当前任务暂时不能继续这一调用，等待条件满足；它不等于整个电脑停止工作。

`status`不是孩子直接返回的那个整数，它还包含“正常退出还是被信号终止”等信息。必须先判断对应类别，再用宏提取。下面是**需要lab.h上下文的函数片段**：

```c
static inline int wait_child(pid_t pid) {
    int status;
    while (waitpid(pid, &status, 0) < 0) {
        if (errno != EINTR) { die("waitpid"); }
    }
    if (WIFEXITED(status)) { return WEXITSTATUS(status); }
    if (WIFSIGNALED(status)) { return 128 + WTERMSIG(status); }
    return 1;
}
```

`&status`提供可写地址，让接口把信息填进去。`WIFEXITED`为真时才使用`WEXITSTATUS`；`WIFSIGNALED`为真时才使用`WTERMSIG`。`128 + 信号编号`是本课辅助函数选择的命令状态约定，不是内核把所有终止都编码成这个数。正常退出码在这套POSIX等待接口中只保留低8位，实验使用0—127范围内的小值。

## 10. 被打断与等待错误

如果`waitpid`被信号打断并报告`EINTR`，辅助函数继续等待同一个孩子。如果传入的并非自己可等待的子进程，可能得到`ECHILD`，这不是靠重试能解决的正常中断。

本章只等待自己创建并记录的正PID。不把`-1`等具有特殊含义的参数随意塞入封装；后续需要“任意孩子”时会单独解释。`WNOHANG`可以用来查询而不阻塞：返回0表示匹配孩子还没有可报告的状态，并不代表它已经退出0。本章不使用忙循环反复查询，因为那会无意义地占用CPU。

## 11. 只创建两个孩子

**完整程序：two-children.c**

```c
#include "lab.h"

int main(void) {
    pid_t children[2];
    int count = 0;
    if (fflush(NULL) == EOF) { die("fflush"); }
    for (int i = 0; i < 2; i++) {
        pid_t pid = fork();
        if (pid < 0) {
            perror("fork");
            for (int j = 0; j < count; j++) { (void)wait_child(children[j]); }
            return 1;
        }
        if (pid == 0) {
            printf("child index=%d\n", i);
            if (fflush(stdout) == EOF) { _exit(1); }
            _exit(i + 3);
        }
        children[count++] = pid;
    }
    for (int i = 0; i < count; i++) {
        int code = wait_child(children[i]);
        printf("reaped index=%d exit=%d\n", i, code);
    }
    return 0;
}
```

编译为`two-children`。应出现`child index=0`、`child index=1`，以及回收结果`reaped index=0 exit=3`、`reaped index=1 exit=4`。两个孩子打印的先后不固定；父进程按数组顺序等待，所以它自己的两条回收输出保持索引顺序。某个回收输出可能出现在另一个孩子的输出之前，这也符合逻辑。

不要把预期写成四行唯一的全局顺序。应检查每个孩子恰好打印一次、每个退出码匹配、两次回收发生。已经结束的孩子也可稍后等待，等待不要求恰好在它结束的那一刻调用。

## 12. 为什么孩子必须在循环里结束

父进程在循环中创建两个孩子；孩子走到`_exit`，不会回到循环继续创建。若删掉子分支的退出，孩子也会进入下一次循环，进程数量就会变化，代码意图被破坏。

本课不运行无限创建进程的程序。理解数量变化可以用纸面树图完成。即使循环只有两次，也应从每条路径问：“谁还会执行下一次fork？”不是只数源码里出现了几个`fork`单词。

## 13. 失败时已经创建的孩子怎么办

假设第一次成功、第二次失败，父进程不能把第一次的孩子当作不存在。示例用`count`记录成功创建的数量；失败时先等待这些有限、会自行结束的孩子，再返回1。

如果孩子执行的是可能长期运行的未知程序，单纯等待就未必合适，需要设计取消协议或信号清理，第15章和综合练习再处理。这里孩子只打印并退出，失败收尾有清楚边界。

创建失败可能来自资源限制。遇到这种情况先查看错误和系统环境，不要不断提高数量重试。实际验证会通过受控的故障注入触发这条路径，不故意耗尽用户机器资源。

## 14. 进程状态按什么理解

| 简化状态 | 是否可以立即使用CPU | 例子 |
| --- | --- | --- |
| 就绪 | 可以，但尚未被选中 | 子进程已创建，等待轮到它 |
| 运行 | 正在使用某个CPU | 执行赋值与计算 |
| 阻塞等待 | 条件未满足，暂时不可以 | 等待孩子结束或等待输入 |
| 已终止待回收 | 不再运行 | 退出信息还等父进程领取 |

这是教学状态模型；真实Linux还细分睡眠、停止等状态，命令显示的字母也有各自定义。不要把“没有打印”直接等同于阻塞，可能只是调度尚未轮到、输出仍在缓冲，或者代码根本没走到那里。

## 15. 内存独立，所有资源都独立吗

不是。普通变量在各自私有地址空间里变化；描述符则可以引用同一个底层打开对象，因而可能共享文件偏移。第14章会画描述符表并验证这一点。

本批fork例程都在单线程进程中运行。多线程程序fork后，子进程到exec之间允许安全调用的函数范围更严格，不能直接套用这里的stdio演示。第17章之后再区分这个场景，不把本章的便利写法推广到所有程序。

## 16. 常见误解怎样修正

“`pid == 0`所以孩子的PID是0”混淆了函数返回值和自身标识；用`getpid`验证。

“孩子先输出，所以fork保证孩子先运行”把一次现象当作约定；只有等待等同步关系才能建立需要的先后。

“父进程wait后能读取孩子改过的普通变量”混淆了等待结果与共享内存；用value表逐步追踪。

“`waitpid`得到7就直接打印status”忽略了状态编码；先分类再提取。

“加一秒sleep就能保证顺序”依赖运行速度；改成等待明确的事件。主线不靠延时完成同步。

## 17. 练习与参考答案

1. 把主线子进程的`value`改为20、退出码改为9，先写预期再编译运行。
2. `two-children`中父进程等待索引0时，索引1能否先结束？提示：等待谁与谁先结束不同。
3. 若第二次fork失败，`children[1]`是否已初始化，可否等待它？
4. 为什么fork以前的输出缓冲需要处理，孩子分支里的`fflush`又解决什么？
5. 对“父进程PID小于孩子PID，因此一定先执行父分支”给出判断。

参考答案：第一题孩子20、父亲10、`child_exit=9`，父亲仍返回0；第二题可以，索引1的退出信息稍后由父亲回收；第三题没有有效记录，只等待`count`个成功创建的孩子；第四题前者避免旧缓冲被复制后重复送出，后者在`_exit`前送出新打印内容；第五题错误，PID大小不建立调度顺序。

进阶手算：只在纸上分析两个连续fork且没有子分支退出的情况，成功后最终可有4个进程。把每次返回的0/正值写在树边；不需要用实际创建更多进程来证明算式。
