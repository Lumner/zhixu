# 06 函数、作用域与文件组织

> **零基础详细版 · 已重写。** 先完成第04—05章，能解释变量、条件与循环。本章连同拆文件和排错建议5—7小时。先用普通整数讲函数，不提前依赖下一章的数组。

## 6.1 为什么要给一组步骤取名字

假设程序要多次把两段学习时间相加。如果每处都重新写计算和检查，规则改变时容易漏掉某个副本。函数让我们把一项职责集中写在一个有名字的位置，通过调用来使用。

上一章main和printf已经是函数相关例子：main包含你这份程序的主要流程，printf提供输出能力。本章开始编写自己的函数，明确输入、输出和可使用的名字。

不要先把函数理解成“让代码变短的技巧”。它的重要作用是建立边界：调用者提供什么，函数保证做什么，失败或无结果如何表达。

## 6.2 目录、完整程序与第一轮预测

在Ubuntu Bash执行：

```bash
mkdir -p ~/os-lab/lesson06
cd ~/os-lab/lesson06
```

[完整源码：functions.c](示例代码/functions.c)

```c
#include <stdio.h>

int add_minutes(int left, int right) {
    return left + right;
}

int main(void) {
    int total = add_minutes(30, 60);
    printf("sum=%d\n", total);
    return 0;
}
```

保存为functions.c，编译运行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -g functions.c -o functions
./functions
```

输出sum=90。与一条直接加法不同，这里main把计算交给add_minutes，再接收它的结果。先确认能运行，随后逐个拆解。

## 6.3 定义、调用、参数与返回值

`int add_minutes(int left, int right)` 是函数定义的开头。最前面的int表示结果类型；add_minutes是函数名；括号里定义两个接收输入的参数，类型都是int。函数体由花括号包围。

`add_minutes(30, 60)` 是一次调用，按位置把30对应给left，把60对应给right。调用处提供的具体值称为实参，定义处接收它们的名字称为形参。先理解对应关系，不必只背两个名词。

函数体计算left+right得到90，return把90交给调用者。main用得到的结果初始化total，再printf它。函数的“输出结果”在这里是返回值，不要求函数体自己打印。

| 时刻 | 当前在执行哪里 | 重要数据 |
| --- | --- | --- |
| 开始main | 准备求total初值 | 需要计算调用表达式 |
| 进入add_minutes | 参数建立 | left=30，right=60 |
| 执行return | 计算30+60 | 返回90 |
| 回到main | 初始化total完成 | total=90 |
| printf | 显示total | sum=90 |

这种“先完成调用，再继续后面的步骤”是理解函数流程的基础。源文件中函数定义排在main之前，不表示程序启动时先无缘无故执行它一次。

## 6.4 调用发生几次，工作就按规则做几次

**完整程序：calls.c**

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    int morning = add(10, 20);
    int evening = add(30, 40);
    int total = add(morning, evening);
    printf("morning=%d evening=%d total=%d\n", morning, evening, total);
    return 0;
}
```

输出morning=30 evening=70 total=100。第一次调用的参数是10与20；第二次是30与40；第三次读取main里已经算出的两个变量值。

不同调用各自建立参数和局部运行状态。不要认为第一次a=10会让以后所有调用的a永久保持10。函数不是一个仅在第一次执行的宏大“初始化区域”。

## 6.5 传值：修改参数为什么不改原变量

C的参数传递按值进行。传普通int时，函数取得值，用自己的参数对象接收。给这个参数重新赋值，不等于给调用者原对象赋值。

**完整程序：parameter-copy.c**

```c
#include <stdio.h>

int increase(int value) {
    value = value + 10;
    printf("inside=%d\n", value);
    return value;
}

int main(void) {
    int minutes = 20;
    int result = increase(minutes);
    printf("outside=%d result=%d\n", minutes, result);
    return 0;
}
```

输出inside=30，然后outside=20 result=30。minutes仍是20，result接收返回的30。参数value是接收到20的新对象，不是minutes的另一个同义名字。

如果希望更新main的minutes，可以明确写 `minutes = increase(minutes);`，用返回值重新赋给它。第08章还会学习通过地址让函数访问调用者对象；那也不改变“指针参数本身按值传递”的规则。

## 6.6 返回值与打印不能互相替代

把计算函数写成只printf而不return结果，调用者就不能把屏幕上那串文字当整数自动接收。反过来，只return90但没有任何输出的函数，也不会为了让你看见而自动在终端打印90。

想复用计算结果，例如继续求平均值、与目标比较，应通过明确返回值或其他约定交回数据。显示如何排版则可以留给调用者。这就是把“计算规则”和“呈现方式”分开的实际意义。

参数与返回类型是接口的一部分。声明返回int，就不能随便省略所有执行路径的结果。编译器的返回值诊断值得认真处理，不能用最后随便加一个数字掩盖本来缺失的分支设计。

## 6.7 没有返回数据的函数用void

**完整程序：show-goal.c**

```c
#include <stdio.h>

void show_goal(int minutes) {
    printf("goal=%d minutes\n", minutes);
}

int main(void) {
    show_goal(30);
    return 0;
}
```

输出goal=30 minutes。void表示这个函数不返回可供调用者使用的值，不是返回一个特殊整数0。不能写 `int x = show_goal(30);` 期待工具猜测结果。

void函数可以用不带表达式的return提前结束；没有参数的函数在本课C17写成 `(void)`，明确表示不接收参数。不要把C17中的空括号声明与其他语言、其他C标准版本的规则混在一起。

## 6.8 作用域：这个名字在哪里能用

作用域描述名字在源代码哪些位置可见。块内声明的普通局部名字，通常从其声明后到该块结束可见。外面不能因为曾经执行过里面的代码，就继续用里面的局部名字。

**故意写错的完整程序：scope-error.c**

```c
#include <stdio.h>

int main(void) {
    if (1) {
        int local = 5;
        printf("inside=%d\n", local);
    }
    printf("outside=%d\n", local);
    return 0;
}
```

编译应失败，因为最后一条printf处的local不在可见范围。这里用if(1)保证分支成立，也不能改变源代码层面的作用域规则。修复方法是根据真实需要把对象声明在合适外层，或在块内完成使用，而不是全都改成全局变量。

## 6.9 作用域与生命期不是同一问题

作用域问“从哪里能用这个名字”；生命期问“对象从何时存在到何时不再作为该对象存在”。两者有关联，但不是同义词。

目前普通自动局部对象通常随对应块的一次执行建立和结束。下一次进入会有相应的新执行状态。第09章学习动态分配时，对象可以在函数返回后继续存在，但访问责任又需要另外管理。

两个函数都可以有叫minutes的参数，它们不是因为同名就共享同一个整数。若在内层声明同名变量，可能遮住外层名字，让阅读困难。本课尽量使用明确命名，不靠这种技巧写出难以跟踪的例子。

## 6.10 参数契约：类型之外还需要什么

函数头写两个int，不代表任何int组合都符合业务。add_minutes的教学契约可以约定：输入各在0—1440内，结果为两段分钟之和，在本课int范围内安全。

如果调用者传入负分钟，可能没有触犯int类型本身，却违反了业务前提；如果改为任意巨大整数，还可能出现有符号溢出。类型检查不能替你决定所有合法范围。

为函数写三句话：输入是什么、什么范围合法、返回值代表什么。含失败可能时再定义如何报告。这会为后面系统调用的返回值和错误协议做准备。

## 6.11 先声明接口，再放实现

函数声明告诉编译工具名字、参数和返回类型；函数定义在此基础上给出实现。前面的例子把实现放在main上方，所以调用前已经知道接口。

**完整程序：prototype.c**

```c
#include <stdio.h>

int add(int a, int b);

int main(void) {
    printf("sum=%d\n", add(2, 3));
    return 0;
}

int add(int a, int b) {
    return a + b;
}
```

输出sum=5。上面的 `int add(int a, int b);` 只有分号，没有函数体，是声明；后面带花括号的是定义。声明不是“已经实现”，但让前面的调用能按正确接口编译。

C17中不要依赖未声明函数被工具猜出类型。函数名、参数类型和返回类型都应保持一致。

## 6.12 为什么拆成多个文件

程序变大后，一份文件负责调用流程，另一份负责计算实现，共享接口放在头文件中，可以让边界更清楚。现在只拆一个很小的add，避免复杂目录遮住概念。

在lesson06建立子目录：

```bash
mkdir -p split
cd split
```

接下来三个文件必须在这个split目录里。每个代码块单独保存，不把三个文件全部粘进同一个main.c。

## 6.13 三个完整文件：接口、实现、调用

**完整文件：stats.h**

```c
#ifndef STATS_H
#define STATS_H
int add(int a, int b);
#endif
```

**完整文件：stats.c**

```c
#include "stats.h"

int add(int a, int b) {
    return a + b;
}
```

**完整文件：main.c**

```c
#include <stdio.h>
#include "stats.h"

int main(void) {
    printf("sum=%d\n", add(2, 3));
    return 0;
}
```

stats.h提供声明，stats.c提供实现，main.c使用它。双引号include在这里用于项目自己的头文件，尖括号stdio.h用于库头文件的常见写法；具体搜索位置由工具规则和选项决定。

头文件里的ifndef/define/endif是一套包含保护：若本次处理还没定义STATS_H，就处理其中内容并作标记，避免同一翻译过程重复包含。现阶段先认识完整形状，不需要自己设计复杂预处理逻辑。

## 6.14 一条编译命令为什么要列两个.c

在split目录的Bash中执行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -g main.c stats.c -o split-demo
./split-demo
```

应输出sum=5。编译工具处理两个源文件，后续链接把调用与实现关联起来。头文件通过include提供声明，不要把它当作遗漏的函数实现。

现在故意只给main.c：`gcc -std=c17 -Wall -Wextra -Wpedantic -g main.c -o missing-demo`。编译器看得到声明，但链接阶段找不到你这个add的实现，通常出现undefined reference等链接诊断。这与漏分号的源代码结构错误不同。

## 6.15 三类问题用不同证据定位

| 问题 | 实际缺什么 | 优先检查 |
| --- | --- | --- |
| 调用处不知道函数 | 正确可见的声明 | 名字、头文件、声明位置 |
| 声明已有但链接失败 | 本次构建中的实现 | 是否列出实现.c/相关库，签名是否一致 |
| 重复定义 | 多个冲突的普通定义 | 是否把实现放进多处，或重复编译同一内容 |

不要为了消除链接错误，随意把全部.c文件include进main.c。那会混淆本应独立编译的实现边界，还可能产生重复定义。先核对构建命令是否表达了正确组成。

## 6.16 对main参数和递归先保留边界

以后你会见到带argc、argv的main，它接收启动时给程序的参数；第10章会用文件工具展开。当前的main(void)已经足够学习函数调用。

函数还可以调用其他函数，甚至调用自己。递归必须设计终止条件和规模推进，也会消耗调用相关资源。本批不把复杂递归混入刚学参数的练习，先确保能跟踪普通调用与返回。

不是越多函数越好。如果拆出来的名字不能说明职责、输入输出仍不明确，只是把相邻三行机械搬走，并没有建立有用边界。

## 6.17 练习：用接口解释程序

题一：实现 `int max_of_two(int a, int b)`，测试-4与-2、5与5、7与3。函数返回较大值，不在里面打印。

题二：写一个int参数传值实验，函数里把值改为99，main仍保留原来的10；再用返回值明确更新main。

题三：把max_of_two拆为max.h、max.c、main.c。先写三个文件负责什么，再写编译命令。

题四：为什么把一个普通局部变量移到全局，虽然可能让名字变得可见，却不一定是正确修复？

提示：先声明接口与范围；main负责提供测试值和显示；每次调用都有自己的参数对象。需要重复调用时，不必把显示逻辑也复制进计算函数。

## 6.18 参考答案与完成条件

题一可使用if判断a>b时return a，否则return b；结果分别-2、5、7。也可在已理解分支后写 `return a > b ? a : b;`，三元表达式选择一个结果，不是循环。

题二：普通参数接收10的副本，把副本改为99不影响原变量；main使用 `value = change(value);` 才明确用返回值更新自己的对象。题三编译命令要包含main.c与max.c，头文件由include提供声明。题四全局改变了数据共享范围与责任，可能掩盖本来应该返回结果或调整结构的问题。

完成条件：能为一个函数写输入、范围和结果的契约；逐步解释一次调用；分清参数副本和调用者对象；修复一次作用域错误与一次漏实现的链接错误。下一章再用数组处理多个数据，届时才引入“函数接收数组还需要什么”的新问题。
