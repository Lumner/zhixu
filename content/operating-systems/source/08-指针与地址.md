# 08 指针与地址

> **零基础详细版 · 已重写。** 先完成第06章的参数传值与第07章的数组。本章建议分三至四次学习，连同画图、实验与复盘约7—10小时。先分清“对象、地址、指针值”，再组合符号。

## 8.1 上一章留下的三个问题

为什么普通int参数在函数里改了，main的原变量不一定改变？为什么数组交给函数后，还要另外传数量？为什么fgets能向你准备的字符数组写入？这些问题都需要建立“通过位置访问对象”的认识。

变量本身是对象，包含当前值。对象在生命期内有可供程序访问的位置，地址用来描述这种位置关系。指针值可以指向对象，指针变量则是用来保存这种值的另一个对象。

先不要把指针等同于一个可以任意加减的普通整数。类型、对象边界、生命期和访问权限都会约束它。知道一个看起来像地址的数字，并不表示你可以合法访问那里。

## 8.2 在纸上画两格，不先背星号

设有整数x，其值为10。再有指针p，保存x的地址，可以画为：

```text
对象p：保存指向x的指针值 ──→ 对象x：保存整数10
```

p不是x本身；p的内容也不是整数10。通过p访问它指向的对象时，才会读到10。如果p后来改为指向另一个对象，x原来的值不会仅因箭头改变就跟着改变。

“箭头图”只画对象关系，不按比例展示内存布局，也不使用虚构的固定物理地址。后面的虚拟内存章节才解释程序地址与物理内存之间的映射。

## 8.4 三个位置的符号分别读什么

`int *p = &x;` 中，声明位置的星号表示p具有“指向int的指针”类型；`&x` 取得x的地址；等号把这个指针值用于初始化p。

表达式 `*p` 中的星号是解引用运算：通过p访问其指向的对象。在右侧读取时取得x的值；作为赋值左侧时修改x。`*p = 25` 没有把p改成25，而是把被指向的整数对象改成25。

| 写法 | 本例改变或取得什么 |
| --- | --- |
| `p = &x;` | 更新指针变量p，让它指向x |
| `*p` | 访问p指向的int对象 |
| `*p = 25;` | 修改被指向对象的值 |
| `&p` | 取得指针变量p自身的地址 |
| `&x` | 取得整数对象x的地址 |

同一个符号还可能有其他语法用途：算术表达式a*b中的星号是乘法。先看符号所在结构，不能只看一个字符就套用同一解释。

## 8.5 跟踪赋值时，不把箭头和格子混起来

对pointer-basics逐步记录：

| 执行后 | p指向谁 | x的内容 | 通过*p读到 |
| --- | --- | --- | --- |
| 建立x | 尚未建立p | 10 | 暂无 |
| p初始化 | x | 10 | 10 |
| 执行*p=25 | 仍是x | 25 | 25 |

若又声明 `int y = 80;`，随后执行 `p = &y;`，变化的是箭头。x仍25，y仍80，通过*p读到80。只有执行 `*p = ...` 才会写当前被指向对象。

## 8.6 两个指针可能访问同一个对象

**完整程序：pointer-alias.c**

```c
#include <stdio.h>

int main(void) {
    int value = 10;
    int *first = &value;
    int *second = first;
    *second += 5;
    printf("value=%d first=%d second=%d\n", value, *first, *second);
    return 0;
}
```

输出value=15 first=15 second=15。复制指针值没有复制出第二个int对象，两个箭头指向同一个value。这种通过多个访问路径指向同一对象的情况常称为别名关系。

以后释放动态对象时，这个关系尤其重要：只把一个指针变量改成NULL，不会自动把其他别名全部清空。现在先记“复制地址关系”和“复制被指向的数据”不是同一件事。

## 8.7 把地址交给函数，仍然是传值

第06章普通int参数接收数值副本。传指针时，函数接收指针值的副本；副本仍指向同一个调用者对象，所以可以通过它访问那个对象。

**完整程序：pointer-output.c**

```c
#include <stdio.h>

int add_ten(int *target) {
    if (target == NULL) {
        return 0;
    }
    *target += 10;
    return 1;
}

int main(void) {
    int minutes = 20;
    int ok = add_ten(&minutes);
    int missing = add_ten(NULL);
    printf("ok=%d minutes=%d missing=%d\n", ok, minutes, missing);
    return 0;
}
```

预期ok=1 minutes=30 missing=0。本例契约：target为NULL时拒绝；否则调用者必须提供有效可写int，且加10不会溢出。检查非NULL不能自动证明任意来历的地址有效。

函数通过target访问的是main的minutes，而不是因为C忽然改成了“引用传递”。把参数本身改为别的地址，仍只改变局部指针副本。

## 8.8 只重绑参数，不会重绑调用者指针

**完整程序：pointer-rebind.c**

```c
#include <stdio.h>

void choose_locally(int *p, int *replacement) {
    p = replacement;
    printf("inside=%d\n", *p);
}

int main(void) {
    int left = 10;
    int right = 20;
    int *current = &left;
    choose_locally(current, &right);
    printf("outside=%d\n", *current);
    return 0;
}
```

输出inside=20，outside=10。函数里p改为指向right，main里的current仍指向left。函数返回后，局部参数p的这次状态结束，不会把重绑结果自动写回current。

对照前一节：修改 `*p` 可以改共享目标，修改 `p` 只改该指针对象。遇到“明明在函数里换了指针却没生效”，先辨别改的是哪一层。

## 8.9 用swap把三个赋值逐步拆开

[完整源码：pointers.c](示例代码/pointers.c)

```c
#include <stdio.h>

void swap(int *left, int *right) {
    int saved = *left;
    *left = *right;
    *right = saved;
}

int main(void) {
    int a = 10;
    int b = 20;
    printf("before=%d,%d\n", a, b);
    swap(&a, &b);
    printf("after=%d,%d\n", a, b);
    return 0;
}
```

在lesson08编译pointers.c并运行，输出before=10,20与after=20,10。调用者为left/right提供两个有效可写int地址；函数未将NULL当作有效输入。

| 操作后 | saved | a | b |
| --- | --- | --- | --- |
| saved=*left | 10 | 10 | 20 |
| *left=*right | 10 | 20 | 20 |
| *right=saved | 10 | 20 | 10 |

若没有saved，第一步覆盖a后，原10可能无法从a取回。若传swap(&a,&a)，两条访问路径指向同一对象，当前实现仍保持原值，并不要求两个地址一定不同。

## 8.10 地址怎样观察，哪些数字不应写死

输出对象地址可用 `%p`，相应实参转为void指针，例如 `printf("address=%p\n", (void *)&a);`。这里的void*是一种通用对象指针表示；用于输出地址，不表示可以忽略对象类型任意解引用。

实际地址会随运行环境、布局与地址随机化等变化。相同源码两次输出不同，不说明变量变成了不同语言规则。也不能从一张地址截图推断它是物理内存位置。

本课用地址观察验证“两个表达式是否指向同一对象”等关系；不要求抄某个固定地址，也不拿地址整数加减替代合法指针运算。

## 8.11 NULL表示什么，不表示什么

NULL可用于表达空指针值，常用于“目前没有指向可用对象”或接口失败结果。指针声明后不会自动因为它看起来像指针就变成NULL，未初始化的局部指针不能随意读取或解引用。

有效访问需要同时满足：指针值有可靠来源、指向合适类型和范围的对象、对象仍在生命期内、该访问被允许。非NULL只排除了其中一种无目标表示，不能替你检查其他条件。

不要通过运行 `*NULL` 观察“到底会不会崩”。它不是一个有可靠输出的合法教学实验；本课对这类错误用规则和图解释，需要诊断工具时也会明确区分受控错误与正常程序。

## 8.12 数组名为什么能交给函数

在大多数表达式中，数组名会转换为指向首元素的指针。例如 `int values[] = {10,20,30}; int *p = values;`，p指向values[0]。

**完整程序：array-pointer.c**

```c
#include <stdio.h>

int main(void) {
    int values[] = {10, 20, 30};
    int *p = values;
    printf("same=%d middle=%d last=%d\n", p == &values[0], p[1], *(p + 2));
    return 0;
}
```

输出same=1 middle=20 last=30。`p[1]` 与 `*(p+1)` 表达相应元素访问。p+1按所指类型前进一个元素，不承诺总是一个字节。

指针运算应留在相应数组及允许的末尾后一位置范围内；末尾后一位置不能被解引用。也不能用两块无关对象的指针随意相减或排序，推算其间可以访问的空间。

## 8.13 数组不是一个能随便重绑的指针变量

数组对象包含固定数量元素；指针变量存放一个指针值，可以在满足规则时重新赋值。数组名通常会转换成指针，不等于数组对象就是指针对象。

在声明数组的作用域，sizeof数组得到整个数组大小；sizeof指针得到该指针类型大小，不能当原数组容量。在函数参数中 `int values[]` 调整为指针参数，因此上一章要额外传count。

同样，给fgets传数组名使其获得首元素地址；容量由你另行提供。库不会从一个普通指针自动恢复出“后面有32格”的通用信息。调用者传错容量依旧会出错。

## 8.14 const约束哪一个访问路径

`const int *reader` 表示通过reader不能修改所指整数，但reader自身可以改指向；`int *const fixed` 表示这个指针变量不能重绑，但它指向的非const整数可以通过它修改。

先读对象关系，再读const修饰位置，不用今天就熟练解开所有复杂声明。下面程序故意尝试通过只读路径写入。

**故意写错的完整程序：const-target-error.c**

```c
#include <stdio.h>

int main(void) {
    const int value = 10;
    const int *reader = &value;
    *reader = 20;
    printf("value=%d\n", value);
    return 0;
}
```

编译应拒绝通过该只读路径赋值。正确修复取决于需求：若本来就不该修改，就删除修改操作；若确实需要可写对象，应从设计上建立可写对象及合适接口。不要靠强制类型转换掩盖原对象的只读性质。

## 8.15 想改“调用者保存的地址”，再加一层

若函数的任务是改main里的current，就要获得current对象本身的地址。current的类型是int*，它的地址对应int**，也就是指向指针的指针。

**完整程序：pointer-to-pointer.c**

```c
#include <stdio.h>

void select_pointer(int **slot, int *choice) {
    *slot = choice;
}

int main(void) {
    int left = 10;
    int right = 20;
    int *current = &left;
    printf("before=%d\n", *current);
    select_pointer(&current, &right);
    printf("after=%d\n", *current);
    return 0;
}
```

输出before=10，after=20。slot指向current对象，*slot访问这个指针对象，给它赋choice会改main的current。没有因此把left改为20：改变的是箭头，不是left内容。

```text
函数slot ──→ main中的current ──→ left
执行*slot=choice后：
函数slot ──→ main中的current ──→ right
```

本例要求slot指向有效可写指针对象，choice指向仍有效的int。后面的动态数组工具会使用同样形状返回新分配地址，先明确每一层代表谁。

## 8.16 strtol的end指针终于可以按层理解

strtol读取字符串前面的整数，把停止位置写到你提供的指针变量中。因此char* end保存“停在哪个字符”，调用时传&end，让库能更新这个指针对象。

**完整程序：conversion-step.c**

```c
#include <stdio.h>
#include <stdlib.h>
#include <errno.h>

int main(void) {
    char text[] = "125x";
    char *end = NULL;
    errno = 0;
    long value = strtol(text, &end, 10);
    if (errno == ERANGE || end == text) {
        fprintf(stderr, "Conversion failed\n");
        return 1;
    }
    printf("value=%ld rest=%s\n", value, end);
    return 0;
}
```

输出value=125 rest=x。它演示“转换停止位置”，并没有把125x判定为合格整数输入。字符串中前三个数字被转换，end指向x；完整校验还需要确认剩余内容符合协议。

如果没有任何数字，end与起点相同；若转换超范围，检查ERANGE。返回0也可能是合法数值，所以不能仅凭value==0宣布失败。接口说明见 [strtol手册](https://man7.org/linux/man-pages/man3/strtol.3.html)。

## 8.17 把完整校验分成四个独立问题

现在可以回到 [完整输入校验](深入练习-完整输入校验.md)：第一步检查整行有没有完整取得；第二步转换并检查是否读到数字及超范围；第三步处理允许的尾随空白，拒绝12abc；第四步检查业务范围。

`end++` 将指针沿字符数组前进；`*end` 访问当前位置字节；`*end == '\0'` 检查是否到字符串结束。isspace按其接口要求接收unsigned char范围的字节值或EOF，将普通char转换为unsigned char可避免负char值造成不合法参数。

这套转换按本例固定十进制规则工作，不是通用Unicode数字或国际化文本解析器。严格的意思是有明确协议与检查，不是给每个失败都无限重试。

## 8.18 生命期：地址还在变量里，不等于对象还活着

函数的普通自动局部对象随相应执行结束生命期。把它的地址返回给外面继续解引用，不能让原对象因此长生不老。

同样，下一章free动态对象后，保存旧地址的指针也不会自动获得继续访问的权利。地址变量里的位模式看起来没变，不代表那个对象仍可使用。

以后设计函数时，把“指针由谁提供、至少活多久、允许读还是写、数量是多少”写进契约。不要让所有调用者只看到一个星号，却猜不出责任。

## 8.19 练习：每次指出改的是哪一层

题一：value=10，first和second都指向它，执行*second=40后分别读到什么？再将second改为指向另一个对象，first会自动跟随吗？

题二：pointer-rebind为什么不能修改main的current？pointer-to-pointer为什么能？

题三：给swap传同一个对象地址两次，按三次赋值推演结果；给它NULL是否仍符合本例契约？

题四：三元素数组p指向首元素，p+3可以解引用吗？sizeof p能可靠给出数组数量吗？

题五：strtol遇到12abc与abc时，end分别帮助你判断什么？为什么不能只看转换结果是不是0？

## 8.20 参考答案与完成条件

题一：都能读到40；重绑second不会改first。题二：前者改局部指针副本，后者通过指向current对象的指针改写了current。题三：同一有效对象保持原值，NULL不在swap契约内，不能拿它做正常解引用。题四：p+3是末尾后一位置，不能解引用；sizeof p是指针大小。题五：前者有数字但剩余非法内容，后者未转换数字；0本身也可能合法。

完成条件：能对三种赋值p=&x、*p=值、*slot=新地址分别画图；解释数组参数为何需要数量；不通过崩溃与否判断合法性；逐步追踪一次swap和end位置更新。
