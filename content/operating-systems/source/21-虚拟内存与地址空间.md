# 21 虚拟内存与地址空间：同一个地址，为什么可以有不同内容

## 1. 先回忆一个问题

第12章fork以后，孩子把value改为99，父亲仍看到10；第17章线程拿到有效对象地址，却可以访问同一个进程里的对象。为什么同样叫“地址”，效果不同？

本章要建立一个层次：C程序操作对象，指针在本课Linux环境中表示相应虚拟地址，地址翻译再联系到物理存储。学完能画两个进程的映射关系，解释地址数字不能单独证明共享，并把对象生命期与页面保护分开。

先复习第08章指针、第09章生命期、第12章fork、第17章线程。本章不要求先会内核源码或汇编。

## 2. 虚拟地址是什么

**地址**是定位位置的编号。**虚拟地址**是进程执行时使用、由地址翻译机制解释的地址。**物理地址**用于定位相应物理内存系统的位置。普通用户程序打印一个指针，通常看到的是前者，不是可以直接拿去定位某条内存芯片的号码。

**地址空间**是一个执行环境中可以用来组织地址的范围及其映射。本课讨论进程的用户地址空间：哪些范围已映射、允许怎样访问、背后对应什么内容，都由具体状态决定。能写出一个整数地址，不表示这个位置就已经属于你。

可以类比两栋楼都有“301室”，必须先知道是哪栋楼，号码才有意义。这个类比解释上下文，不表示每个进程真的拥有一整套独占物理内存。

## 3. 翻译由谁完成

处理器中的**内存管理单元MMU**参与地址翻译和访问检查，内核建立并维护相应映射结构。程序正常读写时不需要自己为每个指针调用一个“翻译函数”。具体硬件的翻译方式不同，第22章用分页模型展开。

翻译不一定每次都完整读取映射表，硬件会缓存近期结果。内核也可能在第一次访问时再补齐驻留状态。这些机制让应用能使用规则明确的地址空间，同时把物理资源分配交给系统管理。

“虚拟”不表示数据是假的，也不等于“必定放在硬盘”。虚拟内存首先是映射与保护机制；交换空间只是某些系统策略的一部分。

## 4. 两个独立地址空间的图

下面是**概念模型，地址和页框编号均为示意**：

```text
进程A：虚拟页3 ──→ 物理页框8，内容10
进程B：虚拟页3 ──→ 物理页框12，内容99
```

虚拟页编号相同，但翻译上下文不同，最终对象可以不同。也可以显式安排共享：

```text
进程A：虚拟页3 ──┐
                 ├─→ 同一个共享后备对象中的页面
进程B：虚拟页7 ──┘
```

因此“地址相同就共享”和“地址不同就不共享”都不成立。判断需要看地址空间和映射语义；线程还需要第18—19章的同步规则，映射共享不会自动消除数据竞争。

## 6. 观察不同存储期对象的地址

**完整程序：address-regions.c**

```c
#include "lab.h"

static int global_value = 10;

int main(void) {
    static int static_value = 20;
    int automatic_value = 30;
    int *dynamic_value = malloc(sizeof *dynamic_value);
    if (dynamic_value == NULL) { die("malloc"); }
    *dynamic_value = 40;
    long page_size = sysconf(_SC_PAGESIZE);
    if (page_size <= 0) {
        fputs("could not obtain page size\n", stderr);
        free(dynamic_value);
        return 1;
    }
    printf("global=%p value=%d\n", (void *)&global_value, global_value);
    printf("static=%p value=%d\n", (void *)&static_value, static_value);
    printf("automatic=%p value=%d\n", (void *)&automatic_value, automatic_value);
    printf("dynamic=%p value=%d\n", (void *)dynamic_value, *dynamic_value);
    printf("page_size=%ld\n", page_size);
    free(dynamic_value);
    return 0;
}
```

编译后执行`./address-regions`，应打印四个地址和数值10、20、30、40，以及正的系统页大小。本次环境查询为4096字节，但程序从sysconf取得，不把它写死。不同运行的地址可能变化，也不要求所有地址具有某种大小顺序。

## 7. 从输出能推出什么

`%p`接收`void *`，所以按第08章做对象指针转换。四个对象都仍在生命期内，dynamic在最后一次读取以后free。程序没有在free以后打印旧指针或尝试访问旧对象。

静态存储期对象持续到程序结束；automatic在所属调用中存在；动态对象持续到明确释放。这是C层面的分类。它们通常分别落在某些加载区域、栈和分配器区域，但C语言并不规定本机内存图必须按教材示意紧密排列。

仅凭这些地址，不能算出每个对象独占了多少物理页，也不能说两个对象地址很近就能合法越界访问它们。对象边界是语言规则，不由你目测地址差来修改。

## 8. 常见区域怎样理解

| 区域或概念 | 常见用途 | 不能据此断言 |
| --- | --- | --- |
| 程序代码与只读数据映射 | 指令、只读常量等 | 任意函数地址都能转成对象指针打印 |
| 可写静态数据 | 全局和静态存储期对象 | 每个static对象都有独立物理页 |
| 栈相关区域 | 调用、局部状态 | 其他线程永远无法通过有效地址访问 |
| 分配器管理区域 | malloc对象 | 每次malloc都单独进入内核 |
| 文件、库等映射 | 文件内容、共享库等 | 映射存在就已全部驻留 |

表格描述本课平台的常见组织，具体布局受编译器、ABI、加载器和运行环境影响。**ASLR**是地址空间布局随机化，使某些区域地址随运行变化；本课不关闭它来追求固定数字。

## 9. fork前后的相同地址实验

**完整程序：fork-address.c**

```c
#include "lab.h"

int main(void) {
    int value = 10;
    if (fflush(NULL) == EOF) { die("fflush"); }
    pid_t child = fork();
    if (child < 0) { die("fork"); }
    if (child == 0) {
        value = 99;
        printf("child address=%p value=%d\n", (void *)&value, value);
        if (fflush(stdout) == EOF) { _exit(1); }
        _exit(7);
    }
    int code = wait_child(child);
    printf("parent address=%p value=%d child_exit=%d\n", (void *)&value, value, code);
    return 0;
}
```

编译为fork-address，执行。两行中value的虚拟地址应相同，孩子数值99、父亲10，父亲观察孩子退出7。父亲最后返回0表示本次观察完成，不是孩子也返回0。

比较的是同一次fork继承的布局；两个完全独立启动的程序不要求有相同地址。等待和刷新使输出关系容易读，不靠sleep决定谁先打印。

## 10. 写时复制解释什么

Linux的fork可以用**写时复制COW**优化普通私有内存：一些页面开始时共用底层物理存储，发生需要独立修改的写入时再按规则分离。这减少不必要的提前复制。

应用应依赖的是父子普通私有修改互不直接可见，不依赖某一时刻物理页是否已复制。本例printf只验证值与虚拟地址关系，没有测量物理页号，也没有证明复制恰好发生在哪条机器指令。

显式共享映射是另一种语义，第24章讨论。不能把COW概括成“fork以后所有资源完全独立”，描述符共享打开状态的问题仍按第14章理解。

## 11. 映射范围与驻留不同

**已映射**表示某个虚拟范围具有相应映射关系和规则；**驻留**表示相应内容当前在可供访问的物理内存中。一个很大的虚拟映射可能只有其中一部分被实际访问和驻留。

**RSS**是驻留集合大小的一种统计，涉及共享、文件页和计量口径。它不是“malloc申请量”的别名。**虚拟大小**也不等于应用真正独占的物理RAM。比较工具数字时先看定义与单位，不把两个不同口径相减后就叫“泄漏”。

本章不通过申请巨量内存来观察系统濒临耗尽。第24章把分配器、free和局部性再连接起来。

## 12. Linux自己的映射清单

Linux的`/proc`提供一些内核状态视图。`/proc/self/maps`表示**打开这个文件的当前进程**的映射清单；self不是永久固定PID，也不是磁盘上事先写好的普通教材文件。

常见行前部包含十六进制起止地址和权限，例如`rw-p`：r可读、w可写、x位置的短横表示此处未标可执行、p表示私有映射。它描述范围与权限，不提供某个C对象的所有权或精确物理页编号。

在Bash运行`cat /proc/self/maps`时，self指cat进程，不是一个已经结束的C练习程序。要观察练习自身，应该让练习读取自己的self路径。

## 13. 只读取自己对象所在的区域

**完整程序：proc-region.c**

```c
#include "lab.h"
#include <inttypes.h>
#include <stdint.h>

int main(void) {
    void *object = malloc(64);
    if (object == NULL) { die("malloc"); }
    FILE *maps = fopen("/proc/self/maps", "r");
    if (maps == NULL) {
        perror("open own maps");
        free(object);
        return 1;
    }
    uintptr_t address = (uintptr_t)object;
    char line[512], permissions[5];
    int found = 0, failed = 0;
    while (fgets(line, sizeof line, maps) != NULL) {
        uintptr_t begin, end;
        if (sscanf(line, "%" SCNxPTR "-%" SCNxPTR " %4s", &begin, &end, permissions) == 3 &&
            address >= begin && address < end) {
            printf("allocation_region=%s\n", permissions);
            found = 1;
            break;
        }
        if (strchr(line, '\n') == NULL) {
            int ch;
            while ((ch = fgetc(maps)) != '\n' && ch != EOF) { }
        }
    }
    if (ferror(maps)) { perror("read maps"); failed = 1; }
    if (fclose(maps) != 0) { perror("close maps"); failed = 1; }
    free(object);
    if (!found) { fputs("allocation region not found\n", stderr); failed = 1; }
    return failed;
}
```

编译为proc-region并运行。在本次Linux环境输出`allocation_region=rw-p`。若受限环境没有/proc或不允许读取，应如实报告，不为了这个选读观察扩大权限。

## 14. 这份观察程序的新语法

`uintptr_t`是在本平台可容纳对象指针整数表示的无符号类型；本例在明确的Linux地址表示环境里把指针转成整数，与maps中范围比较，不把这种转换当作跨所有C平台的地址算法。

`SCNxPTR`是与uintptr_t配合读取十六进制数的格式宏。C会把相邻字符串字面量连接，所以`"%" SCNxPTR`组成合适格式。`%4s`最多读4个权限字符，数组有5格容纳末尾零字符。

我们只需要行前面的地址和权限；如果路径很长、这一段还没有换行，就用fgetc消费剩余行再处理下一条，避免把路径续段误认成新的映射头。程序不打印全部映射路径，不读取别人的进程，也不对扫描到的任意地址解引用。

## 15. 保护异常不是所有C错误的裁判

页面可能带读、写、执行等权限。访问缺失或权限不符的映射会触发相应硬件异常，内核判断是否补齐、调整或拒绝。拒绝时可能向进程发送SIGSEGV等信号。

但C数组只占页中很小一段时，越界到同一已映射页内的别处，也许不会立刻触发页级异常。语言错误已经存在，不能靠“没有崩溃”宣布合法。我们不运行这种越界程序来背某次错误输出。

## 16. 分配成功为什么不是所有保证

malloc成功提供相应C对象与使用契约；底层如何取得区域、何时实际配置页面，涉及分配器与内核策略。它不证明这片对象未来任意访问都不会受到系统资源紧张影响，也不替你检查越界。

同样，一次文件映射成功不表示文件全部读进RAM；缺页处理可能在以后访问时发生。区分申请接口成功、地址映射存在、页面驻留和对象合法访问，后面的章节才不会把所有“内存问题”混成一个原因。

## 17. 用三层图排错

```text
C对象层：生命期、容量、类型、所有权是否正确？
进程映射层：地址范围、读写权限、私有或共享语义是什么？
驻留与资源层：需要补页、回收、读文件，还是申请失败？
```

对象越界先查索引和容量；映射错误先查接口返回和范围；占用高先看统计口径和重复负载。把每一层的证据分别写下，比先扩大内存或关闭保护更有用。

## 18. 常见误解与修正

“虚拟内存就是交换文件”：先解释地址映射与保护，再讨论存储后备。

“两个指针数字相同，一定是同一个对象”：补上进程地址空间上下文。

“free以后RSS没有降，必定泄漏”：分开对象释放与分配器保留区域。

“maps显示可写，所以任何地址都能当int指针访问”：页面权限不代替C类型、对齐、对象边界与生命期。

“孩子改变量，父亲wait以后就看见”：等待提供终止与顺序，不把私有映射改为共享。

## 19. 练习、提示与参考答案

1. 两进程的地址都为0x1000，能否断言物理存储相同？不能，需看地址空间和映射。
2. 同一物理后备页能否出现在两个不同虚拟地址？可以，映射可以这样安排。
3. address-regions中malloc对象该由谁释放？main在最后使用后free；静态和自动对象不能按同一方式free。
4. 为什么不用cat /proc/self/maps当作已结束程序的内存图？self属于实际读取者cat，目标也已结束。
5. 未崩溃的数组越界是否可以保留？不能，页级保护不证明C对象访问合法。

动手练习：把fork-address孩子value改为55、退出码改为3。预期父亲仍10、child_exit=3、同一次fork中的地址对应不变。记录关系而不是某个固定十六进制数字。
