# 23 缺页、页面置换与抖动：内存不够时让谁先离开

> **零基础详细版 · 已重写。** 先分清缺页原因，再逐步填写FIFO、LRU和Clock状态，最后用明确窗口解释工作集。建议8—11小时。

## 1. 目标与先修

先会第22章地址翻译和TLB，复习第05章循环及第07章数组。本章学完要能解释缺页不一定读磁盘，区分装入与命中，逐项演算三种置换策略，并说明为什么不能凭一个序列给算法排永久名次。

本章的frames数组只是“哪些虚拟页当前驻留”的模型，不是真实物理内存分配接口。实验不会制造系统内存耗尽，不调整swap，也不要求观察机器卡顿。

## 2. 缺页异常的几种后续

**按需分页**是先建立相应虚拟范围规则，到真正访问时才按需要配置驻留内容的一类机制。触发异常以后，内核需要先判断这次访问是否合法，再选择处理。

可能是为合法新页面提供零初始化内容；为私有写入执行COW；从文件或交换后备取得内容；也可能因为未映射或权限不符而拒绝。因此缺页不是崩溃的同义词，更不是“每次都从机械硬盘读一页”。

第22章的TLB未命中也可能仅需查找已存在的页表翻译。本章讨论驻留与回收策略，先把这两类“未命中”分开。

## 3. 页面从哪里来、往哪里去

有文件后备的干净页，内容仍可从文件重建，某些情况下可以直接回收；被修改的**脏页**可能需要先适当写回。匿名内存、共享对象、被固定的页面又有不同限制。

**交换空间swap**可作为某些匿名页等内容的后备，不是每一个虚拟页都必须有一个交换槽。文件映射也不等于把文件完整复制到交换区。

下面算法暂时忽略脏页、写回成本、预取、多个进程和不可回收页，只比较固定序列在固定页框数下的驻留命中。这个简化让我们可以把每一步手算出来。

## 4. 把模型假设写在表头

统一小例：三个页框、初始全空、页号序列1、2、3、1、4、2、5；每次只引用一个页号，不带偏移；请求的页面都属于合法可读范围；未驻留就计一次模型缺页并装入。

**命中hit**表示要访问的页已在frames中；**缺页fault**表示不在，需选空位或替换。开始装进空页框也算缺页，不能只统计发生淘汰的次数。

-1只在模型中表示空位，输入页号不使用-1。页框数组下标是固定槽位，数组值才是当前装入的页号；下一章综合项目会重新接上地址和偏移。

## 5. FIFO按装入先后排队

**先进先出FIFO**替换最早装入且仍在内存的那一页；命中不会把它重新排到队尾。用next指向下一次替换槽，缺页时装入并推进，命中时不动。

| 步骤 | 引用 | 命中/缺页 | 槽0/1/2 | 下一替换槽 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 缺页 | 1 / - / - | 1 |
| 2 | 2 | 缺页 | 1 / 2 / - | 2 |
| 3 | 3 | 缺页 | 1 / 2 / 3 | 0 |
| 4 | 1 | 命中 | 1 / 2 / 3 | 0 |
| 5 | 4 | 缺页，淘汰1 | 4 / 2 / 3 | 1 |
| 6 | 2 | 命中 | 4 / 2 / 3 | 1 |
| 7 | 5 | 缺页，淘汰2 | 4 / 5 / 3 | 2 |

合计缺页5、命中2。第4步虽然刚访问1，FIFO仍会在第5步淘汰它；这是策略定义，不是程序忘记更新。

## 6. FIFO主线完整程序

Linux/WSL Ubuntu的Bash，目录`~/os-lab/memory`。

[完整源码：replacement.c](示例代码/replacement.c)

```c
/* Model: 3 frames, FIFO; -1 denotes an empty frame. */
#include <stdio.h>

int main(void) {
    const int refs[] = {1, 2, 3, 1, 4, 2, 5};
    int frames[] = {-1, -1, -1};
    int next = 0, faults = 0;
    for (size_t i = 0; i < sizeof refs / sizeof refs[0]; i++) {
        int hit = 0;
        for (int j = 0; j < 3; j++) { if (frames[j] == refs[i]) { hit = 1; } }
        if (!hit) {
            frames[next] = refs[i];
            next = (next + 1) % 3;
            faults++;
        }
        printf("ref=%d %s frames=%d,%d,%d\n", refs[i], hit ? "hit" : "fault",
               frames[0], frames[1], frames[2]);
    }
    printf("faults=%d\n", faults);
    return 0;
}
```

编译运行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -Werror -g replacement.c -o replacement
./replacement
```

应逐行匹配第5节，最后`faults=5`。`% 3`让槽位循环0→1→2→0；不是让页号对3取余决定该放哪里，那会变成另一种映射规则。

## 7. LRU按最近使用排队

**最近最少使用LRU**淘汰最久没有被引用的页。和FIFO的关键差别是命中也更新“最近使用”信息。下面用“最旧→最新”的逻辑顺序表示，不是物理槽顺序。

| 引用 | 逻辑使用顺序 | 事件 |
| --- | --- | --- |
| 1 | 1 | 缺页 |
| 2 | 1、2 | 缺页 |
| 3 | 1、2、3 | 缺页 |
| 1 | 2、3、1 | 命中，1变最新 |
| 4 | 3、1、4 | 淘汰2 |
| 2 | 1、4、2 | 淘汰3 |
| 5 | 4、2、5 | 淘汰1 |

合计缺页6、命中1。不要把第4步的命中只记在输出，却忘了更新策略状态。

## 8. 用最后访问步数实现LRU

**完整程序：lru-trace.c**

```c
#include <stdio.h>

int main(void) {
    const int refs[] = {1, 2, 3, 1, 4, 2, 5};
    int frames[3] = {-1, -1, -1};
    size_t last[3] = {0, 0, 0};
    int faults = 0;
    for (size_t i = 0; i < sizeof refs / sizeof refs[0]; i++) {
        int slot = -1;
        for (int j = 0; j < 3; j++) { if (frames[j] == refs[i]) { slot = j; } }
        int hit = slot >= 0;
        if (!hit) {
            for (int j = 0; j < 3; j++) {
                if (frames[j] < 0) { slot = j; break; }
            }
            if (slot < 0) {
                slot = 0;
                for (int j = 1; j < 3; j++) { if (last[j] < last[slot]) { slot = j; } }
            }
            frames[slot] = refs[i];
            faults++;
        }
        last[slot] = i + 1;
        printf("ref=%d %s frames=%d,%d,%d\n", refs[i], hit ? "hit" : "fault",
               frames[0], frames[1], frames[2]);
    }
    printf("faults=%d\n", faults);
    return 0;
}
```

编译为lru-trace，最后faults=6，最终槽位为5/4/2。last记录模拟访问步数，不读真实时钟；每一步都更新被访问槽的last，包括命中。步数有限，不涉及长期计数器溢出。

## 9. 为什么LRU这次反而多一次

LRU根据过去预测未来，过去近期常用不保证接下来必用。这个短序列恰好让FIFO在第6步保留2，而LRU已经淘汰2，因此结果不同。

这不证明FIFO普遍优于LRU，也不证明LRU代码有错。评价策略必须说明工作负载与目标。若只换一个序列就能让排名变化，结论应该回到策略取舍，不是把一个分数写成永久排名。

## 10. OPT知道未来，所以只是比较基准

**最优置换OPT**在需要淘汰时，选择未来最晚才再次访问的页；永不再用的页可优先淘汰。本小例访问4时，未来只剩2和5，1与3都不会再用，淘汰任一都可以。

这样仍需最初装入1/2/3，以及4和5，共5次。若多个候选未来都不再用，要明确平局规则才能得到唯一槽位表；缺页最少并不要求每一行物理槽排列唯一。

真实系统无法直接知道完整未来引用序列，因此OPT适合离线比较和理论下界。这里不把它当作可以直接部署到内核的预言能力。

## 11. Clock给近期使用第二次机会

**Clock时钟置换**把槽位看作环，每页有一个使用位。访问页时设位1；需要替换时从hand扫描，遇到1就清0并前进，遇到0就替换，再设1并把hand移到下一格。

使用位近似表达“最近一段扫描以来被用过”，没有保存LRU那样完整时间顺序。hand是扫描位置，不是墙上时钟。真实系统怎样获得、清除访问位依硬件与内核设计而异，本程序用普通数组模拟。

## 12. Clock完整有限模型

**完整程序：clock-trace.c**

```c
#include <stdio.h>

int main(void) {
    const int refs[] = {1, 2, 3, 1, 4, 2, 5};
    int frames[3] = {-1, -1, -1};
    int used[3] = {0, 0, 0};
    int hand = 0, faults = 0;
    for (size_t i = 0; i < sizeof refs / sizeof refs[0]; i++) {
        int slot = -1;
        for (int j = 0; j < 3; j++) { if (frames[j] == refs[i]) { slot = j; } }
        int hit = slot >= 0;
        if (!hit) {
            while (used[hand]) { used[hand] = 0; hand = (hand + 1) % 3; }
            slot = hand;
            frames[slot] = refs[i];
            hand = (hand + 1) % 3;
            faults++;
        }
        used[slot] = 1;
        printf("ref=%d %s frames=%d,%d,%d bits=%d,%d,%d hand=%d\n",
               refs[i], hit ? "hit" : "fault", frames[0], frames[1], frames[2],
               used[0], used[1], used[2], hand);
    }
    printf("faults=%d\n", faults);
    return 0;
}
```

编译为clock-trace，预期faults=5，最后frames=4,2,5，bits=1,0,1，hand=0。这个有限顺序模型里扫描会清位，最终找到0，不存在另一个线程同时不断把位设回1。

## 13. 手推Clock最关键的两次替换

前三次装入后，frames=1/2/3，bits=1/1/1，hand=0。再访问1只把它设1，不移动hand。访问4时，扫描依次清掉三个位，绕回槽0替换1，得到4/2/3、bits=1/0/0、hand=1。

再访问2，把槽1设1，得到bits=1/1/0。访问5从hand=1开始：清槽1为0，槽2已经0，所以替换3，最后4/2/5。把每次“清位”和“替换”分开记录，避免误以为遇到1也直接淘汰。

## 14. 增加页框不一定改善FIFO

换成经典序列1,2,3,4,1,2,5,1,2,3,4,5，初始空。FIFO使用3框缺页9次，4框却10次，这叫**Belady异常**。原因是容量变化也改变了装入与淘汰历史，不能只想“多一格一定保留原先所有内容”。

精确LRU具有相应**栈性质**：对同一序列，在一致规则下，较小容量的驻留集合包含于较大容量的集合中，因此没有这种特定异常。这个性质不表示LRU对所有序列优于FIFO，更不消除维护精确历史的成本。

本批综合项目支持不同框数的FIFO/LRU，可运行核对上述例子，不需要让真实内核使用FIFO。

## 15. 工作集必须带窗口

**工作集**可理解为指定近期窗口内活跃使用的页面集合。序列1,2,1,2,3,4,3,4，在第4步看最近4次引用，集合是{1,2}；第8步看最近4次，集合是{3,4}。

整段不同页共4个，不代表每个阶段都同时需要4框。窗口选得不同，观察到的工作集也可能不同。报告时说明是最近多少次引用或多长时间，不把“工作集大小”当成程序永远不变的常数。

## 16. 抖动是大量无效搬动影响推进

若活跃需求持续超过可用驻留预算，刚换出去的页很快又要换回来，系统大量时间花在回收与补页而非有效计算，这类现象称为**抖动thrashing**。

增加并发进程可能扩大总工作集，使吞吐反而下降。可考虑减少并发、改善局部性或增加适当内存预算，但真实排错必须看证据：缺页类型、I/O、CPU与任务进度，不能只凭某个计数高就下结论。

本课不通过挤爆本机RAM演示抖动；第24章用有限访问序列比较局部性。

## 17. 缺页数量和耗时不是同一个指标

假设普通访问总耗时100ns，某类缺页访问总耗时1000000ns，概率0.1%=0.001，其余命中；平均为`0.999×100+0.001×1000000=1099.9ns`。这是明确简化的加权模型，不是实测。

即使缺页率小，昂贵事件也可能影响平均值。反过来，两个策略缺页次数相同，淘汰脏页的写回量或维护成本可能不同，总耗时不必相同。不要把所有缺页都指定为同一个固定毫秒数。

## 18. 常见错误与排查

把首次装入不算fault：按“访问时是否驻留”重新计数。

FIFO命中移动next：变更了算法定义，回到第5节。

LRU命中不更新last：遗漏最近使用状态，回到第7—8节。

把逻辑顺序当槽位顺序：分别画队列历史与物理数组。

Clock只清一位就随便替换：继续扫描到允许的候选。

缺页计数就是磁盘读取次数：回到第2—3节区分来源与处理路径。

## 19. 练习、提示与参考答案

1. 本小例FIFO、LRU、Clock分别多少fault？5、6、5；先填完整表再对数。
2. 三框、序列2,2,2为什么只有一次fault？第一次装入，后两次命中。
3. 一框、序列1,2,1,2，各策略如何？每次都不在，4次fault；只有一个候选，策略没有余地。
4. 给最近4次引用3,3,4,3，工作集大小多少？2，集合{3,4}，不是引用次数4。
5. OPT遇到多个永不再用页怎么办？明确平局规则；选择不同可得到不同槽表但相同最优计数。
6. 0.1%是否等于0.1？不是，作为概率是0.001。

动手题：在FIFO/LRU正确模型中仅把refs改成2,2,2并更新数组长度表达式所依赖的初始化，预期faults=1；不删边界检查、不修改真实页表。
