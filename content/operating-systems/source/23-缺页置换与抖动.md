## 23.1 缺页不等于崩溃

按需分页可以等到访问某页时再建立实际驻留。缺页异常进入内核后，可能分配零页、完成写时复制、从文件/交换区读取，或因地址与权限非法而拒绝。不能把所有 page fault 都解释成磁盘读取。

物理内存紧张时，系统需要选择可回收页面。干净文件页可能可直接丢弃后再读；脏页需要适当写回；被固定或不可回收的页有不同限制。本章把这些复杂性暂时简化，只比较引用序列中的置换算法。

## 23.2 FIFO 手算与完整模型

三个页框，初始全空，引用序列为 1、2、3、1、4、2、5。FIFO 替换最早装入的页，命中不改变入队先后。

[完整源码：replacement.c](示例代码/replacement.c)

```c
/* Model: 3 frames, FIFO; -1 denotes an empty frame. */
#include <stdio.h>

int main(void) {
    const int refs[] = {1, 2, 3, 1, 4, 2, 5};
    int frames[] = {-1, -1, -1};
    int next = 0, faults = 0;
    for (size_t i = 0; i < sizeof refs / sizeof refs[0]; i++) {
        int hit = 0;
        for (int j = 0; j < 3; j++) { if (frames[j] == refs[i]) { hit = 1; } }
        if (!hit) {
            frames[next] = refs[i];
            next = (next + 1) % 3;
            faults++;
        }
        printf("ref=%d %s frames=%d,%d,%d\n", refs[i], hit ? "hit" : "fault",
               frames[0], frames[1], frames[2]);
    }
    printf("faults=%d\n", faults);
    return 0;
}
```

运行 `make replacement`、`./replacement`，缺页共 5 次。依次为：1 缺、2 缺、3 缺、1 命中、4 换掉 1、2 命中、5 换掉 2；最后页框位置为 4/5/3。next 仅在缺页时推进，是循环队列的替换位置。

## 23.3 同一序列用 LRU

LRU 替换最久未使用的页，命中也更新最近使用顺序。上述序列：装入 1/2/3 后，访问 1 使 1 最近使用；4 替换 2；下一次 2 已不在，替换 3；5 再替换 1。缺页共 6 次。

这个短序列里 LRU 比 FIFO 多一次，不矛盾：LRU 不是对所有输入都最优。OPT 假设能知道未来，淘汰未来最晚才用到的页，用于理论比较；真实系统无法直接知道未来。Clock 等算法用访问位近似跟踪使用情况。

## 23.4 Belady 异常与工作集

FIFO 可能在页框增多后反而缺页更多，称为 Belady 异常。可手算经典序列 1,2,3,4,1,2,5,1,2,3,4,5：3 框缺页 9 次，4 框 10 次。LRU 的栈性质避免这种特定异常，但实现精确 LRU 也有成本。

工作集是某段时间活跃访问的一组页面。活跃需求远大于可用内存，系统频繁在回收与缺页间切换，叫抖动。增加并发进程可能使整体更慢。处理方式包括减少并发、改善访问局部性、调整内存预算，需通过实际测量判断。

## 23.5 练习、答案与完成条件

①FIFO 命中为什么不移动 next？②空页框装入算缺页吗？③缺页数少一定总耗时更短吗？答案：①算法依据装入时间，不按访问更新；②算；③不一定，写回、算法维护与具体 I/O 成本不同。

完成条件：不运行程序也能逐步填出两个算法的页面表，解释为何不能用一次序列宣布某算法普遍最佳。
