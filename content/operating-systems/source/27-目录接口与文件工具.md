## 27.1 从 ls 到自己的查看器

先读路径与 inode。目录不是应该用普通文本逐行解析的文件。POSIX 的 opendir/readdir/closedir 提供遍历接口；它们返回目录项信息，随后可按需要调用其他接口获取类型、权限与大小。

## 27.2 完整例程 listdir.c

[完整源码：listdir.c](示例代码/listdir.c)

```c
#include "lab.h"
#include <dirent.h>

int main(int argc, char *argv[]) {
    if (argc > 2) { fprintf(stderr, "usage: listdir [DIRECTORY]\n"); return 2; }
    DIR *directory = opendir(argc == 2 ? argv[1] : ".");
    if (directory == NULL) { die("opendir"); }
    for (;;) {
        errno = 0;
        struct dirent *entry = readdir(directory);
        if (entry == NULL) {
            if (errno != 0) { die("readdir"); }
            break;
        }
        if (strcmp(entry->d_name, ".") != 0 && strcmp(entry->d_name, "..") != 0) {
            puts(entry->d_name);
        }
    }
    if (closedir(directory) < 0) { die("closedir"); }
    return 0;
}
```

在例程目录运行 `make listdir`，再 `./listdir .` 或 `./listdir /tmp`。输出顺序不保证排序，内容取决于目录。执行 `./listdir no-such-os-lab-directory` 应报错并非零退出，不应悄悄显示“空目录”。

readdir 返回 NULL 有两种意义：正常到结尾，或发生错误。因此每次调用前先清 errno，返回 NULL 后再检查。普通成功调用并不承诺替你清除旧 errno。entry 指向的缓冲由目录流管理，不应 free；后续 readdir 可能复用它，若要长期保存名字须自行复制。

## 27.3 为什么不能只看 d_type

某些文件系统的目录项类型可能返回未知，需要通过 stat/fstatat 等检查。stat 通常跟随软链接，lstat 查看链接自身；fstat 通过已打开 fd 查询对象。目录项名字和你随后操作之间可能被其他参与者改动，称为检查与使用之间的竞态之一。

本程序仅列名字，刻意不声称具有递归安全扫描能力。递归扩展需考虑符号链接环、权限失败、目录在遍历中变化、深度与资源上限。

## 27.4 文件工具的接口契约

好的小工具要写清输入、输出和退出状态。listdir 接收零个或一个目录参数，默认当前目录；忽略 `.` 与 `..`，其他名字原样逐行输出。文件名可以包含换行，因此“每行一个文件名”对任意文件名并不是无歧义编码。本课使用普通实验名字，若扩展为机器处理协议，可设计 NUL 分隔等明确格式。

## 27.5 练习、答案与完成条件

①空目录为什么仍可能有两个特殊项？②输出顺序不同就是程序错了吗？③忽略 permission denied 会造成什么误导？

答案：①接口可能返回 `.` 和 `..`；②不是，排序是额外需求；③会把读取失败伪装成没有文件，用户无法区分数据缺失与访问失败。

改造练习：统计普通命名项个数，先在自己创建的只含三个文件的目录验证，再测空目录与错误路径。完成条件：正确区分“查无结果”“正常结束”“访问失败”，并解释返回指针的生命期。
