# 27 目录接口与文件工具：从列名字到可信地报告结果

> **零基础详细版 · 已重写。** 先读最小目录例程，再编写有界分类统计和NUL分隔工具，区分空目录、结束、读取错误与部分输出。建议8—11小时。

## 1. 学习目标与先修

先完成第25—26章，知道路径、目录项、stat和描述符。本章学完能用opendir/readdir/closedir遍历，解释返回指针生命期，使用目录fd查询条目，设计清楚的输出协议，并在错误后正确关闭资源。

平台Linux/WSL Ubuntu，Bash目录`~/os-lab/files`，lab.h同目录。编译仍使用C17、POSIX200809L、常用警告和-Werror。读取任意不熟悉目录以前，先在自己创建的几个文件上验收。

## 2. 目录不是普通文本清单

目录内部格式由文件系统维护，应用不应拿read把它当每行一个名字的文本。**目录流DIR**是库为遍历维护的对象，opendir建立，readdir返回下一项，closedir关闭。

它与FILE文件流、普通int描述符有关联但接口不同；不要把DIR指针送给fclose，也不要把readdir返回对象free掉。编译器的类型诊断帮助发现这类接口混淆。

## 3. 主线完整程序

[完整源码：listdir.c](示例代码/listdir.c)

```c
#include "lab.h"
#include <dirent.h>

int main(int argc, char *argv[]) {
    if (argc > 2) { fprintf(stderr, "usage: listdir [DIRECTORY]\n"); return 2; }
    DIR *directory = opendir(argc == 2 ? argv[1] : ".");
    if (directory == NULL) { die("opendir"); }
    for (;;) {
        errno = 0;
        struct dirent *entry = readdir(directory);
        if (entry == NULL) {
            if (errno != 0) { die("readdir"); }
            break;
        }
        if (strcmp(entry->d_name, ".") != 0 && strcmp(entry->d_name, "..") != 0) {
            puts(entry->d_name);
        }
    }
    if (closedir(directory) < 0) { die("closedir"); }
    return 0;
}
```

编译：

```bash
gcc -std=c17 -D_POSIX_C_SOURCE=200809L -Wall -Wextra -Wpedantic -Werror -g listdir.c -o listdir
./listdir .
```

默认当前目录，或接受一个目录参数；不排序，忽略`.`和`..`。这个简短例程的致命错误通过die结束整个进程，且未把puts失败纳入完整输出验收；后面的新工具补上正常清理与输出检查。

## 4. 为什么返回NULL还要检查errno

readdir的NULL可能表示正常结束，也可能表示读取错误。每次调用以前设errno=0；返回NULL时检查，非零才按错误处理。不能在循环很久以前只清一次，因为中间的其他接口可能改变errno。

普通成功返回并不负责把旧errno改成0。若先调用别的函数，再回头查看，可能把它的值误认成readdir错误。把检查紧跟返回值，形成一个完整小步骤。

## 5. 返回指针属于谁

entry指向目录流管理的缓冲，后续readdir可能复用；需要长期保存名字时必须自己复制到生命期合适的存储。这里只在本轮立即使用，不保存悬空的entry或d_name。

`.`和`..`是特殊名字；其他以点开头的名字并不等于应该忽略，例如.hidden是普通命名项。本课只明确跳过前两个，不把“隐藏文件”当作不存在。

## 6. 输出次序不是目录排序

readdir不承诺按字母、创建时间或inode排序。两次顺序不同不自动表示工具错，尤其目录内容在变化时。若需求是排序，需要复制名字并明确排序规则与资源上限。

本章统计工具不依赖次序。测试比较名字集合或分类总数，不把本机一次输出顺序写成唯一正确答案。

## 7. d_type为什么不够

一些文件系统会把目录项类型报告为未知，扩展字段的可用性也因平台而异。需要可靠地按当前条目查询类型时，可以使用fstatat等接口。

stat通常跟随符号链接，lstat看链接自身。这里选择`fstatat(base, name, ..., AT_SYMLINK_NOFOLLOW)`，相对于已经打开的目录查询末尾对象自身，所以悬空软链接仍可计为软链接，而不是误报成不存在的普通文件。

## 8. 目录fd的所有权

`dirfd(directory)`取得目录流关联的描述符，供openat/fstatat等定位起点。这个fd仍由目录流管理，本工具不单独close它，最后closedir统一关闭。

锚定目录避免依赖cwd，但不生成原子目录快照：readdir与fstatat之间，条目仍可能被改名或删除。本课受控目录没有并发修改；一般工具遇到查询失败应报告，不把一次检查宣传成递归安全扫描器。

## 9. 分类统计的接口先写清

dir-summary接受一个目录，最多处理1000个非`.`/`..`项；统计regular、directory、symlink、other和普通文件逻辑字节总和。它不递归、不跟随末尾软链接、不去重硬链接。

两个硬链接名字都会算一项，其普通文件size也会各算一次，所以bytes不是“独占磁盘空间”。超过上限、读取或元数据查询失败时，返回非零且不打印成功汇总。

## 10. 完整分类统计工具

**完整程序：dir-summary.c**

```c
#include "lab.h"
#include <dirent.h>
#include <fcntl.h>
#include <inttypes.h>
#include <stdint.h>
#include <sys/stat.h>

int main(int argc, char *argv[]) {
    if (argc != 2) { fputs("usage: dir-summary DIRECTORY\n", stderr); return 2; }
    DIR *directory = opendir(argv[1]);
    if (directory == NULL) { die("opendir"); }
    int base = dirfd(directory), failed = 0;
    unsigned entries = 0, regular = 0, directories = 0, links = 0, other = 0;
    uintmax_t bytes = 0;
    if (base < 0) { perror("dirfd"); failed = 1; goto cleanup; }
    for (;;) {
        errno = 0;
        struct dirent *entry = readdir(directory);
        if (entry == NULL) {
            if (errno != 0) { perror("readdir"); failed = 1; }
            break;
        }
        if (strcmp(entry->d_name, ".") == 0 || strcmp(entry->d_name, "..") == 0) { continue; }
        if (entries == 1000) { fputs("directory limit is 1000 entries\n", stderr); failed = 1; break; }
        entries++;
        struct stat info;
        if (fstatat(base, entry->d_name, &info, AT_SYMLINK_NOFOLLOW) < 0) {
            perror("fstatat"); failed = 1; break;
        }
        if (S_ISREG(info.st_mode)) {
            if (info.st_size < 0 || (uintmax_t)info.st_size > UINTMAX_MAX - bytes) {
                fputs("logical size overflow\n", stderr); failed = 1; break;
            }
            regular++;
            bytes += (uintmax_t)info.st_size;
        } else if (S_ISDIR(info.st_mode)) { directories++; }
        else if (S_ISLNK(info.st_mode)) { links++; }
        else { other++; }
    }
cleanup:
    if (closedir(directory) < 0) { perror("closedir"); failed = 1; }
    if (!failed) {
        if (printf("entries=%u regular=%u directories=%u symlinks=%u other=%u bytes=%ju\n",
                   entries, regular, directories, links, other, bytes) < 0 || fflush(stdout) == EOF) {
            perror("output"); failed = 1;
        }
    }
    return failed;
}
```

编译为dir-summary。在同一个Bash会话中执行：

```bash
cd ~/os-lab/files
fixture_dir=$(mktemp -d "$PWD/directory-fixtures-XXXXXX")
printf 'abc' > "$fixture_dir/a.txt"
mkdir "$fixture_dir/sub"
ln -s a.txt "$fixture_dir/soft"
./dir-summary "$fixture_dir"
```

预期entries=3、regular=1、directories=1、symlinks=1、other=0、bytes=3。保留fixture_dir供后面的名字输出实验使用。

## 11. 为什么逐项查询而不拼一个大路径

fstatat使用目录fd和本轮名字，不用手工把用户目录字符串、斜杠和d_name复制进一个猜大小的char数组。这减少路径拼接边界错误，也明确查询起点。

它仍会进行真实名字查找，不保证对象在遍历期间永远不变。如果要递归或打开文件进一步处理，还需规定链接、深度、权限失败和并发变化策略；本例刻意保持一层目录的契约。

## 12. 先清理，再宣布汇总成功

读取和查询失败都跳到或结束到cleanup，closedir只调用一次。若关闭本身失败，也不打印正常汇总。最后检查printf与fflush，避免“数据输出没送出却返回成功”。

这不是每个系统错误都可恢复的万能库，但它让资源归属和成功边界清楚。错误信息到stderr，汇总到stdout，方便调用者分别保存。

## 13. 文件名可以包含换行

Linux名字不能包含路径分隔符斜杠和NUL字节，但可以有空格、制表符、换行等字符。原listdir用换行分隔名字，对这些名字会产生歧义：一个带换行的名字看起来像两个条目。

人阅读的清单可以另外设计转义；机器处理可以用NUL分隔，因为合法单个文件名本身不含NUL。Shell中的引号负责把参数传完整，不自动给工具输出建立无歧义协议。

## 14. 完整NUL分隔工具

**完整程序：dir-nul.c**

```c
#include "lab.h"
#include <dirent.h>

int main(int argc, char *argv[]) {
    if (argc != 2) { fputs("usage: dir-nul DIRECTORY\n", stderr); return 2; }
    DIR *directory = opendir(argv[1]);
    if (directory == NULL) { die("opendir"); }
    int failed = 0;
    for (;;) {
        errno = 0;
        struct dirent *entry = readdir(directory);
        if (entry == NULL) {
            if (errno != 0) { perror("readdir"); failed = 1; }
            break;
        }
        if (strcmp(entry->d_name, ".") == 0 || strcmp(entry->d_name, "..") == 0) { continue; }
        size_t length = strlen(entry->d_name);
        if (fwrite(entry->d_name, 1, length, stdout) != length || fputc('\0', stdout) == EOF) {
            fputs("could not write complete name record\n", stderr); failed = 1; break;
        }
    }
    if (closedir(directory) < 0) { perror("closedir"); failed = 1; }
    if (!failed && fflush(stdout) == EOF) { perror("flush output"); failed = 1; }
    return failed;
}
```

编译为dir-nul。运行`./dir-nul "$fixture_dir" > names.bin`，再`od -An -tx1 names.bin`观察；00是记录分隔符，名字中的换行是0a，空格是20。names.bin是本次实验输出，不用已有文档作重定向目标。不要把NUL协议直接当屏幕上可见换行的列表。

## 15. 一个可控特殊名字练习

仅在上述fixture_dir中，可用Bash的`$'line\nbreak.txt'`写出包含换行的单个参数，例如：

```bash
printf 'x' > "$fixture_dir"/$'line\nbreak.txt'
./dir-nul "$fixture_dir" > names.bin
od -An -tx1 names.bin
```

`$'...'`是Bash解释反斜杠转义的引用形式，不是C源代码，也不是把两个文件同时创建。输出序列可随遍历顺序变化，但拆成NUL记录后应恰好得到真实名字，不能按0a拆分。

## 16. 部分输出应如何解释

dir-nul可能在输出几个记录后遇到错误。它返回非零表示这次输出不完整，调用者不应把已有前缀当作全部清单。若业务需要“成功才发布结果”，先写自己的临时输出，全部成功以后再发布，第28章会讨论。

本章不承诺目录在扫描期间保持不变，不递归，也不处理任意敌对文件树。把工具契约写窄并如实报告失败，比无条件输出“扫描完成”更有用。

## 17. 按三类结果测试

空目录：成功，summary全0，dir-nul产生0字节。普通受控目录：检查分类、字节和名字集合。失败：不存在、非目录、搜索/读取不允许、读取中错误或元数据查询失败，都不能伪装为空。

配套测试会定点模拟readdir在已返回部分条目后失败，核对新工具关闭DIR并返回失败；同时测试1000/1001项上限及特殊名字。没有用真实目录破坏来制造错误。

## 18. 常见错误

把NULL一律当正常结束：清errno后分辨。

保存所有entry指针等最后打印：目录缓冲可能复用，应复制或即时处理。

拿d_type未知当普通文件：查询元数据或明确报告未知。

closedir后再close dirfd：所有权已由目录流管理，避免重复关闭。

把逻辑字节汇总称为磁盘占用：硬链接、空洞等让口径不同。

## 19. 练习与参考答案

1. 两个普通文件名字是同一硬链接对象，summary计几项？两项，不做去重；bytes也按两次逻辑大小累计。
2. 悬空软链接是否可以被本工具计为symlink？可以，fstatat不跟随末尾链接。
3. 空目录的dir-nul输出应该有一个NUL吗？没有，0个记录是0字节。
4. 输出顺序改变怎么验收？比较相应集合/计数，不假定排序。
5. readdir部分失败后stdout已有数据，可以认为其余没有了吗？不能，非零状态表示清单不完整。

动手题：在新目录加入一个隐藏名字、一个空格名字和一个软链接，先手写分类与原始名字，再用两个新工具核对。不要用“看起来几行”统计任意文件名。
