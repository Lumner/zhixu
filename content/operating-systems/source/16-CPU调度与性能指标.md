# 16 CPU调度与性能指标：沿时间线算清谁在等

> **零基础详细版 · 已重写。** 本章使用明确假设下的单CPU模型，逐步演算FCFS、SJF、时间片轮转与抢占，程序用于核对手算，不修改真实内核调度策略。建议7—10小时。

## 1. 先回答哪个问题

前面创建了多个进程，但一个CPU在一个时刻只能执行一条相应的执行流。**调度**要决定：在目前可以运行的任务里，接下来让谁使用CPU，用多久。

学完应能区分就绪和阻塞，标出到达、首次运行、完成时刻，计算周转、响应和等待时间，并说明某个算法为什么在特定输入上表现好。先修是第05章循环、第09章结构体、第12章进程状态。本章不需要先会线程。

## 2. 机制与策略的分工

**机制**负责把CPU从一个任务切换到另一个任务，例如保存寄存器和恢复执行位置。**策略**负责选择接下来运行谁。前者让切换成为可能，后者决定如何分配机会。

公平、平均完成速度、交互响应、优先级、能耗等目标可能相互牵制。不能只看“某算法平均等待更短”就断言它在所有系统都最好。真实多核系统还要处理CPU亲和性、缓存、负载平衡等问题，本章先固定更小的模型。

## 3. 每次计算先声明假设

第4—12节统一使用：一个CPU；三个任务A、B、C；都在时刻0到达；所需CPU时间分别为5、3、1个时间单位；没有I/O阻塞；没有切换开销；输入顺序A、B、C；任务长度事先已知。

这里的**CPU运行段**或burst是连续需要CPU的工作量。本模型每个任务只有一个这样的段。时间单位可以理解为抽象刻度，不直接等于某台机器的毫秒。

这些假设让我们能专注算法关系。真实系统通常不知道任务未来还要运行多久，因此模型中的“最短”需要额外信息或估计，不能拿未来答案作弊来评价真实调度器。

## 4. 四个时刻与三个时间

| 记号 | 含义 | 怎样在时间线上找 |
| --- | --- | --- |
| A | 到达时刻 | 任务开始进入可调度范围 |
| B | 总CPU工作量 | 累加所有真正运行的片段 |
| F | 首次运行时刻 | 第一次获得CPU的左边界 |
| C | 完成时刻 | 最后一段运行的右边界 |

**周转时间**`T = C - A`，表示从到达到完成的总历时。**响应时间**`R = F - A`，表示多久才第一次得到执行机会，本章采用这个调度模型定义，不等同于网页用户看到完整结果的端到端延迟。

**就绪等待时间**是任务已经可以运行、却在排队的时间。在本章无I/O、无额外暂停的模型里，`W = T - B`。一旦有阻塞，周转中还含等待设备等时间，不能不加条件继续使用这个等式当作就绪等待。

## 5. 先画先来先服务FCFS

**先来先服务**按到达队列依次运行，一个任务不主动阻塞就让它完成。所有同时到达时，还要指定相同到达时刻的顺序，本例为A、B、C。

```text
时刻 0             5       8   9
     |------ A ----|-- B --|-C-|
```

A从0运行到5，等待0；B等A的5个单位，从5到8；C等前面共8个单位，从8到9。区间用左闭右开的理解，例如A占用[0,5)，长度是5，不是数端点得6。

| 任务 | 首次F | 完成C | 周转T | 等待W | 响应R |
| --- | --- | --- | --- | --- | --- |
| A | 0 | 5 | 5 | 0 | 0 |
| B | 5 | 8 | 8 | 5 | 5 |
| C | 8 | 9 | 9 | 8 | 8 |

平均等待`(0+5+8)/3 = 13/3 ≈ 4.333`。平均不是把完成时刻相加后直接叫等待；每一列都要按定义算。

## 6. 用主线程序核对FCFS

Linux/WSL Ubuntu的Bash，目录`~/os-lab/processes`。

[完整源码：scheduling.c](示例代码/scheduling.c)

```c
/* Model: all arrivals are 0, FCFS order A/B/C, no context-switch cost. */
#include <stdio.h>

int main(void) {
    const int burst[] = {5, 3, 1};
    int now = 0;
    int sum_wait = 0;
    for (int i = 0; i < 3; i++) {
        int wait = now;
        now += burst[i];
        sum_wait += wait;
        printf("%c wait=%d turnaround=%d\n", 'A' + i, wait, now);
    }
    printf("average_wait=%.3f\n", sum_wait / 3.0);
    return 0;
}
```

编译运行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -Werror -g scheduling.c -o scheduling
./scheduling
```

预期：

```text
A wait=0 turnaround=5
B wait=5 turnaround=8
C wait=8 turnaround=9
average_wait=4.333
```

`now`表示当前模拟时刻，不是读取真实时钟。`sum_wait / 3.0`使用浮点除法，避免整数除法截断。`'A' + i`在本课Linux字符环境中依次打印A/B/C。

## 7. 最短任务优先SJF怎样算

**非抢占式最短任务优先**在CPU空闲时，从已到达任务中选总运行段最短的那个；一旦开始，不因另一个更短任务到来而中途切走。本例所有任务都在0到达，所以顺序为C、B、A。

```text
0   1       4             9
|-C-|-- B --|------ A ----|
```

C等待0，B等待1，A等待4，平均等待`(0+1+4)/3 ≈ 1.667`。如果按A/B/C顺序列结果，分别是4、1、0，不能因为执行顺序换了就把任务名字对应错。

在这些假设下，短任务先完成减少了许多任务被长任务挡住的时间。它并没有减少总工作量：CPU仍运行9个时间单位。

## 8. 一个有限的SJF模型

**完整程序：sjf-model.c**

```c
#include <stdio.h>

int main(void) {
    const int burst[3] = {5, 3, 1};
    int used[3] = {0};
    int now = 0;
    int sum_wait = 0;
    for (int round = 0; round < 3; round++) {
        int chosen = -1;
        for (int i = 0; i < 3; i++) {
            if (!used[i] && (chosen < 0 || burst[i] < burst[chosen])) {
                chosen = i;
            }
        }
        int start = now;
        now += burst[chosen];
        used[chosen] = 1;
        sum_wait += start;
        printf("%c start=%d end=%d wait=%d\n",
               'A' + chosen, start, now, start);
    }
    printf("average_wait=%.3f\n", sum_wait / 3.0);
    return 0;
}
```

编译为`sjf-model`。结果依次C的0—1、B的1—4、A的4—9，平均1.667。`chosen = -1`表示本轮尚未选到；`||`短路保证尚未选到时不会访问`burst[-1]`。长度相同时，因为只在严格更短时替换，保持输入顺序优先。

程序只处理固定三个、都已到达的任务。把有未来到达的任务不加筛选放进这个数组就直接选最短，不再是正确的对应模型。扩展前先改需求和状态，不只改数字。

## 9. 时间片轮转RR的规则

**时间片**是一次连续分配给任务的最长CPU额度。**时间片轮转**按就绪队列轮流运行；本轮没完成的任务，放到队尾，等待下一轮。

本例时间片q=2。因为所有任务0到达且没有阻塞，可以按A/B/C循环扫描尚未完成者。一般有新到达、阻塞的模型需要显式维护就绪队列，不能机械照搬固定数组扫描。

逐段演算：

| 区间 | 运行者 | 本段结束后剩余A/B/C |
| --- | --- | --- |
| 0—2 | A | 3 / 3 / 1 |
| 2—4 | B | 3 / 1 / 1 |
| 4—5 | C | 3 / 1 / 0 |
| 5—7 | A | 1 / 1 / 0 |
| 7—8 | B | 1 / 0 / 0 |
| 8—9 | A | 0 / 0 / 0 |

C只需要1，因此不占满2个时间单位；完成者退出队列，不再消耗时间片。

## 10. RR的等待不能只看第一次

| 任务 | F | C | T | W=T-B | R=F-A |
| --- | --- | --- | --- | --- | --- |
| A | 0 | 9 | 9 | 4 | 0 |
| B | 2 | 8 | 8 | 5 | 2 |
| C | 4 | 5 | 5 | 4 | 4 |

A第一次就运行，响应为0，但它中途仍等待其他任务共4个单位，因此等待不是0。响应只数第一次得到CPU前的时间，等待要累计所有排队片段。

平均等待仍为4.333，与本例FCFS碰巧相同；平均响应从4.333变成2。单个指标相同不表示调度过程和所有任务体验相同。

## 11. 完整时间片模型

**完整程序：rr-model.c**

```c
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>

struct Job {
    int burst;
    int remaining;
    int first;
    int completion;
};

int main(int argc, char *argv[]) {
    int quantum = 2;
    if (argc > 2) {
        fputs("usage: rr-model [QUANTUM_1_TO_100]\n", stderr);
        return 2;
    }
    if (argc == 2) {
        char *end;
        errno = 0;
        long value = strtol(argv[1], &end, 10);
        if (errno != 0 || end == argv[1] || *end != '\0' || value < 1 || value > 100) {
            fputs("quantum must be an integer from 1 to 100\n", stderr);
            return 2;
        }
        quantum = (int)value;
    }
    struct Job jobs[3] = {{5, 5, -1, 0}, {3, 3, -1, 0}, {1, 1, -1, 0}};
    int now = 0;
    int finished = 0;
    while (finished < 3) {
        for (int i = 0; i < 3; i++) {
            if (jobs[i].remaining == 0) { continue; }
            if (jobs[i].first < 0) { jobs[i].first = now; }
            int run = jobs[i].remaining < quantum ? jobs[i].remaining : quantum;
            printf("%c slice=%d..%d\n", 'A' + i, now, now + run);
            now += run;
            jobs[i].remaining -= run;
            if (jobs[i].remaining == 0) {
                jobs[i].completion = now;
                finished++;
            }
        }
    }
    int sum_wait = 0;
    for (int i = 0; i < 3; i++) {
        int turnaround = jobs[i].completion;
        int wait = turnaround - jobs[i].burst;
        sum_wait += wait;
        printf("%c wait=%d turnaround=%d response=%d\n",
               'A' + i, wait, turnaround, jobs[i].first);
    }
    printf("average_wait=%.3f\n", sum_wait / 3.0);
    return 0;
}
```

编译为`rr-model`，依次执行`./rr-model`、`./rr-model 1`、`./rr-model 20`、`./rr-model 0`。默认结果应匹配第9、10节；0会被拒绝，退出2，避免“每轮消耗0、循环永不结束”。数字解析复用了第10章的`strtol`协议，并限定小范围避免模型算术超出界限。

## 12. 对照三个时间片

| q | A/B/C完成时刻 | A/B/C等待 | A/B/C响应 | 平均等待 |
| --- | --- | --- | --- | --- |
| 1 | 9 / 7 / 3 | 4 / 4 / 2 | 0 / 1 / 2 | 3.333 |
| 2 | 9 / 8 / 5 | 4 / 5 / 4 | 0 / 2 / 4 | 4.333 |
| 20 | 5 / 8 / 9 | 0 / 5 / 8 | 0 / 5 / 8 | 4.333 |

q=20大于每个运行段，行为在本例退化为FCFS。q=1更早让每个任务获得第一次机会，但若真实系统每次切换都要耗时，过小时间片会增加管理成本。本表特意假设切换成本为0，因此不能用它证明“真实系统时间片越小越好”。

## 13. 新任务到来时：抢占与非抢占

现在换一组数据，必须重新声明：A在0到达，需要8；B在1到达，需要4；C在2到达，需要1。仍为单CPU、无I/O、零切换开销。

**抢占**表示正在运行的任务可在尚未完成时被切走。**最短剩余时间优先SRTF**比较已到达任务尚需的CPU量，优先运行剩余最短者。按本例没有相等长度的争议：

```text
0..1 A，1..2 B，2..3 C，3..6 B，6..13 A
```

1时刻A还剩7，B需要4，切到B；2时刻B还剩3，C只需1，切到C；3时刻C完成，B剩3比A剩7短，先让B完成。

## 14. 按公式验证抢占结果

| 任务 | 到达A | 工作量B | 首次F | 完成C | 周转T | 等待W | 响应R |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A | 0 | 8 | 0 | 13 | 13 | 5 | 0 |
| B | 1 | 4 | 1 | 6 | 5 | 1 | 0 |
| C | 2 | 1 | 2 | 3 | 1 | 0 | 0 |

平均等待2。注意B的周转为6-1=5，不是完成时刻6；所有响应0也不表示所有任务都没等待，A后来被抢占等待了5。

若采用非抢占SJF，时刻0只有A可选，于是先A运行0—8，再C运行8—9，再B运行9—13。等待分别A=0、B=8、C=6，平均14/3≈4.667。不能一开始就让未来时刻2才到达的C运行，那违反到达约束。

## 15. 没有就绪任务时CPU要空闲

另换数据：A在2到达需2，B在3到达需1，C在8到达需1。FCFS时间线是：空闲0—2，A 2—4，B 4—5，空闲5—8，C 8—9。

等待A=0、B=1、C=0；总有用CPU时间4。在观察窗口[0,9)内，**CPU利用率**为4/9≈44.4%。若把窗口改为[2,9)，数值就不同，所以报告利用率必须说明统计窗口。

**吞吐量**是在指定时间窗口完成多少任务，不能把“每个任务首次响应快”直接等同于吞吐量高。没有任务可运行时，正确模型应该推进到下一次到达，不能让时钟卡在原地无限选择。

## 16. 等待不一定是CPU不够

程序在read里等待终端输入、在waitpid里等待孩子时，可能处于阻塞状态，不是一直在就绪队列排队。增加CPU核心不必然解决这种等待。

同理，墙上时间过去10秒不表示进程使用了10秒CPU。真实排错先问它在计算、就绪等待、设备等待还是互相等待；第34章再用观察工具把证据串起来。本章程序打印的`now`只是模型数字，不是性能基准测量。

## 17. 优先级、公平和饥饿

**优先级调度**给不同任务不同选择次序；如果低优先级任务长期得不到机会，称为**饥饿**。持续到来的短任务也可能让长任务在某些策略下等待很久。

**老化**是随等待增加而调整待遇的一类思路，避免一直被新任务压后。多级反馈队列根据任务表现调整其所在队列，尝试兼顾交互和计算任务；它还需要明确层级、额度和提升规则，不能仅凭名字就算出结果。

这些是理解设计取舍的入口，不宣称Linux当前默认调度器就是本章某一个简单算法。本批不执行修改调度策略、进程优先级或实时权限的命令。

## 18. 常见算错点

把完成时刻当周转：到达不为0时先相减。

把第一次等待当总等待：抢占任务要累计所有就绪间隔，或在符合本章假设时用T-B。

把所有任务按长度全排序：先筛选已经到达、可运行的任务。

把时间片用满：短任务只占实际剩余量，完成立即离队。

漏掉空闲区间：没有就绪者时CPU不凭空执行未来任务。

把模拟输出当内核证据：本程序只有数组和循环，没有创建三个真实被调度的孩子。

## 19. 练习、提示与参考答案

1. 本章FCFS中，C的周转和等待为什么相差1？
2. q=2时A响应0、等待4，是否矛盾？
3. 对都在0到达、运行段A=4、B=2、C=2，SJF相同长度按输入顺序，画时间线。
4. 若进程周转10、CPU运行3、设备阻塞4，就绪等待能直接写7吗？
5. 总有用运行4、观察窗口长度10，利用率多少？

参考答案：第一题多出的1是C自己运行的时间；第二题不矛盾，A后来也要排队；第三题B 0—2、C 2—4、A 4—8，等待A4/B0/C2，平均2；第四题不能，在已列时间完全覆盖且无其他开销的前提下，就绪等待为10-3-4=3；第五题40%。

改造练习：只在SJF模型中把三个burst改成4、2、2，比较程序与第三题；再手算q=1，确认你没有把SJF和RR的选人规则混用。固定答案是RR时间线A/B/C/A/B/C/A/A，完成A8、B5、C6，等待4、3、4。
