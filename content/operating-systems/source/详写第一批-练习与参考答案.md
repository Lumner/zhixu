## 一、题目：用自己的话解释

**题1：找职责。** 你用编辑器输入一句笔记、保存、退出，第二天又打开。分别说明CPU、内存、持久存储、编辑器和操作系统可能参与什么。不要只给出“CPU像大脑”这种未解释职责的比喻。

**题2：判断边界。** 对每句话写“成立/不成立/信息不足”，再说明原因：①删视频能增加物理内存容量；②屏幕上看见文字说明一定已经可靠保存；③一个窗口一定等于一个进程；④两个程序在同一段时间都有进展，因此一定在两个核心上并行执行。

**题3：数值与单位。** 二进制00001010是多少？一个八位无符号数有多少种取值、最大是多少？UTF-8下 `A中` 为什么不能只凭“两个字”就断定两字节？

## 五、参考答案：概念题

题1：编辑器接收输入、维护文字并显示；CPU执行程序指令；内存保存运行中的相关状态；操作系统组织资源、处理访问请求和结果；持久设备按保存机制记录文件数据，以便以后读取。缓存与设备保证影响持久性，不能从点击动作推导所有后果。

题2：①不成立，释放存储空间不等于增加内存条容量；②不成立，显示和持久保存是不同层；③不成立，窗口与进程并不一一对应；④不成立，一个核心交错运行也可能让多个任务在一段时间内推进。

题3：10，因为8+2=10；256种取值、最大255；两个字符可以编码为四个字节，字符数与字节数单位不同。

## 六、参考答案：终端操作

以下在Ubuntu Bash逐行执行，终端中不输入代码围栏和语言标签：

```bash
mkdir -p ~/os-lab/batch01-review
cd ~/os-lab/batch01-review
pwd
mkdir -p notes
printf 'I can find my files.\n' > notes/review.txt
cat notes/review.txt
cd notes
cat review.txt
cd ..
cat notes/review.txt
```

三个cat应读到同样一行文字。第一次与第三次的查找起点在batch01-review，需要带notes；第二次起点就在notes，所以直接用review.txt。

题7可用pwd确认起点，ls和ls notes确认名字。正确读取方式是 `cat notes/review.txt`，或先进入notes再读。sudo改变权限，不会自动补上漏掉的路径部分。

## 七、参考答案：完整程序和编译

题8的review.c完整内容如下：

```c
#include <stdio.h>

int main(void) {
    printf("I wrote this file myself.\n");
    printf("I can explain each step.\n");
    return 0;
}
```

在同目录执行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -g review.c -o review
./review
echo $?
```

先出现两行指定文字，后出现0。把return后面的0改为5，重新编译，再用相同步骤查看，文字不变、退出状态变成5。状态是返回给环境的结果，不是由字符串描述自动生成。

题10：编辑源文件不会改写已存在的生成文件；编译失败也不保证删除上次的旧可执行文件。应该先修复编译，确认此次成功，再运行正确目录里的结果，不能把旧输出当作新代码通过证明。

题11：补回分号后重新保存、编译、运行。正确复盘应指明哪个文件哪条语句缺了什么，不能只记录“试了几次好了”。
