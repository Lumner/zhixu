## 2. 四层职责再对一次

| 层次 | 主要问题 | 对应例子 |
| --- | --- | --- |
| C对象 | 类型、边界、生命期、所有权 | malloc后只能访问合法范围，free后停止使用 |
| 分配器 | 如何在取得的区域内管理对象 | 小块复用、对齐、空闲链等 |
| 虚拟映射 | 哪段地址有什么访问规则和后备 | mmap私有文件映射 |
| 驻留与物理资源 | 哪些页面实际在RAM，怎样补齐和回收 | 按需分页、置换 |

一个层次的成功不替代另一个层次的规则。mmap得到一段可读写区域，不允许你在区域外访问；free完成对象释放，也不保证分配器马上把整页交回内核。

## 3. malloc不一定每次向内核要一页

分配器可以先取得较大区域，再从中提供多个对象；后续malloc可能只是复用已有空闲块。free把对象交回分配器，分配器可以为后续申请保留区域。

所以“每调用一次malloc就新增一个系统调用”和“free后RSS立刻减少同样字节”都不是通用约定。是否泄漏，应追踪对象是否失去可释放的所有权、重复负载是否持续累积等证据，不只看一次RSS。

本课不依赖某版本glibc内部的精确阈值与空闲链结构，也不把分配器实现细节写成C语言保证。

## 4. 栈与堆不只是地址高低

自动对象常与调用栈有关，动态对象由分配与释放协议管理；但“地址较大就是栈”“小数值就是堆”不是可靠分类办法。优化和具体布局会影响对象实际位置。

递归调用过深或局部数据过大可能耗尽栈资源，但本批不通过无限递归制造故障。需要大量可变数据时，先做容量预算、错误检查与生命期设计，不把所有数组机械搬到堆后就宣布问题解决。

多个线程的栈分别管理，却仍位于同一进程地址空间；把地址交给另一线程仍须保证对象有效并且访问已同步。

## 5. 内部碎片与外部碎片

**内部碎片**是分配单位内部未使用的空间。假设一个专用映射需要5字节，模型页大小4字节，实际需覆盖2页共8字节，最后3字节未用于这次需求。真实小malloc对象可能共用分配器页面，不能逐个按此公式推算RSS。

**外部碎片**是空闲范围分散。例如两个不相邻的4字节空洞，总量8却不能提供一块连续6字节范围。分页降低了连续虚拟区间必须对应连续物理页框的要求，但没有消除所有分配器、虚拟地址和特殊连续物理需求问题。

## 6. mmap把文件内容映射进地址空间

`mmap`建立虚拟映射，不是C对象分配器的同义词。主要参数是地址建议、长度、访问权限、映射方式、描述符、文件偏移。传NULL让系统选择地址；长度必须合理且非零；文件偏移通常需满足页对齐要求。

返回MAP_FAILED表示失败，不能只与NULL比较。成功后访问范围还受映射长度与文件有效内容限制；文件被截短等变化可能使原先访问不再安全，本批文件大小在使用期间固定。

mmap建立映射不承诺马上读入整个文件。这里用3字节小文件观察语义，不把它当作大文件读取性能测量。

## 7. 主线：私有修改不回写文件

[完整源码：mapping.c](示例代码/mapping.c)

```c
#include "lab.h"
#include <sys/mman.h>

int main(void) {
    FILE *file = tmpfile();
    if (file == NULL) { die("tmpfile"); }
    int fd = fileno(file);
    if (fd < 0) { die("fileno"); }
    if (fflush(file) != 0) { die("fflush"); }
    write_all(fd, "abc", 3);
    char *memory = mmap(NULL, 3, PROT_READ | PROT_WRITE, MAP_PRIVATE, fd, 0);
    if (memory == MAP_FAILED) { die("mmap"); }
    memory[0] = 'X';
    char original;
    if (pread(fd, &original, 1, 0) != 1) { die("pread"); }
    printf("mapping=%c file=%c\n", memory[0], original);
    if (munmap(memory, 3) < 0) { die("munmap"); }
    if (fclose(file) != 0) { die("fclose"); }
    return 0;
}
```

编译为mapping并运行，预期`mapping=X file=a`。`tmpfile`提供临时文件流，`fileno`取得关联描述符；先fflush明确完成流到底层描述符的交接，随后不再通过stdio读写这个文件，只在最后关闭流。pread按指定偏移读取，不改变通常的当前文件偏移。

原主线采用“不可恢复错误就结束进程”的简短策略；例如pread意外返回0时，perror未必提供准确原因。下面扩展版把负错误与正的短结果分开，并展示集中清理，不用正常测试替它宣称所有错误处理完备。

## 8. 私有与共享先给出契约

**MAP_PRIVATE**通过这个映射的修改不会用于更新底层文件，本课可写私有映射常用COW实现。**MAP_SHARED**使相应修改与共享映射/文件后备关联，适合需要共享更新的设计，但仍要单独安排同步与持久化。

其他途径修改文件以后，私有映射会不会反映变化存在额外语义边界；本课不据此承诺它是一份永远冻结的完整快照。下面先完成私有实验并撤销，再建立共享实验，避免用不明确的混合观察下结论。

## 9. 完整私有/共享对照程序

**完整程序：map-modes.c**

```c
#include "lab.h"
#include <sys/mman.h>

int main(void) {
    char name[] = "map-modes-XXXXXX";
    int fd = mkstemp(name);
    if (fd < 0) { die("mkstemp"); }
    if (unlink(name) < 0) { perror("unlink temporary"); close(fd); return 1; }
    char *private_map = MAP_FAILED, *shared_map = MAP_FAILED;
    int failed = 1;
    char original;
    ssize_t n;
    do { n = pwrite(fd, "abc", 3, 0); } while (n < 0 && errno == EINTR);
    if (n < 0) { perror("pwrite seed"); goto cleanup; }
    if (n != 3) { fputs("short seed write\n", stderr); goto cleanup; }
    private_map = mmap(NULL, 3, PROT_READ | PROT_WRITE, MAP_PRIVATE, fd, 0);
    if (private_map == MAP_FAILED) { perror("mmap private"); goto cleanup; }
    private_map[0] = 'X';
    do { n = pread(fd, &original, 1, 0); } while (n < 0 && errno == EINTR);
    if (n < 0) { perror("pread private"); goto cleanup; }
    if (n != 1) { fputs("short private read\n", stderr); goto cleanup; }
    printf("private=%c file=%c\n", private_map[0], original);
    if (munmap(private_map, 3) < 0) { perror("unmap private"); goto cleanup; }
    private_map = MAP_FAILED;
    shared_map = mmap(NULL, 3, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (shared_map == MAP_FAILED) { perror("mmap shared"); goto cleanup; }
    shared_map[0] = 'Y';
    if (msync(shared_map, 3, MS_SYNC) < 0) { perror("msync"); goto cleanup; }
    do { n = pread(fd, &original, 1, 0); } while (n < 0 && errno == EINTR);
    if (n < 0) { perror("pread shared"); goto cleanup; }
    if (n != 1) { fputs("short shared read\n", stderr); goto cleanup; }
    printf("shared=%c file=%c\n", shared_map[0], original);
    failed = 0;
cleanup:
    if (private_map != MAP_FAILED && munmap(private_map, 3) < 0) {
        perror("cleanup private"); failed = 1;
    }
    if (shared_map != MAP_FAILED && munmap(shared_map, 3) < 0) {
        perror("cleanup shared"); failed = 1;
    }
    if (close(fd) < 0) { perror("close temporary"); failed = 1; }
    return failed;
}
```

编译为map-modes，正常两行：`private=X file=a`、`shared=Y file=Y`。临时文件由mkstemp创建，再unlink去掉目录名字，已打开描述符仍可使用，最后关闭并撤销映射。文件名中的XXXXXX必须是可修改字符数组，让接口填入唯一名字。

## 10. 新出现的goto与清理标志

`cleanup:`是标签，`goto cleanup`跳到集中清理位置，不是重新调用main，也不会自动撤销之前操作。失败时保留已经成功取得资源的状态，统一按状态释放。

两个映射指针先设MAP_FAILED，只有成功后才代表待撤销资源；private成功撤销后重设哨兵，避免重复munmap。failed先为1，所有主要步骤成功才设0，清理错误仍可把它改回1。

pwrite/pread负返回值按errno解释；意外短结果使用自己的说明，不拿陈旧errno输出Success。此扩展版选择把短初始化写视为失败并收尾，而不是假装3字节已经完整写入；所以不会继续映射一个未完成初始化的小文件。

## 11. msync与持久性不能混成一句话

`msync(..., MS_SYNC)`请求将相应文件映射修改更新到文件系统并等待完成。它不是给MAP_PRIVATE补一个“保存”按钮；私有映射的修改本来就没有更新原文件的契约。

共享可见、写回请求完成、文件及目录崩溃后恢复，是不同层次。第28章再讨论fsync与持久化协议。本实验未断电、未模拟真实存储崩溃，不宣称看到file=Y就完成了所有持久性验收。

## 12. 文件描述符关闭，映射仍可存在

映射建立后有自己的内核引用关系，不要求应用一直保留原描述符。close或fclose结束文件句柄使用，不等于munmap撤销地址范围。

反过来，munmap后旧地址不再属于那份映射，不能因为文件仍打开就继续读旧指针。对象、描述符、映射各自管理生命期，必须说明谁负责哪一步。

## 13. 完整生命期与权限实验

**完整程序：map-lifetime.c**

```c
#include "lab.h"
#include <sys/mman.h>

int main(void) {
    FILE *file = tmpfile();
    if (file == NULL) { die("tmpfile"); }
    char *memory = MAP_FAILED;
    int failed = 1;
    int fd = fileno(file);
    if (fd < 0) { perror("fileno"); goto cleanup; }
    if (fflush(file) != 0) { perror("fflush"); goto cleanup; }
    write_all(fd, "abc", 3);
    memory = mmap(NULL, 3, PROT_READ, MAP_PRIVATE, fd, 0);
    if (memory == MAP_FAILED) { perror("mmap"); goto cleanup; }
    printf("before_close=%c%c%c\n", memory[0], memory[1], memory[2]);
    int close_result = fclose(file);
    file = NULL;
    if (close_result != 0) { perror("fclose"); goto cleanup; }
    if (mprotect(memory, 3, PROT_READ | PROT_WRITE) < 0) {
        perror("mprotect"); goto cleanup;
    }
    memory[1] = 'Z';
    printf("after_close=%c%c%c\n", memory[0], memory[1], memory[2]);
    failed = 0;
cleanup:
    if (memory != MAP_FAILED && munmap(memory, 3) < 0) {
        perror("munmap"); failed = 1;
    }
    if (file != NULL && fclose(file) != 0) { perror("fclose cleanup"); failed = 1; }
    return failed;
}
```

编译运行，预期`before_close=abc`、`after_close=aZc`。先只读映射，文件关闭后成功mprotect增加写权限，才修改第1号字节。没有故意在只读阶段写入，也没有munmap后继续访问。

## 14. 权限变化和C边界仍要同时满足

mprotect要求起始地址满足页对齐等契约；mmap返回的起点符合本例需要。它按覆盖的页面改变权限，不是替某个C数组增加长度。这里只访问3字节已初始化内容，不因为系统映射按页覆盖就读第4个甚至更远字节。

fclose不论成功还是报告关闭错误，都不能继续把旧FILE对象当成仍可用的流；本例调用后立即把file设NULL，清理时不重复关闭。write_all的不可恢复错误仍会终止进程，本版细致清理的是映射、权限和关闭后的正常/失败路径，不是通用服务恢复库。

## 15. 时间与空间局部性

**时间局部性**指近期使用的数据可能很快再次使用；**空间局部性**指访问某位置后，附近位置可能接着被访问。它们是许多缓存和驻留策略有用的工作负载规律，不是对每次未来访问的保证。

C二维数组按行连续组织。遍历顺序改变会改变页面和缓存访问序列，但真实速度还受缓存线、预取、向量化、优化、TLB、数据规模和系统负载影响。本章先用可以手算的页面模型隔离这个因素。

## 16. 局部性的有限页面模型

假设4×4个单元，每个**模型单元固定4字节**，一行16字节；模型页16字节，只有2个驻留框，FIFO。按行访问的页号为0,0,0,0,1,1,1,1等；按列则为0,1,2,3反复四轮。

**完整程序：locality-pages.c**

```c
#include <stdio.h>

static int scan(int column_first) {
    int frames[2] = {-1, -1};
    int next = 0, faults = 0;
    for (int outer = 0; outer < 4; outer++) {
        for (int inner = 0; inner < 4; inner++) {
            int row = column_first ? inner : outer;
            int column = column_first ? outer : inner;
            int address = (row * 4 + column) * 4;
            int page = address / 16;
            int hit = frames[0] == page || frames[1] == page;
            if (!hit) {
                frames[next] = page;
                next = (next + 1) % 2;
                faults++;
            }
        }
    }
    return faults;
}
int main(void) {
    printf("row_major_faults=%d\n", scan(0));
    printf("column_major_faults=%d\n", scan(1));
    return 0;
}
```

编译运行，预期按行4次、按列16次。这只是计算访问序列，未分配真实16字节系统页，也没有测实际CPU缓存。固定4字节单元是模型假设，不声称所有C环境sizeof(int)必为4。

## 17. 若要测真实性能，先定义问题

真实基准需要固定输入规模、编译选项和工作量，多次运行，区分冷启动与缓存已热，避免把大量printf计入数据访问时间。还要确认编译器没有把未使用计算整个优化掉。

本批不从一次小程序时间推导硬件普遍结论。模型解释为什么访问顺序可能重要；真实应用是否受此瓶颈影响，需要另收证据。页替换模型的fault也不能冒充/proc统计到的真实缺页。

## 18. 常见错误与排查

用NULL判断mmap失败：按MAP_FAILED契约。

私有映射改完再fclose期待保存：先检查映射模式，不靠关闭改变语义。

描述符关了就立即认定映射失效：分别画描述符与映射生命期。

munmap后继续读验证“地址还在”：停止使用旧映射，不执行失效访问。

文件长度0或被截短仍直接读旧范围：先建立有效长度与访问协议。

RSS不降就重复free：对象已经释放后不可再次释放，回到所有权与分配器层排查。

## 19. 练习、提示与参考答案

1. 5字节专用映射、模型页4字节，覆盖几页、尾部未用几字节？2页、3字节，不能直接套为每次malloc的物理占用。
2. map-modes私有修改能靠MS_SYNC变成共享保存吗？不能，映射契约不同。
3. map-lifetime在mprotect失败时应继续写Z吗？不能，应清理并失败。
4. 为什么打印三字节用三个%c而不是%s？数据abc没有额外终止字符，%s会寻找未知后续边界。
5. 局部性模型若把驻留框增为4，按列还一定16次fault吗？不再如此，四个页都能保留，初始装入共4次；每次修改模型都重新推导。

动手题：把map-lifetime写入的Z换成Q，预期after_close=aQc；把locality模型框数扩为4时，要同时改数组、命中检查与循环取模，不能只改其中一处。本批综合项目可更方便调整框数。
