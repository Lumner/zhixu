## 24.1 分配器与内核分工

malloc 管理用户空间对象，常向内核申请较大区域再切成小块；free 把对象交回分配器，不保证马上归还物理页或让 RSS 下降。栈对象与动态对象的生命期规则见 C 基础，不能只靠地址高低猜测谁负责释放。

内部碎片指分配粒度大于所需导致内部浪费；外部碎片指空闲区域分散，虽总量足够却难满足连续需求。分页缓解连续物理分配要求，但分配器内部仍有粒度、布局等问题。

## 24.2 文件映射的完整实验

[完整源码：mapping.c](示例代码/mapping.c)

```c
#include "lab.h"
#include <sys/mman.h>

int main(void) {
    FILE *file = tmpfile();
    if (file == NULL) { die("tmpfile"); }
    int fd = fileno(file);
    write_all(fd, "abc", 3);
    char *memory = mmap(NULL, 3, PROT_READ | PROT_WRITE, MAP_PRIVATE, fd, 0);
    if (memory == MAP_FAILED) { die("mmap"); }
    memory[0] = 'X';
    char original;
    if (pread(fd, &original, 1, 0) != 1) { die("pread"); }
    printf("mapping=%c file=%c\n", memory[0], original);
    if (munmap(memory, 3) < 0) { die("munmap"); }
    if (fclose(file) != 0) { die("fclose"); }
    return 0;
}
```

运行 `make mapping`、`./mapping`，输出 `mapping=X file=a`。tmpfile 创建自动管理的临时文件，写入 abc 后，mmap 建立 3 字节的私有可写映射。mmap 失败返回 MAP_FAILED，不能只与 NULL 比较。

MAP_PRIVATE 表示通过该映射的写入不回写原文件，本例把映射首字节改成 X，再用 pread 从文件偏移 0 读取，仍是 a。这与 MAP_SHARED 的语义不同。私有映射不自动变成持久保存文件的方法。

## 24.3 为什么先检查再访问

mmap、pread、munmap 和 fclose 都有自己的返回值；不是调用函数后就默认成功。映射长度与文件长度必须匹配合理区间；访问超出映射或文件有效范围可能产生异常。munmap 后旧指针不再可用，就像 free 后不能继续读取旧对象。

## 24.4 时间与空间局部性

时间局部性：刚使用的数据很可能很快再用；空间局部性：使用某地址后，附近地址可能也会用。连续扫描数组通常比按很大步长跳跃更友好，但实际表现仍受缓存层级、预取、页面、优化与数据规模影响。

测量时先固定输入与编译参数，多次运行，区分冷启动与缓存已热；计时范围不要把大量 printf 包进去。不要用几百个元素的一次结果证明一个适用于所有机器的性能结论。

## 24.5 排查内存问题

越界：核对容量与索引，使用 AddressSanitizer 等工具；泄漏：追踪所有权与失败清理路径；占用高：区分虚拟保留与真实驻留，结合 /proc 和工具；崩溃：记录信号、栈和触发输入。不先靠加大数组、重复 free 或强转指针消除表面错误。

练习：①MAP_PRIVATE 修改后 fclose 能让 X 保存进原文件吗？②free 后 RSS 不降就必定泄漏吗？答案：①不能，映射模式没有回写承诺；②不是，分配器可能保留区域，需结合生命周期与重复负载观察。
