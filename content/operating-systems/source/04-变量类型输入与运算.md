# 04 变量、类型、输入与运算

> **零基础详细版 · 已重写。** 先完成第03章，能保存、编译并运行C程序。本章建议分三次学习，连同改造练习约5—7小时。先处理程序里写好的数字，再认识键盘输入，不要求提前会数组或指针。

## 4.1 为什么程序需要“变量”

上一章每次都显示同一段文字。如果要把90分钟换算成小时与分钟，程序需要先保存90，再用它计算。明天输入的可能是125；我们不想为每个数字重新设计一份程序。

变量让程序给数据对象取名字，通过这个名字读写值。先把它想成一张有名称、类型和当前内容的记录：名称叫minutes，类型是int，当前值为90。这个类比帮助理解状态，不意味着变量只是文件上的标签。

本章将回答：如何声明并初始化变量？赋值为什么不是数学等式？不同类型如何输出？整数除法与小数除法有什么区别？键盘上的一个字符怎样进入程序？

## 4.3 第一份变量程序：先预测变化

**完整程序：variables.c**

```c
#include <stdio.h>

int main(void) {
    int minutes = 90;
    printf("before=%d\n", minutes);
    minutes = minutes + 30;
    printf("after=%d\n", minutes);
    return 0;
}
```

编译运行后应出现：

```text
before=90
after=120
```

先不要把两行输出记成结论。我们逐步追踪：创建minutes并放入90；第一次printf读取此时的90；计算旧minutes加30得到120；将120存回minutes；第二次读取现在的120。

变量名相同，并不表示它在整个程序中必须一直保持同一值。读到哪个值，取决于执行时已经发生了哪些更新。

## 4.4 把声明拆成四个部分

看 `int minutes = 90;`：int指定整数类型；minutes是自己取的名字；等号引入初始值；90是本次初始内容；分号结束声明。

“声明”告诉工具这个名字及其类型；在这里它同时定义了对象并进行了初始化。初始化是对象建立时给定初值。后续 `minutes = 120;` 是给已存在对象重新赋值，不是再次声明。

初学时推荐每个普通局部变量在第一次使用前都明确得到值。不要写 `int total;` 后直接printf(total)，也不要靠“刚好读到0”证明未初始化可以安全使用。

下面是有上下文要求的**说明片段**，不能单独保存成完整程序：

```c
int total = 0;
total = total + 20;
```

第一行建立累计值，第二行才有可靠的旧值可加。后面循环统计会反复使用这个形状。

## 4.5 printf中的占位位置怎样对应

上一章输出固定字符串；现在 `printf("before=%d\n", minutes);` 多了一个逗号和一个参数。

双引号里是输出格式：普通文字before=照原样输出，`%d` 表示在这里输出一个int整数，`\n`换行。逗号后的minutes提供要放进去的值。printf不是把单词minutes印出来，而是取得该表达式当前的结果。

多个值要按顺序对应，例如片段 `printf("left=%d right=%d\n", left, right);` 中，第一个%d对应left，第二个对应right。格式需要几个数据项，就要提供匹配的参数，不能漏掉。

把 `%d` 改成 `%s` 并不能自动把任何类型转换成文字。类型与格式不匹配可能导致未定义行为：语言不再承诺一个可靠结果。警告会帮助发现部分问题，但不能把“没警告”当作所有输入都正确的证明。

## 4.6 赋值不是数学等式

数学里的x=x+1作为等式通常不成立；程序里的 `minutes = minutes + 30;` 表达的是操作顺序：先求右侧结果，再更新左侧对象。

| 执行到哪里 | 右侧计算 | 执行后minutes |
| --- | --- | --- |
| 初始化后 | 初值90 | 90 |
| `minutes = minutes + 30;` | 90+30=120 | 120 |
| 再执行同一条更新 | 120+30=150 | 150 |

`=` 用来赋值，`==` 才用来比较相等。比较返回一个判断结果，不会因为看起来像等号就把左边改成右边。第05章会用这个判断来选分支。

`minutes += 30;` 在本例中等价于加30再存回。先看懂长写法，再采用简写。不要把复杂更新和输出挤进同一表达式，清晰的执行步骤更容易核对。

## 4.7 给变量取一个能说明用途的名字

C区分大小写：minutes和Minutes不是同一个名字。名字可以使用字母、数字和下划线，但不能以数字开头，不能占用int、return等语言关键字。

本课程的新变量优先采用清楚的小写英文组合，例如total_minutes、day_count、is_ready。你不需要英语很好，但应能从名字联想到它的职责。避免把全部数据都叫a、b、x1而不解释。

变量名不是字符串。`minutes` 表示读取变量，`"minutes"` 是一段包含该单词的字符串。它们的用途不同，不能靠增删引号随意互换。

## 4.8 类型告诉程序怎样解释数据

int用于本课范围内的整数计数；long也是整数类型，至少有语言要求的范围，不同平台大小可能不同；double用于浮点数计算；char用于字符代码单元；C17中可以包含stdbool.h使用bool表示真假。

**完整程序：types.c**

```c
#include <stdio.h>
#include <stdbool.h>

int main(void) {
    int count = 3;
    long total = 12345;
    double average = 2.5;
    char grade = 'A';
    bool finished = false;
    printf("count=%d total=%ld\n", count, total);
    printf("average=%.2f grade=%c finished=%d\n", average, grade, finished);
    return 0;
}
```

预期输出：

```text
count=3 total=12345
average=2.50 grade=A finished=0
```

这里%d输出int，%ld输出long，%.2f显示浮点数并保留两位小数，%c输出字符。bool传给printf时按整数提升规则处理，false显示0，true显示1；第05章再用它控制分支。

`'A'` 是字符常量，`"A"` 是字符串。前者在本例放入一个char，后者包含字符串结束标记，不能认为它们只差一种排版习惯。

## 4.9 大小、范围与没有保证的行为

类型大小以平台为准，可以使用sizeof观察。例如在main中写 `printf("int bytes=%zu\n", sizeof(int));`。sizeof给出以C字节为单位的大小，其结果类型size_t用%zu输出；size_t在第07章计算数组数量时会再次出现。

本课Ubuntu环境常见int占4字节，但不要把它背成所有C实现的保证。需要知道范围时可查看limits.h提供的INT_MIN、INT_MAX等常量。当前例程刻意使用很小的数，避免把范围问题藏在简单统计里。

有符号整数计算超出可表示范围属于未定义行为，不能依赖“自动绕回去”。除数为0也不是一种可用来表示“无结果”的写法。本章不通过运行这些错误程序观察随机后果。

未定义行为并不等于“每次一定崩溃”，而是语言没有给这次错误操作承诺一个可依赖的结果。后面数组越界也会用到这个概念。

## 4.10 常量：明确不允许再改

在声明前加const，可以让类型规则限制通过这个名字修改对象，例如 `const int minutes_per_hour = 60;`。这里60表达单位换算规则，通常不应该在后面计算中被改成别的数字。

const不表示“任何时候所有东西都不能变化”，先按本例理解为这个整数对象不能再通过普通赋值修改。若尝试给minutes_per_hour重新赋值，编译器应拒绝相应操作。

把60取名为minutes_per_hour也帮助阅读：`total / minutes_per_hour` 比一串没有解释的数字更容易看出计算口径。

## 4.11 完整分钟换算：运算的输入与输出

**完整程序：arithmetic.c**

```c
#include <stdio.h>

int main(void) {
    const int minutes_per_hour = 60;
    int total = 125;
    int hours = total / minutes_per_hour;
    int rest = total % minutes_per_hour;
    printf("%d minutes = %d h %d min\n", total, hours, rest);
    printf("7/2=%d 7/2.0=%.1f\n", 7 / 2, 7 / 2.0);
    return 0;
}
```

在lesson04编译arithmetic.c并运行，预期：

```text
125 minutes = 2 h 5 min
7/2=3 7/2.0=3.5
```

两个整数相除，结果仍按整数运算，7/2得3。不能先把3存入double，再期待丢掉的小数自动回来；运算发生时就已经决定了结果。7/2.0中有浮点操作数，按相应规则得到3.5。

125/60得2，是完整小时数；125%60得5，是剩余分钟。检查可以反向做：2×60+5=125。这个反算比只看输出长得像答案更可靠。

## 4.12 括号、计算顺序与浮点近似

乘除通常先于加减，括号可以明确分组。比如20+30*2得到80，(20+30)*2得到100。先在纸上标出计算分组，再看代码，避免把一串表达式按从左到右机械计算。

浮点数适合很多近似计算，但不等于十进制小数的无限精确存储。比如有限二进制表示未必能精确表示0.1。当前只用小例子认识类型差异，不能由%.2f显示两位小数推出底层就是精确的两位小数。

若将来做金额等精确业务，需要选合适表示与规则；本课不在这里扩成财务计算教程。

## 4.13 输入先从“一个字符”开始

把输入90变成真正可校验的整数，需要解决整行内容、转换、范围与错误。现在数组和指针还没学，不把一大段strtol模板提前扔给你。

先用getchar读取一个输入字符。输入字符 `'7'` 与整数7不是同一件事：前者是输入文本中的字符代码，后者是参与算术的数值。下一阶段会把文本按明确规则转换成数值。

getchar返回int，而不是char，因为除了字符值，它还需要表示EOF等读入结束/失败结果。EOF是标准库提供的常量，不要把它在所有环境中写死成某个数字。

## 4.14 第一个交互输入程序

**完整程序：character.c**

```c
#include <stdio.h>

int main(void) {
    printf("Type one character, then press Enter: ");
    if (fflush(stdout) == EOF) {
        return 1;
    }
    int key = getchar();
    if (key == EOF) {
        fprintf(stderr, "No character read\n");
        return 1;
    }
    printf("character=%c code=%d\n", key, key);
    return 0;
}
```

编译后运行character，输入7，再按Enter。本课常见Ubuntu字符环境中会显示 `character=7 code=55`。55是这个字符的编码值，不能直接拿它当“用户输入了55分钟”。

这里第一次出现了一个简单if：括号内条件成立，才执行对应花括号的内容。`key == EOF`检查没有读到字符的结果；成立时输出错误并提前返回1，不继续把EOF当普通字符。第05章会系统解释条件语句。

stdout代表标准输出流，fflush请求把提示文字从C输出缓冲交给底层，避免提示一直停留在缓冲中；它失败时返回EOF。本例没有讨论磁盘持久保存，fflush不是第28章的持久化保证。stderr是标准错误流，fprintf在指定流上按格式输出。

如果这些库名字第一次见，先按“显示提示 → 读一个字符 → 检查读入结果 → 显示字符与编码”四步理解，不要求背整个库。

## 4.15 Enter也是输入内容的一部分

你按7再按Enter，输入通常包含字符7和换行。getchar只取一个，不会自动把剩下的换行全部丢弃。

在Bash里可以通过管道提供固定输入，排除每次键盘动作不同的干扰：

```bash
printf '7\n' | ./character
```

这里左侧printf是Shell命令，右侧character是刚编译的C程序；管道把前者输出交给后者输入。暂时把它当作“向程序喂一份可重复输入”的方法，第14章再解释内部描述符。

直接按Enter而不输入其他内容时，读取的可能就是换行，并不等于没有读到任何字符。终端里请求输入结束的操作又是另一种情形。后面的行输入实验会更直观地区分空行和没有输入。

## 4.17 常见错误与检查顺序

| 现象 | 优先核对 |
| --- | --- |
| 输出一个意外数字 | 初始化了吗，更新在哪行发生，输出格式匹配吗 |
| 想得到3.5却得到3 | 运算时两个操作数是否都是整数 |
| 变量名提示不存在 | 大小写、拼写、是否声明在可见范围 |
| 编译器指出格式问题 | %d/%ld/%f/%c与参数类型是否对应 |
| 输入7却看见代码值55 | 是否把字符编码误当成数字本身 |
| 程序没有先显示输入提示 | 是否有换行或显式刷新，程序是否确实运行到这里 |

先用一个小值、一条更新、一条输出定位问题。不要同时更换类型、公式、文件名和编译选项，否则很难知道是哪项修改改变结果。
