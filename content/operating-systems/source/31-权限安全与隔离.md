# 31 权限、安全与隔离

> **零基础详细版 · 已重写。** 先修：第25—28章的路径、权限、文件描述符与保存协议。建议7—10小时。所有变更都在自己的练习目录，不需要提升权限。

## 31.1 学习目标：把安全问题改写成具体请求

看到“Permission denied”时，你应能说出哪个进程、用什么身份、对哪个对象、请求哪种操作；能区别身份验证与操作授权，解释为什么一次路径检查不够；最后实现一个有明确输入边界的小文件读取器。

本章不要求学习攻击工具。重点是把程序运行所需的权限说清，把不可信输入限制在能够解释的范围，并对失败保留证据。先修不熟时，回第25章复习目录的`r/w/x`，回第26章复习“名字与对象”。

## 31.2 主体、对象、操作：先填三格

**主体**是发起请求的一方，本章通常为携带身份信息的进程；**对象**是被访问的资源，如文件、目录或另一个进程；**操作**是读取、写入、查找目录、发送信号等具体行为。

同一个主体对同一个对象，可能允许读但不允许写。因而“我有权限”不完整，必须补上“做什么”。例如：普通用户启动的编辑器，要在个人目录中创建文件；系统检查的是创建所涉及目录等规则，不能只看将来文件的名字。

## 31.3 认证与授权用一个场景区分

图书馆先确认借书证属于谁，这是**认证**；再检查这个读者是否可以借某类资料，这是**授权**。认证成功不代表所有操作都被允许。计算机服务同样需要把“你是谁”和“你能做什么”分开。

本机文件访问常由进程已有的UID、组和其他安全状态参与判定，不是每次`read`都弹登录窗口。网页业务还可能有自己的用户身份；两个网页用户通过同一个服务器进程访问文件时，内核看到的进程身份可能相同，业务授权仍需应用正确实现。

## 31.4 UID、组与实际访问判定

UID是Linux用户身份的数字标识，GID是组标识。进程还有实际、有效等不同身份字段，补充组也可参与访问规则；文件系统访问身份在Linux中另有细节。入门实验使用普通用户启动的普通程序，不设置特殊身份转换。

第25章的所有者、所属组、其他人权限，是常见自主访问控制的一部分。真实系统还可能叠加ACL、强制访问控制、只读挂载、能力和容器策略等规则。因此仅凭`ls -l`的一行输出，不能穷尽所有授权原因。先建立基本模型，再把额外限制作为证据加入。

## 31.5 一次路径打开要经过哪些门

假设请求`open("/home/learner/notes/day.txt", O_RDONLY)`。内核需要沿路径查找目录项，在相应目录上满足搜索条件，解析链接，并对目标打开请求做适当检查。文件本身可读而父目录不可搜索，仍可能失败。

反过来，移除文件名通常涉及父目录的写入和搜索权限，不等于修改文件内容。第七批已经实际对照过“文件不可写”和“名字可移除”。本章把它提升为分析方法：先确认具体操作影响哪个对象，再找它需要的规则。

## 31.6 最小权限怎样落到日常操作

**最小权限**是给完成当前任务所需的权限与资源范围。例如编译个人源码需要读源码、写输出目录、执行编译器；运行本课普通程序不需要修改系统配置。安装软件则涉及系统软件管理，是另一项任务。

为消除错误而把目录统一改成所有人可写，会扩大可以替换程序或文件的人群。把一次成功的管理员运行当作问题已解决，也可能掩盖普通用户路径或所有权错误。先写“需要哪一步成功”，再针对那一步检查，通常比一口气扩大权限更可控。

## 31.7 只读观察自己的身份与目录

在**Ubuntu/WSL的Bash，个人目录**执行：

```bash
id
umask
ls -ld ~/os-lab ~/os-lab/batch08
```

`id`可能显示用户名、主组和补充组；`umask`影响新建对象的初始权限，不会自动修改已存在文件；目录权限需要结合具体访问操作解释。若尚未创建`batch08`，先执行`mkdir -p ~/os-lab/batch08`。

记录身份是否普通用户以及练习目录是否由自己控制即可，不必公开整份机器账号信息。若当前是root，请切回第02章准备的普通学习账号再做权限实验；root的额外能力会使一些拒绝结果与本章不同。

## 31.8 可执行文件与PATH也是信任边界

在Bash输入一个不含斜杠的外部命令名时，Shell通常按PATH等规则查找程序。C中的`execvp`也会使用PATH查找；`execl`给出具体路径时不会做同样的PATH搜索。Shell还存在内建命令等情况，不能用一句“都查PATH”覆盖全部命令。

在自己的实验目录可以执行`type -a gcc`观察命令来源，执行`printf '%s\n' "$PATH"`观察目录列表。不要为了实验把陌生目录永久放到前面。即使使用绝对路径，也必须考虑路径对应的文件和上级目录是否可信；字符串形式本身不会赋予信任。

## 31.9 检查与使用之间为什么会变

TOCTOU是“检查时刻与使用时刻不一致”这一类问题的常用缩写。假设程序先检查`entry`指向允许文件，随后才`open("entry")`。在两步之间，目录项或符号链接可能改变。后一步解析到的对象不一定是前一步检查的对象。

这不是再加一次前缀比较就能完整解决的问题。路径解析还涉及`..`、符号链接、挂载和并发更改。第26章说过路径是名字查找，fd指向打开状态；减少重复按名字解析、检查打开的实际对象，有助于缩小一些竞争窗口，但仍要说明目录与写入者是否可信。

## 31.10 用自己创建的两个文件重演时间窗口

以下是**完整命令实验**，在Ubuntu/WSL的Bash中执行。它创建私有临时目录，不访问他人的文件。两次改变是人为排定的，展示一种可能交错，不声称启动了真实并发竞争。

```bash
cd ~/os-lab/batch08
swap_dir=$(mktemp -d)
(
  cd "$swap_dir" || exit 1
  printf 'A\n' > first.txt
  printf 'B\n' > second.txt
  ln -s first.txt entry
  if test -r entry; then printf 'check: readable\n'; fi
  readlink entry
  ln -sfn second.txt entry
  cat entry
  rm -- entry first.txt second.txt
)
rmdir -- "$swap_dir"
```

预测后再运行：检查时目标是`first.txt`，输出链接名后改成`second.txt`，最终读出`B`。两份内容都属于你，实验只是说明“之前检查过一个名字”不等于“稍后打开同一个对象”。退出子Shell后当前目录恢复；清理失败时检查错误，不要扩大删除范围。

## 31.11 先给小工具定义可实现的边界

接下来读取器的约定是：调用者提供自己控制的目录，以及一个至多64字节、无斜杠、不是`.`或`..`的单个名字；拒绝最后一个名字为符号链接，拒绝非普通文件；最多接收64字节内容，以十六进制输出。

目录及其上级路径由学习者控制，运行期间没有其他写入者。这是实验的**信任假设**。程序不承诺把恶意可变目录变成安全文件服务，不阻止预先放入的硬链接，也不提供文件内容的一致快照。把这些限制写在实现前，才能知道代码实际解决了哪部分问题。

## 31.12 完整程序：按目录fd打开单个名字

保存为`bounded-open.c`，平台Linux/POSIX。完整代码不依赖`lab.h`。

**完整程序：bounded-open.c**

```c
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>

int main(int argc, char **argv) {
    if (argc != 3 || argv[2][0] == '\0' || strlen(argv[2]) > 64 ||
        strchr(argv[2], '/') != NULL || strcmp(argv[2], ".") == 0 ||
        strcmp(argv[2], "..") == 0) {
        fputs("usage: bounded-open OWNED_DIRECTORY SINGLE_NAME\n", stderr);
        return 2;
    }
    int dir = -1, fd = -1, status = 1;
    dir = open(argv[1], O_RDONLY | O_DIRECTORY | O_CLOEXEC | O_NOFOLLOW);
    if (dir < 0) { perror("directory"); goto done; }
    fd = openat(dir, argv[2], O_RDONLY | O_NOFOLLOW | O_CLOEXEC | O_NONBLOCK);
    if (fd < 0) { perror("openat"); goto done; }
    struct stat info;
    if (fstat(fd, &info) < 0) { perror("fstat"); goto done; }
    if (!S_ISREG(info.st_mode)) {
        fputs("regular file required\n", stderr);
        status = 2;
        goto done;
    }
    unsigned char data[65];
    size_t used = 0;
    while (used < sizeof data) {
        ssize_t n = read(fd, data + used, sizeof data - used);
        if (n < 0 && errno == EINTR) { continue; }
        if (n < 0) { perror("read"); goto done; }
        if (n == 0) { break; }
        used += (size_t)n;
    }
    if (used > 64) {
        fputs("content exceeds 64 bytes\n", stderr);
        status = 2;
        goto done;
    }
    status = 0;
    if (printf("bytes=%zu\nhex=", used) < 0) { status = 1; }
    for (size_t i = 0; i < used; ++i) {
        if (printf("%02x", (unsigned int)data[i]) < 0) { status = 1; }
    }
    if (putchar('\n') == EOF || fflush(stdout) == EOF) { status = 1; }
done:
    if (fd >= 0 && close(fd) < 0) { perror("close file"); status = 1; }
    if (dir >= 0 && close(dir) < 0) { perror("close directory"); status = 1; }
    return status;
}
```

## 31.13 把条件、标志和清理逐项读懂

`argc != 3 || ...`利用短路求值：参数数量不对时，后面的`argv[2]`访问不会进行。`strchr(name, '/')`寻找斜杠，返回非空表示包含路径分隔符。限制单个名字，避免把“任意嵌套路径的安全解析”偷偷塞进本例。

`openat`使用已打开的目录fd作为相对查找起点；`O_NOFOLLOW`拒绝跟随最后一个路径分量的符号链接。它不是“所有中间目录都禁止链接”的通用开关。目录参数自身的前面部分仍按正常路径规则解析，本例依赖可信上级目录。

`O_NONBLOCK`避免误传FIFO时先阻塞在打开等待；随后`fstat`检查已经打开的对象。它并不能把所有特殊设备都变成无副作用对象，所以不要拿设备路径测试。`goto done`在这里把收尾集中到一处，fd初值为-1表示尚未拥有资源，避免重复关闭。

## 31.14 编译和正常输入

在**Ubuntu/WSL的Bash，`~/os-lab/batch08`目录**保存源码后执行：

```bash
gcc -std=c17 -D_POSIX_C_SOURCE=200809L -Wall -Wextra -Wpedantic -Werror bounded-open.c -o bounded-open
box_dir=$(mktemp -d)
printf 'Hi\n' > "$box_dir/note.txt"
./bounded-open "$box_dir" note.txt
echo $?
```

应输出`bytes=3`与`hex=48690a`，状态0。`48`是字节`H`，`69`是`i`，`0a`是换行。十六进制让NUL与不可见字符也有明确表示；字节长度不等于中文字符数量。

程序实际最多读取65字节：前64字节仍可能合法，第65字节用于证明超限。没有仅依赖`st_size`提前分配任意大内存，也没有把输入直接交给`%s`要求它恰好是C字符串。

## 31.15 拒绝路径、链接、类型与过长内容

仍在**同一个Bash会话和目录**执行，复用上一节的`box_dir`变量：

```bash
ln -s note.txt "$box_dir/link.txt"
./bounded-open "$box_dir" link.txt
echo $?
./bounded-open "$box_dir" ../note.txt
echo $?
mkdir "$box_dir/sub"
./bounded-open "$box_dir" sub
echo $?
rm -- "$box_dir/link.txt" "$box_dir/note.txt"
rmdir -- "$box_dir/sub" "$box_dir"
```

链接打开失败为状态1；名字含斜杠和目录对象为状态2。错误文本随语言环境变化，不要求逐字一致。超长内容练习可写65个ASCII字节再运行，应状态2；空文件合法，输出长度0和空hex行。不要对系统设备或自己不拥有的目录做实验。

## 31.16 隔离、加固与业务正确性各管什么

地址空间隔离限制普通进程随意访问其他进程内存；系统调用检查跨越用户与内核的请求；seccomp可限制允许的系统调用集合；命名空间和资源控制又解决其他问题。限制某种调用不自动检查网页用户是否有权读取某份订单。

ASLR让地址布局更难预测，不可执行页面与栈保护可缓解一些错误的利用，但不会把数组越界变成合法C代码。第08—10章的容量、类型、生命期和返回值检查仍然需要。安全通常是一组边界共同工作，不能让一个术语替代全部推理。

## 31.17 该工具仍然不保证什么

如果目录中已经有指向另一文件的硬链接，`O_NOFOLLOW`不会拒绝它，因为硬链接不是符号链接。如果另一个写入者同时改内容，同一个fd也不保证读到一个逻辑时刻的完整快照。目录fd稳定的是查找起点关联，不能冻结整个目录和文件。

若真正需求是对不可信多层路径做严格解析，还需研究Linux`openat2`的解析约束、挂载边界、部署权限与应用策略。本章没有实现这类服务，也没有让你把教学程序开放给其他人使用。先把小范围约定正确实现，再扩展需求。

## 31.18 常见错误与定位表

| 问题 | 检查方向 | 应采取的下一步 |
| --- | --- | --- |
| 普通文件打开失败 | 身份、各级目录搜索、目标权限、挂载策略 | 找到具体拒绝层再处理 |
| 链接文件被拒绝 | 查看是否为最后一个符号链接 | 按程序约定使用真实普通文件 |
| 想允许`sub/name`只删除斜杠检查 | 中间路径解析与威胁模型已变化 | 先重新设计边界 |
| 把`access`成功视为后续打开保证 | 名字可变、身份检查语义也不同 | 检查实际打开返回值 |
| 把状态2当作系统故障 | 阅读约定：输入或类型不符合 | 改正输入再运行 |

Linux下`close`出错后本例不盲目重试同一个fd，避免重用编号时产生新的问题；输出或关闭失败可把结果提升为状态1。结束状态描述本次流程是否完成，不是完整安全证明。

## 31.19 练习与参考答案

**A：** 知道一个文件的完整路径，是否等于有权读取？**参考答案：** 否，路径是定位信息，授权还取决于主体、操作和各层规则。

**B：** `openat(dirfd, "a/b", O_NOFOLLOW)`能保证`a`不是链接吗？**参考答案：** 不能。该标志约束最后分量，本章通过只接受单个名字缩小问题，并依赖可信目录。

**C：** 把容量改为64，再在读满时接受，能区别恰好64和超过64吗？**参考答案：** 不能。需要额外探测至少一个字节，或使用其他明确的输入协议。

**D：** 如果把本程序用于多人上传目录，应先补什么？**参考答案：** 先定义谁能创建、改名、写内容和放硬链接，是否需要快照，哪些路径与对象允许；不能只给现有代码加“安全”标签。
