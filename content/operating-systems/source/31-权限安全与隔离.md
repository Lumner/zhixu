# 31 权限、安全与隔离

## 31.1 先确认“谁访问什么”

安全分析从主体、对象、操作开始：哪个用户/进程，要读哪个文件、发哪个信号或监听哪个端口，系统依据什么身份和规则决定。认证确认身份，授权决定允许操作，两者不能混用。

Linux 的 UID/GID、文件权限和能力等参与决策；还可能有 ACL、强制访问控制、命名空间、挂载和容器策略。root 拥有广泛权限，但不能把“使用 root”当作排查所有错误的标准步骤。

## 31.2 最小权限的实际含义

编译自己的程序只需要读源码和写输出目录；复制自己文件只需要相应路径权限；本课例程都不需要日常以管理员身份运行。安装系统软件才使用第 02 章的 sudo。把编译输出目录设为所有人可写，会让其他参与者有机会替换运行文件。

PATH 决定 execvp 的查找范围。把不可信目录排在前面可能运行到同名伪造程序；如果必须明确执行某个文件，可以使用受控绝对路径。固定绝对路径也需保证文件与目录本身可信。

## 31.3 内存、系统调用与沙箱

地址空间隔离限制进程任意读写其他进程内存；系统调用入口检查跨边界请求；seccomp 等机制可以进一步限制允许的调用集合。限制调用种类不自动验证应用数据和所有资源行为，沙箱需要综合权限、资源与文件访问设计。

ASLR 增加地址布局不确定性，栈保护和不可执行页面缓解一些攻击；它们不让越界代码变正确。C 程序依然需要长度、类型、生命期和错误处理。

## 31.4 一个具体检查案例

工具收到用户输入的路径，先检查它位于允许目录，再 open。若检查与打开间符号链接被改动，就可能打开另一对象。这类 TOCTOU 问题不能仅靠多一次字符串比较解决，可结合目录描述符、相对打开、安全打开选项和明确的信任边界设计。

本课的目录查看器只用于你控制的普通实验目录，没有宣称是安全文件服务。把学习工具部署成接受他人输入的服务前，必须重新定义这些边界。

## 31.5 只读观察与练习

运行 `id`、`umask`、`ls -ld ~/os-lab`。记录当前用户、组和练习目录权限，解释为何不需要 sudo 编译。不要把原始系统身份输出随意公开，交作业只保留理解所需信息。

练习：①“知道文件路径”等于“获准读取”吗？②只检查一次路径前缀能保证安全目录限制吗？③内存保护能防止全部应用业务越权吗？答案均是否：需要实际授权、正确解析/打开协议和业务身份规则。

完成条件：面对 Permission denied 能先列出身份、路径各级权限和环境限制，再选择修复，而不是直接扩大所有权限。
