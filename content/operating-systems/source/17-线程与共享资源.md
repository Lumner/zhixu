## 17.1 线程是执行流

先完成进程阶段。一个进程可以有多个线程，共享地址空间与不少进程资源；每个线程有自己的执行位置、寄存器和栈等运行状态。线程的栈虽独立管理，位于共享地址空间中，其他线程若拿到有效指针仍可能访问它，不能理解成硬隔离区。

创建线程常比新建独立进程更轻，但“线程总更快”不成立：共享状态可能带来锁竞争、缓存一致性开销和错误。选进程还是线程，先看隔离、通信方式和故障影响。

## 17.2 完整例程 threads.c

[完整源码：threads.c](示例代码/threads.c)

```c
#include "lab.h"
#include <pthread.h>

struct Input { int value; };
static void *work(void *arg) {
    struct Input *input = arg;
    input->value *= 2;
    return NULL;
}

int main(void) {
    pthread_t threads[2];
    struct Input inputs[2] = {{10}, {20}};
    for (int i = 0; i < 2; i++) {
        thread_check(pthread_create(&threads[i], NULL, work, &inputs[i]), "create");
    }
    for (int i = 0; i < 2; i++) {
        thread_check(pthread_join(threads[i], NULL), "join");
    }
    printf("results=%d,%d\n", inputs[0].value, inputs[1].value);
    return 0;
}
```

编译命令多一个 `-pthread`，用于编译和链接线程支持：

```bash
gcc -std=c17 -D_POSIX_C_SOURCE=200809L -Wall -Wextra -Wpedantic -pthread threads.c -o threads
./threads
```

输出 `results=20,40`。每个线程获得不同 Input 的地址，分别修改自己的元素。main 用 join 等待结束后才读取，所以不会在写入尚未完成时读取同一个元素。

## 17.3 参数与生命周期

线程入口签名是 `void *work(void *arg)`：接收通用指针，在函数体转为正确对象指针。参数对象 inputs 在 main 的作用域，main 等到两个线程结束才返回，因此它们在整个访问期间仍有效。

常见错误是在创建循环里把同一个循环变量地址传给所有线程，各线程读到什么取决于时机，还可能形成数据竞争。应准备每个任务独立参数，并保证生命期持续到最后一次访问。

## 17.4 线程错误码

许多 pthread 函数成功返回 0，失败直接返回错误编号，而不是统一返回 -1 并设置 errno。lab.h 的 thread_check 接收返回码，用 strerror(code) 输出原因。不要把所有接口都套成 `if (result < 0) perror(...)`。

join 还负责回收可连接线程的资源。detach 适合无需再 join 的线程，但需要另行保证参数、共享资源与进程退出时机，不能用“分离”解决所有权不清晰问题。

## 17.5 练习、答案与完成条件

①不 join 就直接打印结果能保证还是 20/40 吗？②两个线程各改一个元素，是否等于完全没有共享资源？③为什么本例不需要互斥锁保护 results 的最终读取？

答案：①不保证，甚至可能在工作结束前 main 就退出；②它们仍共享地址空间等，只是本例没有并发访问同一整数；③join 建立等待关系，读取在对应线程完成之后，且工作线程各有自己的元素。

完成条件：能标注每个数据对象由谁访问、从何时存在到何时销毁，解释“共享地址空间”与“每个线程都能安全同时改任意数据”的差别。
