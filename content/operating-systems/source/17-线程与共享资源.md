# 17 线程与共享资源：在一个进程里安排多条执行流

> **零基础详细版 · 已重写。** 从一个工作线程开始，逐步解释入口函数、参数地址、join、返回结果和生命期。建议7—10小时。

## 1. 学完要能做什么

第12章用fork得到两个进程，普通私有变量分开变化。本章换一种组织方式：在同一个进程里创建多个**线程**，让它们分别做事，再收集结果。

学完应能读懂`void *work(void *arg)`，说清四个创建参数，画出参数对象的生命期，使用join等待并取回结果，处理创建一半失败。先复习第06章函数、第08章指针、第09章结构体与动态内存、第12章等待关系。

## 2. 线程是什么，和进程怎样联系

**线程**是进程内的一条执行流，有自己的执行位置、寄存器和栈等运行状态。**进程**提供地址空间及资源组织，一个进程可以只有一个线程，也可以有多个。

想象同一间工作室里有几位工作人员：他们有各自正在做的步骤，却能访问同一组资料。类比只帮助理解“执行位置不同、资源可能共享”，不表示线程之间天然互相信任或自动协调。

线程的栈分别管理，但仍在进程共享的地址空间里。一个线程若拿到另一个线程仍然有效的局部对象地址，也可能访问它。不能把“每个线程有栈”误读为“其他线程绝对不能碰我的栈”。安全性仍取决于对象生命期与同步规则。

## 3. 共享与独立的清单

| 内容 | 本课如何理解 | 需要注意 |
| --- | --- | --- |
| 普通全局变量、堆对象 | 可被多个线程访问 | 同时读写要有规则 |
| 描述符表等进程资源 | 多线程通常共同使用 | 一个线程close会影响其他使用者 |
| 执行位置、寄存器、栈 | 各有自己的执行状态 | 栈对象地址仍可能被传给其他线程 |
| 线程局部对象 | 每个线程有自己的实例 | 不等同于普通全局变量 |

共享不代表一定同时访问同一字节。第一个主线例程里，两位工作者各改不同的整数，主线程等它们结束再读，因而不需要先引入锁。下一章才讨论双方确实要修改同一状态的情况。

## 4. 并发、并行与速度

**并发**表示多个任务的推进在时间上交错；**并行**表示某些任务在同一时刻实际同时运行。一个CPU也能通过轮流运行实现并发；多个CPU能提供并行机会，但不保证每次创建线程都立即同时运行。

线程不是“免费加速按钮”。创建、调度、共享缓存、锁竞争都会产生开销；任务之间有依赖时也无法任意拆开。先写清可以独立完成的工作和共享规则，再考虑是否值得并发。这里验证功能，不用几次短程序运行时间证明性能。

## 6. 从一个工作线程开始

**完整程序：thread-once.c**

```c
#include "lab.h"
#include <pthread.h>

struct Task { int value; int result; };

static void *work(void *arg) {
    struct Task *task = arg;
    task->result = task->value * 2;
    return NULL;
}

int main(void) {
    struct Task task = {21, 0};
    pthread_t worker;
    thread_check(pthread_create(&worker, NULL, work, &task), "create");
    thread_check(pthread_join(worker, NULL), "join");
    printf("result=%d\n", task.result);
    return 0;
}
```

按上一节命令编译，执行`./thread-once`，预期`result=42`并退出0。先写出你认为谁赋值、谁打印，再运行。这个程序不是主线程直接调用work；创建接口启动新执行流，主线程稍后在join处等待它。

## 7. 创建接口的四个参数

`pthread_create(&worker, NULL, work, &task)`逐个理解：第一个地址让接口写入新线程的标识；第二个NULL选择默认属性；第三个是入口函数；第四个是交给入口函数的参数地址。

`pthread_t`是线程标识类型，不保证就是能用`%d`打印的整数。需要比较两个有效线程标识时用`pthread_equal`；本章没有为了展示编号而强行转换它。线程标识与第12章PID也不是同一种接口。

默认创建的是可连接线程，之后由一个指定管理者join。不要让多个线程同时join同一目标，也不要join自己。创建失败时没有这个新线程，不能继续使用未成功填写的标识去等待。

## 8. 入口函数的星号逐个读

`static void *work(void *arg)`的返回类型是`void *`，参数类型也是`void *`。它接收通用对象地址，并返回一个对象地址或NULL，不表示“返回任意东西都行”。

进入函数后，`struct Task *task = arg;`按双方约定恢复正确类型。`task->result`访问指针所指对象的字段。接口不替你复制一整个Task，也不知道这个地址究竟来自哪种结构体；传错类型或传已失效地址仍是程序错误。

`work`作为参数传入函数入口，不能写成`work(&task)`，后者会先在当前线程直接执行函数，再把它的返回值拿去当入口，类型和意图都不符。复习第15章回调函数也能帮助理解这一点。

## 9. join不只是“等一会儿”

`pthread_join(worker, NULL)`等待指定可连接线程终止，并回收连接所需资源；第二个NULL表示不取它的返回指针。工作线程已经结束时，join也可以立即完成。

成功join还建立相应同步关系：本例主线程在它之后读取result，工作线程的写入已经完成并对该读取可见。不用sleep估计“应该算完了”。如果去掉join再马上读，读取就可能和工作线程写同一对象冲突；这不是仅仅“输出可能晚一点”的小问题。

从`main`返回会结束整个进程及其余线程。它不同于某个普通工作函数返回NULL；后者只是这个工作线程结束。本批统一让main在join后返回，保持收尾清楚。

## 10. 画参数生命期

```text
main创建task ── 创建worker ── worker访问task ── join完成 ── main返回
|---------------- task一直有效 --------------------------|
```

task虽然在main的栈上，但main尚未返回，对象仍存在。地址传给worker并不天然危险；关键是对象活得够久，且访问顺序满足同步要求。

反过来，若某个启动函数在局部栈上创建Task，把地址交给线程后立即返回，Task生命期结束，线程随后再访问就是悬空访问。不要通过“我测试时碰巧没崩溃”判断这种设计正确。本章只画这个错误路径，不执行失效地址实验。

## 11. 两个线程、两个独立参数

[完整源码：threads.c](示例代码/threads.c)

```c
#include "lab.h"
#include <pthread.h>

struct Input { int value; };
static void *work(void *arg) {
    struct Input *input = arg;
    input->value *= 2;
    return NULL;
}

int main(void) {
    pthread_t threads[2];
    struct Input inputs[2] = {{10}, {20}};
    for (int i = 0; i < 2; i++) {
        thread_check(pthread_create(&threads[i], NULL, work, &inputs[i]), "create");
    }
    for (int i = 0; i < 2; i++) {
        thread_check(pthread_join(threads[i], NULL), "join");
    }
    printf("results=%d,%d\n", inputs[0].value, inputs[1].value);
    return 0;
}
```

编译为`threads`并执行，输出`results=20,40`。不是让两个线程争抢同一个value，而是分别修改两个普通整数元素；main等全部join后统一打印，所以输出顺序不依赖工作线程谁先结束。

共享地址空间不等于所有对象都必须加锁：先标出对象和读写者，再判断是否发生冲突访问。数组中不同的普通非位域整数元素可以作为独立对象使用；这不承诺缓存层面没有性能影响。

## 12. 为什么不能把循环变量的地址交给所有线程

错误思路是创建循环中每次都传`&i`。这个地址始终指向同一个循环变量，主线程还会修改它，工作线程又在读取；既没有每人独立参数，也没有同步保护。

修正不是在循环里sleep，而是准备稳定数组`inputs[]`，把`&inputs[i]`逐个交给线程；所有线程结束以前不让数组失效。创建以后谁先执行不确定，因此还要确保对象在创建之前初始化完整，创建之后不随意修改仍被工作者读取的字段。

## 13. pthread错误码与errno不同

许多pthread接口成功返回0，失败直接返回错误编号。不能统一写`if (result < 0) perror(...)`。lab.h里的**函数片段**说明了本课错误策略：

```c
static inline void thread_check(int code, const char *name) {
    if (code != 0) {
        fprintf(stderr, "%s: %s\n", name, strerror(code));
        exit(EXIT_FAILURE);
    }
}
```

它用接口返回的code解释错误，遇不可恢复问题结束整个实验进程。若工作线程调用它，也会结束整个进程，不只是当前线程。它不负责业务回滚。本章下面另写“创建到一半失败时，等待已创建线程”的版本，综合项目再演示如何通知等待者停止。

## 14. 创建一半失败怎样收尾

**完整程序：thread-batch.c**

```c
#include "lab.h"
#include <pthread.h>

struct Job { int value; int factor; int result; };
static void *calculate(void *arg) {
    struct Job *job = arg;
    job->result = job->value * job->factor;
    return NULL;
}

int main(void) {
    struct Job jobs[3] = {{10, 2, 0}, {20, 3, 0}, {30, 4, 0}};
    pthread_t workers[3];
    int created = 0;
    int failed = 0;
    for (int i = 0; i < 3; i++) {
        int code = pthread_create(&workers[i], NULL, calculate, &jobs[i]);
        if (code != 0) {
            fprintf(stderr, "create: %s\n", strerror(code));
            failed = 1;
            break;
        }
        created++;
    }
    for (int i = 0; i < created; i++) {
        thread_check(pthread_join(workers[i], NULL), "join");
    }
    if (failed) { return 1; }
    printf("results=%d,%d,%d\n", jobs[0].result, jobs[1].result, jobs[2].result);
    return 0;
}
```

编译运行，正常输出`results=20,60,120`。`created`只在成功后增加，失败时只join确实存在的线程。这里每个工作者都是有限计算，会自行返回；如果工作者可能等待永远不会产生的数据，还要设计停止协议，第19章展开。

不要为了测创建失败故意耗尽系统线程。本批验证会用测试专用包装器在指定创建次数返回错误，普通运行不改变系统资源上限。

## 15. 通过join取回一个堆结果

**完整程序：thread-return.c**

```c
#include "lab.h"
#include <pthread.h>

static void *square(void *arg) {
    const int *value = arg;
    int *result = malloc(sizeof *result);
    if (result == NULL) { return NULL; }
    *result = *value * *value;
    return result;
}

int main(void) {
    int value = 7;
    pthread_t worker;
    thread_check(pthread_create(&worker, NULL, square, &value), "create");
    void *raw = NULL;
    thread_check(pthread_join(worker, &raw), "join");
    if (raw == NULL) {
        fputs("worker could not allocate result\n", stderr);
        return 1;
    }
    int *result = raw;
    printf("square=%d\n", *result);
    free(result);
    return 0;
}
```

编译运行，输出`square=49`。第二个join参数是`void **`，所以把`void *raw`的地址`&raw`交进去。它不是进程退出状态整数，不能套用waitpid的宏。

## 16. 返回地址后的所有权

square分配结果并返回，成功join后所有权交给main，由main读取并free。工作线程退出不会自动释放这个malloc对象；它不是工作线程的局部栈变量。

禁止返回`&local`指向已经结束的工作函数局部对象；也不要为了偷懒把任意整数直接强转成指针传结果。本例NULL专门表示分配失败，正常结果即使数值为0，仍用有效堆对象保存。

这里create失败时尚无结果分配；join若发生不可恢复错误，辅助函数终止整个进程。本例展示正常所有权转移和明确的分配失败，不声称实现所有线程异常恢复。

## 17. 线程局部对象的对照

**完整程序：thread-local.c**

```c
#include "lab.h"
#include <pthread.h>

static _Thread_local int local = 0;
struct Observation { int id; int before; int after; };
static void *observe(void *arg) {
    struct Observation *item = arg;
    item->before = local;
    local = item->id;
    item->after = local;
    return NULL;
}

int main(void) {
    local = 99;
    struct Observation items[2] = {{1, 0, 0}, {2, 0, 0}};
    pthread_t workers[2];
    for (int i = 0; i < 2; i++) {
        thread_check(pthread_create(&workers[i], NULL, observe, &items[i]), "create");
    }
    for (int i = 0; i < 2; i++) {
        thread_check(pthread_join(workers[i], NULL), "join");
    }
    printf("main_local=%d worker0=%d->%d worker1=%d->%d\n",
           local, items[0].before, items[0].after, items[1].before, items[1].after);
    return 0;
}
```

编译运行，输出`main_local=99 worker0=0->1 worker1=0->2`。`_Thread_local`是C的线程存储期声明，每个线程有自己的local实例；main写99没有把其他实例改为99。不要删掉这个声明再运行冲突版本来“比较谁赢”，那会引入下一章要讲的数据竞争。

## 18. join、detach与资源生命期

**detach**让线程结束后自动释放连接资源，此后不再join它。它不延长参数对象的生命期，不防止main提前结束进程，也不解决共享数据保护。

本批统一采用可连接线程，管理者明确join。分离线程适用于另一类有清楚所有权和停止协议的设计，不能把它当作绕过收尾困难的方法。也不使用强行取消线程来代替正常的关闭标志，因为取消涉及持锁、资源和清理处理，超出本批主线。

## 19. 常见错误、练习与参考答案

常见错误：遗漏-pthread；把work调用结果当入口；所有人拿同一循环变量地址；main没join就返回；把pthread错误当errno；返回局部对象地址；把线程标识当PID。

练习一：把thread-once的输入改为8，应输出什么？答案16，main仍在join以后读取。

练习二：threads中工作者修改不同元素，main却在join以前打印，为什么不安全？答案是main的读取可能与相应工作者写入冲突，独立的工作参数并不保护提前读取。

练习三：thread-batch在第3次创建失败，应该join几个线程？答案2个，不访问第三个未成功建立的标识。

练习四：thread-return若要返回数值0，能用NULL同时表示“正常0”和“分配失败”吗？本协议不能，正常0放进有效结果对象，NULL保留给失败。

练习五：根据第17节输出，画三个local实例和两个Observation对象。前三者各归一线程，后两者在main中创建，各由一个工作者写、main在join后读。
