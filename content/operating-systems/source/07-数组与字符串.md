## 7.1 从一个值走到一组值

前面用一个minutes保存一天时间。五天数据若分别叫day1、day2、day3……，统计时需要重复写名字，也不容易让循环按次序访问。

数组把同类型元素组成一组，按下标访问。先把它想成有固定格数、每格放一个int的表。和普通表格不同，C数组访问有严格边界，工具不会自动替你检查每次下标是否正确。

本章目标是：建立数组并逐项统计；知道最后合法下标；把数组与元素数量交给函数；区分字符数组、字符串与容量；用有明确上限的缓冲区读取一行。

## 7.3 定义数组并逐个读写

`int minutes[4] = {15, 25, 35, 45};` 建立4个int元素，初值按位置排列。方括号中的4表示元素数量；访问时的方括号表示取哪个下标，两个位置的含义不同。

| 下标 | 元素表达式 | 初值 |
| --- | --- | --- |
| 0 | minutes[0] | 15 |
| 1 | minutes[1] | 25 |
| 2 | minutes[2] | 35 |
| 3 | minutes[3] | 45 |

下标从0开始，因此4个元素的最后合法下标是3，不是4。`minutes[1] = 30;` 更新第二个元素；`minutes[1]` 不是“编号叫1的业务任务”，只是数组中的一个位置。

如果初始化时省略方括号内数量，例如 `int minutes[] = {15,25,35,45};`，编译器按初始项推导4个元素。若明确容量更大而只写部分初值，其余元素按相应规则初始化为零；普通未初始化自动数组则不能当作已有可靠值来读取。

## 7.4 循环与数组边界怎样配合

通常让i从0开始，只要i<count就访问values[i]，每轮i增加1。这样count=4时访问0、1、2、3，i=4时条件为假，不访问values[4]。

C不因为看见数组容量4就自动阻止错误下标。读取或写入越界对象属于未定义行为，可能暂时没有崩溃，也不能说正确。把条件改成<=count，是最常见的一位边界错误之一。

这里的“安全边界”是每次访问时的合法对象范围。它与操作系统按页面做内存保护不是同一粒度，所以“没有收到崩溃信号”并不能证明数组访问没有越界。

## 7.5 完整统计器：总分钟与有效天数

**完整程序：array-stats.c**

```c
#include <stdio.h>

int main(void) {
    int values[] = {15, 0, 45, 30, 60};
    size_t count = sizeof values / sizeof values[0];
    int total = 0;
    int active = 0;
    for (size_t i = 0; i < count; i++) {
        int minutes = values[i];
        total += minutes;
        if (minutes > 0) {
            active++;
        }
    }
    printf("count=%zu total=%d active=%d\n", count, total, active);
    return 0;
}
```

预期count=5 total=150 active=4。本例约定记录为非负分钟、总和在int范围内。0分钟也占数组中的一个位置，但不算有效学习天，因而元素数与active不同。

| i | 本轮minutes | 累计total | 累计active |
| --- | --- | --- | --- |
| 0 | 15 | 15 | 1 |
| 1 | 0 | 15 | 1 |
| 2 | 45 | 60 | 2 |
| 3 | 30 | 90 | 3 |
| 4 | 60 | 150 | 4 |

请先逐项核对，再试着改成全0或只有一个元素。不要改变数据后继续拿150当固定答案。

## 7.6 sizeof为什么能在这里算数量

sizeof values给整个数组占用的C字节数，sizeof values[0]给单元素字节数。两者相除，就是这个数组的元素数量。公式不要求你先假定int一定是4字节。

size_t是表示对象大小等数量的无符号整数类型，sizeof的结果使用它。输出size_t用%zu。当前i与count都采用size_t，避免把本来非负的索引与不必要的负数比较混起来。

无符号不代表“自动安全”。如果count为0，直接计算count-1会产生很大的无符号结果，而不是负1。因此反向循环不要凭直觉写 `i >= 0` 就不断减。先把正向边界掌握，再设计反向迭代的停止规则。

数组数量与外部传来的“有效项数”也可能不同：容量100的数组可能只有前3项有效。后续程序需要同时知道容量与有效数量，不能仅有一个含糊的length名字。

## 7.7 把数组交给函数，还要交什么

普通数组实参不会自动携带一个可供函数查询的原数组长度。函数参数中的数组写法按语言规则调整为指针参数，第08章会画出地址关系；当前先掌握接口使用要求：**显式传有效数量，并保证不超过实际可访问元素数。**

**完整程序：array-function.c**

```c
#include <stdio.h>

int sum_values(const int values[], size_t count) {
    int total = 0;
    for (size_t i = 0; i < count; i++) {
        total += values[i];
    }
    return total;
}

int main(void) {
    int days[] = {20, 30, 40};
    size_t count = sizeof days / sizeof days[0];
    printf("all=%d first_two=%d empty=%d\n",
           sum_values(days, count), sum_values(days, 2), sum_values(days, 0));
    return 0;
}
```

预期all=90 first_two=50 empty=0。第三个调用让函数不访问任何元素，返回初始累计值0，不要求声明一个容量为0的标准C数组。

const限制通过values这个访问路径修改元素，不把参数长度变成自动受检，也不保证其他地方永远不能改底层数据。函数内不能再用 `sizeof values / sizeof values[0]` 恢复调用者数组数量，因为那里已不是原数组对象。

注意最后printf的三个函数调用彼此不修改共享状态，因此不依赖它们以哪种顺序求值。不要把参数的书写顺序误当成所有函数实参都保证从左到右执行。

## 7.8 最大值、空数据与初始化

给数组{-4,-2,-7}找最大值，如果先写max=0，再只在元素更大时更新，结果会错误保留0。0根本不在数据中。

对于非空的一般整数序列，可用第一个元素初始化max，再从第二个开始比较。对于可能为空的数据，要先检查count是否为0，并约定如何表达“无最大值”，不能直接访问values[0]。

“空序列求和是0”是一个可用约定，“空序列最大值是0”却不是所有领域的正确约定。程序设计先决定结果语义，再选初始值，而不是把0当万能默认答案。

## 7.9 char数组怎样成为字符串

C字符串是一串字符字节，以值为0的终止字节结尾，常写成 `\0`。它与换行 `\n` 不同，也不是可见数字字符 `'0'`。

`char word[4] = "abc";` 的四个位置如下：

| 下标 | 存放内容 | 用途 |
| --- | --- | --- |
| 0 | a | 第一个文字字节 |
| 1 | b | 第二个文字字节 |
| 2 | c | 第三个文字字节 |
| 3 | `\0` | 告诉字符串接口内容到此结束 |

引号中的abc是3个字节，但作为C字符串保存还需要1个终止位置，因此容量至少4。容量3的普通字符数组并非自动不能存在；它若没有终止符，就不能直接当作这样的C字符串交给%s或strlen。

printf的%s依终止符判断在哪里停止，不会自动知道你分配了多少格。没有终止符时，它可能越过有效对象寻找，已经不再是合法的字符串使用。

## 7.10 strlen与sizeof回答两个问题

**完整程序：strings.c**

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char word[4] = "abc";
    printf("capacity=%zu length=%zu\n", sizeof word, strlen(word));
    word[1] = 'X';
    printf("changed=%s\n", word);
    return 0;
}
```

输出capacity=4 length=3，然后changed=aXc。sizeof word回答这个数组对象占多少字节，strlen回答从开头到第一个终止符之前有多少字节，不计终止符本身。

strlen需要已经是有效字符串的输入，不能用它来证明一个任意未终止缓冲区安全。先有边界和终止保证，再调用长度接口。

把word容量改为16、仍初始化abc，sizeof变16，strlen仍3。第一个终止符之后的预留空间并不会因为存在就成为正文的一部分。

## 7.11 字符数、字节数与修改边界

UTF-8下字符串 `"A中"` 含两个文字字符，但正文占4字节，再加C字符串终止符，需要至少5字节容量。strlen返回4，不是2。

随意用下标修改中文编码中间的一个字节，可能破坏编码，不等于“替换第二个汉字”。本章可写修改练习使用简单英文，先掌握字节级规则，再在后续需要时学习文本处理。

字符串字面量本身不能被改写。要在本例中修改内容，我们创建并初始化了可写的char数组word。第08章会进一步解释“保存一个指向字面量的地址”为什么不是同一种可写数组。

## 7.12 字符串比较不靠普通等号

要判断两个字符串内容是否相同，使用有明确契约的接口，例如string.h中的strcmp。其结果等于0表示内容相同，小于0或大于0表示相应次序；不要要求非零结果恰好等于1或-1。

**完整程序：compare.c**

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char left[] = "os";
    char right[] = "os";
    if (strcmp(left, right) == 0) {
        printf("same\n");
    } else {
        printf("different\n");
    }
    return 0;
}
```

先输出same；把right初始内容改为OS，重新编译，应输出different。在当前比较规则下大小写不同，不会自动做不区分大小写的匹配。

用两个数组名直接写==不是逐字节内容比较，相关地址转换规则下一章解释。本章先把“字符串内容比较有自己的接口”落实到可运行程序。

## 7.13 把数组与字符串放回原主线例程

[完整源码：arrays.c](示例代码/arrays.c)

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    int minutes[] = {15, 25, 35, 45};
    size_t count = sizeof minutes / sizeof minutes[0];
    int total = 0;
    for (size_t i = 0; i < count; i++) { total += minutes[i]; }
    char title[16] = "OS lab";
    printf("count=%zu sum=%d length=%zu\n", count, total, strlen(title));
    return 0;
}
```

保存为arrays.c并编译，预期count=4 sum=120 length=6。这里有三种不同数量：minutes的4个元素、title的16字节容量、title正文的6字节长度。不能因为都与“多少”有关，就混为同一个数。

请逐段解释：声明数组，求元素数，循环累计，创建有效字符串，再按类型对应输出。现在它依赖的语法都已经出现，不必靠看不懂的模板拼接。

## 7.14 fgets如何在有限空间中读取一行

fgets接收目标缓冲区、容量和输入流，最多放入容量减1个输入字节，再补终止符。若读到换行，换行通常也保存在缓冲中；没有读到任何字符就遇到结束或发生错误时，可返回NULL。[fgets接口说明](https://man7.org/linux/man-pages/man3/fgets.3.html)

这里的NULL先作为接口约定的“没有成功交回字符串”结果来检查，第08章再解释指针类型。数组名交给fgets，使库函数能向该缓冲区写入；它不会因为你传了一个数字容量，就自动知道你是否撒谎，因此必须传真实可写容量。

我们给本次练习一份清楚协议：只处理一次输入；正文最多30字节；输入必须以换行完成。太长或没有形成完整行时结束本次程序并报告失败，不把前半段安静当成整行接受。

## 7.15 完整行输入：容量、换行与正文

**完整程序：line-input.c**

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char line[32];
    if (fgets(line, sizeof line, stdin) == NULL) {
        fprintf(stderr, "No line read\n");
        return 1;
    }
    size_t length = strlen(line);
    if (length == 0 || line[length - 1] != '\n') {
        fprintf(stderr, "Line too long or missing newline\n");
        return 1;
    }
    line[length - 1] = '\0';
    length--;
    printf("text=%s bytes=%zu\n", line, length);
    return 0;
}
```

32字节容纳至多30字节正文、1个换行、1个终止符。先检查成功，再求长度；用短路条件避免length为0时计算并访问length-1；检查末尾是换行后，把该位置改为终止符，正文长度减1。

没有读取成功时不能继续把line当作已经初始化的有效字符串。错误分支尽早return，使正常分支的前提更清楚。

本例协议针对普通文本，不含内嵌零字节，不承担任意二进制输入解析。它只读取第一行，第二行不在本次处理范围内。真实交互组件若要重试，还需处理残留输入与EOF策略。

## 7.16 用固定输入逐项验收

编译line-input.c后，在同一个Ubuntu目录执行：

```bash
printf 'hello\n' | ./line-input
printf '\n' | ./line-input
printf 'A中\n' | ./line-input
```

预期分别为 `text=hello bytes=5`、`text= bytes=0`、`text=A中 bytes=4`。空行是成功读到了换行，去掉换行后正文为空，和完全没有输入不同。

再执行 `printf 'hello' | ./line-input`，因为缺少本协议要求的换行，应该报错；输入31个a再换行，也应被拒绝，因为第一轮缓冲放不下整行。

终端手动输入时按Enter完成行；重定向文件或管道可能没有末尾换行，因此程序必须按协议检查，不能从“通常用户会按Enter”推出所有输入都完整。

## 7.17 拷贝、拼接与格式化需要容量意识

如果目标只有4字节，就只能安全容纳3字节正文加终止符。把长字符串不加检查地复制进去，不会因为函数名含copy就自动扩容。

需要格式化拼接时可了解snprintf：它接收容量，返回若空间足够本来需要生成的正文长度；返回非负且不小于容量，表示发生截断。先处理负数错误，再按合适类型比较。截断不一定是业务可接受结果，必须由调用者决定。

本章不通过堆叠更多字符串函数名代替边界分析。每次操作先回答：目标容量是多少？正文已经多长？还需要终止位置吗？失败后结果能否继续使用？
