## 为什么不在第一次学变量时直接复制

## 完整主线例程 minutes.c

[完整源码：minutes.c](示例代码/minutes.c)

```c
#include <stdio.h>
#include <stdlib.h>
#include <errno.h>
#include <ctype.h>
#include <string.h>

int main(void) {
    char line[64];
    char *end;
    printf("Minutes (0..10080): ");
    if (fgets(line, sizeof line, stdin) == NULL) {
        fprintf(stderr, "No input\n");
        return 1;
    }
    if (strchr(line, '\n') == NULL && !feof(stdin)) {
        fprintf(stderr, "Input too long\n");
        return 1;
    }
    errno = 0;
    long minutes = strtol(line, &end, 10);
    if (end == line || errno == ERANGE) {
        fprintf(stderr, "Invalid integer\n");
        return 1;
    }
    while (isspace((unsigned char)*end)) { end++; }
    if (*end != '\0' || minutes < 0 || minutes > 10080) {
        fprintf(stderr, "Expected 0..10080\n");
        return 1;
    }
    printf("%ld h %ld min\n", minutes / 60, minutes % 60);
    return 0;
}
```

在自己的例程目录保存程序，Ubuntu Bash中使用 `gcc -std=c17 -Wall -Wextra -Wpedantic -g minutes.c -o minutes` 编译，再运行 `./minutes`。

此例接受0—10080的整数分钟。90得到1h30min，10080得到168h0min；空行、12abc、-1、10081与超长输入被拒绝，进程非零退出。它对超长输入采用结束本次程序的策略，不是继续循环提示的完整交互组件。

## 理解转换协议

调用前清零errno，失败后检查ERANGE；end与起点相同表示没有转换任何数字。end指向转换停止的位置，随后跳过空白，要求到达字符串结束标志。这样12abc不会被安静接受成12。最后独立检查业务范围，转换成功不代表符合课程限制。

有关接口原始说明见 [strtol手册](https://man7.org/linux/man-pages/man3/strtol.3.html)。本例固定base=10，不依赖较新库对其他前缀的支持。

## 逐步追踪一份实际输入

假设line保存空格、9、0、空格、换行、终止符。strtol允许前导空白，转换90，在数字后的空格处停止，并通过&end更新end。随后while跳过该空格和换行，到达终止符，最终业务检查接受90。

| 输入正文 | 是否取得数字 | 停止位置或问题 | 本例结果 |
| --- | --- | --- | --- |
| 0 | 是 | 数字后到结尾 | 合法0分钟 |
| 90 | 是 | 数字后到结尾 | 1小时30分钟 |
| 12abc | 是 | end指向a | 拒绝尾随非法内容 |
| abc | 否 | end与起点相同 | 拒绝无数字 |
| 仅空白 | 否 | 没有可转换数字 | 拒绝，不能把返回0当合法0 |
| -1 | 是 | 转换本身可以成功 | 业务范围拒绝 |
| 10081 | 是 | 转换本身可以成功 | 超过业务上限 |
| 很长但仍能完整取得的整数 | 可能超long范围 | errno为ERANGE | 拒绝范围错误 |

本例首先用fgets控制单次输入。未读到换行且也未确认EOF时，按不完整行拒绝；不是看到缓冲已有一些字符就默认整行完成。达到读取上限时尤其要保守，不能先接受前缀再丢弃剩余内容。

`char *end`本身是main里的一个指针对象；strtol的第二参数要能更新它，因此传&end。`*end`访问停止位置的字节，`end++`推进到后一个字符。可以按第08章的箭头图逐个追踪，不再把这些符号当作要背的装饰。

## 转换、协议与业务范围不要混成一个判断

即使strtol能够把前缀转换成整数，你的输入协议也可以要求整行只包含一个数及允许的空白。即使整个数转换成功，业务也可以拒绝负数或过大分钟。每层失败由不同证据判断。

接口的0返回值可能是合法数值，LONG_MAX也可能是合法边界；先清errno，再结合end和ERANGE检查，而不是只比较一个返回数字。最后业务范围检查与long转换范围分开。

本例固定base=10，所以前导0也按十进制处理。它没有实现循环重试与多字段文件格式，不能直接宣称可作为所有用户输入场景的通用组件。第三批综合项目将按自己的行长度、数量与分钟上限复用同一思路。
