# 详写第九批：观察、Shell改造与毕业参考答案

范围第34—36章。综合练习建议6—8小时；连同三章25—36小时，共31—44小时。这一批完成后，36章详细版主线齐全。读者自己的验收仍按真实记录完成，不由教程状态代替。

## 一、先提交观察问题卡

使用第34章measure-self，分别保存cpu与wait各三次结果，写编译参数、内核版本、checksum、wall与cpu。先检查成功状态，再比较数字。不要求固定毫秒数，也不要求安装strace。

参考结论应类似：“当前环境下，wait模式主要增加经过时间，进程CPU累计较少。”还应说明未测磁盘、未统计任意子进程、短区间受精度和负载影响。把这句话换成“所有程序慢都是等待”便超出了证据。

## 二、用纸笔准备Shell验收

对`printf abc | wc -c > answer.txt`画三个进程、各自fd0/1、管道原fd与文件fd。再标两次fork、两次exec、两次wait所在的进程。请先自己画，别仅抄最终图。

参考：父进程创建两侧后关闭自己持有的管道端；左侧stdout接写端；右侧stdin接读端、stdout接文件；两侧dup后关闭原fd。数据是abc三个字节，右侧读到EOF后输出计数；父回收双方，结果取右侧。文件可读不证明掉电持久性。

## 四、改造第一处：统一识别内置命令

下面是**需要上下文的替换片段**，不是独立C程序。在mini-shell-help.c中找到完整`is_builtin`函数，用下列函数整体替换，其他代码保留。

**替换片段：help识别**

```c
static int is_builtin(const char *name) {
    return strcmp(name, "cd") == 0 || strcmp(name, "pwd") == 0 ||
           strcmp(name, "exit") == 0 || strcmp(name, "help") == 0;
}
```

为什么不只加一个打印分支？主循环先用is_builtin统一拒绝内置与管道/重定向的组合。如果只新增后面的分支，help可能绕过这层统一规则，形成与cd/pwd不一致的行为。

## 五、改造第二处：在父主循环输出帮助

在主循环中，找到处理`exit`的`if`分支；把以下代码插在它之前、统一内置组合检查之后。它使用已有的count与status，不能移到函数外面。

**插入片段：help分支**

```c
        if (strcmp(command.left[0], "help") == 0) {
            if (count != 1) {
                fputs("usage: help\n", stderr);
                status = 2;
                continue;
            }
            status = (puts("commands: cd DIR, pwd, help, exit; external [| external] [> FILE]") == EOF ||
                      fflush(stdout) == EOF) ? 1 : 0;
            continue;
        }
```

成功时更新状态0，参数不符为2，输出失败为1；continue回到读取下一行，不会再把help当外部程序exec。这里只展示改动片段；完整上下文就是第35章基线，不要用这个片段覆盖整个文件。

## 六、编译改造版本并核对预期

在**Ubuntu/WSL的Bash，batch09目录**执行：

```bash
gcc -std=c17 -D_POSIX_C_SOURCE=200809L -Wall -Wextra -Wpedantic -Werror mini-shell-help.c -o mini-shell-help
mkdir -p graduation-box
cd graduation-box
../mini-shell-help
```

进入**mini-shell-help**后分别输入`help`、`help extra`、`help | wc -c`、`help > help.txt`、`echo a | help`。第一条打印支持范围；其余拒绝。help重定向被拒绝时不应生成help.txt，因为没有进入外部执行或打开输出目标。

每个错误后都可输入`echo recovered`观察主循环仍可用。要验收某条错误的状态，单独运行这一条后立即exit，再回Bash查看`echo $?`；成功恢复命令会更新状态，不要把它误算为原错误消失。

## 七、正常功能矩阵

在自己的graduation-box中新开改造版Shell，按表分组测试。输出目标均使用本目录新测试文件。

| 能力 | 输入 | 验收 |
| --- | --- | --- |
| 外部程序 | `echo hello` | hello加换行 |
| 父目录状态 | `pwd`、`cd ..`、`pwd` | 目录相应改变 |
| 两段管道 | `printf abc | wc -c` | 数值3并结束 |
| 较大输出 | `seq 1 50000 | wc -l` | 数值50000并结束 |
| 文件输出 | `echo saved > result.txt` | 文件含saved加换行 |
| 管道加文件 | `printf abc | wc -c > count.txt` | 文件数值3 |
| 帮助 | `help` | 列出已实现范围 |
| 空白 | 空行或空格行 | 不运行命令，不改变上次状态 |

seq与wc是本Linux实验已有的外部工具；缺少时记录环境差异，不靠虚构输出补齐。较大输出验证两端已启动，测试程序有超时保护；若自己的改造挂起，回看fd表与创建顺序，不随意终止其他任务。

## 八、失败与恢复矩阵

| 输入/条件 | 最终状态约定 | 重点检查 |
| --- | --- | --- |
| 找不到的命令后立即exit | 127 | exec错误，父仍能回收 |
| 没有执行权限的普通文件 | 126 | 与ENOENT区别 |
| `echo a |` | 2 | 缺右侧，不启动执行 |
| `echo a > missing/file` | 1 | 打开目标失败 |
| `pwd > x`或`help > x` | 2 | 内置组合在执行前拒绝 |
| 64个token | 2 | argv必须保留NULL |
| 1024字节输入或含NUL | 2 | 消耗整行，不执行前缀 |
| 上述错误后`echo recovered` | 0 | 后续合法命令仍可运行 |

自动验证还模拟pipe失败、第一/第二次fork失败、dup2/open失败和wait被中断。第二次fork失败时用一个仅等待的直接子进程确认能被终止并回收，避免仅用会很快退出的小命令掩盖问题。失败注入不等于真实系统资源耗尽。

## 九、两个适合闭卷的反例

**反例A：** 左侧返回7，右侧成功，父是否必须返回7？参考答案：本工具约定结果取右侧，因此可以返回0；但仍必须回收左侧。若要pipefail，需要另行定义规则和测试，不能悄悄改变。

**反例B：** 读到一行前半部，先执行，发现尾部过长后再拒绝是否可行？参考答案：不符合本项目约定。可能已经产生输出或改变目录，拒绝已来不及；应先消耗并验证整条输入记录，再执行。

再自选一个反例：文件可读但目录不可搜索、recv短于帧长、相同地址不同内容等。写出最小条件和预期，再回对应章节核对。反例让你从“总是”改为明确条件。

## 十、毕业说明怎样写

用下列模板组织一页主要说明，可另外附原始日志：

```text
作品：基于mini-shell的独立help改造
平台与工具版本：
源码与编译命令：
支持输入及容量：
正常验收：输入、输出、状态、产生文件
失败验收：输入、诊断、状态、恢复操作
资源设计：父子关系、fd关闭、状态回收
改动：哪两个位置，为什么都需要
限制：语法、终端作业控制、后代管理、持久性等
下一步：一个小目标及其验收
```

说明应能让另一个人按步骤重跑，而不需要猜“当时你在哪个终端”。不要附整份无关系统环境或私人文件；保留能支持结论的证据即可。
