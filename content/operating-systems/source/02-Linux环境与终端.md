# 02 Linux 环境与终端

> **零基础详细版 · 已重写。** 先读第01章。本章从打开窗口开始，不要求你已经会Linux。建议拆成“进入环境”“认识命令”“文件练习”三次完成，连同排错约4—6小时。安装等待时间因机器与网络不同而变化。

## 2.1 学完以后应该能做什么

你将准备一个能编译C程序的Ubuntu环境，知道命令输入到哪里，能创建自己的练习目录、写入一份笔记，再把它找回来。下一章会在这个环境里完成第一个程序。

本章有两类窗口，必须先分清：**Windows PowerShell**用于查看和启动WSL；**Ubuntu终端中的Bash**用于Linux命令和后面的C实验。外观都像文字窗口，不代表里面运行的是同一种环境。

接下来每组操作都会标明执行位置。读到“在Ubuntu执行”时，不要继续往仍显示Windows路径的PowerShell窗口输入。

## 2.2 四个经常被混用的词

**终端**是显示文字、接收键盘输入的界面。你看到的黑色或其他底色的文字区域，可以承载一个交互终端。

**Shell**是解释命令、启动程序的一类软件。你输入 `pwd`，由Shell理解你要运行哪个命令，并把结果呈现出来。

**Bash**是一种Shell，本课在Ubuntu里使用它。Shell是类别，Bash是具体实现，好比“浏览器”和某个浏览器产品的关系。

**命令**是你交给Shell处理的一段输入。例如 `pwd` 请求显示当前位置。命令本身不是C语言源代码，`gcc hello.c -o hello` 也不是要写进hello.c文件的内容。

可以暂时把整个过程画成：

```text
你在终端输入一行 → Shell解释这行 → 运行相应操作或程序 → 终端显示结果
```

终端不是操作系统内核，Bash也不是内核。第01章的“界面、应用、资源管理”区别在这里仍然适用。

本课以Ubuntu为具体实验环境，目的是减少安装与接口差异。你可以先离线阅读教材，真正运行系统实验时再使用Linux环境。

## 2.4 Windows：先检查，不要重复安装

按Windows键，输入“PowerShell”，打开普通PowerShell窗口。常见提示符可能类似：

```text
PS C:\Users\你的Windows用户名>
```

这里的文字是窗口提示当前位置，不是要你输入的命令。光标处只输入下面这一行，然后按Enter：

```powershell
wsl --list --verbose
```

它的意思是：让wsl列出已安装的Linux环境，并显示较详细的信息。参数 `--list` 表示列出，`--verbose` 表示详细显示。此刻不需要背全部选项。

如果已有Ubuntu，示意结果可能是：

```text
  NAME      STATE      VERSION
* Ubuntu    Stopped    2
```

NAME是环境名称；STATE是当前运行状态，Stopped并不表示损坏，只表示尚未运行；VERSION这一列是WSL版本。星号标记默认环境，不是错误提示。你的名称可能是Ubuntu-24.04，其他版本数字或状态也可能不同。

**如果已经有可用Ubuntu且VERSION为2，不要重新安装。** 记住NAME列的实际名称，直接进入2.6。若显示WSL 1或其他配置，先参考官方文档核对是否适合本课，不在没有理解影响前随意卸载或转换已有环境。

## 2.5 Windows：确实没有环境时再安装

下面是安装分支，已有环境的读者跳过。当前常见安装命令适用于满足微软文档前提的Windows版本；旧版本和受管理电脑可能需要不同准备。

在开始菜单找到PowerShell，右键选择“以管理员身份运行”，按系统要求允许打开。然后输入：

```powershell
wsl --install -d Ubuntu
```

这会请求安装WSL及Ubuntu相关组件。需要网络，可能要求重启，按提示完成。重新进入Windows后，从开始菜单打开Ubuntu，等待首次初始化，按提示设置Linux用户名与密码。

安装指引核验于2026-11-04，适用前提及具体排错以[微软WSL安装文档](https://learn.microsoft.com/en-us/windows/wsl/install)为准。本课不通过重装现有系统、卸载已有发行版来解决普通命令问题。

第一次设置的Linux用户名可以与Windows用户名不同。Ubuntu里的普通用户密码也不要求与Windows登录密码相同。终端输入密码时通常没有星号和字符回显，按正常方式输入后按Enter，不要因为看不见就连续重输。

遇到安装失败，先把完整错误码和出错命令记下来，再查对应官方说明。安装失败属于环境准备问题，不能靠改下一章的C代码解决。

## 2.6 进入Ubuntu，确认自己到了哪里

方法一：开始菜单搜索并打开已安装的Ubuntu。

方法二：在Windows PowerShell输入下面命令，示例假设实际名称是Ubuntu：

```powershell
wsl -d Ubuntu
```

如果NAME列写的是Ubuntu-24.04，就把命令最后一个名字换成该实际名称。不要把教材里的“实际名称”四个汉字原样输入。

进入后常见提示符类似：

```text
learner@computer:~$
```

learner通常是Linux用户名，computer是机器名，`~` 代表用户主目录，末尾 `$` 是常见普通用户提示符。它们的具体样子可以不同，**本教材命令块里不附带这个提示符**，方便你只复制命令。

现在在Ubuntu执行：

```bash
uname -s
```

常见输出为：

```text
Linux
```

再输入一个最小的显示命令：

```bash
printf 'ready\n'
```

应显示ready并换到下一行，再次出现提示符。说明终端、Shell和这次命令已经能配合工作。

## 2.7 输入命令时，空格和Enter都做什么

看 `uname -s`：uname是命令名，空格把后面的 `-s` 与命令名隔开，`-s` 是选择行为的参数。按Enter才会把整行交给Shell处理。

看 `printf 'ready\n'`：引号把一段内容作为参数；`\n` 在这个例子里由printf解释为换行。外面的英文单引号不作为ready文字输出。下一章还会见到C语言的printf，它们承担类似的格式化输出工作，但分别处在Shell与C程序环境里。

注意输入英文半角的 `-`、`'`、`/`，不要换成长破折号或中文引号。`uname-s` 把空格漏掉后，会变成另一个名字，Shell通常找不到它。

如果按Enter后出现第二行 `>` 提示，可能是引号没有闭合，Shell还在等剩余内容。这时按Ctrl+C取消这次未完成的输入，再重新输入完整命令，不要把下一条命令继续接在未结束的引号里。

## 2.8 准备本批真正需要的工具

先检查，避免以为“有版本输出”也是报错。以下均在Ubuntu执行：

```bash
gcc --version
```

```bash
nano --version
```

GCC是用来编译C程序的工具；nano是本批采用的简单文字编辑器。输出版本号和一段说明是正常结果，不要求与你看到的教材截图逐字相同。

如果提示找不到gcc或nano，再依次执行安装命令：

```bash
sudo apt update
```

```bash
sudo apt install build-essential nano
```

逐个词理解：sudo请求以管理员权限完成这一条操作；apt是Ubuntu的软件包管理工具；update更新可安装软件的信息；install请求安装指定软件；build-essential包含常用编译工具；nano是编辑器包名。

第一次sudo可能要求Linux密码。看不见回显仍属正常。安装时若询问是否继续，先看清它计划安装什么，再按提示输入确认。没有网络、软件源异常或没有管理权限时应先处理环境条件。

安装后重新运行前面两条版本命令。现在只装学习起步需要的工具，调试器等在后续需要时再说明。**编译和运行你自己的普通练习，不需要每次都加sudo。**

## 2.9 文件、目录、路径：先把名字说清

文件保存内容，例如note.txt保存一段文字。目录用于组织名字，可以包含文件和其他目录；图形界面里常叫文件夹。路径则说明怎样找到某个对象。

例如，在一个用户主目录下面，可能有：

```text
用户主目录
  os-lab/
    lesson02/
      note.txt
      notes/
```

末尾的斜杠在这张示意图里提醒你“这是目录”，不意味着所有工具显示目录都必须加斜杠。note.txt的扩展名是txt，用来帮助人和程序理解常见用途，文件实际内容仍由写入的字节决定。

Shell始终有一个“当前工作目录”。后面输入相对路径时，就从这里出发。它不一定是终端窗口对应的某个Windows文件夹，也不会因为你打开网页某一章就自动切到那章的示例目录。

## 2.10 第一步：确认位置，再建立练习目录

在Ubuntu输入：

```bash
pwd
```

pwd显示当前工作目录。输出可能是 `/home/learner`，也可能是其他位置。如果从Windows某个目录启动WSL，初始位置也可能位于 `/mnt/c/...`。不用根据这个差异猜安装失败，下一步会明确进入自己的练习目录。

执行：

```bash
mkdir -p ~/os-lab/lesson02
```

mkdir是创建目录；`-p` 允许创建缺少的上级目录，目标目录已存在时也不会仅因此报错；`~` 是当前Linux用户主目录的简写；os-lab与lesson02是本课为你选的普通目录名。

然后进入它：

```bash
cd ~/os-lab/lesson02
```

cd改变当前工作目录。通常成功后没有单独的成功消息。再检查一次：

```bash
pwd
```

如果用户主目录为 `/home/learner`，结果应是 `/home/learner/os-lab/lesson02`。用户名不同很正常，重点是末尾为本次目录。如果前面mkdir失败，不要忽略失败继续往下做。

## 2.11 第二步：列出目录中的内容

输入：

```bash
ls
```

ls列出当前目录的部分可见名字。新目录里没有可见文件时，可能不输出任何文件名，直接回到提示符。这不等于命令没有执行。

再输入：

```bash
ls -l
```

`-l` 请求较详细的形式。不同工具或语言设置下，可能先显示total/总计等信息。现在先关注文件名，权限和大小在后续章节展开，不要求你第一次看到就读懂每一列。

目录里已有东西也不必删除；这是你可能之前做过练习的目录。使用自己的新文件名，或确认要重写的是本次练习文件，再进行下一步。

## 2.12 第三步：创建一份能读回来的笔记

确认仍在lesson02目录，然后执行：

```bash
printf 'My first OS note\n' > note.txt
```

左边printf产生一行文字；`>` 把这次标准输出交给右边指定的文件；note.txt不存在时会创建，已经存在时会被这次内容覆盖。因此只对本次实验允许覆盖的note.txt执行这条命令。

“标准输出”现在可以先理解为程序默认的输出通道。通常它连接终端，所以前面ready出现在屏幕上；这里用 `>` 改了去向，文字进入文件。

这次屏幕没有显示My first OS note，反而是正确现象：输出已交给文件。验证时不要靠猜，输入：

```bash
ls
```

应能看到note.txt。接着：

```bash
cat note.txt
```

cat读取文件并输出内容，应显示：

```text
My first OS note
```

你已经完成“产生数据 → 写文件 → 定位文件 → 读回”的小闭环。这里用到的写文件请求，就是第01章讲过的操作系统服务的一种实际用途。

## 2.13 第四步：亲自改变当前位置

创建一个子目录：

```bash
mkdir -p notes
```

进入它：

```bash
cd notes
```

再输入pwd，结果末尾应变成 `/os-lab/lesson02/notes`。现在若输入 `cat note.txt`，系统会在当前notes目录查找这个名字；而文件实际在上一层lesson02里，所以可能提示找不到。

这不是文件凭空消失，而是查找起点变了。先回上一级：

```bash
cd ..
```

再运行 `pwd` 确认回到lesson02，执行 `cat note.txt`，又应读到之前的内容。`..` 表示上一级目录，必须是两个英文句点，中间没有空格。

`cd notes` 只改变位置，没有搬动note.txt。请把这个区别用自己的话说一遍，后续“文件找不到”的大部分入门问题都与它有关。

## 2.14 相对路径与绝对路径

相对路径从当前目录出发。在lesson02里，`note.txt` 指当前目录中的文件；`notes/day1.txt` 指notes子目录里的day1.txt；`../` 表示往上一级走。

绝对路径从Linux目录树根 `/` 开始，例如 `/home/learner/os-lab/lesson02/note.txt`。同一个绝对路径不会因为当前目录改变就变成另一个相对位置，但对象本身仍可能被修改或删除。

`~` 会由Shell展开成你的主目录，不是要在文件管理器中寻找一个叫波浪号的目录。比如 `~/os-lab` 通常展开成 `/home/你的Linux用户名/os-lab`。示例中的用户名不要照抄。

Linux路径里使用 `/`。Windows常见路径是 `C:\Users\...`，这两种写法不是可以随意混用的同一条路径。在WSL里，Windows的C盘通常经 `/mnt/c/` 访问。你可以暂时只在Linux主目录练习，把系统之间的文件复制留到需要下载示例时。

## 2.15 文件名的大小写、空格与扩展名

本课在Ubuntu主目录下操作，通常区分大小写：`note.txt` 与 `Note.txt` 是不同名字。若你用小写创建，却用大写读取，报“找不到”有充分理由。

为减少额外规则，起步练习统一使用小写英文字母、数字和短横线命名，先不在文件名里使用空格。以后可以学习给含空格路径加引号，不需要现在同时处理所有情况。

第03章要创建的是hello.c。它的完整名字应当就是hello.c，而不是hello.c.txt。若用Windows图形编辑器保存，尤其要检查隐藏扩展名；使用本章的nano可以直接控制保存名。

## 2.16 怎样读错误，不把所有失败都当成一件事

| 看见的内容 | 先理解成什么 | 第一项检查 |
| --- | --- | --- |
| command not found | Shell找不到要运行的命令名 | 拼写、空格、工具是否安装 |
| No such file or directory | 某个需要的路径不存在或未能定位 | pwd、ls、大小写、上一级目录 |
| Permission denied | 当前操作没有被允许 | 访问位置、权限、是否在运行错误文件 |
| 提示符直接回来，没有文字 | 有些命令成功时本来不输出 | 用pwd、ls或读文件验证结果 |
| 输入密码没有显示 | 终端可能隐藏密码回显 | 正常输入一次并按Enter |
| 行首变成 `>` 等待更多输入 | 可能有引号等尚未结束 | Ctrl+C取消，重新输入完整行 |

这张表提供第一步检查，不保证每个同样英文片语都只有一个原因。请保留完整命令和完整错误，再结合当时位置判断。

不要把sudo当作通用修复按钮。路径拼错时增加权限不会把不存在的名字改正确；自己练习目录的文件若被以管理员身份创建，反而可能给之后编辑带来不便。

## 2.17 暂停、退出与下次继续

Ctrl+C通常用于中断当前前台程序或取消未完成输入；它不是复制快捷键的通用替代。在终端里复制粘贴的快捷方式依使用的终端应用而不同，可以使用终端自己的右键菜单，不要假定所有窗口都一样。

输入 `exit` 会退出当前Shell。若你在PowerShell中进入Ubuntu，退出后可能回到PowerShell提示符。它不会因此删除已经保存的note.txt。

下次打开Ubuntu后，先执行：

```bash
cd ~/os-lab/lesson02
```

再执行 `pwd`、`ls`、`cat note.txt`。能重新找到文件，才说明你已经不依赖“碰巧处在正确目录”。

## 2.18 独立练习与参考答案

**练习一：** 在lesson02里创建practice目录，把一行文字写入practice/day1.txt，再读出来。

参考步骤：先 `cd ~/os-lab/lesson02`，再 `mkdir -p practice`，执行 `printf 'Day 1\n' > practice/day1.txt`，最后 `cat practice/day1.txt`。该文件属于练习，可以覆盖重做；不要把命令中的路径换成未确认的私人文件。

**练习二：** 进入practice后，怎样读上一级的note.txt？

答案：`cat ../note.txt`；也可以先 `cd ..` 再 `cat note.txt`。第一种改变查找路径但不改变cwd，第二种先改变cwd。两种方式的思路不同。

**练习三：** 为什么cd成功后没输出不能直接判断它失败？

答案：命令不一定用文字报告成功。用pwd核对当前位置，是直接观察结果的方法。

**练习四：** 在notes里执行cat note.txt失败，第一反应为什么不应该是重新安装Ubuntu？

答案：错误与当前查找位置能直接对应，应先核对路径。重装系统不针对这个原因，还可能影响已有数据。
