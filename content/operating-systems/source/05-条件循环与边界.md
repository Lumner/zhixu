# 05 条件、循环与边界

> **零基础详细版 · 已重写。** 先完成第04章，能跟踪变量赋值、区分数值与字符。本章建议分三次学习，连同手算与改错约6—8小时。请在运行前画步骤，不只复制输出。

## 5.1 为什么一份程序需要不同路线

假设你规定每天学习至少30分钟，达到目标显示“完成”，否则显示“继续”。同一份程序要根据minutes的当前值选一句话，不能同时把两句都当最终结论输出。

再假设你要统计七天数据。重复粘贴七段相同代码容易漏改，也不容易扩展到30天。循环让程序按明确规则重复步骤。

本章只引入两类变化：条件决定“接下来走哪条路”，循环决定“是否再做一轮”。每次选择和重复仍要遵守清楚的执行顺序。

## 5.2 准备与完整的分支程序

在Ubuntu Bash执行：

```bash
mkdir -p ~/os-lab/lesson05
cd ~/os-lab/lesson05
```

**完整程序：branch.c**

```c
#include <stdio.h>

int main(void) {
    int minutes = 35;
    if (minutes >= 30) {
        printf("goal reached\n");
    } else {
        printf("keep going\n");
    }
    printf("checked=%d\n", minutes);
    return 0;
}
```

保存后编译运行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -g branch.c -o branch
./branch
```

预期先显示goal reached，再显示checked=35。把minutes改为20并重新编译，应先显示keep going，再显示checked=20。

最后一条printf位于整个if/else后面，无论选哪条分支，正常走完后都会继续到它。花括号的位置决定“这条操作是否属于某个分支”，缩进只是帮助人看清。

## 5.3 条件结果从哪里来

`minutes >= 30` 是比较表达式。minutes为35时结果真，为20时结果假。C中的关系与相等比较产生int结果：真为1，假为0。用于条件判断时，0视为假，非零视为真。

常见运算：`<`小于，`<=`小于等于，`>`大于，`>=`大于等于，`==`相等，`!=`不等。注意 `=` 是赋值，不是相等判断。

在本例中 `minutes >= 30` 不会增加或减少minutes。它读取当前值，产生判断结果。若把它写成 `minutes = 30`，不仅检查含义变了，还会修改变量，并把赋值结果用于判断。不要靠“输出看起来合理”忽略这个错误。

| minutes | `minutes >= 30` | 选中分支 |
| --- | --- | --- |
| 0 | 假 | else |
| 29 | 假 | else |
| 30 | 真 | if |
| 31 | 真 | if |

30这个边界很重要：规则说“至少”，就包含30；如果规则是“超过”，应使用大于而不包含30。

## 5.4 三条以上路线：else if的顺序

**完整程序：levels.c**

```c
#include <stdio.h>

int main(void) {
    int minutes = 70;
    if (minutes >= 60) {
        printf("long session\n");
    } else if (minutes >= 30) {
        printf("regular session\n");
    } else {
        printf("short session\n");
    }
    return 0;
}
```

程序从上往下判断，选中第一条成立的分支后，跳过这一串中的后续分支。70同时满足至少60和至少30，但本程序只输出long session。

如果先判断至少30，再在else if判断至少60，那么70已被前一条接走，后面的高档位不会得到机会。这不是编译问题，而是规则顺序问题。

三个独立if与一串if/else if不同：三个if可能分别执行；同一串互斥分支只选择其中一条。先问自己的规则是否互斥，再选结构。

## 5.5 把多个判断连起来

`&&`表示两边都满足，`||`表示至少一边满足，`!`表示把当前真假取反。`minutes >= 0 && minutes <= 60` 表达区间0到60，两端都包含。

不要照搬数学写成 `0 <= minutes <= 60`。C会先算前一比较得到0或1，再拿这个结果与60比较，和你原本的区间意思不同。

&&和||具有短路规则：&&左边假时右边不必再算；||左边真时右边不必再算。例如先确认count不是0，再计算total/count，可以把“不能除零”的前提放在左边。

这不意味着任意函数参数都按你看到的从左到右执行。短路是这些运算符明确规定的行为；初学时把复杂操作拆成语句，不猜其他表达式的执行先后。

## 5.6 for循环先读执行顺序

先看这份完整程序，再拆解每次执行顺序。

**完整程序：repeat.c**

```c
#include <stdio.h>

int main(void) {
    for (int day = 1; day <= 3; day++) {
        printf("day=%d\n", day);
    }
    printf("finished\n");
    return 0;
}
```

运行应输出day=1、day=2、day=3，最后finished，各占一行。不要把括号内的三部分当成“每轮都从头执行一遍”。

执行顺序是：①只初始化一次day=1；②检查day<=3；③真则执行循环体；④执行day++；⑤回到条件检查。条件为假时跳出循环，继续后面的finished。

day++在这里把day增加1。它与day=day+1在这个独立更新位置表达同样意图。此时不把自增塞到其他复杂表达式中，避免混入尚未说明的值与执行顺序问题。

## 5.7 用跟踪表验证“究竟做几次”

| 检查前day | `day <= 3` | 本轮输出 | 更新后day |
| --- | --- | --- | --- |
| 1 | 真 | day=1 | 2 |
| 2 | 真 | day=2 | 3 |
| 3 | 真 | day=3 | 4 |
| 4 | 假 | 不再进入循环体 | 不再执行本轮更新 |

循环体执行3次，但条件检查4次。最后一次检查的意义，就是发现“不应该再做”。

把 `<= 3` 改成 `< 3`，只会输出1和2；把初值改成4且仍判断<=3，循环体执行0次。不要把“出现for就至少执行一次”当成规则。

本例day在for的初始化部分声明，其可见范围覆盖该for语句相关部分，不应在循环外直接使用它。第06章会系统解释作用域。

## 5.8 累计值为什么必须放在循环外

假设每天记录10、20、30分钟，想得到总和。需要一份贯穿多轮的累计状态，从0开始，每轮把新贡献加进去。

**完整程序：sum-days.c**

```c
#include <stdio.h>

int main(void) {
    int total = 0;
    for (int day = 1; day <= 3; day++) {
        int minutes = day * 10;
        total = total + minutes;
        printf("day=%d minutes=%d total=%d\n", day, minutes, total);
    }
    printf("sum=%d\n", total);
    return 0;
}
```

每轮结果应为total=10、30、60，最终sum=60。day*10是为了产生一组简单固定教学数据，不表示真实学习记录总按天数倍增。

若把 `int total = 0;` 放进循环体，每次进入都会重新建立本轮对象并初始化为0，就不再保留前几轮的累计值。你可能看到10、20、30，而不是累计10、30、60。代码能编译，不代表统计口径正确。

## 5.9 把选择和重复组合起来

[完整源码：control.c](示例代码/control.c)

```c
#include <stdio.h>

int main(void) {
    int total = 0;
    for (int day = 1; day <= 7; day++) {
        int minutes = day * 10;
        if (minutes >= 30) { total += minutes; }
    }
    printf("total=%d\n", total);
    return 0;
}
```

在lesson05保存同名文件，编译 `gcc -std=c17 -Wall -Wextra -Wpedantic -g control.c -o control`，再执行 `./control`，应输出total=250。

这里每轮仍然都会推进day；只有累计动作受if控制。第1、2天的10和20不计入，第3—7天计入30+40+50+60+70=250。

| day | minutes | 本轮是否累计 | 轮末total |
| --- | --- | --- | --- |
| 1 | 10 | 否 | 0 |
| 2 | 20 | 否 | 0 |
| 3 | 30 | 是 | 30 |
| 4 | 40 | 是 | 70 |
| 5 | 50 | 是 | 120 |
| 6 | 60 | 是 | 180 |
| 7 | 70 | 是 | 250 |

把>=30改成>30，只去掉30，结果为220；把循环<=7改成<7，少了70，结果为180。两种修改都让总数变小，但原因不同，不能只凭“结果不对”就随机改条件。

## 5.10 while：不知道次数时先检查条件

for适合把初始化、继续条件、更新放在一起；while突出“这个条件仍成立，就继续”。二者都可以表达很多相同流程，不是严格按任务分类的两套能力。

**完整程序：countdown.c**

```c
#include <stdio.h>

int main(void) {
    int left = 3;
    while (left > 0) {
        printf("left=%d\n", left);
        left--;
    }
    printf("done\n");
    return 0;
}
```

预期left=3、2、1，再done。left--把值减1。先检查再执行，所以初值0时不会打印任何left行，只显示done。

如果漏掉left--，条件永远保持真，本例会不停输出。不要真的运行无限输出才理解它；先用表推演并检查“什么操作会让条件最终变假”。不小心运行时可用Ctrl+C中断，再修源码。

## 5.11 do while：为什么会至少执行一次

**完整程序：at-least-once.c**

```c
#include <stdio.h>

int main(void) {
    int count = 0;
    do {
        count++;
    } while (count < 0);
    printf("count=%d\n", count);
    return 0;
}
```

输出count=1。do先执行体，再检查条件。虽然条件count<0并不成立，第一轮仍已发生。末尾while后的分号是这套语法的一部分，不要因为普通while写法不同就删掉。

“至少做一次”有时适合菜单交互，但不能用来解决所有需要重复的任务。确定可以执行0次还是必须执行1次，是选结构前要回答的问题。

## 5.12 break与continue改变哪一段流程

break退出最近一层循环；continue跳过本轮剩余循环体。在for中，continue之后仍会进入更新部分，再检查下一轮条件。

**完整程序：skip-stop.c**

```c
#include <stdio.h>

int main(void) {
    int total = 0;
    for (int day = 1; day <= 7; day++) {
        if (day == 3) {
            continue;
        }
        if (day == 6) {
            break;
        }
        total += day;
        printf("used=%d\n", day);
    }
    printf("total=%d\n", total);
    return 0;
}
```

使用1、2、4、5，最终total=12。day=3跳过本轮的累计和输出，但循环继续；day=6直接结束整个for，7没有机会进入。

在while里，如果更新语句放在continue后，可能总被跳过，导致状态不再变化。因此每次加入continue，都重新核对推进发生在哪里。

## 5.13 嵌套循环先看“谁包着谁”

若外层day从1到2，内层session从1到3，每进入一次外层体，就会完成一遍内层1、2、3。输出组合为(1,1)、(1,2)、(1,3)、(2,1)、(2,2)、(2,3)，共6次。

这不是把两个上限相加成5。两层枚举所有组合时，次数在该固定模型下是2×3。内层break通常只退出内层，不会自动同时退出外层。

实际写嵌套前，先确认数据是否真的有两层关系。初学的七天统计只需一层，不为了练语法而增加没有用途的层次。

## 5.14 空语句、花括号与错误位置

`if (condition);` 中的分号形成一条空语句，可能让后面的代码不再受该条件控制。`for (...);` 也可能让你想重复的语句实际上落在循环后。

正确做法是把受控操作明确放进花括号，即使暂时只有一句。缩进与括号保持一致，不靠屏幕对齐猜代码含义。

另外，终止条件中的<与<=只差一个符号，却可能影响最后一轮。每个循环至少测试0次、1次、普通多次与最后边界，不只测一个“看起来正常”的中间值。

## 5.15 switch和三元表达式放在什么位置

switch可按一个整数类表达式的值选择case，常用于离散选项。case之间如果没有break等控制转移，可能继续执行后面的内容；它不是自动互斥的一串按钮。本批先熟练if，后续遇到实际离散命令解析时再展开switch完整设计。

`condition ? left : right` 根据条件选择一个表达式结果，适合简短取值，不用于替代清楚的多步处理。例如选择较大的两个小整数时可用，但复杂校验仍优先写成容易跟踪的分支。第06章会在函数练习中接触它。

知道还有这些表达方式即可，不必为了“学完整语法列表”在刚理解for时又背一套新规则。
