## 2. 描述符是一张表中的编号

文件描述符不是文件内容，也不是全系统唯一的文件号码。每个进程有自己的描述符表，整数是表的索引。两个不同进程都可能使用3，却引用完全不同的对象。

**打开文件描述**是内核中保存一次打开状态的对象，包含当前位置、访问模式等信息。它与磁盘文件也不同：同一个磁盘文件可以被独立打开多次，得到不同打开状态。

下面是**概念模型**：

```text
进程描述符表           内核打开状态             数据对象
fd 3 ──────────────→ 当前位置=0 ─────────────→ 文件
fd 4 ──────────────↗   （dup得到的另一引用）
```

`dup`得到第二个描述符，但这两个引用可以指向同一个打开状态，所以共享偏移。对同一路径另做一次独立`open`通常得到另一份打开状态，偏移不因此自动共享。

## 3. FILE *在这张图的哪里

`FILE *`指向C库维护的流对象，里面有缓冲、错误标志和底层I/O关联。`int fd`是POSIX描述符。`fopen/fread/fclose`和`open/read/close`是两组不同层次的接口，不能随意把参数互换。

`fclose`会处理流缓冲并关闭关联资源；`close`处理描述符，不替stdio刷新。已有流若还要继续使用，不能偷偷关闭其底层描述符再假装无事发生。本批大多数POSIX实验只用描述符读写，诊断输出才用stderr，减少混用问题。

## 4. 标准输入输出是接线约定

| 描述符 | 名称 | 普通程序怎样使用 |
| --- | --- | --- |
| 0 | 标准输入 | 从这里读取数据 |
| 1 | 标准输出 | 将结果数据写到这里 |
| 2 | 标准错误 | 输出诊断与管理信息 |

终端、文件和管道都可能成为这些编号的目标。程序只需遵守输入输出接口，不必知道自己有没有被另一个程序连接。这正是命令行工具容易组合的原因。

**重定向**就是让某个约定编号指向另一个已打开对象。把1改接到文件以后，目标程序照常写1，内容就进入文件，不需要修改目标程序源码。

## 5. dup与dup2的差别

`dup(oldfd)`复制一个引用，返回新的可用描述符；`dup2(oldfd, newfd)`把指定编号`newfd`接到`oldfd`引用的对象，必要时先关闭原目标。检查返回值失败后不能继续假定接线完成。

不要用`close(1); dup(fd);`模拟`dup2(fd, 1)`：前者把操作拆开，接口意图不直接，复杂程序还可能有其他活动抢先占用编号。`dup2`为指定目标提供一个接口。

如果`oldfd == newfd`且有效，`dup2`可以直接成功。之后清理原描述符时，不能又把这个目标编号关掉。后面的程序会明确检查这个情况。

## 6. 实验：两个编号共享偏移

**完整程序：fd-dup.c**

```c
#include "lab.h"
#include <fcntl.h>

int main(int argc, char *argv[]) {
    if (argc != 2) {
        fprintf(stderr, "usage: %s NEW_FILE\n", argv[0]);
        return 2;
    }
    int first = open(argv[1], O_WRONLY | O_CREAT | O_EXCL, 0666);
    if (first < 0) { die("open new file"); }
    int second = dup(first);
    if (second < 0) {
        perror("dup");
        close(first);
        return 1;
    }
    write_all(first, "A", 1);
    write_all(second, "B", 1);
    off_t position = lseek(first, 0, SEEK_CUR);
    if (position < 0) {
        perror("lseek");
        close(second);
        close(first);
        return 1;
    }
    printf("shared_offset=%ld\n", (long)position);
    int failed = 0;
    if (close(second) < 0) { perror("close second"); failed = 1; }
    if (close(first) < 0) { perror("close first"); failed = 1; }
    return failed;
}
```

编译为`fd-dup`，然后：

```bash
./fd-dup dup-new.txt
cat dup-new.txt
./fd-dup dup-new.txt
echo $?
```

第一次打印`shared_offset=2`，文件内容为`AB`无换行；第二次因文件已存在而失败，原内容保留。`O_CREAT`表示可创建，`O_EXCL`与它组合表示要求原先不存在；`0666`是初始权限请求，实际还受umask等规则影响，第26章详讲。

关键推导是：first写A把同一打开状态的偏移从0移到1；second从这个偏移写B再移到2。不是两个编号分别都从0写。如果后面的`write_all`发生致命错误，程序会终止，由操作系统回收仍打开的描述符；它不是可供大型库复用的精细清理接口。

## 7. fork以后为什么能共用管道

**管道**是内核维护的单向字节流通道，有读端和写端。`pipe(fd)`把两个描述符填入数组：`fd[0]`读、`fd[1]`写。数组下标0/1与它们实际得到的描述符编号是两回事；实际可能是3和4。

先pipe再fork，父子都继承指向这两个端点的描述符引用。这样孩子写入同一个内核管道，父亲才能读取。若两边分别各自pipe，得到的是不同通道，不会因为变量名相同而连通。

## 8. 主线完整程序

[完整源码：pipe-demo.c](示例代码/pipe-demo.c)

```c
#include "lab.h"

int main(void) {
    int fd[2];
    if (pipe(fd) < 0) { die("pipe"); }
    pid_t pid = fork();
    if (pid < 0) { die("fork"); }
    if (pid == 0) {
        close(fd[0]);
        const char text[] = "hello through pipe\n";
        write_all(fd[1], text, sizeof text - 1);
        close(fd[1]);
        _exit(0);
    }
    close(fd[1]);
    char buffer[16];
    for (;;) {
        ssize_t n = read(fd[0], buffer, sizeof buffer);
        if (n < 0 && errno == EINTR) { continue; }
        if (n < 0) { die("read"); }
        if (n == 0) { break; }
        write_all(STDOUT_FILENO, buffer, (size_t)n);
    }
    close(fd[0]);
    return wait_child(pid);
}
```

编译为`pipe-demo`，正常输出`hello through pipe`并退出0。原例把关闭操作写得简短，未逐次报告close失败；本章主要验证端点归属、读循环和等待，不把它称作完备的资源库。

## 9. 把四个引用逐个关掉

| 进程 | 读端fd[0] | 写端fd[1] | 理由 |
| --- | --- | --- | --- |
| 孩子 | 立即关闭 | 写完关闭 | 孩子只生产数据 |
| 父亲 | 读到EOF后关闭 | 立即关闭 | 父亲只消费数据 |

fork后一共有四个描述符引用，两边各两个。关闭父亲自己的写端，不会取消孩子的写端；引用是分别存在的。孩子写完关闭写端并退出后，如果没有其他写端引用，父亲读完缓冲中的所有字节，下一次read才返回0。

“写了一次就应该EOF”是误解。EOF依赖写端全部关闭和已有数据读完，不依赖写调用次数，也不依赖有没有换行。

## 10. 为什么buffer不是字符串

`read(fd, buffer, sizeof buffer)`最多填入16字节，实际返回多少就有多少有效数据；它不自动在后面补`\0`。因此这里用`write_all(..., (size_t)n)`发送明确数量，而不是`printf("%s", buffer)`。

即使孩子一次写了整行，父亲也可能分多次读到。管道是**字节流**，不保存“这次write是一条消息”的边界。对于多行协议，你需要自己累计字节、识别分隔符或长度，第32章网络字节流也会复用这个思想。

## 11. 三种read结果不要混淆

| 返回情况 | 含义 | 本例处理 |
| --- | --- | --- |
| 正数n | 读到n字节 | 只处理这n字节 |
| 0 | 已到输入结束 | 跳出循环 |
| -1且EINTR | 被信号中断 | 重试 |
| -1且其他错误 | 读取失败 | 报错结束 |

阻塞管道暂时为空且仍有写端时，read通常等待；不是自动返回0。因此父亲忘记关闭自己的写端，可能让自己永远等不到EOF：它在等“所有写者关闭”，自己却还持有一个写者引用。

## 12. 不让程序卡住的EOF对照

**非阻塞**表示条件暂未满足时直接返回，而不是停在调用里等待。这个实验只用它观察两种状态，不把它作为所有读写的默认策略。

**完整程序：pipe-eof-probe.c**

```c
#include "lab.h"
#include <fcntl.h>

int main(void) {
    int fd[2];
    if (pipe(fd) < 0) { die("pipe"); }
    int flags = fcntl(fd[0], F_GETFL);
    if (flags < 0) { die("fcntl get"); }
    if (fcntl(fd[0], F_SETFL, flags | O_NONBLOCK) < 0) { die("fcntl set"); }
    char byte;
    ssize_t n = read(fd[0], &byte, 1);
    if (n != -1 || (errno != EAGAIN && errno != EWOULDBLOCK)) {
        fputs("expected temporarily empty pipe\n", stderr);
        close(fd[1]);
        close(fd[0]);
        return 1;
    }
    puts("writer_open=would_block");
    if (close(fd[1]) < 0) { die("close writer"); }
    n = read(fd[0], &byte, 1);
    if (n != 0) {
        fputs("expected EOF\n", stderr);
        close(fd[0]);
        return 1;
    }
    puts("writer_closed=EOF");
    if (close(fd[0]) < 0) { die("close reader"); }
    return 0;
}
```

编译运行后应为`writer_open=would_block`和`writer_closed=EOF`两行。前一次没有数据但还有写者；后一次没有数据也没有写者。这里`flags | O_NONBLOCK`是按位或，保留原有标志并添加一个位；不是逻辑或`||`。

## 13. 管道满了会发生什么

管道容量有限。阻塞写者写到容量不足时可能等待，直到读者消费数据。这种让生产速度受到消费速度约束的现象常叫**背压**。

因此搭两段管道时，应先启动生产者和消费者，再等待它们结束。若先启动生产者并等待它全部结束，才启动消费者，大输出就可能卡住：生产者等空间，父亲等生产者，消费者还没出现。

`PIPE_BUF`约束某些小写入的原子性，主要讨论多个写者的内容是否交错；它不等同于管道总容量，更不保证一次read恰好得到一次write。本课不依赖固定容量数字。

## 14. 读端都关了又怎样

当所有读端关闭后，继续写管道会产生`SIGPIPE`；默认行为通常是终止写者。若程序忽略或处理该信号，write可报告`EPIPE`。第15章再解释信号和等待结果。

这不是“内核把字节默默丢掉还宣布成功”。组合工具时，消费者提前退出可能导致生产者被信号终止，必须根据整体协议解释，而不是只看最后一段的状态猜测所有段都成功。

## 15. 自己实现拒绝覆盖的重定向

**完整程序：redirect-new.c**

```c
#include "lab.h"
#include <fcntl.h>

int main(int argc, char *argv[]) {
    if (argc < 3) {
        fprintf(stderr, "usage: %s NEW_OUTPUT PROGRAM [ARG ...]\n", argv[0]);
        return 2;
    }
    if (fflush(NULL) == EOF) { die("fflush"); }
    pid_t child = fork();
    if (child < 0) { die("fork"); }
    if (child == 0) {
        int fd = open(argv[1], O_WRONLY | O_CREAT | O_EXCL, 0666);
        if (fd < 0) { perror("open new output"); _exit(1); }
        if (dup2(fd, STDOUT_FILENO) < 0) {
            perror("dup2");
            close(fd);
            _exit(1);
        }
        if (fd != STDOUT_FILENO && close(fd) < 0) {
            perror("close original");
            _exit(1);
        }
        execvp(argv[2], &argv[2]);
        perror("execvp");
        _exit(127);
    }
    return wait_child(child);
}
```

编译为`redirect-new`，确保`argv-view`已编译：

```bash
./redirect-new redirected-new.txt ./argv-view demo
cat redirected-new.txt
./redirect-new redirected-new.txt ./argv-view changed
echo $?
```

第一次目标程序的标准输出进入新文件；第二次拒绝覆盖并退出1，原文件内容保留。父进程没有改变自己的1；只有孩子在exec前改接，所以目标继承接线，父亲仍可在原终端管理。

## 16. 重定向成功不等于命令成功

如果新文件成功创建，随后exec失败，文件仍可能留下，甚至为空。程序没有承诺“命令成功才发布文件”，也没有实现第28章要学的持久化协议。

如果要保证旧文件不被覆盖，必须在打开时表达这个要求，不能先用`access`检查不存在、再普通创建：两步之间状态可能变化。本例用`O_CREAT | O_EXCL`把要求交给内核的一次打开操作。

清理时`fd != STDOUT_FILENO`非常关键。若调用前标准输出恰好关闭，open可能直接返回1；dup2(1,1)成功后再无条件close(1)，会把刚接好的输出关掉。

## 17. 常见错误与定位办法

没有EOF：列出每个进程持有的写端引用，不只查看“真正发送数据”的那个进程。

输出乱码：检查是否把read缓冲当成自动终止字符串，是否使用了实际返回数量。

小输入成功、大输入卡住：检查是否在创建消费者以前就等待生产者。

重定向后目标无输出：检查dup2返回值和close是否误关1；目标是否本来只写stderr；新文件是否早已存在。

文件偏移与预测不同：区分dup/fork共享打开状态与两次独立open，不用“文件名相同”代替引用图。

## 18. 练习、提示与参考答案

1. 将pipe-demo的读缓冲改为3字节，完整文字应改变吗？提示：按n字节转发。
2. 父亲保留写端但从不写，孩子退出后一定EOF吗？
3. `read`返回5时，能直接用`%s`打印buffer吗？
4. dup后关闭其中一个编号，另一个是否也立即失效？
5. redirect-new创建文件后目标不存在，为什么可能看到空文件？

参考答案：第一题正文不变，只是可能增加读取次数；第二题不能保证，父亲自己的写端仍在；第三题不能，接口没补终止字符；第四题不会，另一个引用仍有效；第五题创建与程序执行是两个步骤，没有事务式撤销。

动手题：用两个不同的新文件名，各运行一次fd-dup。应分别得到AB，而不是第二个文件接着偏移2写，因为每次open创建了新的打开状态。不要通过删除不确定来源的文件来重复测试，换一个练习文件名即可。
