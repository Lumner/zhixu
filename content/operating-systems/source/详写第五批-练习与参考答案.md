## 2. 题目：先写状态与预期

1. 两个工作者各改不同结果格，main在join以后读，需要仅因此给每格加锁吗？
2. atomic_load后再atomic_store为什么不自动成为原子加一？
3. queue为空、closed=0，消费者该做什么？空且closed=1呢？
4. queue非空但closed=1，消费者应该立刻退出吗？
5. 容量4，head=3、tail=1、count=2，下一次取出后、再放入后分别是什么？
6. 如果第二个消费者创建失败，第一个已在wait，main直接join它能否完成？
7. 同一把锁下count合法且总和正确，能否仅凭这两点证明每项恰好消费一次？
8. 所有线程先低ID锁后高ID锁，为什么无法形成这类获取锁的等待环？

提示：第5题按模4推进索引；第6题寻找能改变等待谓词的人；第7题想想重复一项与漏另一项是否可能抵消总和。

## 3. 参考答案与边界

第一题本例无并发冲突，创建前初始化、工作者独占各自元素、join后读取即可。第二题它是两个原子步骤，中间仍可穿插；用单次读改写或完整锁协议。

第三题等待，wait期间释放锁；空且关闭则结束。第四题先取完剩余数据，只有关闭且读空才退出。

第五题先取后head=0、tail=1、count=1；再放后head=0、tail=2、count=2。head指向下一项读位置，tail指向下一次写位置，不能交换。

第六题不能只join，因为消费者还在等数据或关闭；main应持锁设closed并广播，解锁后join。第七题不能，数量与总和是必要检查但不唯一；配套验证还记录实际取出序列逐项比较。第八题等待边要求编号严格递增，闭环又回原编号不可能。

## 4. 项目需求与不变量

命令格式`./ring-queue [N]`，默认N=20，接受0—10000。main依次生产整数1到N，容量4，两个消费者各自在自己的结果对象里累计项数和总和。结束时main汇总，期望项数N、总和N(N+1)/2。

共享队列包含data、head、tail、count、closed，全部受queue.lock保护。范围不变量是0≤count≤CAPACITY，head/tail保持有效下标。**环形**表示索引到数组末尾后回到0，逻辑队列可以持续使用固定数组，不需要每次搬移全部项目。

closed表示不再接受新任务；pop在关闭以后仍允许取现存数据。它不是强行丢弃，也不是pthread_cancel。所有工作者结束以后才销毁条件变量与mutex。

## 5. 先画状态和责任

| 角色 | 工作 | 什么时候结束 | 谁读它的结果 |
| --- | --- | --- | --- |
| main | 创建消费者，push 1..N，关闭队列，join | 全部回收并校验以后 | 自己汇总 |
| 消费者0 | pop并累计自己的Task | 关闭且队列读空 | main在对应join后 |
| 消费者1 | 同上，使用另一Task | 同上 | main在对应join后 |

同一项只在锁内从队列取出一次；取出的整数副本可以解锁后处理。FIFO保证的是**取出顺序**，两个消费者后续处理完成的先后可以不同。不要把某个消费者必须分到一半任务当作需求，普通调度和mutex没有给出这个承诺。

## 6. 完整项目参考实现

**完整程序：ring-queue.c**

```c
#include "lab.h"
#include <pthread.h>

enum { CAPACITY = 4, CONSUMERS = 2 };
struct Queue {
    int data[CAPACITY];
    int head, tail, count, closed;
    pthread_mutex_t lock;
    pthread_cond_t not_empty, not_full;
};
static struct Queue queue = {
    .lock = PTHREAD_MUTEX_INITIALIZER,
    .not_empty = PTHREAD_COND_INITIALIZER,
    .not_full = PTHREAD_COND_INITIALIZER
};
struct Result { int items; long total; };

static void check_queue(void) {
    if (queue.count < 0 || queue.count > CAPACITY ||
        queue.head < 0 || queue.head >= CAPACITY ||
        queue.tail < 0 || queue.tail >= CAPACITY) {
        fputs("queue invariant broken\n", stderr);
        exit(EXIT_FAILURE);
    }
}
static int push(int value) {
    thread_check(pthread_mutex_lock(&queue.lock), "lock push");
    while (queue.count == CAPACITY && !queue.closed) {
        thread_check(pthread_cond_wait(&queue.not_full, &queue.lock), "wait not full");
    }
    if (queue.closed) {
        thread_check(pthread_mutex_unlock(&queue.lock), "unlock closed push");
        return 0;
    }
    queue.data[queue.tail] = value;
    queue.tail = (queue.tail + 1) % CAPACITY;
    queue.count++;
    check_queue();
    thread_check(pthread_cond_signal(&queue.not_empty), "signal not empty");
    thread_check(pthread_mutex_unlock(&queue.lock), "unlock push");
    return 1;
}
static int pop(int *value) {
    thread_check(pthread_mutex_lock(&queue.lock), "lock pop");
    while (queue.count == 0 && !queue.closed) {
        thread_check(pthread_cond_wait(&queue.not_empty, &queue.lock), "wait not empty");
    }
    if (queue.count == 0) {
        thread_check(pthread_mutex_unlock(&queue.lock), "unlock drained pop");
        return 0;
    }
    *value = queue.data[queue.head];
    queue.head = (queue.head + 1) % CAPACITY;
    queue.count--;
    check_queue();
    thread_check(pthread_cond_signal(&queue.not_full), "signal not full");
    thread_check(pthread_mutex_unlock(&queue.lock), "unlock pop");
    return 1;
}
static void close_queue(void) {
    thread_check(pthread_mutex_lock(&queue.lock), "lock close");
    queue.closed = 1;
    thread_check(pthread_cond_broadcast(&queue.not_empty), "broadcast close empty");
    thread_check(pthread_cond_broadcast(&queue.not_full), "broadcast close full");
    thread_check(pthread_mutex_unlock(&queue.lock), "unlock close");
}
static void *consume(void *arg) {
    struct Result *result = arg;
    int value;
    while (pop(&value)) {
        result->items++;
        result->total += value;
    }
    return NULL;
}
static void destroy_queue(void) {
    thread_check(pthread_cond_destroy(&queue.not_full), "destroy not full");
    thread_check(pthread_cond_destroy(&queue.not_empty), "destroy not empty");
    thread_check(pthread_mutex_destroy(&queue.lock), "destroy lock");
}
int main(int argc, char *argv[]) {
    int n = 20;
    if (argc > 2) {
        fputs("usage: ring-queue [N_0_TO_10000]\n", stderr);
        return 2;
    }
    if (argc == 2) {
        char *end;
        errno = 0;
        long parsed = strtol(argv[1], &end, 10);
        if (errno != 0 || end == argv[1] || *end != '\0' || parsed < 0 || parsed > 10000) {
            fputs("N must be an integer from 0 to 10000\n", stderr);
            return 2;
        }
        n = (int)parsed;
    }
    struct Result results[CONSUMERS] = {{0}};
    pthread_t workers[CONSUMERS];
    int created = 0, failed = 0;
    for (int i = 0; i < CONSUMERS; i++) {
        int code = pthread_create(&workers[i], NULL, consume, &results[i]);
        if (code != 0) {
            fprintf(stderr, "create consumer: %s\n", strerror(code));
            failed = 1;
            break;
        }
        created++;
    }
    if (!failed) {
        for (int value = 1; value <= n; value++) {
            if (!push(value)) {
                fputs("queue closed before production completed\n", stderr);
                failed = 1;
                break;
            }
        }
    }
    close_queue();
    for (int i = 0; i < created; i++) {
        thread_check(pthread_join(workers[i], NULL), "join consumer");
    }
    destroy_queue();
    if (failed) { return 1; }
    int items = 0;
    long total = 0;
    for (int i = 0; i < CONSUMERS; i++) {
        items += results[i].items;
        total += results[i].total;
    }
    printf("items=%d total=%ld\n", items, total);
    long expected = (long)n * (n + 1) / 2;
    if (items != n || total != expected) {
        fputs("final result mismatch\n", stderr);
        return 1;
    }
    return 0;
}
```

初始化中的`.lock = ...`按字段名指定初值；其余静态对象字段零初始化。它是C的结构体初始化语法，不是运行时去复制一把正在使用的锁。enum提供本程序固定整数常量，数组容量在编译时确定。

## 7. 分开理解push、pop和close

push：持锁检查满与关闭；满且未关闭就wait；关闭后拒绝新增；有空位则写tail、环绕、增加count、通知非空、解锁。

pop：空且未关闭就wait；循环结束后count仍为0，说明已经关闭且读空；否则复制head中的值、推进head、减少count、通知非满、解锁。不能先看closed就退，也不能在解锁以后再读可能被重写的数组格。

close：持锁设置持久状态，广播两类条件，解锁。它不等待所有数据处理完；随后join负责确认消费者已经结束。即使关闭发生在某个消费者尚未开始wait以前，消费者稍后也会看见closed，不会把已结束通知错过后一直等。

## 8. 从空队列手算一圈

假设容量4，初始head=tail=count=0。main依次放1、2、3、4，tail依次1、2、3、0，count到4。数组满时head与tail都为0，所以不能只用两者相等来判断空。

消费者取1后head=1、count=3，main就能把5写到tail=0的位置，tail变1，count再到4。此时逻辑次序为2、3、4、5，虽然5在数组第0格。画数组时分别标出物理格子和逻辑顺序，别把显示的下标顺序误当队列顺序。

## 10. 错误输入与创建失败

`./ring-queue -1`、`./ring-queue 10001`、`./ring-queue two`、`./ring-queue 2x`应拒绝并退出2。数字转换采用此前的strtol协议，接受其允许的前导空白或正号，但必须完整转换且位于范围内，不声称自己实现了另一套严格字符语法。

创建消费者以前没有生产数据。若第一个创建失败，关闭空队列并销毁；若第二个失败，第一位可能正在等not_empty，关闭广播使它退出，join以后再销毁。不要改成只join，也不要销毁仍被使用的mutex。

运行期间lock/wait等出现不可恢复错误仍采用thread_check的“结束整个实验进程”策略；本项目细致处理的是**创建一半失败**和正常关闭，不宣称支持任意线程崩溃后的继续服务。

## 11. 验证为什么要超过总和

数量N和总和N(N+1)/2能发现许多错误，但不能唯一确定实际数据序列。配套脚本另外生成测试专用跟踪版本，在**锁内取出位置**记录每个值，比较是否恰好为1..N，检查FIFO、不重复、不遗漏。

测试还将容量改为1与7，保留同样的接口与协议；模拟wait在谓词未变时返回；定点让第1或第2次create失败；在已有消费者确实进入等待路径后再触发第2次失败，检查关闭、join与销毁。

这些测试辅助代码只在临时目录编译，不加入普通使用输出，不修改系统资源上限。实际通过范围见[验证记录](验证/验证记录.md)，不能把重复测试当作穷尽所有线程交错的证明。
