# 17 指令编码与机器码

## 17.1 从助记符再往下看一层

前面用add、lw、beq描述动作，汇编器替我们生成机器指令。本章反过来问：CPU拿到一串0和1，怎样知道动作、寄存器与常数？

先修是二进制、十六进制、补码、寄存器编号及分支。学完应能手工编码和解码addi，区分R/I/S/B/U/J字段，解释负偏移的拆分，并把机器字转换成小端字节。主线RV32I，不启用16位压缩指令。

建议五次小课：17.2—17.5认识字段；17.6—17.8做整数指令；17.9—17.12做访存与分支；最后两次做跳转、字节序、工具核对。第一次不要求背完整opcode表，先会按给定规则摆位、取位和交叉检查。

## 17.2 32位像一排编号固定的格子

本章机器字有32位，最右最低位叫bit0，最左最高位叫bit31。`[11:7]`表示从bit11到bit7，含两端共5位，不是十进制数11除以7。

**字段**是这排格子中负责同一任务的一组位置。opcode是操作大类；funct3和funct7进一步区分动作；rd是目的寄存器编号，rs1/rs2是源编号；imm保存立即数的编码部分。

每个整数寄存器编号5位，因为2⁵=32，能表示x0—x31。字段中放的是编号，不是寄存器当时保存的数。例如rs1=5表示运行时读x5，不能把“x5当时为7”直接编码为rs1=7。

本章所有十六进制机器字都带0x或明确标注。8个十六进制位正好32bit，每位对应4个二进制位；显示时最左组是高位，不等于最低内存地址处的字节。

## 17.3 常用字段为何保持相同位置

许多格式固定opcode在[6:0]、rs1在[19:15]、rs2在[24:20]、rd在[11:7]，方便译码和读取寄存器。但某格式不需要的寄存器位置会改用于立即数，不能不看格式就把那几位叫rd。

| 格式 | 主要位域，从高到低 | 典型用途 |
| --- | --- | --- |
| R | funct7[31:25]、rs2[24:20]、rs1[19:15]、funct3[14:12]、rd[11:7]、opcode[6:0] | add/sub |
| I | imm[11:0]放[31:20]、rs1、funct3、rd、opcode | addi/lw/jalr |
| S | imm[11:5]放[31:25]、rs2、rs1、funct3、imm[4:0]放[11:7]、opcode | sw |
| B | 分散的分支偏移、rs2、rs1、funct3、opcode | beq |
| U | 高立即数字段[31:12]、rd、opcode | lui/auipc |
| J | 分散的跳转偏移、rd、opcode | jal |

例如S型没有rd，bit11—7是偏移的一部分。若解码脚本机械取这5位得到一个数字，不表示store真的会写那个寄存器。必须结合opcode和具体格式赋予含义。

## 17.4 左移是把一个字段放到指定位置

假设编号5二进制00101，要放进[11:7]，就将它左移7位。5×2⁷=640，十六进制0x280。左移后最低7位都是0，留给其他字段。

多个互不重叠字段用按位OR合并；因为占的位置不重叠，也可以在手算时把对应数值相加。不是对任意两个数都能把加法当OR：一旦位置重叠，加法可能产生进位改变其他字段。

解码做相反动作：先右移让字段最低位落到bit0，再用全1掩码留下需要的宽度。例如rd=`(word右移7) AND 31`。31二进制11111，保留低5位，清除其他位。

## 17.5 先确定指令，再填写字段

本章用到的部分规则如下，不是一张完整ISA表：

| 指令 | opcode | funct3 | 其他条件 |
| --- | --- | --- | --- |
| add | 0x33 | 000 | funct7=0000000 |
| sub | 0x33 | 000 | funct7=0100000 |
| addi | 0x13 | 000 | I型12位有符号立即数 |
| lw | 0x03 | 010 | I型字节偏移 |
| sw | 0x23 | 010 | S型字节偏移 |
| beq | 0x63 | 000 | B型相对偏移 |
| lui | 0x37 | 无此字段用途 | U型高20位 |
| jal | 0x6F | 无此字段用途 | J型相对偏移 |

仅看到opcode=0x33还不够确认add，因为sub等也在同一类。反过来，不能用I型立即数运算的funct7位置来一律限制所有addi：那部分本来就是常数高位。

## 17.6 完整手算：addi x5,x0,7

先把语义写出：从x0读0，加常数7，写x5。字段是imm=7、rs1=0、funct3=0、rd=5、opcode=0x13。

| 字段 | 编码 | 放置后的数值 |
| --- | --- | --- |
| imm[11:0] | 000000000111 | 7左移20 = 0x00700000 |
| rs1 | 00000 | 0 |
| funct3 | 000 | 0 |
| rd | 00101 | 5左移7 = 0x00000280 |
| opcode | 0010011 | 0x00000013 |

合并得0x00700000+0x00000280+0x13=**0x00700293**。这里7的字段是12位，rd的字段是5位，不能因为两个值都小就按相同宽度拼起来。

反向核对：低7位是0x13；bit11—7取出5；bit19—15取出0；bit31—20取出7。因此恢复到addi x5,x0,7。编码后再解码是检查漏位、放错位置的一种方法，但还要用独立工具交叉核对，避免编码和解码共享同一个错误。

## 17.7 add与sub只有部分字段不同

`add x7,x5,x6`中，rd=7、rs1=5、rs2=6，两个功能字段0，opcode=33十六进制。

rs2左移20得00600000，rs1左移15得00028000，rd左移7得00000380，加opcode00000033，合并为**0x006283B3**。

若改sub，寄存器与opcode不变，只把funct7改为0100000，即0x20。它放在[31:25]，贡献0x40000000，得到**0x406283B3**。不是把源寄存器交换，也不是在机器字前写一个文本负号。

## 17.8 负1保存12位补码，不保存32位全文

`addi x5,x5,-1`的立即数字段只有12位。−1在12位补码中为0xFFF，放入[31:20]得到FFF00000；rs1=5贡献28000，rd=5贡献280，opcode13，合并**0xFFF28293**。

解码取出FFF，是4095这个字段的无符号读法；看到字段最高位为1后，按12位补码减4096，恢复−1，再符号扩展用于32位加法。

不要在机器字外再附32个1当立即数，也不要把正4095当addi能直接表示的数。字段位串与它作为有符号数的解释要分开；第11章的−2048至2047边界在这里落到了实际12个格子。

## 17.9 lw与sw：同样算地址，字段安排不同

`lw x7,4(x5)`是I型：imm4、rs1=5、funct3=2、rd=7、opcode3。合并0x00400000+0x00028000+0x00002000+0x00000380+3，得**0x0042A383**。

`sw x6,-4(x5)`写内存，没有rd。−4的12位补码为FFC：高7位[11:5]=1111111，低5位[4:0]=11100。高部分放指令[31:25]，低部分放[11:7]，中间保留rs2=6、rs1=5、funct3=2。

贡献依次FE000000、00600000、00028000、00002000、00000E00、00000023，合并**0xFE62AE23**。解码时把两块立即数拼回FFC，再恢复−4；不能把指令高12位整体当store偏移。

存储宽度4字节来自funct3定义，不是偏移4自动决定了宽度。偏移−4、0、4的sw都写4字节，只是起始地址不同。

## 17.10 分支为什么还有一个隐含0

B型偏移表示相对当前分支PC的字节距离，其最低bit0隐含为0，因此只能编码偶数字节距离。重组后是13位有符号偏移，范围−4096至4094字节。

| 偏移的位 | 在指令中的位置 |
| --- | --- |
| imm[12]，符号位 | bit31 |
| imm[10:5] | bit30—25 |
| imm[4:1] | bit11—8 |
| imm[11] | bit7 |
| imm[0]=0 | 不单独存储 |

本课无C扩展，取指仍要求4字节对齐。能编码偶数偏移不保证跳到PC+2就合法；编码表达范围和当前实现的取指对齐是两个检查。

## 17.11 正8与负8，一正一反检查重组

给beq x0,x0一个+8偏移，imm[4:1]=0100，放到bit11—8贡献0x400，其余偏移位0，加opcode63，得**0x00000463**。条件永真，当前PC=100十六进制时目标108，跳过顺序104那条。

负8的13位补码为0x1FF8：符号1、imm11=1、imm10:5全1、imm4:1=1100。贡献80000000、80、7E000000、C00，加63，得**0xFE000CE3**。

若当前PC=108，偏移−8回100。这里都相对**当前分支自身PC**，不是先PC+4再加偏移。标签由汇编器计算，不建议把“+8”当成所有汇编器源语法都相同的操作数写法；工具夹具使用真实标签。

## 17.12 U与J也要先确认字段含义

`lui x5,0x12345`把20位字段放高部，rd=5，opcode37，机器字**0x123452B7**，运行写入值12345000。机器字末尾2B7不是结果值的一部分，而是rd与opcode编码。

J型jal的偏移位排列为：imm20放bit31，imm10:1放bit30—21，imm11放bit20，imm19:12放bit19—12，最低0隐含。重组为21位有符号字节偏移。

例如`jal x1`跳前方8字节，imm[10:1]=4，左移21得00800000，rd1贡献80，opcode6F，合并**0x008000EF**。目标相对当前PC，链接值另存PC+4；两条计算不能混成同一地址。

第一次先会用+8验证位域，不要求立即手工编码所有J型边界。编写通用汇编器还要检查范围、对齐、重定位等，不是几条移位公式就全部完成。

## 17.13 字段摆位与小端写内存是两步

机器字00700293按bit31到0解释字段；存到小端内存时，从最低字节开始写：93、02、70、00。每个字节内部的bit顺序不反转。

假设指令地址P，P处是93，P+1是02，P+2是70，P+3是00；取回32位机器字时又组成00700293。不要把字节串93027000直接当原来的32位数值，它是另一种显示排列。

如果反转全部32个bit，opcode也被破坏，那不是字节序转换。字节序处理的是多个字节如何对应地址，不是任意反写文本。

## 17.14 用RARS只汇编夹具，独立核对

下载[encoding.s](示例代码/05-datapath/encoding.s)。它是**只用于汇编与导出的编码清单**，没有为lw等准备运行地址，不是完整可运行程序，不能点击Go执行。

将它与JAR放在练习目录，在**PowerShell、该目录**执行：

```powershell
java -jar .\rars1_6.jar nc a dump .text SegmentWindow .\encoding-text.txt .\encoding.s
Get-Content .\encoding-text.txt
```

核对前六条依次00700293、006283B3、406283B3、FFF28293、0042A383、FE62AE23。标签两条分支是相对+8与−8；最后jal标签距离+8。某些Basic列按偏移展示，不必与源标签字面一样。

本批已用官方RARS v1.6只汇编并导出，13条机器字全部与预期一致，见[导出原文](验证/stage5-encoding-text.txt)与[第五阶段验证记录](验证/第五阶段详细版验证记录.md)。这证明汇编器接受这些编码，不表示执行过清单中的所有指令，也不是CPU时序验证。

## 17.15 自测、参考过程与完成条件

先做八题：①寄存器编号为何5位；②rd5放[11:7]贡献多少；③I型负1字段；④sw的[11:7]是不是rd；⑤分支PC100偏移8的目标；⑥jal同样偏移时链接值；⑦机器字00700293的小端字节；⑧li是否各自拥有固定opcode。

参考：①2⁵覆盖32个编号；②0x280；③FFF；④不是，是低立即数；⑤108；⑥104；⑦93 02 70 00；⑧不是，伪指令先展开为基础指令。完成条件：独立手算addi、反解其字段，再用RARS导出核对一条负立即数和一个分支；明确“汇编通过”与“执行通过”。下一章：[18 C语言入门与编译链接](18-C语言入门与编译链接.md)。本章按[RV32I官方原文](https://raw.githubusercontent.com/riscv/riscv-isa-manual/main/src/unpriv/rv32.adoc)核对于2026-11-05。
