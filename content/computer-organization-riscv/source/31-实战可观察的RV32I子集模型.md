# 31 实战：可观察的RV32I子集模型

## 31.1 目标与模型边界

综合指令编码、PC、寄存器和访存，运行一个可逐步检查的软件模型。它直接读取32位机器字，支持37种整数、访存与控制流指令，并把EBREAK作为教学停止标记；不支持ECALL、FENCE、CSR、虚拟内存、流水时序或完整异常处理。

模型是软件写的参考实现，不是HDL电路、官方ISA一致性认证或RARS替代品。零基础学习者可先运行并检查状态，再选读JavaScript源码；不要求从空文件独立写出整套解释器。

## 31.2 怎样运行

电脑需Node.js20或以上。命令行先执行`node --version`，然后在网站项目根目录运行：

```powershell
node content/computer-organization-riscv/source/示例代码/08-mini-rv32/run.cjs
node content/computer-organization-riscv/source/示例代码/verify.cjs
```

下载ZIP后也可在解压目录运行`node 示例代码/08-mini-rv32/run.cjs`。没有第三方依赖，不用npm install。第一条打印机器状态追踪和求和12；第二条运行本地实验检查。源码与入口见[模型说明](示例代码/08-mini-rv32/README.md)。

## 31.3 从零读必要的JavaScript

`const x=3`创建一个名字绑定，`let`允许重新赋值。函数`function add(a,b){return a+b;}`把输入变成返回值。数组`[3,-2,7]`按索引访问，`if`作判断，`while`重复执行。`require('./cpu.cjs')`读取相邻模块，`module.exports`导出功能；这是Node的CommonJS写法。

模型用Uint32Array保存32个寄存器，用DataView读写内存。JavaScript普通Number不等于32位整数，位运算会作32位转换：`x>>>0`取无符号32位解释，`x|0`取有符号32位解释；`>>`符号右移，`>>>`零填充右移。

DataView的`getUint32(address,true)`最后的true表示小端。检查地址和对齐在读写之前完成，不能拿JavaScript数组的越界行为代替CPU规则。

## 31.4 一步执行分成五件事

1. 用PC读取机器字；检查取指对齐与范围。
2. 取opcode、funct和寄存器字段，按格式重组立即数。
3. 读取旧寄存器，算结果/地址/分支目标。
4. 检查支持范围和访问条件，写寄存器或内存；写x0被忽略。
5. 更新PC，返回本步追踪，包括旧PC、机器字、指令名和状态变化。

默认nextPC=PC+4，跳转时覆盖。JALR须先读取旧rs1再写rd，即使rd与rs1相同也不能读到刚覆盖的链接值。无效编码抛出明确模型错误，不当作nop。

## 31.5 求和程序怎样进入模型

程序放地址0，数组放0x100，内存共1024字节。机器字初始化指针x5、剩余数x6、和x10，然后循环beq/lw/add/addi/jal。它只实现第16章的求和核心，不声称也运行完整RARS统计器和打印服务。

五项累计和仍为3、1、8、8、12。退出后x5=0x114，x6=0，x10=12；EBREAK处停止。轨迹计数含停止标记，不拿它冒充某个真实流水处理器的cycle计数。

空数组立即退出、全负数组保持符号解释、达到步数上限会报错，避免错误跳转无限运行。访存越界、非对齐和不支持的指令也分别检查。

## 31.6 改造与练习

练习1：把输入改成`[-5,-2]`。参考：sum=-7，x10无符号显示为4294967289，转有符号后才显示−7；位串应为FFFFFFF9。

练习2：删掉x0保护会怎样？参考：`jal x0,label`本来只跳转，却会改写zero；后续常数和判断可能全部错误。

练习3：模型执行得快，能证明设计的CPU频率高吗？参考：不能，主机解释器时间不等于被模拟硬件时钟。
