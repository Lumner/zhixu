# 示例02：全加器与状态更新

对应第05—08章。在本目录执行`node logic.cjs`，需Node.js20或以上，无第三方依赖。

输出全加器的8种输入、7+1的4位结果8与进位0，以及三次同时更新的状态：A/B依次2/1、3/2、4/3。这里“进位0”不代表4位补码7+1没有溢出。

`add4`把低位进位传给高位，输入用于0—15；`simultaneous`先计算两个next，再统一赋值。它们是逻辑/状态模型，不含晶体管电气行为和真实传播延迟。

总验证入口另外穷举全部256对4位输入，与数学加法交叉核对。回到[第06章](../../06-组合电路加法器与ALU.md)。

## 第二阶段详细版的可选核对

主线仍然是纸笔，不要求先会Node或JavaScript。已经安装Node的读者，可在网站根目录的PowerShell执行：

```powershell
node content/computer-organization-riscv/source/示例代码/02-logic/stage2-lab.cjs
```

如果终端就在本目录，只写`node stage2-lab.cjs`。下载ZIP后，先解压，在解压目录执行`node 示例代码/02-logic/stage2-lab.cjs`。无需npm安装依赖。

[stage2-lab.cjs](stage2-lab.cjs)依次输出MUX选择、译码、5+3逐位进位、3−5逐位计算、四种ALU操作、寄存器状态、13×11、25÷3和浮点字段。

| 部分 | 预期核对点 |
| --- | --- |
| MUX，A=10、B=6 | S=0得10，S=1得6 |
| 译码10₂ | 0、0、1、0，按D0至D3顺序 |
| 4位5+3 | 结果8，最终进位0 |
| 4位3−5 | 原始结果14即1110，按补码为−2 |
| ALU四种选择 | 8、2、1、7 |
| 同时更新A/B | 2/1、3/2、4/3 |
| 13×11 | 累计13、39、39、143 |
| 25÷3 | 商8、余1 |
| 浮点1.5 / 2.5 / −2.5 | 3fc00000 / 40200000 / c0200000 |
| 每步binary32的加法次序 | 左式0，右式1 |

addSub4的trace逐行列bit编号、处理后的B位、Cin、和位与Cout，bit0先计算，最终结果仍按高位到低位解释。divideTrace只接受其教学范围内的无符号、非零除数，不冒充RISC-V M扩展的完整除法环境。

这个软件模型不测量传播延迟，不模拟晶体管、建立保持违例或亚稳态，也不是HDL综合与真机证据。作者验算见[第二阶段详细版验证记录](../../验证/第二阶段详细版验证记录.md)。
