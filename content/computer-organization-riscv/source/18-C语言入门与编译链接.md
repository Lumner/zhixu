# 18 C语言入门与编译、链接

## 18.1 这一章不把C当成你已经会的先修

我们已会汇编，接下来从最小C语法认识另一种表达相同算法的方法。目标是能读懂数组求和函数，自己编译一个完整程序，区分预处理、编译、汇编、链接与运行，并知道目标代码的架构来自哪里。

不要求先学另一门C课。这里不覆盖文件、动态内存等完整C课程内容，只补本课读取编译结果所需基础。建议五次小课：18.2—18.5读语句；18.6—18.10学循环、数组和指针；18.11—18.15运行与分文件；最后两次比较编译产物及目标架构。

纸上阅读无需工具。可选实操使用已有GCC；本机实测GCC 8.1.0、Windows x86-64目标。**本批实际运行的是宿主C程序，未执行RISC-V交叉编译**。看到C结果12不等于已经在RISC-V CPU执行了它。

## 18.2 先读一个变量和一次赋值

**类型**约定数据能表示什么及允许怎样使用。`int`是有符号整数类型；本课RV32 ILP32目标中int为32位，但C标准并不承诺所有平台int都恰好32位。此次宿主GCC的int也为32位，指针宽度却与RV32不同。

下面是放在函数内部的**语法片段**，不是完整程序：

```c
int total = 0;
total = total + 3;
```

第一行声明名为total的变量并初始化为0；第二行读旧total，加3，再写回total。分号结束语句。这里单个`=`是赋值，不是永远保持相等的数学等式；第二行完成后是3，之后不会自动因其他值变化而重算。

变量名是程序里标识对象的名字，不是承诺一定对应某个特定寄存器。编译器可以使用寄存器、栈或在优化后消除多余存储。不能看到total就要求汇编中必须存在同名内存标签。

## 18.3 大括号、注释与函数外形

`{`与`}`把一组语句组成代码块。`//`之后到行末为注释；`/* ... */`也是注释写法。它们帮助读者，不作为运行时算术动作。

一个函数的形状是“返回类型、名字、括号中的参数、函数体”。例如`int twice(int x)`表示名为twice、接受一个int参数x、返回int。

```c
/* 完整函数，但不是完整独立程序。 */
int twice(int x) {
    return x + x;
}
```

`return`结束本次函数并提供返回值。它不像RARS的退出服务10那样结束整个程序；调用者会在调用之后继续。函数调用时写`twice(5)`，把5作为参数值交给这次调用，不要求手写a0和jal，编译器负责按目标ABI安排。

## 18.4 条件判断不要把=与==混淆

`if (条件) { 动作 }`在条件非0时执行动作；可接`else`处理另一条路径。`==`比较是否相等，`<`比较小于，结果用于选择；单个`=`是修改左边对象。

下面仍是函数内片段，假设x已初始化、answer已声明：

```c
if (x < 0) {
    answer = 0;
} else {
    answer = x;
}
```

它对应第13章的两条路径：负数赋0，否则保留。编译器可能用分支，也可能用其他等价实现；C源代码提供语义，不固定唯一机器指令序列。写`if (x = 0)`会先把x改0再判断，这与比较x是否为0完全不同。

## 18.5 完整main与输出

**main**是这里普通宿主程序的入口函数。`int main(void)`中void表示不接收参数，最后`return 0`给运行环境成功状态。不要把main的返回0和程序算出的数组和混为一谈。

`printf`是标准库中的格式化输出函数，需要`#include <stdio.h>`提供声明。格式串`"sum = %d\n"`中的%d在这里输出一个int，反斜杠n输出换行。双引号圈定字符串文本，逗号分隔传入的实参，不是把%d换成寄存器编号。

`#include`由预处理处理，不是CPU运行到这行才去读取头文件。主程序运行需要启动代码、标准库和系统环境；这些步骤由宿主工具链提供，不能拿一个裸函数当成所有环境都能直接运行的完整程序。

## 18.6 把for拆成四个动作

**for循环**括号内用两个分号隔开初始化、条件、更新，后面大括号是体。先初始化一次；每轮先判断；真则执行体、执行更新；再判断；假则跳出。

```c
/* 函数内片段：处理下标0至4。 */
for (int i = 0; i < 5; i = i + 1) {
    total = total + i;
}
```

初始total=0时，体依次用i=0、1、2、3、4，得到10；i=5时条件假，不进体。对应第13章顶部循环，条件6次、体5次。

第一次读代码时先用`i=i+1`，暂不引入容易混淆的新写法。分号与括号不能凭外观省掉；在for右括号之后误加一个分号，可能使循环体成为空语句，后面的块不再是你想重复的动作。

## 18.7 数组声明与下标

`int numbers[5] = {3,-2,7,0,4};`创建五个int并依次初始化。方括号5是元素数量；初始化的大括号列数据，与函数体大括号角色不同。

下标从0起，`numbers[2]`取第三项7，合法下标0—4。`numbers[5]`不因为“数组有5项”而合法。与汇编一样需要尊重对象边界，不能靠相邻内存碰巧可读证明C访问合法。

在本课int为4字节的目标中，第i项地址比第一项多4i字节。C表达式`p[i]`已含元素大小规则，写成`p[i*4]`会再把下标乘4，跳到第4i项，通常不是你想要的访问。

## 18.8 指针声明、取地址与解引用

**指针**保存某个对象的地址。下面是一个函数内片段：

```c
int x = 3;
int *p = &x;
int copy = *p;
*p = 9;
```

`int *p`声明p指向int；`&x`取得x地址；表达式`*p`访问p所指对象。第三行把当时的3复制给copy；第四行通过指针把x改9，copy仍是3。

星号在声明中描述指针类型，在表达式中表示解引用；另一些位置还可表示乘法，要结合上下文。未初始化p就解引用，或者让p指向不再有效的对象，不能被当成正常实验。

`const int *p`表示不能通过p写所指int；不表示p这个局部指针值永远不能改变。const是一种访问约束，不意味着CPU给那片内存自动安装了不可改写硬件。

## 18.9 C中的指针加1与汇编地址加1不同

当p指向int数组的一个元素，`p+1`表示下一项。在本课4字节int目标中，地址前进4字节；汇编`addi t0,t0,1`只加地址数值1。C编译器依据类型完成缩放，不能把两种语言的表面数字直接等同。

只能在同一数组的有效范围与允许的末尾之后位置内作这些指针运算。末尾之后指针可以用于边界判断，但不能解引用成一个额外元素。类型不替你自动发现所有越界，程序仍需给出正确长度。

## 18.10 参数按值传递：指针值也会被复制

完整[pointer-demo.c](示例代码/05-datapath/pointer-demo.c)安排数组[3,4]，main的p指向首项。调用advance_local(p)后，函数把自己的p移到第二项并打印4；回来后main的p仍指首项，打印3。

再调用set_first(p)，函数执行`*p=9`，改的是共享的首元素，所以main看到9。预期三行：inside = 4，after local = 3，after store = 9。

“指针参数按值传递”不代表不能通过它改数据，也不代表函数可以自动改调用者那个指针变量。复制地址值与通过该地址访问对象是两件事，和第12章的地址/内容分界对应。

## 18.11 求和函数逐行读

[sum.c](示例代码/05-datapath/sum.c)包含下面的函数。它是单个翻译单元中的函数定义，需要配套main才能组成这里的完整宿主程序：

```c
int sum(const int *p, int n) {
    int total = 0;
    for (int i = 0; i < n; i = i + 1) {
        total = total + p[i];
    }
    return total;
}
```

p提供首地址、n提供元素数。初始化total与i；每轮先检查i<n，再取第i项加到total；更新i；循环结束返回total。

调用约定前提是0<=n、对应n项可读，所有中间有符号累计值可用int表示。n=0时不执行p[i]，可以不读取任何元素。不要拿第16章汇编统计器的32位回绕承诺替这段有符号C函数补一个未规定的行为。

## 18.12 与熟悉的汇编状态表对应

| C角色 | 默认值/序列 | 一种RV32实现的对应动作 |
| --- | --- | --- |
| p与n参数 | 数组地址、5 | a0/a1等参数位置 |
| total | 0、3、1、8、8、12 | 初始化累计寄存器、add |
| i | 0至5 | 下标初始化、比较、加1 |
| p[i] | 3、−2、7、0、4 | 下标缩放、算地址、lw |
| return total | 12 | 结果放返回位置并返回 |

这是一种语义对应，不保证每行C固定编译成某一条指令。优化后可能改为移动指针、减少局部栈访问，甚至把已知常数计算提前；只要符合语言对有效输入的要求，实现可以不同。

## 18.13 分成三个文件，各自做什么

配套完整求和程序由[sum-main.c](示例代码/05-datapath/sum-main.c)、sum.c与[sum.h](示例代码/05-datapath/sum.h)组成。

main文件包含头文件，创建数组，调用sum并打印。sum.c包含同一头文件并定义函数。sum.h的`int sum(const int *p,int n);`是**声明**，告诉调用处参数与返回类型，末尾只有分号，没有函数体。

头文件开头的ifndef/define和末尾endif用于防止重复包含同一声明区域，是预处理条件，不是运行时if。第一次可先理解其作用，不必自行写复杂宏。`#include "sum.h"`表示包含项目自己的头文件，与标准库stdio.h的尖括号写法用途不同。

如果只编译main文件，编译器有声明能检查调用，但链接时仍需要找到sum的定义。头文件不会凭空制造函数的机器码；把声明复制五遍也不能替代定义。

## 18.14 可选安装与第一次实际编译

若已有gcc命令，无需重装。先在**Windows PowerShell、任意目录**执行`gcc --version`和`gcc -dumpmachine`，记录工具版本与默认目标。本机结果为GCC 8.1.0与x86_64-w64-mingw32，指明生成宿主Windows代码。

若没有命令，可从[GCC官方安装入口](https://gcc.gnu.org/install/)和[MinGW-w64下载说明](https://www.mingw-w64.org/downloads/)了解适合Windows的工具发行方式。不同发行物安装路径不同，不要把作者D盘的路径当成你的必选路径。暂不安装也可先完成语法与纸上追踪。

将本组四个C/头文件复制到自己的练习目录，在**PowerShell、该目录**执行：

```powershell
gcc -std=c17 -Wall -Wextra -Werror -O0 sum.c sum-main.c -o sum-demo.exe
.\sum-demo.exe
gcc -std=c17 -Wall -Wextra -Werror pointer-demo.c -o pointer-demo.exe
.\pointer-demo.exe
```

第一程序预期`sum = 12`并换行，第二程序预期18.10的三行。`-std=c17`选语言版本；Wall/Wextra开启常用警告；Werror让警告也导致构建失败；O0降低优化便于初步观察；小写o指定输出文件。命令本身不能贴进RARS编辑器。

本批在宿主GCC 8.1.0上，求和与指针程序均已分别用O0、O2构建并运行，输出与上述预期一致。分步编译/链接、四组有效求和输入、缺少sum定义的链接失败也已实测；记录见[第五阶段验证](验证/第五阶段详细版验证记录.md)。这与18.18尚未执行的RV32交叉编译分开。

## 18.15 不同错误发生在不同阶段

| 现象 | 通常在哪层 | 先检查 |
| --- | --- | --- |
| gcc不是命令 | 工具准备 | PATH、完整路径、重开终端 |
| 找不到sum.h | 预处理/编译 | 三个文件是否放对位置 |
| expected分号等语法消息 | 编译 | 报错行及前一行的标点/括号 |
| undefined reference to sum | 链接 | 是否提供了sum.c或sum.o的定义 |
| 程序输出旧结果 | 构建/执行选择 | 编译是否成功、运行哪个exe |
| 输出不合题意但能运行 | 程序语义 | 长度、边界、初始化和类型 |

不要在编译失败后继续运行旧exe并把旧输出当成新代码已通过。先检查命令退出状态与消息，再运行本次成功生成的文件。以完整命令、输入和产物名记录过程。

## 18.16 一条构建命令内部也有阶段

工具链大致经历预处理、编译成汇编、汇编成目标文件、链接。预处理处理include等；编译决定怎样实现语言语义；汇编给指令编码；链接组合多个文件、解析符号位置。

```mermaid
flowchart LR
  A[C与头文件] --> B[预处理文本]
  B --> C[目标架构汇编]
  C --> D[带符号与重定位的目标文件]
  D --> E[链接后的程序]
  E --> F[匹配的运行环境加载执行]
```

**符号**可理解为函数或对象等的名字记录；**重定位**记录某些地址还需要在组合文件时补定。目标文件除机器码外还有这些元数据，不能把整个.o逐字节当成从PC开始的指令数组执行。

## 18.17 亲手拆开编译与链接

在**PowerShell、存有sum.c/sum-main.c/sum.h的练习目录**执行，每条输出不同产物：

```powershell
gcc -std=c17 -E sum.c -o sum-preprocessed.i
gcc -std=c17 -O0 -S sum.c -o sum-host-O0.s
gcc -std=c17 -O2 -S sum.c -o sum-host-O2.s
gcc -std=c17 -c sum.c -o sum.o
gcc -std=c17 -c sum-main.c -o sum-main.o
gcc sum.o sum-main.o -o sum-linked.exe
.\sum-linked.exe
```

E停在预处理文本，S停在汇编，c停在目标文件；最后gcc驱动链接器生成exe。上面的.s是**宿主目标汇编**，本机含x86-64指令，不应复制到RARS声称观察RISC-V。

O0与O2可能有不同栈访问、循环与指令数量。先核对目标和有效输入语义，不以文本不一样断定编译器错。局部变量不保证固定驻留栈，优化后的程序也不保证逐行对应原文。

## 18.18 真要生成RV32，需要指定合适的目标工具

**交叉编译**是编译器运行的平台与生成代码的平台不同。安装支持RV32的RISC-V GCC后，才能在其终端使用下面命令。以下为**可选、当前未实测路线**，不是普通宿主gcc一定支持的选项：

```text
riscv64-unknown-elf-gcc -std=c17 -march=rv32i -mabi=ilp32 -O0 -S sum.c -o sum-rv32-O0.s
riscv64-unknown-elf-gcc -std=c17 -march=rv32i -mabi=ilp32 -O2 -S sum.c -o sum-rv32-O2.s
riscv64-unknown-elf-gcc -std=c17 -march=rv32i -mabi=ilp32 -c sum.c -o sum-rv32.o
riscv64-unknown-elf-objdump -dr sum-rv32.o
```

在**工具链自带终端、存有sum.c/sum.h的练习目录**执行，工具前缀以实际安装为准。有些前缀含riscv64的工具链支持RV32，但必须核对配置，不能仅靠名字判断库、链接与运行支持。

march规定允许的指令集，mabi规定数据与调用约定，两者不能互相替代。这里仅观察不依赖stdio的sum函数生成汇编/目标文件；链接带printf的完整RISC-V程序还需要匹配标准库、启动代码与运行环境。本课不会把它混作RARS的打印服务。

## 18.19 不要靠“实际看起来回绕”定义C规则

RV32 add保留低32位；C的有符号int溢出属于未定义行为，优化器可依据语言规则处理，不承诺像汇编一样回绕。测试某个编译器刚好显示负数，也不能把它当成可移植保证。

若需求是模2³²运算，应选明确的无符号32位类型与相应接口，并重新考虑比较与输出，不能仅把本函数的int一处改名就宣称等价。基础C样例只用不溢出的输入；本批不会通过运行未定义行为来“验证一个标准输出”。

同样，数组越界、读取未初始化值、无效指针都不作为“只要没崩溃就正确”的普通实验。C语言对象规则与机器允许某次读写是不同层次。
