# 10 寄存器、指令与程序计数器

## 10.1 从“能运行”到“能解释每一步”

第09章让hello.s显示7。这一章暂时减少打印，把注意力放回机器状态：输入保存在哪里，一条指令先读谁、再写谁，程序又怎样知道下一次执行的位置。

先修是能在RARS中汇编、复位与单步。学完要能按寄存器编号和别名找到同一格；解释三操作数；给五条基础指令填写状态表；从机器指令地址判断普通顺序执行的下一PC。主线仍是RV32I，不启用压缩指令。

建议三次小课：10.2—10.5节练语法与别名；10.6—10.10节追踪完整程序；其余内容用于显示、排错和独立练习。每次45—75分钟，状态表必须自己填一次。

## 10.2 寄存器不是任意长度的便笺

**通用寄存器**是CPU中可被这些整数指令直接指定的数据存储位置。RV32I有x0至x31，每个32位。这里是“32个位置，每个32位”两件事，不是全部加起来只能放32位。

一个32位寄存器可以保存整数编码、地址编码或位掩码；解释取决于接下来使用它的指令。硬件不会给t0永久贴上“有符号整数”的类型。把一个地址打印成十进制整数，只是改变显示解释，不会自动把该地址中的数据取出来。

它和内存也有区别。寄存器用编号选择，内存用字节地址选择。`add`直接指定t0与t1，不需要先给它们计算内存地址；内存里的数据则要用第12章的load取进来。

寄存器数量有限，所以之后长程序要安排哪些值当前放寄存器、哪些保存到内存。现在不需要学习复杂的寄存器分配算法，只需避免把仍要使用的旧值提前覆盖。

## 10.3 x5和t0是同一个位置的两个名字

汇编中可以写x编号，也可以写常用别名。别名来自软件的**应用二进制接口约定，ABI**，帮助不同程序遵守相同使用规则。不是每种用途都有独立额外硬件。

| 编号 | 常用别名 | 当前先认识的用途 |
| --- | --- | --- |
| x0 | zero | 读取恒为0，写入不保存 |
| x1 | ra | 后面函数返回时使用的地址 |
| x2 | sp | 后面栈所在位置的指针 |
| x3 | gp | 全局数据相关约定，当前不改 |
| x4 | tp | 线程相关约定，当前不改 |
| x5、x6、x7 | t0、t1、t2 | 临时计算位置 |
| x8、x9 | s0、s1 | 需遵守保存规则的位置，x8也叫fp |
| x10—x17 | a0—a7 | 参数与返回值等约定，当前也用作RARS服务参数 |
| x18—x27 | s2—s11 | 需遵守保存规则的位置 |
| x28—x31 | t3—t6 | 另外四个临时计算位置 |

例如执行`addi x5,zero,3`后，再读t0就是3；不是x5与t0各有一份3。执行`addi a0,zero,9`后，在x10行观察到9也完全相同。

别名并不连续覆盖所有编号。t0—t2在x5—x7，t3却在x28，而不是x8。初学用上表查，不根据字母后的数字自行推测硬件编号。

第15章会讲临时、参数、保存寄存器之间的协作规则。本阶段是独立main、没有函数调用；示例使用s寄存器用于观察，不能由此推断函数里可以随意覆盖调用者的s寄存器。正式约定可查[psABI整数寄存器表](https://riscv-non-isa.github.io/riscv-elf-psabi-doc/#_integer_register_convention)。

## 10.4 一条三操作数指令怎样读

以`add t2,t0,t1`为例，按“操作、目的、源1、源2”读：把t0与t1的旧值相加，结果写到t2，保留低32位。教材使用箭头表示状态更新：

```text
t2的新值 ← t0的旧值 + t1的旧值（保留32位）
```

箭头不是数学上要求永远相等的等号。执行完之后你继续改变t0，t2不会自动跟着改变。它也不是把三个寄存器全部相加，更不是把结果写进最后的t1。

指令介绍中常见`rd`表示目的寄存器，`rs1`和`rs2`表示两个源。它们是说明位置的代号，不是需要在RARS里输入的新寄存器名。例如`add rd,rs1,rs2`是格式说明，完整程序必须换成t0、a0等实际名字。

源寄存器执行后通常保留原值，但目的与某个源相同时，该位置会被写回覆盖。是否有内存变化，要看指令功能；单独的整数add没有“把结果顺便写回原内存”的动作。

## 10.5 立即数是指令里的常数，不是寄存器编号

**立即数**是直接编码在指令中的一个数。`addi t0,zero,3`读zero的0，与常数3相加，把3写到t0。这里第三个操作数3不是“去读x3”。

对比两个可放进main的片段，假设t1原来是8：

```asm
# 说明性片段，不是独立文件。
addi t0, t1, 3
add  t2, t1, t1
```

第一行得到t0=8+3=11；第二行得到t2=8+8=16。两条都读t1，但一个来源是编码中的数3，一个来源是寄存器里当时的8。

`addi t0,t1,t2`不表示“加第三个寄存器里的数”，而是格式不匹配。想加两个寄存器用add；想加一个可编码的小常数用addi。立即数的范围在第11章详细算。

## 10.6 完整程序：先读旧值，再覆盖

打开配套[register-trace.s](示例代码/03-rars-basics/register-trace.s)。这是完整独立程序，不接受输入，也不打印输出；观察寄存器就是本实验的结果。

```asm
.text
.globl main
main:
    addi t0, zero, 3
    addi t1, zero, 4
    add t0, t0, t1
    add zero, t0, t1
    add a0, t0, t0
    addi a7, zero, 10
    ecall
```

前五条都是真实基础整数指令，没有li这类伪指令，便于观察一条一条的变化。最后两条请求RARS退出。若界面没有显示文字，不要添加打印服务“补救”：本例故意只看内部状态。

先在纸上画t0、t1、a0、zero四列，再汇编并Reset。每执行一条，把当前值填入新行。尚未由程序写入的初值可以记为“原值”；不要自行假定所有启动寄存器都是0。

## 10.7 逐条追踪，不跳过被覆盖的旧值

| 已执行 | 本条先读取什么 | 本条写回什么 | t0 | t1 | a0 | zero |
| --- | --- | --- | --- | --- | --- | --- |
| 第1条addi | zero=0、常数3 | t0=3 | 3 | 原值 | 原值 | 0 |
| 第2条addi | zero=0、常数4 | t1=4 | 3 | 4 | 原值 | 0 |
| 第3条add | 旧t0=3、t1=4 | t0=7 | 7 | 4 | 原值 | 0 |
| 第4条add | t0=7、t1=4 | 试图写zero，结果不保存 | 7 | 4 | 原值 | 0 |
| 第5条add | 两个源都是旧t0=7 | a0=14 | 7 | 4 | 14 | 0 |

第三行目的和源都是t0，不会形成“结果需要先知道结果”的循环。指令先取得旧值3和4，再写7。第五行虽然t0出现两次，但读两次相同的旧7，写到a0的是14。

如果是`add a0,a0,a0`且原a0=6，两个源也都是6，最终12；不是先写一次再把新结果当第二个源，错误地算成18。这个“先读旧状态、后写新状态”的原则与第07章同时更新状态的分析相通。

## 10.8 x0为什么存在，写它到底怎样

zero为常数0提供一个固定来源。`add t0,t1,zero`可把t1的位串复制到t0；`sub t0,zero,t1`可按32位回绕规则计算0减t1。后面会看到汇编器借助它表示常用伪指令。

给x0写非零数不会把它改成“可用的第33个状态”。本例第4条算出了11，但目标zero不保存结果，t0和t1也没有因此改变。

然而“写x0不保存”不能推导成“凡是目的为x0的指令都可以完全忽略”。例如后面的load到zero仍可能做内存访问并产生访问错误。这一章的add没有访存副作用，所以丢弃结果比较简单。看一条指令时要分别问：算了什么、写了哪里、是否还有其他效果。

## 10.9 PC保存的是地址，不是执行条数

**程序计数器，PC**，保存当前指令所在地址，帮助CPU确定取指位置。它是额外的架构状态，不属于x0—x31中的某一行，不能把PC当作x32来写add。

这里未启用16位压缩指令，每条基础指令长32位，即4字节。普通顺序执行后，下一条地址因此是当前地址加4。注意单位：是地址加4字节，不是“增加4个时钟”或“跳过4条指令”。

RARS Default配置中本例第一条在`0x00400000`，前五条如下。这个起始地址是工具配置，不是所有RISC-V机器必须采用的地址。

| 当前要执行的指令 | 当前地址 | 执行后普通顺序的下一地址 |
| --- | --- | --- |
| 第1条addi | 00400000 | 00400004 |
| 第2条addi | 00400004 | 00400008 |
| 第3条add | 00400008 | 0040000C |
| 第4条add | 0040000C | 00400010 |
| 第5条add | 00400010 | 00400014 |

地址列采用十六进制，因此`08+04=0C`，`0C+04=10`。看到10不要按十进制误读成加了4变10的“异常”。

## 10.10 源代码行号为什么不能代替PC

空行、注释、`.text`和标签定义不各占4字节机器指令。源文件即使第5行才出现第一条操作，其机器地址仍由代码布局决定，不是`5×4`。

反方向也不保证一行一条。第11章的`li t0,0x12345abc`在本课RARS中展开成两条基础指令，占两个4字节位置。下一行源代码的地址便前进8，而不是4。单步时两步都可能对应同一条源语句。

正确方法是先Assemble，再看Text Segment中的Address、Basic与Source列：Address定位机器指令；Basic描述展开后的动作；Source帮助找到原文。不是要求现在背机器码，先能把这三个层次分开。

## 10.11 断点暂停在什么位置

**断点**让连续运行在某条指令执行前暂停。在Execute的Text Segment中，给目标行的Bkpt复选框打勾，再用Go运行。按[官方调试说明](https://raw.githubusercontent.com/TheThirdOne/rars/v1.6/src/help/Debugging.html)，可从暂停位置继续Go或单步。

可以在`add a0,t0,t0`上设置断点。暂停时前四条已执行，t0=7、t1=4，而a0还没有由这条指令写成14；再Step一次，才应看到14。

若断点打在退出的ecall上，说明前面的计算都已完成，不代表该ecall也完成了。若高亮与预测差一行，先分清“下一条待执行”与“上一条已执行”，不要立即怀疑CPU计算错。

本课作者的命令行验证可用执行步数上限观察对应前缀，但不等于已经点击了你的图形界面断点。你自己的断点操作仍应保留截图或记录。

## 10.12 同一位串，三种观察

假设t0保存`0xFFFFFFFF`。从位串看是32个1；按32位补码是−1；按无符号是4294967295。这是同一个寄存器状态的不同解释。

如果窗口显示−1，切换十六进制变成FFFFFFFF，期间没有执行指令，状态没有改变。下一章的`slt`与`sltu`会把解释落实为不同运算规则，而不仅仅是显示选项。

寄存器高亮颜色常用于标记刚更新的位置，不是“负数是红色”的ISA规定。界面宽度、行顺序、颜色也不进入程序执行语义。排错时写下寄存器名、位串和解释，证据比“有一格变色了”明确。

## 10.13 a0并不会因为名字特殊就自动输出

本例最后a0=14，却没有打印，因为没有服务号1的ecall。寄存器用途来自程序与环境约定；仅向a0赋值不会触发屏幕事件。

同样，向t0装入一个内存地址并不会自动读取它，向sp写一个数也不等于真的执行了某种高级语言的入栈操作。指令做什么由操作定义，寄存器名字只是参与位置。

程序开始时不该无目的地改gp、tp或sp。它们可能被环境和后续约定使用；当前例子用t寄存器保存临时数即可。函数、栈与返回地址会在第15章从具体调用展开。

## 10.14 可选命令行观察同一实验

将本例与RARS放在自己的练习目录，在**PowerShell、该目录**执行：

```powershell
java -jar .\rars1_6.jar nc sm t0 t1 a0 zero .\register-trace.s
```

运行结束会显示指定寄存器；十六进制应分别为00000007、00000004、0000000E、00000000。这里a0的E就是十进制14，不是14变成了别的值。

想观察执行三条后的状态，在**同一终端、同一目录**执行：

```powershell
java -jar .\rars1_6.jar nc sm 3 t0 t1 .\register-trace.s
```

数字3是本次模拟的最多基础指令步数，达到后停下；应得t0=7、t1=4，并出现步数上限提示。下一次改成5是**从初态重新运行前五条**，不是在刚才的第三条之后接着跑两条。它与图形窗口中的继续单步有区别。

## 10.15 先找第一处偏差，再定位错误

| 偏差 | 常见原因 | 核对办法 |
| --- | --- | --- |
| 第1条t0不是3 | 文件未重汇编、观察错寄存器 | 看Source与x5/t0行 |
| 第3条t0仍是3 | 把高亮的待执行行当成已执行 | 再确认刚完成哪一条 |
| t1意外变7 | 把目的写成t1 | 检查指令第一个操作数 |
| 期待zero=11却仍0 | 没掌握x0规则 | 分开记录计算值与保存值 |
| PC间隔不按源行数变化 | 忽略声明、标签或伪指令 | 以机器指令表为准 |
| a0=14却没输出 | 混淆寄存器与打印服务 | 这是本实验设计，不是运行失败 |

可以把原版复制成自己的实验文件，故意交换第三条的目的和源，再预测新轨迹。不要直接改教材原文件而丢失可对照基线。

## 10.16 独立练习：自己选择保留哪些值

用片段把t0设6、t1设−2，计算`t2=t0+t1`，然后把t0增加1。先写预期：t2是4，t0变7，t1仍−2。写完可放入本例main，保留最后退出两条。

参考片段如下，它需要放在完整程序的代码段与main内：

```asm
addi t0, zero, 6
addi t1, zero, -2
add  t2, t0, t1
addi t0, t0, 1
```

为什么t2没有随着t0变成5？因为第三条已经把当时的4保存，第四条只写t0。若你要最终t2=5，必须再次执行计算；汇编中的寄存器不是自动维护关系的电子表格公式。

## 10.17 自测、答案与完成条件

先回答八题：①x10与a0能保存不同值吗？②t3是x8吗？③`add t0,t0,t1`原值6与−2，结果是什么？④`add a0,a0,a0`原值6，结果是什么？⑤写zero后能读出非零吗？⑥PC=0x100，普通32位顺序指令后的地址是什么？⑦标签占一条指令吗？⑧五条基础指令的模拟步数能直接当芯片五周期吗？
