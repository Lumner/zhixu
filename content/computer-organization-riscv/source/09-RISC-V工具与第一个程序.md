# 09 RISC-V工具与第一个程序

## 9.1 这一章从“怎样打开工具”开始

前八章在纸上追踪数、电路和状态。这一章第一次把步骤写成汇编文件，让模拟器执行。你不需要先会Java、C或命令行；遇到必要操作，我们在这里解释。

学完应能独立完成四件事：找到正确的RARS发行文件；保存并运行一个完整程序；单步核对寄存器；修改输入后重新汇编得到新结果。若还不能解释补码和地址，可先回看[第03章](03-有符号整数补码与溢出.md)与[第04章](04-内存地址字节序与字符编码.md)。

建议分四次学习：先认识工具并准备Java；再打开程序观察各窗口；第三次逐条运行；第四次改造与排错。安装所需时间受网络影响，不以网页标注的阅读分钟为限。本阶段的安排见[第三阶段学习记录](第三阶段-学习记录与验收清单.md)。

## 9.2 RISC-V、RV32I和RARS分别是什么

**指令集架构，ISA**，是软件与处理器之间关于可见行为的约定。例如`add`读哪些寄存器、把结果写到哪里。**RISC-V**是一系列相关指令集的名称，读作“risk five”。它不是本章某个按钮或某一种具体CPU。

本课以**RV32I**为整数主线：RV表示RISC-V；32表示这套基础整数寄存器每个有32位；I表示基础整数指令集。32不是“只有32条指令”，也不是“你的电脑必须安装32位Windows”。宿主电脑可以是64位Windows，模拟的目标仍选RV32。

**RARS**是汇编器与运行模拟器。汇编器把人可读的指令文本转换成机器指令；模拟器在你的电脑上维护目标机器的寄存器、PC和内存，按指令规则改变这些状态。它不会把宿主电脑的处理器改造成RISC-V。

RARS还支持本课暂不用的扩展。工具接受某指令，不等于它属于RV32I。例如`mul`属于M扩展，后面另讲。现在不需要买开发板、搭电路或配置C交叉编译器。

## 9.3 一份文件到屏幕上的7，中间发生什么

先看流程，而不要急着背命令：

```mermaid
flowchart LR
  A[hello.s文本] --> B[汇编器检查语法并生成指令]
  B --> C[模拟器从入口逐条执行]
  C --> D[寄存器保存计算结果]
  D --> E[RARS打印服务显示7]
```

文本写对了才进入执行阶段。拼错寄存器名，通常在汇编阶段报错；服务号写错，可能汇编成功，却在运行时没有预期输出。排错的第一步是分清“尚未生成程序”和“程序已经开始执行”。

保存只是把编辑结果写入文件；汇编才生成当前要执行的指令；运行才改变机器状态。三者不是同一个动作。以后每次改代码，都重新走保存、汇编、运行这一条链。

## 9.4 准备两个工具文件，不先写代码

本章以Windows PowerShell为操作主线，RARS固定用**v1.6**说明。2026-11-05核对了[维护者发布页](https://github.com/TheThirdOne/rars/releases/tag/v1.6)和[项目说明](https://github.com/TheThirdOne/rars)。从该版本Assets下载`rars1_6.jar`；Source code ZIP是源码，不能把它改名为JAR来运行。

JAR是Java程序的打包文件。RARS维护者说明需要Java 8或以上；本课程作者本批命令行检查使用Java 17运行时。**运行时**提供执行Java程序的工具，**JDK**还包含开发Java程序的工具。只运行RARS不要求你学习Java；已有合适的Java也不需要再装一份。

建议建立自己的文件夹，例如`C:\riscv-study`，放RARS与练习文件。教材中的这个路径是示例；若你放在D盘，就把命令中的路径改成实际路径。不要在ZIP内部直接编辑，先解压课程下载包，再复制要练的`.s`文件。

若Java未准备好，可从[Eclipse Adoptium安装说明](https://adoptium.net/installation)选择适合系统的Temurin。Windows通常选与你的机器匹配的架构；x64与ARM64是不同下载。可用安装程序，也可按官方说明解压ZIP后通过完整路径运行。下载入口会更新，以官方页面与你实际下载的版本为准。

## 9.5 第一次打开PowerShell，怎样看目录

PowerShell是一个接收文字命令的终端。Windows开始菜单中搜索PowerShell并打开。提示符可能包含`PS C:\Users\你的名字>`，它说明当前目录；**不要把提示符也复制进命令**。

下面两行在**PowerShell、任意初始目录**执行。先把第一行改为你真正建立的文件夹：

```powershell
Set-Location 'C:\riscv-study'
Get-Location
```

第一行切换当前目录，第二行显示它。路径外的单引号把整条路径当成一个参数，尤其适合路径含空格时。命令不会替你自动建立不存在的文件夹；报“路径不存在”时先在文件资源管理器中建立它，或检查盘符和拼写。

在**同一个PowerShell、当前练习目录**执行：

```powershell
Get-ChildItem
java -version
```

第一行列出当前文件；应能找到`rars1_6.jar`。第二行查看可用Java版本；它不启动RARS。看到版本文字表示命令可用。若提示不认识java，可能未安装，也可能终端没有更新PATH；安装后先关闭再重开终端检查。

**PATH**是系统寻找命令程序的目录清单。初学不必立即修改它。若使用ZIP版Java，找到解压目录中的`bin\java.exe`，可用完整路径执行。例如下方仍在**PowerShell、练习目录**执行，路径必须换成实际存在的路径：

```powershell
& 'C:\riscv-study\java\bin\java.exe' -version
```

`&`让PowerShell执行引号中的程序路径，不是汇编指令，也不用复制到RARS编辑器。后文使用`java`命令；采用完整路径的人，可把每条命令开头的`java`替换成`& '你的路径\bin\java.exe'`。

## 9.6 启动RARS，先确认设置

在**PowerShell、存有JAR的练习目录**执行：

```powershell
java -jar .\rars1_6.jar
```

`-jar`表示执行后面的Java打包程序；`.\`表示当前目录。若文件实际叫别的名字，就使用那个名字；“Unable to access jarfile”先查当前目录与文件名，而不是修改汇编代码。

打开后查看Settings。v1.6本课使用下列设置：RV64模式关闭；允许伪指令与扩展指令格式；不要启用“汇编当前目录全部文件”的选项；内存配置保持Default。建议启用从全局`main`标签开始执行的设置。不同版本名称可能略有变化，结合菜单文字与Help确认，不只按记忆点击位置。

本课示例每个文件都有自己的`main`，它们是**独立程序**。一次只打开和汇编一个实验；把整个目录同时汇编会遇到重复标签，不能通过随意删除别人的`main`解决。

## 9.7 保存第一个完整程序

在RARS中选择File的新建功能，将下方完整内容复制到编辑区，再保存为`hello.s`。`.s`是这里采用的汇编源文件后缀。用文件资源管理器开启“显示文件扩展名”，确认不是`hello.s.txt`。

也可直接在RARS打开配套的[hello.s](示例代码/03-rars-basics/hello.s)。它与下方内容对应，不需要拼接其他代码，也不需要任何键盘输入：

```asm
# RARS RV32: print 3 + 4, then exit.
.text
.globl main
main:
    li t0, 3
    li t1, 4
    add a0, t0, t1
    li a7, 1
    ecall
    li a7, 10
    ecall
```

最后七条缩进行描述执行动作；前面的声明、标签和注释有另外的用途。缩进用于方便阅读，不会凭空增加一次执行。

## 9.8 先读懂标点和每一行的角色

| 写法 | 怎样读 | 是否直接执行一次动作 |
| --- | --- | --- |
| `# ...` | 注释，给读者看的说明 | 否 |
| `.text` | 后面是代码段 | 否 |
| `.globl main` | 声明main可作为全局符号被找到 | 否 |
| `main:` | 给当前位置起名，冒号表示标签定义 | 否 |
| `li t0, 3` | 把常数3装入t0 | 汇编器先展开，执行对应基础指令 |
| `add a0, t0, t1` | 读t0与t1，把和写a0 | 是 |
| `ecall` | 请求当前执行环境提供服务 | 是 |

`li`、`add`这些表示操作的单词叫**助记符**；后面说明操作对象的部分叫**操作数**。`t0`、`t1`、`a0`都是寄存器名，类似机器状态表中不同的格子。逗号分隔操作数，使用英文半角`,`；中文全角逗号`，`不能替代。

`li`中的常数3直接写在文本里；执行后t0里保存3的32位编码。`add`先读取两个源的旧值，再写目的寄存器。两条`li`把3与4准备好，`add`因此把7写入a0。寄存器并不是变量名声明，不需要先写“创建t0”。第10章会完整讲名字与编号。

## 9.9 为什么放到a0里还不够，必须ecall

`add`算出7，只更新寄存器，不负责让Windows屏幕显示字符。程序需要请求RARS的打印服务：先把参数放a0，再把服务号1放a7，然后执行`ecall`。

可把a7理解为本次请求的“服务选择”，a0是这项服务要使用的参数。只执行`li a7,1`是准备请求，不会提前打印；只有`ecall`才真正发出请求。第二次把a7换成10，表示退出，因此第二个`ecall`不会再打印一次7。

| 执行ecall前的a7 | 本课所用RARS服务 | a0在这里怎样使用 |
| --- | --- | --- |
| 1 | 打印有符号整数 | 要显示的整数 |
| 10 | 结束当前程序 | 本例不需要提供参数 |

服务号来自[RARS环境调用表](https://github.com/TheThirdOne/rars/wiki/Environment-Calls)，不是ISA把1永久定义成打印。`ecall`是基础指令；服务编号、参数约定和屏幕输出行为由环境提供。以后在Linux、Ripes或真实开发板上，必须重新核对环境，不能照抄服务号就期待相同结果。

## 9.10 第一次汇编与运行，看三个地方

保存后，通过Run菜单选择Assemble；v1.6常用快捷键F3。汇编成功后进入Execute视图，能看见Text Segment的机器指令表，以及寄存器和数据区。若下方Messages出现错误，先定位报错行，还没有进入正确执行阶段。

先不单步，使用Go运行；常用快捷键F5。观察三处：运行消息是否报告正常结束；Run I/O控制台是否显示`7`；寄存器a0是否保存7。程序没有打印换行，因此终端提示或其他消息紧挨在后面，不代表结果多了一个数字。

**控制台**在这里是程序显示输出的区域；不是PowerShell窗口，也不是汇编错误区。不要把`java -jar ...`贴进RARS编辑器，不要把`.text`当PowerShell命令运行。

若你看到的菜单位置与教材不完全相同，先按功能找Assemble、Go、Step与Reset。快捷键可能被系统或笔记本功能键拦截，菜单功能本身仍可使用。

## 9.11 再来一次，这次先预测再单步

用Reset回到汇编后的初始状态，再选择Step；v1.6常用F7。每按一次推进一条**基础机器指令**，不是保证推进一行源代码。小常数的`li`在本例各展开成一条，因此这次容易一一对应。

下表“执行后”是本条已经完成后的状态；屏幕高亮通常指向**下一条**。若你正在看`add`的高亮行，先问它是待执行还是刚执行，避免差一步。

| 已执行的动作 | 读什么 | 写什么或产生什么效果 | 此时应核对 |
| --- | --- | --- | --- |
| `li t0,3` | 常数3 | t0=3 | t0显示00000003 |
| `li t1,4` | 常数4 | t1=4 | t0仍3、t1变4 |
| `add a0,t0,t1` | 旧t0=3、旧t1=4 | a0=7 | 两个源都保留 |
| `li a7,1` | 常数1 | a7=1 | 控制台仍未打印本次7 |
| 第一个`ecall` | 服务号1与参数7 | 显示7 | 计算与输出发生在不同步骤 |
| `li a7,10` | 常数10 | a7=10 | a0仍保存7 |
| 第二个`ecall` | 服务号10 | 结束程序 | 不再取后续普通指令 |

本表不要求其他寄存器都为0。启动时sp、gp等可能已有环境初值；只观察本程序约定的状态。记录自己的初值，别把每个寄存器的初始化方式推广为ISA规定。

## 9.12 十六进制的FFFFFFFF不是乱码

寄存器窗口可切换数值显示进制。相同位串`00000007`在十进制下是7。把第一条改成`li t0,-2`，第二条改成`li t1,7`，重新汇编后，t0的十六进制为`FFFFFFFE`，a0应为5。

这不是“负数不能保存”，而是第03章的32位补码。显示格式改变不会改变寄存器位串。要确认结果，先说明读的是哪个寄存器、哪一步、哪种显示解释，再比较数字。

再把计算改为`sub a0,t0,t1`，两个输入仍−2与7，预测结果−9，即`FFFFFFF7`。若得到9，常见原因是把两个源交换；若仍得到5，常见原因是还在运行旧的汇编结果。

## 9.13 一条可靠的修改流程

每次只改一个因素，按下面顺序做：记下原始预测 → 修改源文件 → 保存 → Assemble → Reset或确认新初态 → 单步/Go → 写下实际结果。不要同时改输入、指令、模式和内存配置，否则第一处偏差很难定位。

模拟器运行中寄存器里的数字不会因为你在编辑区改了文本而自动重算。Reset用于回到初态，重新汇编用于接纳源文件改动；按顺序操作最容易复现。先不要通过双击寄存器单元格手改状态来“修好”输出，那会绕过你想检查的程序。

建议记录表包括：文件名、RARS版本、RV32设置、输入、预期a0、实际a0、控制台、差异原因。记录的是你实际完成的操作，没运行的格子写“待执行”。作者的验证记录不替代你的学习记录。

## 9.14 可选：不打开图形窗口也能运行

若图形界面不方便，可在**PowerShell、同时存有JAR和hello.s的练习目录**执行：

```powershell
java -jar .\rars1_6.jar nc sm .\hello.s
```

`nc`隐藏启动版权横幅；`sm`要求从全局main开始；最后是要汇编并运行的文件。不加`rv64`，本课使用默认RV32。成功时程序输出7，可能另有正常退出消息。此命令每次都会重新读取并汇编文件。

需要只检查汇编时，在**同一终端、同一目录**执行：

```powershell
java -jar .\rars1_6.jar nc a .\hello.s
```

`a`表示只汇编，所以不应期待打印7。查看当前JAR支持的选项，用`java -jar .\rars1_6.jar h`。更多用法见[官方命令行说明](https://github.com/TheThirdOne/rars/wiki/Using-the-command-line)。命令行通过不等于练过图形界面单步；两种证据分别记录。

## 9.15 出错时，按发生阶段定位

| 现象 | 先检查什么 | 怎样缩小问题 |
| --- | --- | --- |
| java不是命令 | Java是否可用、终端是否重开 | 先单独运行版本检查，或用完整路径 |
| 找不到JAR | 当前目录、后缀、文件名 | Get-ChildItem确认实际文件 |
| duplicate main或重复符号 | 是否启用了目录整体汇编 | 改回只汇编当前独立程序 |
| invalid operand一类错误 | 英文逗号、t0是否误写成to | 回到报错行对照原始hello.s |
| 汇编成功却没有7 | 是否真正Go到打印ecall | 在打印前核对a7=1、a0=7 |
| 改输入后还是旧结果 | 是否保存、重新Assemble | 从新初态单步第一条观察输入 |
| 程序只汇编不执行 | 命令中是否带了a | 区分只汇编与模拟运行 |

不必先重装全部软件。把最小的hello.s恢复到可运行状态，再逐处加回修改，比面对几十行代码同时猜测有效。

## 9.16 自测与参考过程

先回答：①Windows是64位，目标能选RV32吗？②保存是否已经执行？③`li a7,1`之后就会打印吗？④加法的目的寄存器是哪一个？⑤为什么负2显示FFFFFFFE？⑥从3+4改成9−14，应改哪里？⑦`.globl main`会自动执行一次加法吗？⑧命令行a选项没有输出7是否一定失败？

参考：①可以，宿主与目标不同；②没有，仍需汇编和运行；③不会，还要ecall；④`add a0,t0,t1`中的a0；⑤32位补码；⑥两条li设9与14，计算改sub，保存重汇编，结果−5；⑦不会，它是汇编器声明；⑧不一定，a仅汇编，应用退出码和消息判断。

完成条件：自己运行原版7，再运行修改版5与−9；保留输入和结果记录；能说明源码、机器指令、机器状态、输出之间的关系。下一章：[10 寄存器、指令与程序计数器](10-寄存器指令与程序计数器.md)。工具核验日期为2026-11-05，作者本批实际执行范围见[第三阶段验证记录](验证/第三阶段详细版验证记录.md)。
