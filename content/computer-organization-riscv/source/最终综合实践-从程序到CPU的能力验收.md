# 最终综合实践：从程序到CPU的能力验收

完成第32章后使用。交付“代码/机器字、输入、预测、实际结果、解释、待执行项”六部分。可以在普通Markdown文件记录，不要求购买硬件或先学HDL。

## 任务卡与通过条件

| 卡 | 必须产出 | 通过条件 |
| --- | --- | --- |
| 1 数据 | 五项整数的补码、小端字节、地址 | 地址每项加4，−2正确编码 |
| 2 汇编 | 自己改写的stats.s与边界输入 | 默认12/7/3，全负max不为0，空输入不读 |
| 3 调用 | 两层函数调用和栈帧图 | ra正确恢复，s寄存器保持，sp对齐并恢复 |
| 4 编码 | addi/lw/beq各一条字段表 | 能从机器字反向解释，不只贴工具截图 |
| 5 CPU | lw与sw的数据流/控制表 | 地址、内容、读写使能、写回来源清楚 |
| 6 流水 | 至少含ALU依赖、load-use、分支 | 明确模型假设，结果正确，等待与冲刷区分 |
| 7 存储 | Cache逐项追踪与页地址转换 | 参数完整，tag/valid和VPN/offset不混淆 |
| 8 模型 | 本地求和追踪及一个新输入 | x0/PC/访存正确，知道EBREAK简化与范围 |
| 9 系统边界 | 解释RARS打印、陷入、DMA | ISA、ABI、环境和硬件角色分开 |

## 建议的实验输入

默认`[3,-2,7,0,4]`，全负`[-5,-2]`，单个0，长度0，及自己构造的测试。另用`[2147483647,1]`研究32位回绕：求和位串80000000，若按补码显示为−2147483648。这不是数学上精确求和；报告要写明结果语义。

## 报告模板

```text
环境：工具名、版本、RV32/RV64、扩展、操作方式
问题：本次要验证的规则
输入：源码/机器字、数组、长度、缓存参数
预测：手算表与理由
运行：命令或操作步骤、实际输出
解释：对照预测，若不符定位是哪一层
状态：已运行 / 手工推导 / 待执行
```

## 如何复盘

如果只能复制默认代码，选择一项最小修改重做，例如改最大值比较、加负数计数、改Cache块大小。每次修改先写预测，让结果能证伪自己的理解。拿出一个原实现会失败的反例，比多贴十张相同输出截图更有用。

全套正文和本地模型齐备不表示你已完成这些任务，也不表示官方工具、真机或FPGA验证已通过。按自己的证据勾选，后续再把未执行项补齐。
