# 14 数组、指针与字符串

## 14.1 目标与先修

先会load/store和循环。学完能遍历32位数组，比较“下标乘元素宽度”和“直接移动指针”，编写以0结尾的ASCII字节串长度循环。

## 14.2 从一个数走到一排数

数据定义`.word 3,-2,7,0,4`连续放5个32位整数。基址B+0、B+4、B+8、B+12、B+16分别是五项起始地址。访问数组需要额外保存长度，因为内存不会自动在最后一项贴上“结束”标签。

下面是核心片段，完整输入、打印与退出在[sum.s](示例代码/04-rars-programs/sum.s)中：

```asm
la t0, numbers     # 当前地址p
li t1, 5           # 剩余元素数
li t2, 0           # 累计和
loop:
    beq t1, zero, done
    lw t3, 0(t0)
    add t2, t2, t3
    addi t0, t0, 4
    addi t1, t1, -1
    j loop
done:
```

每次先检查是否还有元素，才执行lw。这样长度0不会读取第一项。循环后p=B+20，它指向数组末尾之后的位置；可以用于边界比较，不能据此再加载一个本数组元素。

## 14.3 下标形式也能做到

若i保存在t1，基址在t0，32位元素偏移为i×4，可用`slli t2,t1,2`再`add t2,t0,t2`，最后`lw t3,0(t2)`。

两种写法的本质都是算出字节地址。RV32I基础lw的偏移是常数，不能写`lw t3,t1(t0)`来表示动态寄存器下标，先用add计算地址。

指针本身只是一串地址比特；“每次前进几个字节”由代码决定。高级语言的指针加法会按类型缩放，第18章会解释，这里`addi t0,t0,1`永远只加数值1。

## 14.4 字节串为何用另一个结束规则

RARS可用`.asciz "RISC-V"`保存ASCII字节并追加0。下面计算结束0之前的字节数：

```asm
la t0, message
li t1, 0
scan:
    lbu t2, 0(t0)
    beq t2, zero, end_scan
    addi t1, t1, 1
    addi t0, t0, 1
    j scan
end_scan:
```

结果6。字符串每项1字节，所以指针加1；数组word加4。结束标记0不计入长度。这里数的是字节，UTF-8中文字符可能占多个字节，不能把这个循环称为通用字符计数器。

若输入缺少结束0又没有长度上限，扫描会越过缓冲区。更稳妥的接口同时接收最大可读字节数，先检查边界，再读取。字符串内容中间出现0时，本规则就在该处结束。

## 14.5 完整实验怎样核对

先运行sum.s，预期12；单步观察五个载入值依次3、−2、7、0、4，累计和3、1、8、8、12。再运行[strlen.s](示例代码/04-rars-programs/strlen.s)，预期6。

改动实验：字符串改为空串，预期0；数组长度改为0，预期0且不load。不要只修改长度为6而保留5项数据，这会制造越界读。

## 14.6 错误与练习

常见错误是每次lw后只加1、忘记更新剩余数、把0当数组通用结束标记。数组合法元素可以等于0，本例第四项就是0，不能提前结束。

练习1：数组长度3，循环结束指针是多少？参考：B+12，三次分别读B、B+4、B+8。

练习2：字符`"0"`会触发零结束吗？参考：不会，ASCII数字字符0编码48；字节数值0才结束。

练习3：怎样只统计大于0的元素？参考：加载后用有符号分支跳过<=0的情况，否则计数加1；数组指针和剩余数每轮都更新。
