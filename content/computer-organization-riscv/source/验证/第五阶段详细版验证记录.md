## 工具与执行位置

作者使用本课缓存中的官方RARS v1.6、Temurin Java 17.0.21+9和机器上已有的MinGW-w64 GCC 8.1.0。Java/JAR/编译产物只放课程.cache，不打入source与教材ZIP；未改系统DLL、全局PATH或安装新编译器。

在**Windows PowerShell、网站根目录**执行下方命令，参数应换成自己的真实工具路径。Java运行时与RARS准备步骤见[第09章](../09-RISC-V工具与第一个程序.md)，GCC路线见[第18章](../18-C语言入门与编译链接.md)。

```powershell
node content/computer-organization-riscv/source/验证/verify-stage5.cjs --java 'C:\riscv-study\java\bin\java.exe' --jar 'C:\riscv-study\rars1_6.jar' --gcc 'C:\你的工具目录\bin\gcc.exe'
```

报告中的源码校验值可与当前文件比对。宿主生成的x86-64汇编不能当作RISC-V机器码，也不能复制到RARS作为同一环境程序运行。

## 环境故障与恢复

最初默认沙箱启动旧GCC出现系统DLL映射错误，宿主环境单次求和构建随后成功。首次完整工具验证请求又因自动审批的使用额度限制未执行；这表示审批未能完成，并非判定代码不安全。服务恢复后重新提交同一验证动作并获准，实际完成了上面的36场景。此前“待执行”状态已依据本次真实结果更新，没有绕过审批或补造人工通过记录。

## 未执行项与模型边界

本批未执行RISC-V C交叉编译、RARS图形界面断点/单步、Ripes、HDL、FPGA或真实芯片。命令行通过不等于这些操作也通过。

datapath-lab只支持add/addi/lw/sw/beq，不是完整RV32I。step表示一次架构功能事务，不生成真实时钟、毛刺、建立/保持或trap状态。多周期状态表在纸上推导，脚本仅核对相关数字，没有实现并运行这套多周期硬件。题设延迟与1.43GHz算术结果不是实测物理频率。
