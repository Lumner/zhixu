# 第四阶段详细版验证记录

日期：2026-11-05。本批详细重写第13—16章，配36题逐题解析、18次小课、四项实验和整数统计器。该批次将详细版范围扩展到第01—16章，后续累计状态见[课程导览](../00-整体规划与学习路线.md)。

## 环境与执行方式

实际平台为Windows PowerShell、Node.js v24.15.0作者检查脚本、Temurin Java 17.0.21+9、官方RARS v1.6。继续使用第三批本课程缓存中的隔离工具，没有重新改系统PATH。Java与JAR的来源、SHA-256及缓存边界见[第三阶段记录](第三阶段详细版验证记录.md)。工具二进制不在source内，也不纳入教材ZIP。

每次RARS调用采用RV32（不传rv64）、Default内存、小端、sm全局main入口、允许伪指令，单文件独立汇编。nc隐藏横幅，me分开程序输出与模拟器消息，ae2/se3区分汇编错误与运行错误。普通检查最多10000条基础指令；两个故意不正常返回/推进的故障副本限制100条，避免无限运行。

脚本[verify-stage4.cjs](verify-stage4.cjs)实际通过**58个命名场景、57次RARS调用**。结构化输出、退出码、选定寄存器与九个源文件的SHA-256在[stage4-rars-checks.json](stage4-rars-checks.json)。一个场景可能同时检查多项结果，数量不表示穷举ISA或所有程序输入。

## 实际核对范围

| 范围 | 检查结果 |
| --- | --- |
| branch-demo | 输入−3、0、5，输出0、0、5 |
| range-sum | N=0、1、5、10、1000，和与结束i符合整数计算 |
| sum / sum-index | 长度0、1、3、5，结果、指针终点或下标一致 |
| strlen | ASCII、空串、数字0、中间0、显式UTF-8三字节，长度6/0/1/1/3 |
| bounded-strlen | 无0、首0、中间0、末0、容量外0与容量0，长度及找到标志正确 |
| functions | 输入5、−3、0、7，输出11/−5/1/15，最终sp保持16字节对齐 |
| abi-lab | 输入5与−3，输出101与85；t0=90、s0=123、sp恢复并保持对齐 |
| stats完整main | 输出12/7/3，s0—s3保存12/7/3/1 |
| stats直接调用夹具 | 11组数组，含空、全负、0、单项、重复最大值、混合与正负回绕；核对四返回值、全部s寄存器及sp |
| stats空保护 | 基址0、长度0和−1，不发生无效输入访问错误，返回全0 |

stats夹具采用原文件提取的完整函数，提供自己的main、参数和保存寄存器哨兵，不把另一个重新实现的算法当作受测对象。sum、max与正数个数由独立JavaScript数组演算给出预期；sum按32位截断。非正长度夹具用不可用基址，专门核对判空先于读取。

原示例组04有range-sum、sum、strlen、functions、stats五个程序，本批全部实际执行，并新增branch-demo、sum-index、bounded-strlen、abi-lab四程序，现共九个。第三批示例组03的七程序与40场景是另一份历史结果，不合并计数为本批58场景。

## 故障注入

检查脚本只在本课`.cache/stage4-run/`生成故障副本，不修改source中的正确基线。九种故障均得到预先推导的错误结果或有限步数停机，检查能区分它们与正确期望：

| 故障 | 实际观察 |
| --- | --- |
| 分支汇合前缺j | 正5错误变0 |
| 包含终点被改为提前退出 | N=5只得到10 |
| i不推进 | 达到100条上限 |
| 调用者不恢复t0 | 输出−88而非101 |
| 被调用者不恢复s0 | 输出仍101，但s0变5而非123 |
| 嵌套返回不恢复旧ra | 100条内未正常结束，达到步数上限 |
| max错误初始0 | 全负数组max错误0 |
| 0被错算正数 | 单个0计数错误1 |
| 数组指针不前进 | 正常结束却得到15/3/5而非12/7/3 |

这些是有意损坏后被检测出的行为，不是九个正确功能，也不作为已修复的外部软件缺陷统计。

## 机器表与复现

[stage4-functions-text.txt](stage4-functions-text.txt)是RARS SegmentWindow实际导出，检查了两次jal和ret的jalr展开。各章的分支执行次数、load次数及纸上栈地址表依据明确控制路径推导；本批没有运行GUI逐步录屏，也没有把这些次数换算成芯片周期。

在**PowerShell、网站根目录**运行，参数替换为实际的Java和RARS路径：

```powershell
node content/computer-organization-riscv/source/验证/verify-stage4.cjs --java 'C:\riscv-study\java\bin\java.exe' --jar 'C:\riscv-study\rars1_6.jar'
```

脚本固定同一个v1.6 JAR指纹，更新旁边JSON与机器表。学生日常运行只需各章的Java命令，不要求先会Node。下载包不依赖作者机器的.cache，自己获取工具后可用完整路径指定。

## 未执行与限制

本批实测为官方RARS命令行，不包括图形界面菜单、断点、单步或Reset实际点击；相应操作步骤依据维护者文档编写，学习者须自己完成。未执行Ripes、交叉编译、HDL、FPGA、真实芯片、特权内核或设备I/O。
