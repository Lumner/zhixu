# 32 综合实践与后续学习

## 32.1 目标与交付

本章把“数据 → 汇编 → 机器码 → CPU → 性能 → 系统边界”连成自己的解释。先完成各阶段练习，交付一个可复现的学习报告，而不只是收集截图。详细任务表见[最终综合实践](最终综合实践-从程序到CPU的能力验收.md)。

主输入仍是`[3,-2,7,0,4]`，另加空输入、全负输入和单个0。汇编统计器给出和、最大值、正数个数；教学机器码模型只运行求和核心，两者相同部分交叉核对。

## 32.2 第一层：解释数据与程序

写出每个数的32位补码、小端四字节、元素地址；手动跟踪sum/max/positive。说明为什么max从首项初始化、空输入为什么需要存在标志、为什么数组遇到0不结束。

运行RARS时记录版本、模式、源码、输出及关键寄存器；尚未运行就保留为待执行。用新的数组预测再运行，不能只提交默认答案12/7/3。

## 32.3 第二层：解释机器怎样执行

选一条addi、一条lw、一条beq，手工写字段和机器字。展示lw的有效地址与加载值不同；展示分支偏移从当前分支PC算起。

为同一组指令画单周期数据路径与五级流水时序，标明转发路径、load-use气泡、分支冲刷；写出你的模型假设。如果用Ripes观察，与手算不同先核对处理器配置和统计边界。

## 32.4 第三层：解释性能与存储

给定IC、CPI、频率，计算总时间，再假设一项优化，用Amdahl定律判断上限。为数组顺序访问建立明确Cache参数：数据容量、块大小、路数、初始状态、基址对齐和读写策略，然后逐项写hit/miss。

例如64 B数据、16 B块、直接映射、初始空、基址0x100，五项地址0x100、104、108、10C、110：首次访问两块，得到2 miss、3 hit。若重复扫描且没有其他干扰，第二遍五次都可命中。给定程序包含代码取指和其他数据时，结果还取决于缓存是否分离等条件，不能直接照搬。

## 32.5 第四层：说明模型没覆盖的系统问题

教学模型没有页表、设备、特权级或真正trap处理，EBREAK被简化为停止。解释若把它发展成完整系统，需要补哪些机制：异常现场、权限、地址转换、环境服务、设备协议和验证。

软件参考模型可以检查状态语义，HDL时序模型还要验证时钟、复位、停顿、冲刷与信号稳定。两者各有用途，不能用一份Node输出替代芯片验证。

## 32.6 答辩题与参考方向

题1：为什么32位寄存器装的数不一定是整数？参考：它也可装地址、掩码或浮点编码等比特；指令与约定决定含义。

题2：为什么更高GHz不保证程序更快？参考：执行时间同时取决于指令数、CPI和频率，还有完整任务的等待部分。

题3：为什么TLB miss不是Cache miss？参考：前者缺翻译，后者缺数据/指令块；查表成功也不一定缺页。

题4：为什么把RARS的ecall原样放Linux可能失败？参考：ISA只定义陷入动作，服务编号和参数属于执行环境接口。

题5：为什么两个相同ISA的CPU能有不同流水级数？参考：ISA规定可观察行为，微架构负责内部实现与性能。

## 32.7 下一步怎么学

若仍容易混淆地址与内容，回到第04、12、14章做字节表与单步；若会写汇编却看不懂CPU，回到第06、07、19、20章画状态更新；若性能题常错，先检查单位与题目假设。

继续操作系统可从异常、页表、调度和进程进入；继续C语言可系统学习类型、对象生命周期、指针和编译；继续数字设计可学习Verilog/SystemVerilog、仿真、时序约束和FPGA；继续体系结构可学习多级Cache、多核一致性、乱序与向量。每条路线可作为独立课程并行建设，不必先重排本课32章。

最后完成[第八阶段练习](第八阶段-练习与参考答案.md)，再查[术语与指令速查](附录-术语与RV32I指令速查.md)。把“能解释、能预测、能运行、能改错”作为完成标准。
