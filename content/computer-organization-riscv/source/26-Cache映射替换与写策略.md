# 26 Cache映射、替换与写策略

## 26.1 目标与假设

会算二进制地址和AMAT。本章从直接映射算到组相联，再讨论替换与写策略。基础例题：32位字节地址，数据容量64 B，块16 B，直接映射，初始全部无效；容量不含tag、valid等元数据，只统计读访问。

## 26.2 地址拆成tag、index、offset

块内有16字节，offset需4位；64/16=4行，index需2位；余下32−4−2=26位为tag。

```text
块号   = floor(地址 / 16)
index  = 块号 mod 4
tag    = floor(块号 / 4)
offset = 地址 mod 16
```

访问`0x00000024`即十进制36：块号2，index=2，tag=0，offset=4。Cache先定位第2行，再检查valid与tag；仅index匹配不够，因为许多不同块映射到同一行。

## 26.3 一步一步算命中

| 字节地址 | 块号 | 行号 | tag | 结果与更新 |
| --- | --- | --- | --- | --- |
| 0 | 0 | 0 | 0 | miss，行0装块0 |
| 4 | 0 | 0 | 0 | hit，同块 |
| 16 | 1 | 1 | 0 | miss，行1装块1 |
| 0 | 0 | 0 | 0 | hit |
| 64 | 4 | 0 | 1 | miss，行0被块4替换 |
| 0 | 0 | 0 | 0 | miss，重新装块0 |

共2 hit、4 miss，命中率1/3。最后一次不是首次访问引起的强制缺失，而是映射冲突。容量仍空着的其他行不能容纳这两个互相冲突的块，因为直接映射规定了位置。

可运行[cache.cjs](示例代码/07-cache/cache.cjs)，输出逐步映射和结果；它只模拟这里的读缓存，不模拟写回或真实硬件时序。

## 26.4 组相联与替换

2路组相联、相同64 B数据容量和16 B块时，共2组，每组2路。offset仍4位，组index为1位，tag为27位。块0和块4都映射组0，但可同时占两路。

LRU选择最近最少使用的路，FIFO按进入先后，随机策略随机选择。组中有无效路时通常先填无效路。全相联只有一组，任何块可放任意行，减少部分冲突但比较硬件更复杂。

强制缺失来自首次触及块；容量缺失来自工作集超过容量；冲突缺失来自有限映射位置。区分原因需要对照同容量全相联等模型，不能仅看一次miss就随口分类。

## 26.5 写策略分两条维度

写直达write-through：写命中时同时向下层传播；写回write-back：先改Cache并置dirty，驱逐脏块时写下层。写回减少部分流量，但要管理dirty和一致性。

写分配write-allocate：写缺失时先调入块再写；不写分配no-write-allocate：写缺失绕过本级。前一组讨论“命中时怎样写”，后一组讨论“缺失时是否装入”，两组不是同义词。

多核还需缓存一致性协议；一致性不等于语言层并发正确，也不代替内存顺序规则，本课先建立单核基础。

## 26.6 练习与错误

练习1：数据容量256 B、块16 B、4路组相联，多少组、各字段几位？参考：256/(16×4)=4组，offset4、index2、tag26，32位地址假设不变。

练习2：块变大命中率必然提高吗？参考：不必；同容量下行数减少，冲突或容量行为可能变差，缺失传输成本也改变。

练习3：写回Cache的dirty=0表示无效吗？参考：不是。valid表示是否有有效内容，dirty表示是否修改且尚未写下层。
