# 09 RISC-V工具与第一个程序

## 9.1 目标、先修与工具选择

先理解比特、补码、地址和寄存器。学完能打开汇编文件、汇编运行、单步看寄存器，并知道模拟器做了什么。使用RARS的32位模式；它模拟RISC-V，不会把电脑本身变成RISC-V处理器。

RV32I中的32表示通用寄存器宽度，I表示基础整数指令集。RARS支持的范围更大，本课先自觉限制为RV32I。`mul`等扩展指令暂不使用。

## 9.2 第一次安装与打开

1. 从维护者的[RARS发布页](https://github.com/TheThirdOne/rars/releases)获取稳定版可执行JAR，不选源码ZIP当程序。记录实际版本；本课按v1.6所用的通用功能编写。
2. RARS维护者说明需要Java 8或以上。若命令行执行`java -version`提示找不到命令，先从可信JDK发行方获取适合系统的Java，安装后重开终端。无需为阅读网页安装Java。
3. 在保存JAR的目录打开终端，使用下方命令。文件名不同就替换文件名，带空格的路径加引号。

```powershell
java -jar rars1_6.jar
```

4. 新建文件，保存为`hello.s`，确认不是`hello.s.txt`。在Settings中确认没有启用64位模式，允许伪指令。入门时一次只打开和汇编当前例子。
5. 点击汇编/Assemble（常见快捷键F3），再运行/Go（常见F5）或单步/Step（常见F7）。界面名称可能随版本变化，找不到时用菜单与帮助，不要只依赖快捷键。

## 9.3 一个完整的RARS程序

可下载[hello.s](示例代码/03-rars-basics/hello.s)。这是完整文件，不需要拼接其他片段。

```asm
.text
.globl main
main:
    li t0, 3
    li t1, 4
    add a0, t0, t1
    li a7, 1
    ecall
    li a7, 10
    ecall
```

`.text`告诉汇编器后面放指令，`.globl`声明全局符号，`main:`是位置标签；它们不是CPU逐条执行的算术指令。`li`是装入常数的伪指令，汇编器可展开为真实指令。`add a0,t0,t1`读两个源寄存器，把和写入目的a0。

RARS约定a7=1时的`ecall`打印a0中的整数，a7=10时退出。输出应为7，末尾没有要求自动换行。`ecall`属于ISA，服务编号1和10属于RARS环境；这段打印方式不能直接当Linux或任意Ripes环境的通用程序。维护者的[环境调用表](https://github.com/TheThirdOne/rars/wiki/Environment-Calls)可核对服务参数。

## 9.4 先预测再单步

| 执行到 | 应观察到的变化 |
| --- | --- |
| 第一条li后 | t0=3 |
| 第二条li后 | t1=4 |
| add后 | a0=7，t0和t1保留原值 |
| 第一个ecall后 | 控制台显示7 |

可把寄存器显示切换为十六进制/十进制，7分别显示`00000007`和7。观察“源代码行”与“机器指令行”的区别，一个伪指令可能对应多条机器指令。

下一次改代码后重新汇编并复位，再单步；不要在旧程序暂停状态下以为源文件一改机器状态就同步改变。

## 9.5 Ripes什么时候加入

从[Ripes维护者仓库](https://github.com/mortbopet/Ripes)的说明进入官方发布/网页入口。第19章起选择RV32单周期模型，第22章选择明确带转发与冒险处理的五级模型。先学习Editor、Processor、Registers/Memory等视图的用途，不必现在配置C编译器或设备。

RARS重在写程序和调试；Ripes重在观察微架构。移植例子时先核对支持的伪指令、入口、退出服务和处理器设置，不靠同名按钮推断行为。

## 9.6 排错与练习

没有输出：检查是否执行到第一个ecall、a7是否为1、a0是否先写7。汇编失败：检查逗号、寄存器名、全角标点、标签冒号和保存路径。输出旧结果：重新汇编和复位。

练习：把3和4改成−2和7，先预测再运行。参考：a0=5；t0的十六进制是`FFFFFFFE`，不是错误。再把`add`改成`sub a0,t0,t1`，应得−9。

验收：提交程序、工具版本、模式、预测表和实际结果；当前教材的本地模型验证不能代替你自己的RARS运行记录。下一章：[10 寄存器、指令与PC](10-寄存器指令与程序计数器.md)。
