# 10 寄存器、指令与程序计数器

## 10.1 目标与先修

先完成第09章的运行步骤。学完能读懂三操作数语法、区分寄存器编号与别名、用PC跟踪执行位置。实验仍为RV32I，不启用压缩指令扩展。

## 10.2 32个通用寄存器

RV32I有x0—x31共32个32位通用寄存器。名字a0、t0、sp等是ABI约定的别名，不是额外寄存器。

| 编号 | 常用别名 | 暂时怎样用 |
| --- | --- | --- |
| x0 | zero | 读恒为0，写入被忽略 |
| x1 | ra | 函数返回地址 |
| x2 | sp | 栈指针 |
| x3、x4 | gp、tp | 全局/线程相关用途，入门例子不改 |
| x5—x7 | t0—t2 | 临时值 |
| x8、x9 | s0、s1 | 跨函数保存，s0也可作帧指针 |
| x10—x17 | a0—a7 | 函数参数与部分返回值 |
| x18—x27 | s2—s11 | 跨函数保存 |
| x28—x31 | t3—t6 | 临时值 |

硬件不会因为寄存器叫a0就自动打印它；使用环境调用才会请求服务。参数/临时/保存的含义将在第15章作为调用约定训练。

## 10.3 目的在前，源在后

`add x7,x5,x6`的语义是`x7 ← (x5+x6)的低32位`。箭头表示赋值，右边先读旧值，再写左边。不是把三个寄存器相加，也不是把结果写到最后一个参数。

```asm
# 说明性片段：先在RARS的main中设置初值
addi t0, zero, 3
addi t1, zero, 4
add  t0, t0, t1
add  zero, t0, t1
```

第一行t0=3，第二行t1=4，第三行读取旧t0=3和t1=4后把7写回t0，第四行试写zero但不会改变x0。最后t0=7、t1=4、zero=0。

`addi`中的i表示有立即数；立即数是编码在指令中的常数，不是寄存器编号。第三个参数写3意味着数字3，不是x3。

## 10.4 PC告诉CPU下一次从哪取指令

PC是程序计数器，保存当前取指地址；它不属于x0—x31。没有跳转且本课未启用压缩指令时，普通32位指令之后下一PC=当前PC+4，因为一条指令占4字节。

若第一条地址为`0x00400000`，后面依次是`0x00400004`、`0x00400008`。这是RARS常见代码地址示例，不是所有RISC-V机器必须使用的起始地址。

程序的“第几行”和PC不同：标签、注释、空行不占机器指令；一个`li`可能展开两条。跟踪时读汇编器的机器码视图。

## 10.5 ISA状态与调试器显示

同一寄存器`0xFFFFFFFF`显示为有符号−1或无符号4294967295，状态本身没有变化。a0在屏幕上变红/高亮通常表示刚更新，颜色不是ISA状态。

一条指令是否写内存也要明确：`add`只读写寄存器，不会顺便更新保存原数据的内存格。CPU可观察状态包括寄存器、PC和内存等，而界面窗口位置不属于程序语义。

## 10.6 实验与练习

实验：单步上面四条，记录PC、t0、t1、zero。先在纸上预测，再对照工具。若发现步数与源行数不等，检查伪指令展开。

练习1：`add a0,a0,a0`，原a0=6，执行后？参考：读两次旧值6，写12；不是先写一次再读导致18。

练习2：当前PC为`0x100`，普通RV32I指令执行后没有跳转，下一PC？参考：`0x104`。

练习3：x10与a0能分别保存两个不同值吗？参考：不能，是同一寄存器的两个名字。

常见错误是从右向左猜目的寄存器、把PC当计数循环次数的变量、误改gp/tp。下一章：[11 运算、立即数与伪指令](11-整数运算立即数与伪指令.md)。
