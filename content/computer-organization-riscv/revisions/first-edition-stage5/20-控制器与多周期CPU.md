# 20 控制器与多周期CPU

## 20.1 目标与先修

先完成单周期数据通路。本章说明机器字怎样产生控制信号，填写五种指令的控制表，再把一条指令拆成多个周期。目标是理解CPU如何协调部件，而不是背整张opcode表。

## 20.2 控制信号就是部件的开关和选择

RegWrite决定是否写寄存器；ALUSrc决定第二ALU输入是寄存器还是立即数；MemWrite决定是否写数据内存；ResultSrc选择写回ALU结果或内存数据；Branch与比较结果共同决定nextPC。

教学模型的控制表：

| 指令 | RegWrite | ALUSrc | MemWrite | 写回来源 | ALU用途 |
| --- | --- | --- | --- | --- | --- |
| add | 1 | 寄存器 | 0 | ALU | 加法 |
| addi | 1 | 立即数 | 0 | ALU | 加法 |
| lw | 1 | 立即数 | 0 | 内存 | 地址加法 |
| sw | 0 | 立即数 | 1 | 无 | 地址加法 |
| beq | 0 | 寄存器 | 0 | 无 | 比较 |

beq的立即数仍用于分支目标加法器，即使主ALU第二输入来自寄存器。一个信号描述一条路径，不代表其他路径不需要立即数。

## 20.3 指令字段如何产生信号

opcode可先判断load/store/branch/运算大类，再结合funct3/funct7选择宽度、符号行为和具体操作。例如add/sub大类与寄存器字段位置相同，某个高位功能字段区分加减。

控制器不能只看到“看起来像add的opcode”就接受任意funct组合。遇到不支持或非法编码应进入明确异常/错误路径，不默默当nop继续。这也是附带教学模型做严格解码的原因。

单周期控制信号主要由当前指令组合产生；多周期控制还取决于当前状态。

## 20.4 多周期CPU为什么需要中间寄存器

若同一ALU、存储器要被分时复用，可以把lw分成：取指、译码/读寄存器、算地址、读数据、写回。每步一个较短周期，中间结果必须被寄存器保存，否则下一步改变输入后旧结果会丢失。

| 状态 | 动作 | 需保存什么 |
| --- | --- | --- |
| IF | 读取指令，计算顺序地址 | 指令IR、PC相关值 |
| ID | 译码，读源寄存器 | 操作数A/B |
| EX | ALU计算有效地址 | ALUOut |
| MEM | 从数据内存读取 | MDR数据寄存器 |
| WB | MDR写回rd | 更新架构寄存器 |

这只是教学调度，真实设计可不同。sw不需要WB，分支也有不同终止位置，因此多周期CPU中不同指令的CPI可能不同。

## 20.5 比较时间要乘起来

若单周期每条700 ps，多周期周期200 ps，lw用5周期，则lw为1000 ps，反而更慢。若其他指令更少周期、硬件复用节省资源，整体评价仍可能不同。不能只看“时钟更快”或“周期更多”就下结论。

多周期是把一条指令分段串行完成；流水线则让不同指令同时处于不同段，第22章再学。名字都含“阶段”，并不表示相同执行方式。

## 20.6 实验、错误与练习

纸笔把第19章每个部件标上控制信号，然后分别模拟add、lw、sw、beq；只画有数据流过的路径，最后列出真正改变的架构状态。

练习1：lw误选ALU结果写回会怎样？参考：目的寄存器得到有效地址，不是该地址处数据。

练习2：多周期中MDR为何存在？参考：保存上一周期内存输出，让后续写回不依赖内存继续保持同一组合输入。

练习3：把非法指令当nop有什么问题？参考：隐藏程序/解码错误，且不符合相应ISA的异常语义；教学子集也应明确拒绝不支持编码。
