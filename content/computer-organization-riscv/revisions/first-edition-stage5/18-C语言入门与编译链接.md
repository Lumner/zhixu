# 18 C语言入门与编译、链接

## 18.1 目标与先修

会读汇编即可，不要求会C。本章介绍理解编译结果所需的最小C语法，并拆开源文件、汇编、目标文件、链接和加载。本章C是对照语言，不把它变成另一门完整课程。

## 18.2 变量、循环与函数从零读

```c
int sum(const int *p, int n) {
    int total = 0;
    for (int i = 0; i < n; i = i + 1) {
        total = total + p[i];
    }
    return total;
}
```

这是单独函数，不是有操作系统入口的完整程序。int表示整数类型；在本课ILP32目标中int为32位。`total=0`创建并初始化局部变量，分号结束语句，大括号圈定代码块。for依次执行初始化、条件检查、循环体、更新。

`return`返回结果，函数参数p指向整数，n是元素数量。`const int *p`表示不能通过p修改所指的int，不是说指针值永远不能变化。`p[i]`等价于从p指向的数组取第i项；在这里地址偏移是4i字节。

## 18.3 地址、解引用和局部状态

`int x=3; int *p=&x;`中，`&x`取得x的地址，`*p`读写指向的对象。星号在声明中表示指针类型，在表达式中可表示解引用，要根据位置读。

函数参数一般按值传递：函数内部修改自己的指针p，不会直接修改调用者的指针变量；若通过`*p`写数据，则会影响所指对象。局部变量不保证都占栈位置，优化器可能把它们放寄存器或完全消除。

C语言有类型和对象规则。数组越界、访问失效指针、使用未初始化值都不能凭“硬件似乎读到了内容”证明合法。C有符号整数溢出是未定义行为，不能直接假定像RV32I add那样回绕；无符号运算按类型位宽取模。

## 18.4 工具链分成哪几步

```mermaid
flowchart LR
  A[C源文件] --> B[编译得到汇编]
  B --> C[汇编得到目标文件]
  C --> D[链接得到可执行文件]
  D --> E[加载与运行环境]
```

目标文件包含机器码、符号、重定位等信息。链接器把多个文件合并，解析“这个函数究竟在哪个地址”。加载器或裸机启动代码负责把程序安排到可运行环境中。

RARS内的`.word`、打印服务和工程组织不是GCC/Linux完整程序的替代品。编译出了机器码，不表示它已经有栈、标准库、设备或可直接双击运行。

## 18.5 可选的交叉编译观察

交叉编译器在当前电脑运行，生成另一目标架构的代码。仅当你已安装对应工具链时，可保存上面函数为sum.c并执行：

```text
riscv64-unknown-elf-gcc -march=rv32i -mabi=ilp32 -O0 -S sum.c -o sum-O0.s
riscv64-unknown-elf-gcc -march=rv32i -mabi=ilp32 -O2 -S sum.c -o sum-O2.s
riscv64-unknown-elf-gcc -march=rv32i -mabi=ilp32 -c sum.c -o sum.o
riscv64-unknown-elf-objdump -dr sum.o
```

前缀虽含riscv64，有些工具链可生成RV32，但是否有对应库/配置取决于安装版本；本章只要求观察编译/汇编，不要求链接运行。`-S`停在汇编，`-c`生成目标文件，`-O2`开启优化。参数含义见[GCC整体选项](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html)和[RISC-V目标选项](https://gcc.gnu.org/onlinedocs/gcc/RISC-V-Options.html)。本环境未执行交叉编译。

## 18.6 实验与练习

纸笔把C循环与第14章汇编一一对应：total对应累计寄存器，p[i]对应地址计算加lw，i<n对应分支，return对应a0返回。优化后可能不再逐行对应，但可观察行为仍需符合语言规则。

练习1：编译器名、`-march`、`-mabi`分别描述什么？参考：工具系列/目标配置、允许的ISA、二进制调用与数据约定，三者不能互相替代。

练习2：`int *p`在本课RV32 ILP32占几字节？参考：指针4字节；p指向的数组可以远大于4字节。

练习3：把O0与O2汇编不同判定为编译错误合理吗？参考：不合理，优化可改变实现；需比较规定输入下的语义。
