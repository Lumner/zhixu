# 17 指令编码与机器码

## 17.1 目标与先修

会读RV32I算术、访存、分支。本章把可读指令变成32位机器字，理解R/I/S/B/U/J格式，并说明机器字在小端内存中的排列。本章不启用C压缩扩展。

## 17.2 字段怎样分工

一个32位机器字用不同位置描述操作和参数。opcode用于大类，funct3/funct7进一步区分；rd表示目的寄存器编号，rs1/rs2表示源编号，每个寄存器字段5位，足够编码32个编号。

| 格式 | 从bit31到bit0的主要字段 | 典型指令 |
| --- | --- | --- |
| R | funct7 / rs2 / rs1 / funct3 / rd / opcode | add、sub |
| I | imm[11:0] / rs1 / funct3 / rd / opcode | addi、lw、jalr |
| S | imm[11:5] / rs2 / rs1 / funct3 / imm[4:0] / opcode | sw |
| B | 分散的分支立即数 / rs2 / rs1 / funct3 / opcode | beq |
| U | imm[31:12] / rd / opcode | lui、auipc |
| J | 分散的跳转立即数 / rd / opcode | jal |

S型没有rd，因为store写的是内存。B/J立即数不是按高低连续摆放，需要按规范重组。保留多个固定寄存器位置，有利于硬件及时读取寄存器编号。

## 17.3 手工编码addi

编码`addi x5,x0,7`：imm=7，rs1=0，funct3=000，rd=5，opcode二进制0010011即`0x13`。

```text
机器字 = (7<<20) | (0<<15) | (0<<12) | (5<<7) | 0x13
       = 0x00700000 + 0x00000280 + 0x13
       = 0x00700293
```

写到小端内存的四字节是`93 02 70 00`。机器字的字段分布与内存字节顺序是两个步骤，不能把opcode误看成显示串最左边那一组。

再看`add x7,x5,x6`：funct7=0、rs2=6、rs1=5、funct3=0、rd=7、opcode=`0x33`，机器字为`0x006283B3`。

## 17.4 负立即数与分支重组

`addi x5,x5,-1`的12位立即数字段为`0xFFF`，解码时符号扩展恢复−1。整条机器字是`0xFFF28293`。

B型分支偏移由`imm[12]、imm[10:5]、imm[4:1]、imm[11]`散放在指令里，最低bit0隐含0。解码后偏移范围−4096至4094字节，目标=分支自身PC+偏移。未启用C扩展的本课程序还要让目标按4字节对齐。

例如`beq x0,x0,+8`总会跳过下一条4字节指令，编码`0x00000463`。若当前PC=0x100，目标是0x108，不是0x10C。`jal`也相对自身PC计算目标，但链接寄存器保存PC+4。

## 17.5 用解码检查编码

先取机器字低7位`word & 0x7F`得到opcode；再`(word>>7)&31`取rd。这里右移和掩码组合是在取字段，不是对程序数据做算术。

对于I型，取bit31—20后按12位补码解释。不能把所有机器字的高12位都当I型立即数，因为R型那里包含funct7与rs2。

实验：在RARS机器码视图核对上面三条；再运行[数据通路追踪](示例代码/05-datapath/README.md)，用已知机器字而非源代码驱动教学模型。后者验证的是附带模型，不是官方模拟器。

## 17.6 练习与错误

练习1：rd=31需要几位？参考：5位，二进制11111；6位没有必要。

练习2：`0x00700293`的低7位是什么？参考：`0x13`，对应立即数算术类别；还要看funct3确认具体操作。

练习3：为什么不能把所有伪指令都分配一个opcode？参考：它们是汇编层便利写法，可能展开多条真实指令；现有ISA不为每个伪指令单独定义机器编码。

验收：不用汇编器也能手算一条addi，再用工具交叉核对。下一章：[18 C语言与编译链接](18-C语言入门与编译链接.md)。
