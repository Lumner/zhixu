# 03 有符号整数、补码与溢出

## 3.1 目标与先修

先会第02章的位权与固定宽度运算。学完能编码负整数，区分无符号溢出与有符号溢出，说明符号扩展。先用8位演算，再推广到RV32的32位。

## 3.2 同一串比特可以有不同解释

8位`11111111`按无符号解释为255。补码解释给最高位权重−128，其他位仍为64、32、16、8、4、2、1，于是得到−128+127=−1。

| 位串 | 无符号解释 | 8位补码解释 |
| --- | --- | --- |
| 00000000 | 0 | 0 |
| 01111111 | 127 | 127 |
| 10000000 | 128 | −128 |
| 11111111 | 255 | −1 |

比特本身不带“我一定是负数”的标签，指令和数据约定决定解释。n位补码范围为−2^(n−1)到2^(n−1)−1，负数比正数多一个，这是零占用了一个非负模式。

## 3.3 怎样求−5的补码

先写+5的8位表示`00000101`；逐位取反得到`11111010`；再加1得到`11111011`。验证：−128+64+32+16+8+2+1=−5。

另一条路是模256：−5对应256−5=251，即`0xFB`。补码加法保留低8位，等价于以256为模运算。于是5+(-5)得到`00000101 + 11111011 = 1 00000000`，丢掉第9位后为0。硬件可复用同一套加法电路。

最小值−128的8位表示是`10000000`，对它取反加1仍是`10000000`。不是计算规则失效，而是+128超出了8位补码范围。

## 3.4 两种溢出不能混淆

`255+1`按8位无符号运算数学结果256超范围，低8位为0，有最高位进位。`127+1`按补码算，数学结果128超范围，低8位是`10000000`即−128，却没有第9位进位。

因此“有进位”与“有符号溢出”不等价。补码加法中，同号相加而结果异号是溢出信号；异号相加不发生有符号溢出。

RV32I的普通`add/addi/sub`保留低32位，不因有符号溢出自动抛异常。若程序需要检查，必须通过比较等办法自行判断。C语言对有符号溢出的规则不同，第18章会单独解释，不能直接套用硬件回绕。

## 3.5 符号扩展与右移

把8位−5扩成16位时复制最高符号位：`11111111 11111011`，数值仍为−5。若在前面补0，则变成+251。无符号扩宽才通常使用零扩展。

逻辑右移在左边补0：8位`11111000`右移1得到`01111100`，无符号值从248变124。算术右移复制符号位，结果`11111100`，补码值−8变−4。

算术右移对负数相当于向负无穷取整的除以2^k，例如−3算术右移1为−2；许多语言的有符号整数除法向零截断，−3/2会得到−1。这是不同规则，不能把两者永远视作相同。

## 3.6 纸笔实验、错误与练习

先编码−2：`11111110`。再写+7：`00000111`。相加保留8位得到`00000101`即5。用数学−2+7=5交叉验证。若结果错，检查是否忘记加1或误读最高位。

练习1：`0xF0`按8位补码是多少？参考：240−256=−16；也可取反加1得到16，因此原值是−16。

练习2：把8位`0x80`符号扩展到32位。参考：`0xFFFFFF80`，值仍为−128。

练习3：8位`0x80+0x80`，两种解释分别怎样？参考：低8位为0。无符号128+128超出255；补码−128−128超出−128，两者都溢出。这一次有进位且有有符号溢出，但前面例子已证明它们不是同一条件。
