# 13 条件分支与循环

## 13.1 程序不必永远从上往下走

前四章汇编例子大多顺序执行。这一章解决两个新问题：根据一个数选不同动作，以及让同一段指令重复执行。无需先学C语言中的if或while，我们先用中文描述选择与重复，再翻译成指令。

先修是第10章的PC、第11章的有符号解释，以及第09章的运行与单步。学完应能解释六种基本条件分支，画两条执行路径，逐轮计算1到N的和，并用边界输入定位少算一次、漏更新和错误跳转。

建议四次小课：13.2—13.6练选择；13.7—13.10做完整循环；13.11—13.14解释正确性与排错；其余实验和自测。工具仍是RARS v1.6、RV32、Default、允许伪指令，一次只汇编一个独立文件。

## 13.2 条件分支先比较，再决定下一PC

**条件分支**是一条根据比较结果选择下一位置的指令。以`beq t0,t1,equal`为例：若两个源位串相同，下一条从equal标签处执行；否则从这条分支后面的普通下一条执行。

“跳到标签”是改变下一PC，不是把标签文字写到某个数据寄存器，也不是从整个程序重新开始。标签只给一个代码位置命名，CPU运行的是汇编器算出的目标地址。

| 指令格式 | 满足什么条件就跳 | 否则怎样 |
| --- | --- | --- |
| beq rs1,rs2,target | 相等 | 执行紧接的下一条 |
| bne rs1,rs2,target | 不相等 | 同上 |
| blt rs1,rs2,target | 有符号源1小于源2 | 同上 |
| bge rs1,rs2,target | 有符号源1大于等于源2 | 同上 |
| bltu rs1,rs2,target | 无符号源1小于源2 | 同上 |
| bgeu rs1,rs2,target | 无符号源1大于等于源2 | 同上 |

这些指令直接比较两个源，不要求先执行slt，也不依赖某个先前算术指令留下的通用条件标志。本课格式中没有rd，不写普通整数结果，主要效果是选择接下来的执行位置。

## 13.3 先把比较句子说完整

`blt t0,t1,small`读成“若t0小于t1，跳small”，不能只记“小于就跳”而忘了谁与谁比较。设t0=2、t1=5，它跳；交换源后5<2不成立，不跳。

想表达“t0大于t1”可交换源写`blt t1,t0,target`。想表达“t0小于等于0”可写`bge zero,t0,target`：比较的是0>=t0，等价于t0<=0。后面统计器会用到这一形式。

第11章的slt会把比较结果0/1写寄存器，但不改变顺序；blt选择执行路径，但不保存那个0/1。两者都能参与表达条件，当前能直接用分支就不必额外生成一个布尔寄存器。

## 13.4 相等比较与大小比较的解释差别

设t0=FFFFFFFF、t1=00000001。有符号时是−1与1，因此`blt t0,t1,target`跳；无符号时是4294967295与1，因此bltu不跳。寄存器位串没有变化，改变的是比较规则。

beq/bne只比较是否相同，不区分有符号版本；两个FFFFFFFF位串无论怎样解释都相等。用有符号还是无符号大小关系，必须由数据含义决定，不能为了让某次结果“看起来对”随便替换助记符。

如果一个本来表示小范围非负次数的寄存器意外保存−1，使用无符号比较可能把它当成巨大数。这通常是输入、更新或约定出了问题，不是工具要你等待几十亿次才算“正常”。

## 13.5 无条件跳转把两条路径分开

**无条件跳转**不检查数据，直接去指定位置。这里用伪指令`j target`，RARS将其表示为`jal zero,target`：跳转但不保存可用的返回地址。下一章函数调用才用ra保存返回位置。

例子把一个有符号数截到至少0：输入负数输出0，非负数保留。完整[branch-demo.s](示例代码/04-rars-programs/branch-demo.s)如下，不需要键盘输入，改第一条li即可：

```asm
.text
.globl main
main:
    li t0, -3
    blt t0, zero, negative
    mv a0, t0
    j show
negative:
    li a0, 0
show:
    li a7, 1
    ecall
    li a7, 10
    ecall
```

输入−3时分支跳到negative，只把0写a0；随后到show打印。输入5时不跳，mv令a0=5，j跳过negative，再到show。两条路径最后汇合到同一段展示代码。

## 13.6 漏掉j，为什么正数也变成0

若删除`j show`，输入5的路径会先把5写a0，然后顺序执行后面的`li a0,0`，最后打印0。标签negative不会自动阻止非负路径进入；标签不是一面只允许某类输入通过的门。

用表预测正常版本与故障版本：

| 输入 | 分支是否跳 | 正常a0 | 删j后的a0 |
| --- | --- | --- | --- |
| −3 | 是 | 0 | 0 |
| 0 | 否 | 0 | 0 |
| 5 | 否 | 5 | 0 |

只测负数和0发现不了这处错误。**对照输入**应覆盖每条重要路径，尤其要让两条路径产生不同结果。先保留正确文件，只在自己的副本里制造故障。

## 13.7 循环不是新硬件按钮，是一段回到前面的路径

**循环**让一段动作重复。先以“把1到N相加”为例，N=5的数学目标是1+2+3+4+5=15。

设计四部分：初始化i=1、sum=0、N=5；条件检查i>N就结束；循环体执行sum=sum+i；更新i=i+1后跳回检查。少一部分，就可能不开始、算错、永不结束或跳错位置。

这里i是当前准备相加的数，不是PC；sum是已处理部分的和；N是最后一个要处理的数。先把三个状态的意义写清，再分配t0、t2、t1，能减少混用。

## 13.8 一个完整的区间求和程序

完整[range-sum.s](示例代码/04-rars-programs/range-sum.s)如下。主练习限制N为0—1000，便于快速运行并避免本题整数范围问题；负数输入直接得到0是这个实现的行为，不是通用求和数学定义。

```asm
.text
.globl main
main:
    li t0, 1
    li t1, 5
    li t2, 0
loop:
    blt t1, t0, done
    add t2, t2, t0
    addi t0, t0, 1
    j loop
done:
    mv a0, t2
    li a7, 1
    ecall
    li a7, 10
    ecall
```

条件写`blt t1,t0,done`，读作N<i就退出，等价于i>N。它不是“i<N就退出”。正常情况下执行循环体后，j回到loop处，重新检查更新后的i。

打印只放在done，不在每轮打印；因此默认输出15，没有自动换行。若想观察中间值，先用断点与单步，不要立即在循环里插入会占用a0/a7的展示代码，增加额外干扰。

## 13.9 五次相加，却检查了六次条件

下表每行表示刚到loop、尚未执行该次分支的状态：

| i=t0 | sum=t2 | N<i吗 | 本轮是否相加 | 更新后i、sum |
| --- | --- | --- | --- | --- |
| 1 | 0 | 否 | 是 | 2、1 |
| 2 | 1 | 否 | 是 | 3、3 |
| 3 | 3 | 否 | 是 | 4、6 |
| 4 | 6 | 否 | 是 | 5、10 |
| 5 | 10 | 否 | 是 | 6、15 |
| 6 | 15 | 是 | 否，退出 | 保留6、15 |

前五次分支“不跳”后继续体内动作，第六次分支“跳”出去。j执行五次，add执行五次，条件分支执行六次。不要看到源代码只有一条add就说程序总共只做一次加法，也不要把所有指令次数都写成5。

N=0时，初态i=1，0<1立即成立，体执行0次、条件检查1次，sum保持0。N=1时体执行1次、条件检查2次，输出1。两者能快速发现“先算后检查”造成的边界问题。

## 13.10 为什么等于N时还要执行

题意包含最后的N。如果错误改成`bge t0,t1,done`，条件成为i>=N，i=5那次在相加前就结束，默认只得到10。

如果题目改成0到4相加，可以让i从0开始，结束条件i>=5，得到10。不能只照搬某一条比较，必须把“起点、是否包含终点、更新步长”一起确定。

**差一错误**常发生在包含与不包含边界之间。最有用的测试不是把N从5改100，而是N=0与N=1：正确程序与漏最后一项的程序会立即出现明显差别。

## 13.11 用一句始终成立的话解释正确性

循环每次回到loop时，sum等于从1到i−1的和。这个在固定观察位置每次都成立的描述，叫**循环不变式**；意思不是寄存器数值完全不变。

初始i=1，还没有处理任何数，1到0的空和约定为0，与sum初值一致。若进入一轮时描述成立，add把当前i算进去，更新i后，sum又成为“新i之前那些数的和”。

退出时i=N+1，sum就覆盖1至N。这个解释把初始化、每轮保持和结束联系起来，比只说“我的N=5输出15”更能说明为什么算法合题意。不过它依赖输入范围和未发生破坏题意的回绕；不能据此承诺任意巨大N都能精确保存数学总和。

## 13.12 判断会不会结束，先看状态能否接近边界

默认每轮i加1，有限的小N会被超过。若漏掉`addi t0,t0,1`，i一直是1，条件永远不成立，sum却不断增加并回绕；输出位置永远到不了。

若j误跳到main，三个初值每轮重新设定，也到不了预期终点。若j跳到add而绕开条件，会一直相加。这三种故障最后都可能表现为“没有输出”，但看loop处的i与路径就能区分。

暂停运行，记录当前PC与i，不要只是反复点击Go。命令行可设置最多执行步数，让故障副本在有限步骤后停下；达到上限是调试证据，不是正确终止。

## 13.13 目标地址与距离，先理解规则再学编码

本课普通未跳分支后的下一PC是PC+4；跳转目标由当前分支PC与有符号相对偏移得到。偏移单位是字节，不是“源代码几行”。用标签能让汇编器替你算地址，但机器编码仍有距离限制。

本章不要求手工拆分分支位域；第17章会展开。现在只要能在汇编后的机器表中指出分支地址、目标地址和下一条顺序地址，先别把机器视图某个经过工具处理的操作数当作通用的可直接复制源语法。

基础条件分支没有“跳过一条后还必定执行它”的延迟槽规则。本课按RISC-V语义，分支成立后下一条就是目标处指令。

## 13.14 图形实验怎样记录

在RARS单独打开range-sum.s，汇编、Reset。在loop的条件行设置断点，Go到首次暂停，此时i=1、sum=0；断点处指令尚未执行。Step过条件、add、更新与j后，再看下一次到loop的状态。

逐轮填写13.9表，至少自己追踪前两轮和最后一轮，再Go到退出。改N为0与1，分别重汇编从新初态运行。branch-demo.s另用−3、0、5覆盖两条路径，不与range-sum.s同时汇编。

命令行复现：将JAR与本章两个.s放在自己的练习目录，在**PowerShell、该目录**执行：

```powershell
java -jar .\rars1_6.jar nc sm .\branch-demo.s
java -jar .\rars1_6.jar nc sm t0 t2 .\range-sum.s
```

默认前者输出0，后者输出15，最终t0=6、t2=15。故障副本若命名range-bug.s，可用`java -jar .\rars1_6.jar nc sm 100 .\range-bug.s`限制本次最多100条基础指令。此命令不会自动修正死循环，也不是在测芯片100周期。

## 13.15 把判断与更新放在哪里，都要明确

本章先判断再做循环体，空输入可以不进体。另一种结构先做体再在末尾判断，至少会做一次；若也要支持空输入，就必须在进入前加一个保护判断。第16章会采用这样的“入口判空、底部继续”的结构。

遇到某题问“检查几次”时，先画实际路径。不能把顶部循环的n+1次条件检查直接套给所有底部循环，更不能把入口判空、最大值判断与循环继续分支混成同一个计数。

## 13.16 独立练习：只加正数需要哪些路径

假设一轮已加载v到t3，sum在t2。想只加正数，可先`bge zero,t3,skip_add`，正数路径执行add，其他跳过；两条路径在skip_add汇合后，都继续更新地址和剩余数。

这是**需要数组循环上下文的片段设计**，还不是完整程序。第14章会提供数据与遍历。思考如果把更新只放在正数路径，输入0或负数时会怎样：指针与剩余数不变，可能反复处理同一项。控制流正确不仅要求“算哪一项”，也要求各条路径都走到必要的推进动作。

## 13.17 自测、参考过程与完成条件

先做九题：①beq是否要先slt；②bge zero,t0表示什么；③−1与1用blt/bltu各怎样；④删除branch-demo的j，用5测试会怎样；⑤N=5的add/条件检查次数；⑥N=0的体与条件次数；⑦误用i>=N退出的N=1结果；⑧不变式“不变”指什么；⑨分支检查次数是否等于芯片周期。

参考：①不需要；②0>=t0，即t0<=0；③blt跳、bltu不跳；④被后面的赋0覆盖；⑤5/6；⑥0/1；⑦0，漏最后一项；⑧固定位置每次成立的关系，不是数值不变；⑨不是，微架构时间以后再分析。
