# 31 综合项目验证与故障定位

> **详细版重写提示：本章目前仍为原简版，尚未完成详细重写。** 已完成的详细版为第01–16章。后续将补充逐步讲解、完整操作、代码逐行解释与过程答案；进度见[课程导览](00-课程框架与学习方法.md)。

本章目标：检查计时器全部重要边界，形成可复现的调试过程。预计 4–6 小时。

## 31.1 必测矩阵

| 需求 | 测试方法 | 预期 |
| --- | --- | --- |
| 复位 | rst覆盖上升沿 | 停止、秒数0、部分秒0 |
| 启动 | toggle脉冲 | running变1，当前沿不计时 |
| 周期 | 连续运行完整参数周期 | 加一秒 |
| 暂停 | 在部分秒中间切换 | 秒数和部分秒保持 |
| 恢复 | 再次toggle后运行 | 补满剩余间隔 |
| 清零 | 运行中clear | 停止并全部归零 |
| 冲突 | clear与toggle同沿 | clear优先 |
| 回绕 | 跨过59秒 | 回到0 |
| 参数1 | CLKS_PER_SEC=1 | 每个运行且非控制沿加1 |

`15-timer` 同时实例化参数 1 和 3，用整数参考模型逐沿核对 running 与 seconds，并运行足够久经过 59→0。模型在下降沿驱动，下一上升沿后采样。

## 31.2 先缩小失败

如果第 117 拍错了，先保留从复位到第 117 拍的输入序列。看是否有控制脉冲，再检查 phase 与终值比较，最后检查秒值。不要先改所有条件。

如果每秒都慢一拍，怀疑终值写成参数而非参数−1，或引入了额外寄存的 tick 延迟。如果恢复时立即跳秒，检查部分秒状态是否被错误清零或旧 tick 残留。暂停时还变化，检查 running 条件与非阻塞旧值语义。

## 31.3 数据与控制对齐

板上显示闪烁不一定是核心错，可能是扫描频率、极性、按键抖动或显示译码。先直接观察核心 seconds；核心正确后再逐层接显示模块。每增加一层都定义输入输出在哪一拍有效。

## 31.4 记录真实证据

交付表至少包含工具版本、命令、参数、已跑测试、日志位置、已知限制。没有开发板就写“未做板上验证”，没有综合时序报告就不声称达到 50MHz。软件网页能打开也不能证明 HDL 功能正确。

## 31.5 练习与答案

故意把 clear 分支放到 toggle 后，现有哪项测试应失败？答案：clear 与 toggle 同沿的优先级检查。把 seconds 的终值改成 60，哪项应失败？答案：59→0 回绕。恢复代码后重跑全部项目测试，完成[第七阶段练习](第七阶段-练习与参考答案.md)。
