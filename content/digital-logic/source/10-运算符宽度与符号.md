# 10 运算符、宽度与符号

> 零基础详细重写版。先修：会读向量、常量、切片与拼接。建议分三次：先区分运算类别，再看宽度与signed，最后运行对照实验。

**本章目标：** 分清逐位、逻辑、归约、比较与选择；对结果注明位宽；用具体数值解释进位保留、混合符号比较和两种右移。

## 10.1 一样是“与”，为什么会有三个写法

令a=4'b1010，b=4'b1100。`a&b`、`a&&b`、`&a`名字里都含与，却回答三个问题：

| 写法 | 输入怎么处理 | 结果 | 结果宽度 |
| --- | --- | --- | --- |
| a & b | 对应位两两AND | 1000 | 本例4位 |
| a && b | 两个整体是否都为非零 | 1 | 1位 |
| &a | a里面所有位是否都为1 | 0 | 1位 |

先说你要问的问题，再选符号。不能只凭两个图标看起来接近，就替换掉其中一个。

## 10.2 逐位运算：把四位分成四道小题

```text
a： 1 0 1 0
b： 1 1 0 0
与：1 0 0 0
```

每个位置独立用第4章的两输入与表计算。逐位或得到1110，逐位异或得到0110。`~a`则把a每一位取反，得到0101。

两个操作数宽度不同时还涉及扩展，后面会讨论。初学先让同类数据宽度一致，并对拼接和中间结果明确声明，不把“逐位”误认为自动选择较窄的一段。

## 10.3 逻辑运算：把整个数当成条件

`a&&b`先判断a是否非零、b是否非零，然后做一位逻辑AND。1010和1100都非零，因此得到1。若a=0000，即使b=1111，逻辑AND仍为0。

逻辑或写`||`，表示至少一个整体条件为真；逻辑非写`!`，表示整个操作数是否为零。a=1010时，`!a=0`，不是逐位反转的0101。

条件判断输出只有一位。只要是确定二值输入，一个四位向量里有任何1，就可以判为非零；若含未知且无法确定真假，逻辑结果也可能为X。

## 10.4 归约：一个向量压成一位

`&a`把所有位AND起来；`|a`把所有位OR起来；`^a`把所有位XOR起来。它们只有一个操作数。

对于a=1010：归约AND是1&0&1&0=0；归约OR是1；归约XOR因为有两个1，得到0。对于a=1111，归约AND为1，归约XOR仍是0，因为四个1为偶数。

归约XOR常用来检查奇偶性。不要把四位归约XOR读成“是否恰好一个1”，因为三个1也会输出1。第4章已经用111举过反例。

## 10.5 算术：结果宽度是设计的一部分

加减使用`+`、`-`；乘法`*`；整数除法`/`；余数`%`。例如7/2得到整数商3，7%2得到余数1。本阶段不靠复杂乘除实现时间等待，时间行为由后续时序结构负责。

考虑四位a=1111、b=0001。如果只把和保存到四位narrow，结果为0000；希望保存进位，则应让结果有五位。推荐把参与本次加法的输入也明确扩为五位：

```systemverilog
// 模块内部片段，a、b已经声明为四位
logic [3:0] narrow;
logic [4:0] wide;
assign narrow = a + b;
assign wide = {1'b0,a} + {1'b0,b};
```

wide得到1_0000，wide[4]是进位，wide[3:0]是低四位。a、b各在高位补一个0后，表达式意图很清楚。

SystemVerilog有上下文定宽规则，某些赋值目标宽度会影响表达式计算。不能一概说“a+b总是四位”或“左边够宽所有中间结果必然正确”。复杂表达式先写清每一步位宽，显式扩展可减少依赖隐含规则的机会。

## 10.6 赋值与比较不能混用

`a=b`是赋值，让a获得b的值；`a==b`是判断两个值是否相等。前者改变信号，后者产生一位判断结果。

例如在测试中，先写`a=4'd3;`是给输入；随后`if(a==4'd3)`才是检查。把if里的比较误写成赋值，不是在简写“等于”，而是改了代码含义，工具也可能直接报语法错误或警告。

比较还包括`!=`、`<`、`<=`、`>`、`>=`。注意`<=`在比较表达式里可表示小于等于；到时序赋值语句中又有非阻塞赋值的角色，第17章会按语句上下文区分。

## 10.7 ==和===，为什么测试喜欢!==

普通相等`==`比较中，若含X/Z而无法确定真假，结果可能是X。例如`1'bx == 1'bx`不是确定1，因为两个未知未必代表同一个真实值。若其他已知位足以判定不同，普通比较也可能直接得到0，并非有X就一定返回X。

`===`把X、Z也作为要精确比较的符号，返回确定0或1。`!==`是其不等形式。因此测试里用`if(actual !== expected)`，当预期为确定0、实际却为X时，也能可靠进入错误分支。

这是一种验证方法，不是鼓励设计业务电路依赖“某根线在仿真里为X才执行功能”。正常RTL先给出确定二值功能与合法输入合同。

## 10.8 signed改变比较，不改变位的数量

把s声明成八位signed，s=1111_1111代表−1。比较`s < 8'sd1`时，两边按同类有符号数据解释，−1<1为真。

但若右边写成无符号`8'd1`，混合运算会影响表达式的符号规则；在这个相同八位的比较中，s的位模式会按无符号255参与，255<1为假。本实验专门同时输出signed_less与mixed_less，让差别可见。

| s位模式 | 有符号含义 | s小于有符号1 | 与无符号1混合比较 |
| --- | --- | --- | --- |
| FF | −1 | 1 | 0 |
| 80 | −128 | 1 | 0 |
| 00 | 0 | 1 | 1 |
| 01 | 1 | 0 | 0 |

不要把“同一个负数有时比1小、有时不小”当成数学矛盾。代码在两种写法下选择了不同解释，错误往往在类型合同上。

## 10.9 $signed不是自动增加一位

`$signed(u)`可把位模式重新解释为有符号类型，但不会凭空扩宽。u=8'hFF若原本表示无符号255，直接$signed(u)就读成−1，而不是九位的+255。

若确实需要把八位无符号数完整转到能容纳它的有符号范围，可先零扩展到九位，再赋给九位signed变量。下面是模块内部片段：

```systemverilog
logic [7:0] u;
logic signed [8:0] positive_value;
assign positive_value = $signed({1'b0,u});
```

九位补码能表示−256…255，因此0FF能作为+255。设计时先问“我想保留数值，还是重新解释同一串位”，再选择扩展与转换。

## 10.10 两种右移：>>与>>>

逻辑右移`>>`把位向右移动，左端补0；算术右移`>>>`只有在左操作数具有有符号类型时，才按符号位填充。仅把符号写成三个大于号，不会让无符号数据自动变负数。

八位位模式1000_0000：

| 操作数类型与运算 | 新位模式 | 解释 |
| --- | --- | --- |
| signed数据 >> 1 | 0100_0000 | 逻辑补0，结果编码40 |
| signed数据 >>> 1 | 1100_0000 | 复制符号1，补码−64 |
| unsigned数据 >>> 1 | 0100_0000 | 左操作数无符号，仍补0 |

左移`<<`把位往左移，右侧补0；若保留宽度不变，高位可能丢失。它在没有截断等前提下才对应乘2，不应把所有有限宽度移位都当无限精度数学乘除。

## 10.11 三元运算符是选择器

`condition ? value_if_true : value_if_false`表示按条件选一路。问号前是条件，冒号分隔真、假两种结果。

例如`assign y=sel?b:a;`，sel=1取b，sel=0取a。这个表达式描述组合选择，不是“等待条件成立以后才开始运行模块”。两路位宽与符号性也要保持清楚。

当条件为X时，四态语义可把两路相同的位保留、不同的位合并成X。它与if在未知条件下的行为可能不同，因此不要以为所有改写在包含未知时也必然等价。第11章先以确定二值规格设计，再单独理解未知暴露问题的作用。

## 10.12 括号比猜优先级可靠

希望检查a的第1位，写`(a & 4'b0010) != 0`。先取出掩码覆盖的那一位，再比较是否非零。**掩码**就是用0/1标出哪些位需要保留，AND中0的位置会被清掉。

若写成`a & 4'b0010 != 0`，比较与逐位与的优先级会让含义偏离“先按位与再比较”。当a=0010时，正确括号式为真，错误顺序可能得到0。混合比较、位运算、逻辑运算时主动加括号，不把背优先级表当成可读性的替代。

## 10.13 把本章所有对照放进一个模块

下面是10-operators/design.sv完整内容：

```systemverilog
module operators_demo(
  input logic [3:0] a,b,
  input logic signed [7:0] s,
  input logic [7:0] u,
  output logic [3:0] bit_and,
  output logic logical_and, all_bits, odd,
  output logic [4:0] wide_sum,
  output logic signed_less, mixed_less,
  output logic [7:0] logical_right, arithmetic_right, unsigned_right
);
  assign bit_and = a & b;
  assign logical_and = a && b;
  assign all_bits = &a;
  assign odd = ^a;
  assign wide_sum = {1'b0,a} + {1'b0,b};
  assign signed_less = s < 8'sd1;
  assign mixed_less = s < 8'd1;
  assign logical_right = s >> 1;
  assign arithmetic_right = s >>> 1;
  assign unsigned_right = u >>> 1;
endmodule
```

前四条assign分别是逐位与、逻辑与、归约与、归约异或。第五条五位加法保留进位。之后两条对照有无s的比较，再后三条对照右移规则。

本模块没有状态，输出都只依赖当前输入。变量名字不同并不表示它们按前后顺序执行。

## 10.14 先手算第一组，再运行四组

第一组a=A、b=C、s=−1、u=80。对应结果：

| 输出 | 预期 | 来由 |
| --- | --- | --- |
| bit_and | 8，即1000 | 对应位AND |
| logical_and | 1 | 两者均非零 |
| all_bits | 0 | A里有0 |
| odd | 0 | A里有两个1 |
| wide_sum | 22，即五位10110 | 十进制10+12 |
| signed_less / mixed_less | 1 / 0 | −1与255两种解释 |

## 10.15 练习与完成条件

题1：a=1000、b=0010，逐位与与逻辑与？前者0000，后者1，因为两者均非零。题2：四位15+1低四位为几，保留五位呢？分别0000、1_0000。题3：u=FF，$signed(u)是255吗？不是，是同八位补码−1。

题4：为什么只写>>>不保证算术填充？还要看左操作数类型。题5：~4'b1010与!4'b1010一样吗？前者四位0101，后者一位0。做题时每次写“输入宽度、符号性、输出宽度”，不要只写一个十进制答案。
