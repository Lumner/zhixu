# 第三阶段实践：扩展ALU验收

本实践对应第13–16章。目标是把“想加一种功能”落实成规格、实现、独立预期与可复现记录，不只展示一张PASS截图。建议在阅读第16章后另用1–2小时整理已有实验，不要求额外购买硬件。

## 1. 先确认交付的是哪个版本

固定使用[组合实验16](组合实验/16-alu-regression/design.sv)：四位a/b、三位op、五种合法操作、三个保留码，输出y/C/V/Z/valid。与第14章四操作、两位op版本分别保留；本实践没有把原工程示例05-alu改成新接口。

## 2. 不看代码先写规格

在自己的记录中写出000加、001减、010与、011异或、100或；101/110/111拒绝，y/C/V固定0、Z=1、valid=0。减法C=1表示无借位，V判断四位补码范围−8…7。再独立手算7+1、F+1、8−1、A与C以及一个保留码。

## 3. 在独立目录运行

复制下载包source/组合实验/16-alu-regression为自己的实验目录。用PowerShell进入该目录，以Get-Location、Get-ChildItem确认看到design.sv和tb.sv，版本准备见第7章。逐条运行：

```powershell
iverilog -g2012 -s tb -o sim.vvp design.sv tb.sv
vvp sim.vvp
```

编译成功才运行第二条，记录两次退出码。预期主要结果为`PASS extended ALU: 2048 binary input cases including 3 reserved opcodes`，并生成alu.vcd。2048=16×16×8，要能说明合法1280、保留768的组成。

## 4. 证明至少一种错误会失败

另外复制实验目录，修改加法V为carry。重新编译运行，预期以非0退出且日志指出op=000、a=1、b=7时V与预期不同。也可选择把OR误写成AND，但记录中必须写清到底改了哪一处，不把两个错误混成一个难以解释的失败。

保留错误副本与失败日志，恢复正确目录后重新编译运行。不要将错误副本放回正式课程目录，不要把expected一同改错来换取PASS。

## 5. 将日志和波形联系起来

由序号oi×256+ai×16+bi定位输入区间。正常仿真的7+1对应113…114ns，采样中点113.5ns；故障的1+7对应23…24ns。核对时间单位，并记录你实际查看了哪些信号。若只生成文件而没打开GUI，记录“已生成VCD，未操作GUI”，不能写成完成了波形界面验证。
