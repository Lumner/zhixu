# 01 从电压到比特

> 本章是零基础详细重写版。先修要求：无。建议分两次学习，每次 40–60 分钟；纸笔练习另外留出时间。本章暂不写代码，也不要求连接真实电路。

**本章目标：** 完成本章讲解与练习后，你应能解释电压、逻辑值、含义的区别；写清输入输出约定；判断一个问题是否需要保存状态。

## 1.1 我们先做一盏会判断的灯

设想一个最小报警系统：门开着、而且系统已经布防，报警灯就亮。否则灯灭。

这句话包含三类信息：门有没有开、系统有没有布防、灯应不应该亮。前两项由外部提供，是**输入**；后一项是我们要产生的结果，是**输出**。能根据输入产生输出的一组部件和连接，组成这里要研究的电路。

你可以先把电路画成一个盒子，不必知道盒子内部有多少晶体管：

```mermaid
flowchart LR
A[门是否打开] --> C[判断电路]
B[是否已经布防] --> C
C --> D[报警灯是否点亮]
```

本章的任务，就是弄清这些信息怎样进入盒子、为什么能用 0 和 1 表示，以及什么时候盒子还需要“记住过去”。

## 1.2 什么叫信号

**信号**是用来携带信息的、能够被观察和区分的变化。交通灯的颜色、扬声器发出的声音、导线上的电压都可以携带信息。我们研究的数字电路主要通过电气信号连接。

可以先把电压想成某一点相对于参考点的电气“高度”。这里不需要计算电流；只要知道两件事：电压是物理量，有单位伏特 V；现实中的电压可以连续变化，不是天然只会取数字 0 和 1。

**引脚**是器件与外界连接的端点；你可以先把输入引脚理解成电路接收外部信号的位置。同一个输入引脚在不同时刻可能测到不同电压。为了让电路进行可靠判断，器件会规定怎样的电压范围算“低”，怎样的范围算“高”。

## 1.3 0、1 是我们对电气状态的解释

下面是一组**专门为了说明概念而假设的阈值**，不是任何开发板的接线规范：

| 假设测到的电压 | 这个假想输入怎样解释 |
| --- | --- |
| 0.0–0.8 V | 有效低电平 |
| 大于 0.8、小于 2.0 V | 不能保证识别为低还是高 |
| 2.0–3.3 V | 有效高电平 |

如果电路把低电平记作 0、高电平记作 1，那么 0.2 V 和 0.6 V 都可以被解释为逻辑 0。我们不必因为它们相差 0.4 V，就为报警系统建立两种不同情况。这种做法把复杂的物理细节压缩成两个逻辑值。

注意中间区域不是第三个可放心使用的逻辑值。器件在那一区域不能保证判断结果；在实际设计中要查真实器件手册。本课程早期的题目假设输入已经稳定在有效范围内。

![从电气信号到逻辑值，再到含义的三个层次](images/01-signal-layers.svg)

可以把这个过程分成三个层次：先有物理电压，再把电压解释为逻辑 0 或 1，最后按系统约定赋予含义。例如逻辑 1 可以表示“门开了”，也可以表示“电机应该停止”。第三层含义不是电压自动决定的。

## 1.4 一个比特能装多少信息

**比特**的英文是 bit，表示一个可以在两种逻辑状态之间区分的位置。一个比特可为 0，也可为 1。

把一个比特比作一张只有正反两面的卡片：正面写 0，反面写 1。你可以约定 0 表示门关、1 表示门开。只用这一张卡片，就能完整表示“门开或关”这两个情况。

但如果要表示“关、半开、全开”三个状态，一张卡片就不够，因为它只有两种不同面。增加到两张卡片后，可形成 00、01、10、11 四种组合，才有足够位置给三个状态分别取名。

| 状态 | 一种可行的两位编码 |
| --- | --- |
| 门关 | 00 |
| 门半开 | 01 |
| 门全开 | 10 |
| 暂未使用 | 11 |

**编码**就是给不同含义分配不同位模式的规则。这里完全可以换一套规则，例如用 11 表示全开；重要的是发送端和接收端采用同一套约定。

## 1.5 两位为什么有四种组合

第一位取 0 时，第二位有 0、1 两种选择，得到 00、01；第一位取 1 时，又有 10、11 两种。因此两位共有 `2×2=4` 种，而不是 `2+1=3` 种。

再增加第三位，每一种旧组合又可以在后面接 0 或 1，所以组合数再次翻倍，成为 8 种：

```text
000  001  010  011
100  101  110  111
```

一般说 N 位，就表示有 N 个这样的二值位置，组合数是把 2 连乘 N 次，写成 `2^N`。这里的 `^` 是本章排版中表示乘方的写法，读作“2 的 N 次方”。等到学 SystemVerilog 时，代码里的 `^` 有另外的含义，不能混用。

现在只需记住：增加一位，**可区分的模式数量翻倍**。至于每个模式代表哪个数，下一章再讲。

## 1.6 位、字节、位宽分别是什么

8 个比特组成 1 个**字节**，英文 byte。bit 与 byte 不是同一个单位。例如 2 字节等于 16 比特，不是 2 比特。

一个数据整体使用多少个比特，称它的**位宽**。例如 0101 是一个 4 位模式；00000101 是一个 8 位模式。两个模式若都按无符号整数解释，数值都是 5，但需要保存的位数不同。数值与位宽要分开说。

在纸上，我们把多位横着写。在最简单的并行连接中，4 位数据可以对应 4 根信号线，同一时刻各携带一位；也可以约定在一根线上先后传多个位，那叫串行传输。位宽描述的是数据有多少位，不总等于实际连接有多少根线。

## 1.7 为报警器写清楚“1 到底是什么意思”

回到开头的系统。我们先取三个名字，方便后面画表和写代码：

| 名字 | 中文含义 | 0 表示 | 1 表示 |
| --- | --- | --- | --- |
| door_open | 门是否打开 | 门关 | 门开 |
| armed | 是否布防 | 未布防 | 已布防 |
| alarm | 是否报警 | 不报警 | 报警 |

下划线只是把英文单词连起来，使名称容易读；它不表示减法。此时不要求记住英文拼写，可以先用“门开”“布防”“报警”画表。

像这样约定输入输出名称、方向、位宽和含义，称为定义**接口**。接口好比两个人约定用哪种语言和哪些词交流。后面即使电路内部换了实现，只要外部仍按同样接口交流，就比较容易连接和测试。

## 1.8 高有效与低有效

如果一个控制信号等于 1 时表示功能生效，称**高有效**。刚才 alarm=1 表示报警，是高有效语义。

如果信号等于 0 时功能生效，就称**低有效**。例如有一个灯的控制引脚，实际硬件规定输出 0 时灯亮、输出 1 时灯灭。我们就不能直接说“1 一定代表开、0 一定代表关”。

工程名称常在低有效信号后加 `_n`，例如 reset_n。reset 是复位，表示让状态回到预先规定的初始值；n 提醒我们低有效：reset_n=0 才表示复位生效。名字本身不会让电路自动取反，它只是给读者的约定。

如果内部 alarm=1 表示报警，而外部灯需要 0 才亮，连接处需要把逻辑意义转换成合适电平。怎样取反会在第 4 章学习。现在先学会在接口表中写清楚极性。

## 1.9 第一次完整推演：四种输入

报警条件是“门开，而且已经布防”。两个输入各有两种可能，因此一定有四种组合。我们按不遗漏的顺序逐行检查：

| 门开 door_open | 布防 armed | 逐字理解 | 报警 alarm |
| --- | --- | --- | --- |
| 0 | 0 | 门关，而且没有布防 | 0 |
| 0 | 1 | 虽然布防，但门关 | 0 |
| 1 | 0 | 门开，但没有布防 | 0 |
| 1 | 1 | 门开，而且布防 | 1 |

这样的表叫**真值表**：把可能输入和对应输出列完整。第 4、5 章会正式使用。这里请注意两件事：第一，0 和 1 是每个信号各自的状态；第二，输出 1 的条件来自需求，不是因为“这一行看起来数字最大”。

## 1.10 如果还需要记住“以前开过门”呢

现在改变需求：“布防后只要门打开过一次，报警就保持；重新关门也不停，直到按清除键。”

看下面两个时刻：

| 情形 | 现在门开吗 | 现在布防吗 | 以前开门触发过吗 | 是否应继续报警 |
| --- | --- | --- | --- | --- |
| 刚布防，还没有开门 | 0 | 1 | 否 | 0 |
| 开门触发后又关门 | 0 | 1 | 是 | 1 |

现在的两个输入完全相同，输出却不同。区别来自过去留下的信息。这个必须保存的信息叫**状态**。最小情况下，可以用一位记录“此前是否触发”。

输出只由当前输入决定的电路叫**组合电路**，例如前面的简单报警器。行为还取决于保存状态的电路叫**时序电路**。这里“时序”不是说它运行得慢，而是说时间先后与历史会影响行为。

以后会用**寄存器**保存状态，用**时钟**约定何时更新。暂时不需要知道它们的代码；只要能用“同样当前输入是否可能因历史不同得到不同结果”区分两类问题。

## 1.11 学习中会遇到的三样工具

电路可以先画图，也可以用硬件描述语言写下来。SystemVerilog 就是本课使用的语言。它用于表达电路连接、组合计算以及状态更新规则，不是给每个比特安排一位小人逐行执行命令。

**仿真器**是在电脑里计算这些描述的工具。我们给它模拟输入，它按规则产生模拟输出，再检查是否符合预期。**综合器**把支持的硬件描述转换成更具体的电路结构。它们做的工作不同。

| 活动 | 你在问什么 | 本阶段是否需要安装工具 |
| --- | --- | --- |
| 纸笔推演 | 给定输入，输出应该是什么 | 不需要 |
| 仿真 | 描述出来的电路是否遵守规则 | 第 7 章再准备 |
| 综合与上板 | 怎样映射到真实器件并运行 | 后续阶段再讲 |

先能手算预期，再让工具检查实现，学习会更清楚。

## 1.12 跟着做：给风扇写接口

问题：温度太高且允许自动运行时，风扇才转。按以下顺序做。

第一步，找输入：温度是否太高、是否允许自动运行。第二步，找输出：风扇是否应转。第三步，把每个量都规定为一位，1 分别表示“太高”“允许”“应转”。第四步，列 00、01、10、11 四行。

当温度不高时，即使允许运行也不转；当温度高但不允许时也不转；只有两个条件都为 1 才转。因此输出依次为 0、0、0、1。它与前面报警器的判断结构相同，只是信号的现实含义变了。

这说明数字逻辑可以反复使用同一种判断结构解决不同问题。

## 1.13 常见误解

| 容易误解成 | 应怎样修正 |
| --- | --- |
| 逻辑 1 就是固定 5V | 真实电压范围由器件规定，逻辑值是抽象 |
| 0 一定代表关，1 一定代表开 | 意义和极性由接口约定 |
| 多位比特天然就是一个整数 | 它也可以编码状态，先说明解释规则 |
| 2 字节就是 2 比特 | 1 字节等于 8 比特 |
| 电路输出都只看现在 | 需要保存历史时还要看状态 |
| 代码能运行就说明理解了电路 | 还要能预测输入输出，并解释验证依据 |

## 1.14 自己做，再对答案

**题 1：** 两位能否分别编码红、黄、绿三种灯状态？如果能，写一种方案。**题 2：** 三个独立按钮有多少种组合？请列全。**题 3：** “按着按钮时灯亮”和“按过一次后灯一直亮”，哪一个需要状态？**题 4：** 低有效控制信号为 0 时，功能是否生效？

参考过程：题 1，两位有四种组合，多于三种，所以可以用 00、01、10 分别表示三种颜色，11 暂不用。题 2，每个按钮两种，`2×2×2=8`，从 000、001、010、011、100、101、110 到 111。题 3，前者只看当前按钮，后者要记住以前是否按过，因此后者需要状态。题 4，低有效的定义就是 0 时生效，不能根据“0 看起来像没有”判断。
