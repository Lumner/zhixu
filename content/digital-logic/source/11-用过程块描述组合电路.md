# 11 用过程块描述组合电路

> 零基础详细重写版。先修：会assign、三元选择、向量与比较。本章分三次完成：二选一、完整赋值与优先级、case与固定循环。

**本章目标：** 从决策表写出always_comb；解释begin/end、if/else、case与阻塞赋值；识别缺少分支导致的保持行为；运行完整输入检查。

## 11.1 为什么还需要一种写法

二选一可写`assign y=sel?b:a;`，但如果有清零、优先级、多个输出，挤成一条表达式会越来越难读。SystemVerilog允许在过程块中按步骤写出判断，同时仍表达组合逻辑。

**过程块**是包含一组按规则执行语句的结构。`always_comb`表示这组语句的设计意图是组合计算。相关输入变化时，仿真器重新计算该过程，通常也会在仿真开始时求值一次。不能把“always”读成它每隔固定一秒自动执行。

组合的关键仍是：稳定输出只依赖当前输入，不需要保存历史。代码改成过程写法，并不自动给电路增加时钟。

## 11.2 从决策表写二选一

先约定a、b都是四位，sel是一位。sel=0输出a，sel=1输出b：

| sel | y应当等于 |
| --- | --- |
| 0 | a |
| 1 | b |

放在模块内部的完整过程块为：

```systemverilog
always_comb begin
  if (sel) y = b;
  else     y = a;
end
```

always_comb后跟begin开始一组语句，end结束；if后的圆括号是条件，条件为确定1时执行后面的语句，否则执行else。这里sel是一位，所以不必再写sel==1。

如果某个分支要做两件事，也使用begin/end包住该分支。不要因为缩进看起来在同一层，就以为两条语句都属于if；语法由关键字决定。

## 11.3 =是阻塞赋值，是什么意思

在这个过程块内，`=`赋值先更新当前左值，再继续下一条语句，称**阻塞赋值**。下面是模块内部片段，tmp、y、a、b、c均已声明为四位：

```systemverilog
always_comb begin
  tmp = a & b;
  y = tmp ^ c;
end
```

第二句使用本次刚计算的tmp，因此表达先求与、再异或的数据依赖。这里的“先后”是过程语义，不是每句用一个时钟周期，也不是人为加入了物理等待时间。

临时量应先计算再读取。若把两行反过来，第一句可能用到旧tmp，不要指望块内给tmp赋值一定会触发同一个块反复重算直到符合你的直觉。

本课程组合过程使用`=`；时序寄存器更新使用`<=`会在第17章解释。先养成分清语句上下文的习惯。

## 11.4 漏掉else为什么不是“输出零”

看这个**故意不完整的错误片段**：

```systemverilog
always_comb begin
  if (sel) y = b;
end
```

当sel=0，没有任何语句告诉y新的值是什么。语言行为会保留先前的值，而不是默认给零。保留旧值需要某种存储，综合工具可能推断锁存器或针对always_comb意图报告错误。

| 时刻顺序 | sel | b | 错误片段的y可能怎样 |
| --- | --- | --- | --- |
| 第一次 | 1 | 6 | 获得6 |
| 后来 | 0 | 9 | 没赋值，仍保留6 |

**锁存器**是一种能保存状态的存储结构；这与我们“当前输入决定输出”的组合目标冲突。不是看到always_comb关键字，工具就会替你修补遗漏的else。

## 11.5 两种完整写法

第一种就是完整if/else，两条路径都赋值。第二种先给默认，再在条件成立时覆盖：

```systemverilog
always_comb begin
  y = a;
  if (sel) y = b;
end
```

先给y=a，确保sel=0也有本次结果；sel=1时后面覆盖成b。两种写法对本例确定二值sel都满足同一个决策表。

“默认值”不是随便填一个常量，而应是未被后续分支覆盖时正确的结果。如果需求sel=0取a，默认写零却没有其他赋值，功能仍然错误，只是可能不再推断存储。

## 11.6 加clear之前，先规定谁优先

现在给二选一加一位高有效clear。约定clear=1时selected全零，clear=0再按sel选择。clear只清这个selected输出，不影响稍后的独立operation输出。

| clear | sel | selected |
| --- | --- | --- |
| 1 | 0或1 | 0000 |
| 0 | 0 | a |
| 0 | 1 | b |

可以先selected=0，再在!clear时进行完整二选一。本章完整设计就采用这种写法。也可以写`if(clear)... else if(sel)... else...`，两者都让清零优先。

两个独立if则要特别留意覆盖顺序。若先`if(clear) y=0;`，后面又`if(sel) y=b;`，clear与sel同时1时后句把零覆盖为b，不再是clear优先。

## 11.7 if遇到未知条件时

if条件为X或Z、无法判真时，不会像确定1那样进入真分支；这可能让错误被else中的确定值遮住。因此不能因为某次波形y仍为0，就断言clear或sel已经是合法输入。

本课组合功能表先定义二值输入。需要进一步检查未知时，可以在测试里检测输入是否合法、用!==发现未知结果，再追踪未初始化或连接问题。不要通过随意使用casex把X当通配符，让问题“消失”。

## 11.8 case：按编码选择一路

设op两位，定义四种输出operation：00取a、01取b、10取按位与、11取按位异或。case比嵌套多层if更直观。

```systemverilog
// always_comb内部片段，信号均已声明
operation = 4'b0000;
case (op)
  2'b00: operation = a;
  2'b01: operation = b;
  2'b10: operation = a & b;
  2'b11: operation = a ^ b;
  default: operation = 4'b0000;
endcase
```

case后的括号是要检查的表达式；每个标签后是冒号和语句；endcase结束这次选择。普通case采用包含四态值的精确匹配。default是没有标签匹配时使用的分支，不是“最后一种操作”的隐含简称。

四种二值编码已列全，但仿真op也可能含X。这里默认零只是本模型的明确处理，不代表硬件里存在一个可可靠识别“模拟未知电压”的功能。合法二值合同与仿真暴露未知要分开理解。

## 11.9 每一个输出都要检查路径

有两个输出时，selected每路完整不代表operation也完整。临时变量也可能被读取，因此同样要检查“本次读取前是否有本次赋值”。

一种检查办法是画表：对每个if真/假分支、case每个标签和default，逐个勾选每个输出是否获得值。写了默认值但后面又读取另一个没有赋值的临时量，也不能算整体完整。

同一个变量只在一个组合过程负责。不要为了“把case分两页”就让两个always_comb同时写operation；应分出不同中间信号再单点组合。

## 11.10 for循环是不是要花四拍

下面是模块内部片段，逐位生成四个异或结果：

```systemverilog
always_comb begin
  for (int i = 0; i < 4; i++) begin
    y[i] = a[i] ^ b[i];
  end
end
```

括号里依次是：i从0开始；只要i<4就继续；每次循环后i加一。int是整数循环变量，i++是加一的简写。循环访问i=0、1、2、3，四个输出位都被本次赋值。

这里没有时钟，也没有#延时。固定范围组合循环通常展开为相应结构，不表示运行四拍后才得到y。若需要逐拍处理四份数据，要用计数器与状态控制，那是后续时序设计。

对简单逐位运算直接`assign y=a^b;`更简明；本段是为了说明循环语义，不要求所有向量操作都拆成循环。

## 11.11 完整的组合实验面板

保存下面完整design.sv到11-comb目录：

```systemverilog
module comb_panel(
  input logic [3:0] a,b,
  input logic sel,clear,
  input logic [1:0] op,
  output logic [3:0] selected,operation
);
  always_comb begin
    selected=4'b0000;
    if (!clear) begin
      if (sel) selected=b;
      else selected=a;
    end
    operation=4'b0000;
    case(op)
      2'b00: operation=a;
      2'b01: operation=b;
      2'b10: operation=a&b;
      2'b11: operation=a^b;
      default: operation=4'b0000;
    endcase
  end
endmodule
```

a、b是两路四位数据，sel与clear控制selected，op控制独立的operation。always_comb里先处理selected的全部路径，再处理operation的全部路径，两者不需要等待对方一拍。

读例子：a=3、b=12、sel=1、clear=0、op=10，则selected=12；operation=0011 AND 1100=0000。若只把clear变1，则selected变0，operation仍按op计算为0。若op改00，operation为a=3，即使clear仍为1也不改变它。

## 11.12 自动检查4096组输入

配套[tb.sv](语言实验/11-comb/tb.sv)用三层循环：a的16个值、b的16个值、四位control的16个值。control按`{clear,sel,op}`拆成1+1+2位，共计16×16×16=4096组。

这与第7章手写四组刺激是同一思想，只是输入空间变大，交给循环避免漏行。测试中先按规格算expected_selected和expected_operation，#1后再比较实际输出。不要把4096组误写成4096个时钟周期；该实验没有时钟。

在11-comb目录执行：

```powershell
iverilog -g2012 -s tb -o sim.vvp design.sv tb.sv
```

确认本次没有编译错误、退出码为0，再运行：

```powershell
vvp sim.vvp
```

预期最后为`PASS comb: 4096 input combinations`。如果工具因always_comb或宽度给出提示，应读清文字；不能把所有提示都当失败，也不能把明确编译错误当作通过后继续跑旧产物。

## 11.13 故意漏赋值，观察测试拒绝错误

在**练习副本**中，同时删掉selected默认赋零和`else selected=a;`。这时clear=0、sel=0的路径没有本次赋值，可能保留旧值或保持X。重新编译运行，应被测试拒绝。

只删else而保留默认零，则未必形成锁存器，但会把“sel=0取a”错成“取零”。这两种错误不同：完整赋值检查与功能检查都需要做。恢复正确源码后重新通过。

## 11.14 练习与完成条件

题1：在组合块里省略else，工具一定自动填0吗？不会，需要分析所有路径。题2：默认y=a后if(sel)y=b，sel=0输出？是本次a，不是旧y。题3：两个独立if同时满足，后一个能否覆盖前一个？能，块内阻塞赋值有行序。

题4：for循环4次是否代表4拍？不代表；没有时钟或等待时，不能把次数当时间。题5：本实验clear是否清operation？按规格不清，只清selected。写出输入clear=1、op=00、a=5作为核对，operation仍应5。

完成本章：能从决策表写完整组合块；指出哪些语句决定优先级；解释测试为何会拒绝两个不同的错误版本。进入[第12章](12-测试平台时间与波形.md)，系统编写自己的测试，而不只是运行配套tb。
