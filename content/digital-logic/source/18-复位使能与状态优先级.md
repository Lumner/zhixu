## 18.1 同步复位

`always_ff @(posedge clk)` 内首先 `if(rst)` 是同步复位。rst 在两次上升沿之间短暂变高又变低，若没有覆盖采样沿，寄存器不会清零。测试必须保证复位覆盖有效边沿。

优点是所有更新遵循同一时钟，方便时序分析；代价是需要时钟工作，并可能影响数据选择路径。不能说同步复位在所有器件上必然更省资源。

## 18.2 异步复位

```systemverilog
// 模块内部片段：低有效异步复位
always_ff @(posedge clk or negedge rst_n) begin
  if (!rst_n) q <= '0;
  else q <= d;
end
```

rst_n 下降可不等时钟立即清零；解除复位仍有恢复、移除时间约束。工程中常对每个时钟域采用异步置位、同步释放的复位结构。它需要按目标器件和启动顺序设计，不能只靠修改敏感列表解决。

## 18.3 定义优先级表

计数器合同可以写为：rst 最高，其次 clear，其次 en，最后保持。使用单一 if/else-if 链表达：`if(rst)... else if(clear)... else if(en)...`。两个独立 if 同时写同一寄存器会让后一个赋值覆盖前一个的效果，容易与需求不一致。

| rst | clear | en | 更新 |
| --- | --- | --- | --- |
| 1 | 任意 | 任意 | 清零 |
| 0 | 1 | 任意 | 清零 |
| 0 | 0 | 1 | 执行操作 |
| 0 | 0 | 0 | 保持 |

## 18.4 不用门控普通时钟

`wire slow_clk=clk&en` 可能产生窄脉冲和时钟偏斜，不能当作通用节能手段。入门设计保持一个干净的 clk，在寄存器更新处用使能。需要门控或生成时钟时使用器件支持的专用资源并建立约束。

## 18.5 实验与答案

在 `07-register` 的同步复位测试中，于两个上升沿之间拉高再拉低 rst，预期 q 不变；让 rst 覆盖上升沿，预期清零。练习：rst 与 en 同为 1 会加载 d 吗？答案：不会，复位优先。验收：在波形上标出真正采样的沿，解释每个更新。
