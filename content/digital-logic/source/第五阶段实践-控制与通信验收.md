# 第五阶段实践：控制与通信验收

对应第22–25章，建议在各章实验后另用2–3小时整理。目标是从规格判断每个沿到底接受了什么，不能只用“仿真结束了”当验收。

## 1. 先准备四份预测

画三状态FSM六行表，区分沿前灯与沿后状态；为一项缓冲写出A1堵住、B2等待、同沿替换的过程；对四项FIFO列空/中间/满时同时请求；手画53的8N1十格并标每格中心。

先预测再运行。预测错误时，保留第一处不一致并说明是状态、位序、延迟还是接口合同读错，不要事后无痕抄成相同图。

## 2. 分目录运行

复制[四组控制通信实验](控制通信实验/README.md)。每个目录独立有design.sv、tb.sv，在该目录PowerShell逐条执行：

```powershell
iverilog -g2012 -s tb -o sim.vvp design.sv tb.sv
vvp sim.vvp
```

先编译成功，再运行；每次改文件保存后重编译。不把不同目录同名tb混在一起。记录实际工具版本、目录、退出码、正常计数与日志。

## 3. 核对验收范围

| 实验 | 应留下的证据 |
| --- | --- |
| FSM | 十次脚本沿，正常六行表、沿间Moore保持和复位优先 |
| 握手 | 13周期，5项接受、4项交付、1项复位丢弃，两端保持 |
| FIFO | 220周期，111写/107读/1复位丢弃/剩3，拒绝请求另记 |
| UART | CPB1/4各256完成帧，合计5120中心；两次中止另记 |

UART还生成uart.vcd。自己使用GUI时，写清实际看了哪份配置、哪个字节、哪些中心；如果只运行脚本或生成文件，就如实记录，没有打开GUI不填GUI完成。

## 4. 在副本里制造一次错误

可选：GREEN跳回RED；背压时覆盖stored；FIFO满时悄悄接受写；UART改为最高位先发。一次只改一处，重新编译，保存首个失败输入、周期或符号编号，并解释实际与预期。

恢复正确目录后重新编译通过。全部九类维护故障见[第五阶段验证记录](验证/第五阶段详细重写验证记录.md)，课程记录不能代替自己的运行结果。

## 5. 明确没有完成的部分

本批是单时钟RTL功能验证，没有硬件跨域、完整AXI认证、异步FIFO、UART接收器、USB/RS-232电气适配、综合时序或上板。有限序列与两种UART参数也不等于所有历史与配置的穷举。

## 6. 后续组合练习先写延迟合同

若尝试用FIFO给UART供字节，先解释同步pop沿后dout才有效，而UART在接受沿锁存输入。适配器要把读请求、数据到达和发送接受分成明确状态，并处理复位与忙中请求。参考[第32题](第五阶段-练习与参考答案.md)，本批未交付该组合版本，不能只画连线就填写“已联调通过”。
