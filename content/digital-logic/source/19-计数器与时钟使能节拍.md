# 19 计数器与时钟使能节拍

> 零基础详细版。先修：第15章参数与位宽，第17章旧值/新值，第18章优先级和保持。建议5–7小时，先用DIV=4画表，再把数字换成真实时间。

**本章目标：** 设计从0到DIV−1循环的计数器；理解tick是沿前使能而不是新时钟；解释消费者在哪个沿更新；验证DIV=1、非二次幂、暂停与复位；从时钟频率估算节拍间隔和位宽。

## 19.1 计数器也是寄存器加组合关系

计数器保存当前计数count。在允许更新的有效沿，把count+1装回去；到指定终点时，下一值改成0。它仍然由触发器保存状态，并不是一种神秘的“时间变量”。

**模N计数器**的N表示一个循环有N个状态。N=4时状态为0、1、2、3，再回0；不是数到4才回0。状态从0开始，所以最后值为N−1。

若写成“到4才清零”，实际经历0、1、2、3、4五个状态，周期变成5拍。这种多一或少一的错误常叫**差一错误**。先写状态列表，是最简单的防错方法。

## 19.2 要输出的是节拍，还是慢时钟

本章的**节拍tick**是告诉其他寄存器“这次clk上升沿允许执行一次”的条件。消费者仍用同一个posedge clk，只在tick为1的沿更新。

它不是把clk换成另一根低频时钟，也不是保证50%占空比的方波。慢时钟需要自己的时钟资源与约束；这里用时钟使能完成“隔几拍做一次”，结构更容易统一推演。

| 想做的事 | 本章方法 |
| --- | --- |
| 每4个有效时钟沿让事件数加1 | clk不变，用tick作使能 |
| 每秒让秒计数加1 | 用足够大的DIV生成使能 |
| 产生另一根可驱动大量寄存器的时钟 | 不由本章普通逻辑直接代替专用时钟设计 |

## 19.3 先把tick的时刻定义清楚

本章合同：`tick = en && !rst && (count==DIV-1)`。它由**当前、也就是有效沿前的状态**判断。rst=1屏蔽节拍，en=0也屏蔽；其余时候，count在终值就允许下一上升沿消费。

计数器与消费者在同一个沿读取旧tick。该沿之后count回0，组合tick通常随之变0。若你只在沿后看到tick=0，就说“刚才没有节拍”，会把事件发生时机看错。

这里的消费者叫events，是一个四位事件计数器，只在tick被消费的沿加1；16次后低四位回0。它用来把“沿前条件被沿上采样”变成可检查的状态变化。

## 19.4 连续使能时，第四个沿才消费

复位后count=0，DIV=4，假设en一直1、rst一直0：

| 复位后的有效沿 | 沿前count | 沿前tick | 沿后count | 沿后events |
| --- | --- | --- | --- | --- |
| 1 | 0 | 0 | 1 | 0 |
| 2 | 1 | 0 | 2 | 0 |
| 3 | 2 | 0 | 3 | 0 |
| 4 | 3 | 1 | 0 | 1 |
| 5 | 0 | 0 | 1 | 1 |

第三沿后count变成3，因此tick在接下来的周期为1；第四沿消费它。不要把“tick变高的周期”和“events更新的沿”拆开后又各算一拍，凭空多加一级。

## 19.5 暂停必须同时考虑状态和输出

本课约定en=0时**保持已有计数**，恢复后接着数。若在count=2暂停两个周期，恢复后第一次有效沿到3，再下一次消费tick。

如果在count=3暂停，tick会因en=0变0，消费者不应继续加；count仍保持3。恢复en=1后，tick重新为1，在下一上升沿正好消费一次，随后count回0。

保持部分进度，与“每次启动重新等满DIV拍”是不同合同。后者需要明确启动清零控制；不能把暂停偷偷实现成清零，再沿用保留进度的测试答案。

## 19.6 参数与最小值

位宽CW至少能表示0…DIV−1。DIV=4需2位，DIV=5需3位；三位能表示0…7，不表示我们应该用到5、6、7。本模块在4回0，所以仍为5个状态。

DIV=1时只有状态0，位宽仍保护成1。终值DIV−1=0，因此非复位且en=1时tick始终为1，每一个有效沿都允许消费者更新。这是“每拍一次”，不需要tick在两拍之间先低一下。

本实验允许正整数DIV，实际验证1、4、5三种。参数很大时还要考虑整数范围、资源与工具限制，不能从三个实例通过推出所有取值都已验证。

## 19.7 第一份完整文件：design.sv

在`logic-lab/19-tick/`保存两文件，或复制下载包`source/时序实验/19-tick/`。下面是[design.sv](时序实验/19-tick/design.sv)完整内容。

```systemverilog
module tick_counter #(
  parameter integer DIV=4,
  localparam integer CW=(DIV<=1)?1:$clog2(DIV)
)(
  input logic clk,rst,en,
  output logic [CW-1:0] count,
  output logic tick,
  output logic [3:0] events
);
  assign tick=en && !rst && (count == DIV-1);
  always_ff @(posedge clk) begin
    if (rst) count <= '0;
    else if (en) begin
      if (tick) count <= '0;
      else count <= count + 1'b1;
    end
  end
  always_ff @(posedge clk) begin
    if (rst) events <= 4'h0;
    else if (tick) events <= events + 1'b1;
  end
endmodule
```

参数头的localparam CW先计算宽度，供count输出声明使用。本例把count暴露出来用于教学观察；真实模块也可以将它留在内部，但tick合同要保持清楚。

第一个always_ff更新count：rst优先，en=0省略赋值表示保持；en=1时若终值条件tick成立就回0，否则加1。第二个always_ff更新events。两块没有共同驱动同一个状态变量，它们只是读取相同tick。

`count+1'b1`按目标状态宽度保存；正常状态不会超过DIV−1，因而在DIV=5时也不会走到三位自然溢出。不要把“按位宽回绕”与“按任意DIV回绕”混为一谈。

## 19.8 为什么本章不把tick寄存一拍

如果另写`tick_reg <= (count==DIV-1)`，再让消费者在同沿if(tick_reg)，消费者拿到的是旧tick_reg，更新时刻可能推后一沿。两种接口都能设计，但必须重新说明延迟，不能把组合tick直接换成寄存tick却保留原来的逐沿表。

本章选择沿前组合终值使能，便于计数器与消费者在同沿完成回零和加1。它也意味着en、rst变化会组合地影响tick；接收者仍只在clk上升沿采样，不把tick拿去当时钟沿。

## 19.9 第二份完整文件：tb.sv

下面是[tb.sv](时序实验/19-tick/tb.sv)完整内容。三份实例共用时钟与控制，分别采用DIV=1、4、5。

```systemverilog
`timescale 1ns/1ps
module tb;
  logic clk=0,rst,en,t1,t4,t5;
  logic c1;
  logic [1:0] c4;
  logic [2:0] c5;
  logic [3:0] h1,h4,h5;
  integer r1=0,r4=0,r5=0,e1=0,e4=0,e5=0,old4;
  logic want1,want4,want5;
  tick_counter #(.DIV(1)) u1(.clk(clk),.rst(rst),.en(en),.count(c1),.tick(t1),.events(h1));
  tick_counter #(.DIV(4)) u4(.clk(clk),.rst(rst),.en(en),.count(c4),.tick(t4),.events(h4));
  tick_counter #(.DIV(5)) u5(.clk(clk),.rst(rst),.en(en),.count(c5),.tick(t5),.events(h5));
  always #5 clk=~clk;
  initial begin
    rst=1; en=0;
    for (int i=0; i<25; i++) begin
      @(negedge clk);
      rst=(i==0 || i==14);
      en=!(i==3 || i==4 || i==6 || i==7);
      want1=!rst && en && (r1+1==1);
      want4=!rst && en && (r4+1==4);
      want5=!rst && en && (r5+1==5);
      #1;
      if ({t1,t4,t5} !== {want1,want4,want5})
        $fatal(1,"pre-edge tick i=%0d actual=%b%b%b expected=%b%b%b",i,t1,t4,t5,want1,want4,want5);
      old4=r4;
      if (rst) begin r1=0;r4=0;r5=0;e1=0;e4=0;e5=0; end
      else if (en) begin
        r1=(r1+1)%1; r4=(r4+1)%4; r5=(r5+1)%5;
        if (want1) e1=(e1+1)%16;
        if (want4) e4=(e4+1)%16;
        if (want5) e5=(e5+1)%16;
      end
      @(posedge clk); #1;
      if (c1 !== r1[0] || c4 !== r4[1:0] || c5 !== r5[2:0] ||
          h1 !== e1[3:0] || h4 !== e4[3:0] || h5 !== e5[3:0])
        $fatal(1,"post-edge counter i=%0d actual=%0d/%0d/%0d events=%0d/%0d/%0d",i,c1,c4,c5,h1,h4,h5);
      $display("TRACE tick i=%0d rst=%b en=%b pre4=%0d use4=%b post4=%0d events4=%0d",i,rst,en,old4,want4,c4,h4);
    end
    $display("PASS tick: 25 cycles, DIV=1/4/5, pause at middle/terminal and reset");
    $finish;
  end
  initial begin #400; $fatal(1,"tick timeout"); end
endmodule
```

参考状态r1/r4/r5与e1/e4/e5使用整数，初值0。驱动后先检查沿前tick，再用数学余数更新预期：`(旧计数+1)%DIV`。`%`是取余，DIV=5时4+1除以5余0；DIV=1时任何非负整数除以1余0。

消费者预期按**沿前want**决定是否加1，不使用DUT沿后的tick。接着等上升沿后1ns，检查count和events，分别验证“条件对不对”和“状态有没有按条件更新”。只检查其中一个可能漏掉连接或时机错误。

整数参考不读取DUT内部count作为自己的状态来源，否则设计数错，参考也跟着错，会失去独立判断价值。

## 19.11 运行与故障定位

在**19-tick目录的PowerShell**执行，编译成功后运行：

```powershell
iverilog -g2012 -s tb -o sim.vvp design.sv tb.sv
vvp sim.vvp
```

最后应有：

```text
PASS tick: 25 cycles, DIV=1/4/5, pause at middle/terminal and reset
```

故障一：把终值误写成count==DIV，DIV=1实例在第一个非复位沿前就给不出应有tick，测试失败。最小参数经常能比常用值更快暴露错误。

故障二：在en=0时将count清0，i=3应保持的2变成0，沿后状态检查失败。每次只在副本改一处，恢复后重编译；不能只看events还没加1，就忽略已经错掉的部分进度。

## 19.12 从频率换算真实间隔

若输入时钟50MHz，每秒有50,000,000个上升沿，周期20ns。连续使能时，DIV=50,000,000使每秒消费一次tick。计数范围0…49,999,999，2^25=33,554,432不够，2^26=67,108,864够，所以需26位。

如果暂停en，事件之间的真实时间会拉长；“每秒一次”是在持续使能、时钟频率准确、复位条件明确的前提下成立。计数器不是独立于输入时钟误差的精密钟表。

仿真先用DIV=4、5，是缩短测试时间，不代表已经实际等待一秒或检查了50MHz板卡。大参数改变后仍需相应验证，尤其是位宽与边界；本批真实执行范围见[第四阶段记录](验证/第四阶段详细重写验证记录.md)。

## 19.13 常见错误与练习

| 错误 | 结果 | 先用什么例子检查 |
| --- | --- | --- |
| 从0数到DIV才清零 | 周期多一拍 | 列DIV=4状态 |
| 暂停时count归零 | 丢部分间隔 | count=2暂停 |
| 终值时en=0仍输出tick | 暂停期间误计事件 | count=3暂停 |
| 沿后tick低就认为未消费 | 误读状态与事件顺序 | 比较沿前tick、沿后events |
| DIV=1要求高低交替 | 把使能当方波 | 每个有效沿应更新 |

练习1：DIV=5、count从0开始，第几个连续有效沿消费tick？第5个，因为前四个沿后依次1、2、3、4，第5个读到终值4。练习2：DIV=4，在count=3暂停三次，再恢复，几次有效沿后消费？恢复后的第一个沿。练习3：1MHz时钟、DIV=1000，间隔是多少？1000/1,000,000秒=1ms，事件频率1kHz，不是方波时钟的定义。
