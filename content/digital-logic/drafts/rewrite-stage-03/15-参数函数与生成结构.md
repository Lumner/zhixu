# 15 参数、函数与生成结构

> 零基础详细版。先修：第8章的模块类型与实例，第9章的向量，第12章的循环，第14章的完整组合模块。建议4–6小时，先手工把WIDTH=1、4分别展开，再读实验代码。

**本章目标：** 分清改变结构的参数与运行中变化的输入；用localparam推导内部位宽；避免只有一个元素时的边界错误；读懂组合函数和generate；用同一模块的三份不同参数实例进行验证。

## 15.1 为什么不复制三份几乎一样的模块

假设需要一位、四位、七位异或电路。你可以分别写xor1、xor4、xor7，但以后修改接口或修错误，就可能漏掉其中一份。更好的方式是写一份规则：“宽度由WIDTH决定，第i位输出等于两路输入的第i位异或。”

**参数**是制作某份模块实例时确定的常量。`WIDTH=4`表示这份实例具有四位数据口；`WIDTH=7`表示另一份有七位口。它不是接在电路上的一个信号，也不是运行中随时能把四根线变成七根线的开关。

生活中可类比按图纸选择书架层数再制作；制作好后放进哪本书，对应运行输入。类比只帮助区分两个时机，并不是说综合电路真的按软件步骤去钉木板。

## 15.2 先分清编译、展开和仿真

工具首先读入模块定义并检查语法，再根据顶层、实例与参数建立具体结构，这一步通常叫**展开**，英文elaboration。随后运行仿真时，输入变化，已经建立的结构计算输出。

| 内容 | 什么时候决定 | 本章例子 |
| --- | --- | --- |
| 模块类型 | 读源文件时看到定义 | parameter_demo |
| 实例参数 | 展开该实例时确定 | u1的WIDTH=1，u7的WIDTH=7 |
| 端口宽度、生成块数量 | 由该实例参数推导 | u7有七位a和七路逐位异或关系 |
| 输入a、b、addr | 仿真运行中可改变 | a从0000变0011 |
| 输出y、addr_ok | 随当前输入计算 | y随a/b重新计算 |

这里“先后”描述工具处理设计的阶段，不是你的电路内部有这些时钟周期。修改参数后要重新编译、展开；不能在tb中写`u1.WIDTH=7`当运行激励。

## 15.3 参数头怎样逐字符读

先看一个**完整的小模块**，用于理解语法，不是后面综合实验的全部文件：

```systemverilog
module parity_small #(
  parameter integer WIDTH = 4
)(
  input logic [WIDTH-1:0] data,
  output logic odd
);
  assign odd = ^data;
endmodule
```

module后是类型名；`#(...)`内列参数；`parameter`声明可由实例选择的常量；`integer`说明这里用整数类型；`=4`给出未覆盖时的默认值。后面的另一对括号才是普通输入输出端口。

`[WIDTH-1:0]`是从WIDTH−1编号到0，共WIDTH位。WIDTH=4形成[3:0]；WIDTH=1形成[0:0]，仍然有一位。`^data`是归约异或，输出输入中1的个数是否为奇数，odd自身始终只有一位。

本章参数用于非零正整数宽度。本实验限定1≤WIDTH≤16、1≤DEPTH≤16，便于纸笔分析；没有给WIDTH=0定义一个“零根线端口”。可调不等于任何数字都合法，模块说明需要写出范围。

## 15.4 参数连接和端口连接是两件事

下面是**父模块内部的实例化片段**，要求父模块先声明四位data4与一位odd4，并拥有上一节的模块定义：

```systemverilog
parity_small #(.WIDTH(4)) u_p(.data(data4), .odd(odd4));
```

按顺序读：使用parity_small类型；为这份实例把WIDTH设为4；实例名u_p；把端口data接到父信号data4，把odd接到odd4。

`#(.WIDTH(4))`中的4是展开期参数值；`.data(data4)`中的data4是运行时信号。两个地方都用了点号具名连接，但属于不同列表，不能把它们交换。若省略参数列表，就使用默认WIDTH=4。

同一父模块可放多份不同参数的实例，互不改变对方。对u1设置WIDTH=1，不会把类型的所有实例都改成1，也不会改掉u7的七位端口。

## 15.5 localparam为什么不能由外面随意覆盖

假设模块有DEPTH个条目，地址宽度应由DEPTH推导。若让使用者分别填写DEPTH=5、地址宽度=2，就发生矛盾：两位只能表示0…3，找不到第4项。

**localparam**是局部常量，用来保存内部推导规则，不能通过实例的`#(...)`直接覆盖。本实验把地址宽度AW写成localparam，DEPTH是使用者选择的量，AW由模块负责算。

完整实验会在参数头中同时出现parameter与localparam。这是SystemVerilog语法，AW又被后面的端口声明使用，因此放在端口前便于阅读。实例只覆盖WIDTH、DEPTH，不写`.AW(...)`。

本章不使用旧式defparam去远处修改实例参数。具名`#(...)`让“哪份实例采用什么配置”留在同一处。相关工具提示可查[Verilator官方DEFPARAM说明](https://verilator.org/guide/latest/warnings.html#defparam)，核验日期2026-11-05；本批实际仿真仍使用Icarus11。

## 15.6 $clog2究竟在算什么

若有8个条目，编号0…7，三位足够，因为2^3=8；若有5个条目，编号0…4，两位不够，三位才足够。`$clog2(DEPTH)`表示以2为底的对数向上取整，也就是“至少几位能容纳这么多种编号”。

不必先学对数公式，可以从1开始不断翻倍：1、2、4、8、16。找第一个不小于DEPTH的数，翻倍次数就是这个整数结果。

| DEPTH | 合法编号 | $clog2结果 | 本实验AW | 地址端口能表示但无效的值 |
| --- | --- | --- | --- | --- |
| 1 | 0 | 0 | 1 | 1 |
| 2 | 0…1 | 1 | 1 | 无 |
| 3 | 0…2 | 2 | 2 | 3 |
| 5 | 0…4 | 3 | 3 | 5…7 |
| 8 | 0…7 | 3 | 3 | 无 |

最容易漏掉DEPTH=1：只剩一个条目，从信息量上不需要区分编号，所以$clog2(1)=0。但在常规向量端口写`[$clog2(1)-1:0]`会形成[-1:0]，并不是你以为的“没有线”。SystemVerilog允许某些向上/负编号范围，工具不一定替你拒绝这个声明。

## 15.7 保留一位之后，还得检查地址是否合法

本实验用下面的**参数声明片段**保护最小宽度：

```systemverilog
localparam integer AW = (DEPTH <= 1) ? 1 : $clog2(DEPTH)
```

这里它处在参数列表中，末尾由列表的逗号或右括号收尾；如果在模块体单独声明，需要分号。DEPTH=1时AW=1；其他正整数时取$clog2。不要把“保护向量位宽”误认为“所有一位地址都变合法”。

当DEPTH=1、addr=1时，端口能表示这个值，但不存在编号1的条目。仍需要`addr<DEPTH`检查；DEPTH=5也要拒绝5、6、7。**能装进端口，与指向合法条目，是两种条件。**

本实验只输出addr_ok，不读写存储器。它是地址范围检查器的教学模型，尚不是RAM。以后使用RAM时，还要规定无效地址是否拒绝、返回什么数据等行为。

地址宽度与“当前有几个元素”的计数宽度也不同。8个位置只需要表示0…7，三位；数量需要表示0…8，共九种，至少四位。可用`$clog2(DEPTH+1)`思考数量位宽，不能把地址位宽机械照抄过去。

## 15.8 function先当作一个有名字的计算规则

我们还想判断一个四位输入是不是十进制数字0…9。四位能表示0…15，只有前十个是合法的BCD数字。**BCD**是binary-coded decimal，即用一组二进制位表示一位十进制数字；本节只判断一组四位码，不处理多位十进制加法。

定义一个函数，输入value，返回value≤9。函数把一段计算关系取名，调用者可使用返回值。它与module不同：module是可实例化的硬件层次，function是在表达式或过程里被调用的语言结构。

完整设计里的函数为：

```systemverilog
function automatic logic is_bcd(input logic [3:0] value);
  return value <= 4'd9;
endfunction
```

这是**模块内部定义片段**，外面还有module/end­module。`logic`在这里是一位返回类型；is_bcd是函数名；括号里是四位输入value；return把比较结果作为返回值；endfunction结束定义。

`automatic`规定调用时局部存储的生命周期，使不同调用具有独立的局部变量语义。本函数没有需要保持的历史，每次由输入得到返回值。它不等于“硬件每次调用就动态创建一份”，综合器仍会按调用位置与表达式优化逻辑。

本章用于组合逻辑的函数不等待时间，不加`#1`、等待时钟或暂停。它计算的是同一时刻的关系；需要多拍完成的任务要用后面的时序电路描述，不能靠函数里睡一会儿。

## 15.9 generate：把结构按常量展开

若WIDTH=3，逐位异或关系实际是：

```text
y[0] = a[0] XOR b[0]
y[1] = a[1] XOR b[1]
y[2] = a[2] XOR b[2]
```

generate的for描述“按规则生成这些结构”，genvar i是展开使用的索引。`i<WIDTH`由常量决定，工具能在开始仿真前确定建立多少份关系。

`begin : g_xor`给生成块取名字。WIDTH=3时，可把层次想成g_xor[0]、g_xor[1]、g_xor[2]，便于查看每位结构。它不是程序运行到for时，先在第一拍计算第0位、第二拍计算第1位。

本例可以更短地写成`assign y=a^b;`，功能相同。我们展开每位只是教学；不要得出“所有向量运算都必须用generate”的结论。generate适合结构复制、按常量选择不同硬件等情况。

## 15.10 三种for分别在哪里发生

| 写法位置 | 索引用途 | 是否意味着过了多拍 |
| --- | --- | --- |
| generate中的genvar | 展开固定数量的结构 | 否 |
| always_comb中的有限循环 | 描述组合计算步骤 | 否，不能靠循环自动得到时钟 |
| tb的initial中含#1循环 | 依次设置输入并推进虚拟时间 | 本例每次等1ns，但没有DUT时钟 |

它们可能长得相似，但上下文与是否存在延时决定语义。不要把测试平台的运行循环移到设计里，期待得到“每圈一拍”的计数器。

在`logic-lab/15-parameter/`保存两文件，或复制下载包`source/组合实验/15-parameter/`。下面是[design.sv](组合实验/15-parameter/design.sv)完整内容。

```systemverilog
{{LAB15_DESIGN}}
```

本模块把四项独立组合关系放在一起：y是逐位异或；odd是a中1的奇偶；addr_ok判断地址范围；digit_ok判断BCD。digit固定四位，刻意不写成`a[3:0]`：当WIDTH=1时，a根本没有第3位，这种切片会破坏最小参数情况。

## 15.12 第二份完整文件：tb.sv

下面是[tb.sv](组合实验/15-parameter/tb.sv)完整内容。它同时建立三份参数组合：(WIDTH=1,DEPTH=1)、(4,5)、(7,8)。

```systemverilog
{{LAB15_TB}}
```

u1端口a/b/y均一位，u4为四位，u7为七位。地址宽度分别1、3、3；不是因为u7数据七位，地址就也得七位。三份实例共用digit四位输入，各自调用同一份函数定义。

先初始化全部输入，避免无关实例一直处于X。随后分三段穷举每份数据口的a、b：2×2、16×16、128×128，共4+256+16384=16644组。`data_checks++`表示将整数计数加1，等价于`data_checks=data_checks+1`。

奇偶参考没有再用归约异或，而是逐位查看ai。`1<<k`生成第k位为1的整数掩码；若该位有1，就把expected_odd翻转一次。偶数次翻转回0，奇数次留1。这给出了与DUT不同的求解过程。

地址随后独立遍历：DEPTH=1检查0、1两值；DEPTH=5和8各检查三位地址0…7，共2+8+8=18项。最后digit从0…15共16组，每组同时核对三份实例的BCD输出。这里没有把“数据×地址×digit”的所有交叉输入穷举；各输出在设计规格上互相独立，本测试按功能分组检查。

## 15.13 运行结果怎样对应覆盖范围

```powershell
iverilog -g2012 -s tb -o sim.vvp design.sv tb.sv
vvp sim.vvp
```

主要输出是：

```text
PASS parameter: data=16644 address=18 digit=16; WIDTH=1/4/7 DEPTH=1/5/8
```

这个结果验证了三组明确参数，不能扩大成“所有合法参数均已穷举”。以后加WIDTH=16或DEPTH=3，应在新实例与验证记录里明确增加；不能只更改课程说明中的数字。

工具位宽提示的含义可查[Verilator官方WIDTH说明](https://verilator.org/guide/latest/warnings.html#width)，核验日期2026-11-05。该资料帮助理解检查方向；本批并未运行Verilator，不把阅读文档写成该工具检查通过。

## 15.14 用最小值发现边界错误

在副本中把地址条件`< DEPTH`改成`<= DEPTH`。重新编译运行后，DEPTH=1、addr=1应被错误地接受，测试报告`DEPTH=1 addr=1`并失败。原因不是位宽不够，而是上界应排除DEPTH本身：一个条目只有编号0。

这是为什么测试不能只选“看着很常见”的8。DEPTH=8的三位地址最大7，错误的`<=8`恰好不会在可表示地址上暴露；DEPTH=1和5则能检出。

另外，若写`a[WIDTH-2:0]`，WIDTH=1时范围变成[-1:0]，通常不再是想要的低位切片。更复杂的参数模块应先逐个代入最小值，查切片、拼接次数、除数和数组范围，而不是等默认值通过后再猜边界也会通过。

## 15.15 常见错误

| 错误 | 判断方法 | 修正方向 |
| --- | --- | --- |
| 把WIDTH当输入信号 | 问它是否要在仿真中改变 | 结构选择用参数，数据选择用端口 |
| `.WIDTH(...)`写在端口列表 | 看前面是否有# | 参数与端口分别连接 |
| 直接用$clog2(1)作宽度 | 把数值代入声明 | 至少保留一位，再检查合法地址 |
| DEPTH=5放行地址5 | 把条目编号列出来 | 有效范围0…DEPTH−1 |
| 数据宽度和地址宽度相同 | 写出两者分别编码什么 | WIDTH管数据，AW管编号 |
| function里加入延时 | 问这是组合关系还是多拍行为 | 多拍行为留给时序设计 |
| generate被理解成循环耗时 | 找结构里的时钟或延时 | 常量展开不会自动增加拍数 |

## 15.16 练习与过程答案

练习1：WIDTH=1时，`[WIDTH-1:0]`是多少位？代入得[0:0]，包含编号0的一位；不是0位。若WIDTH=0，得到[-1:0]，不能把它当合法零宽端口，本模块不允许。

练习2：DEPTH=3，AW和合法地址是什么？2^1=2不够，2^2=4够，所以AW=2；00、01、10合法，11表示3，无效。端口有四种表示，不表示模块有四个条目。

练习3：WIDTH=7、a=1010101，odd是多少？1在第6、4、2、0位，共四个，偶数，所以odd=0。若再把第1位置1，就有五个1，odd变1。

练习4：DEPTH=8的地址与占用数量分别几位？地址0…7三位足够；占用数量0…8有九种，三位最多7，所以需要四位。先写范围再选宽度。
