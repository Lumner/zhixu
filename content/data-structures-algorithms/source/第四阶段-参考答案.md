## 一、接口题答案

1. get/set/erase合法位置[0,n)，insert合法边界[0,n]，后者还需容量。
2. 0作为正常值通过输出参数得到；返回状态区分DS_OK、DS_EMPTY、DS_RANGE等，不能用数值0同时表达失败。
3. 若输出地址在容器内部，删除后再写结果可能改坏有效序列，甚至指向已释放节点；这里约定独立可写int且生命周期覆盖整个调用。
4. reserve只改容量不改数量；删除不缩容，空可仍保留分配，clear才释放。
5. 不能；按位置还要遍历找前驱，最坏线性。
6. root链接保存原root地址，按值复制不自动建立新root自环，还可能制造共享拥有者。
7. 用count=0或1区分；链队列删最后节点后head与tail都NULL。
8. 队列保存待处理符号的输入顺序，栈保存尚未被组合的最近数值。

## 二、同一逻辑序列的对照

| 操作完成后 | 有效值 | 数量 |
| --- | --- | --- |
| 插10、30，中间插20 | [10,20,30] | 3 |
| 把位置1改25 | [10,25,30] | 3 |
| 删头，返回10 | [25,30] | 2 |
| 删尾，返回30 | [25] | 1 |
| 删唯一，返回25 | [] | 0 |
| 再删0 | []，DS_RANGE，输出仍999 | 0 |

值相同不是所有不变量已满足：顺序表核对count/容量；单链表恰好走count节点后为NULL；循环双向表正反都回root且相邻互反。检查有界遍历，不能对可能自环无限打印。

动态数组初始自动容量4，第5次成功追加容量8；追加失败时旧内容保留。循环双向表不保存结构体副本来做快照，只比较单独的逻辑数据和数量。

## 三、表达式模块分工

expression.h声明结果类型与函数，expression.c负责协议、排队与求值，main.c只处理参数和显示。它复用第25、26章的stack与queue，不重写另一套未经解释的栈队列。

完整文件expression.h：

```c
#ifndef DSA_EXPRESSION_H
#define DSA_EXPRESSION_H
#include <stddef.h>
typedef enum { E_OK, E_TOKEN, E_CAPACITY, E_ARITY, E_DIVZERO, E_RANGE, E_LENGTH, E_INVALID } ExprStatus;
ExprStatus expression_evaluate(const char *text, int *out, size_t *error_token);
const char *expression_status_name(ExprStatus status);
#endif
```

完整文件expression.c：

```c
#include "expression.h"
#include "stack.h"
#include "queue.h"
#include <string.h>

ExprStatus expression_evaluate(const char *text, int *out, size_t *error_token)
{
    if (text == NULL || out == NULL || error_token == NULL) {
        return E_INVALID;
    }
    if (strlen(text) > 127) {
        *error_token = 0;
        return E_LENGTH;
    }
    Queue tokens;
    if (queue_init(&tokens, QUEUE_MAX_CAPACITY) != DS_OK) {
        return E_INVALID;
    }
    size_t number = 0;
    for (size_t i = 0; text[i] != '\0'; i++) {
        char ch = text[i];
        if (ch == ' ') {
            continue;
        }
        if (!((ch >= '0' && ch <= '9') || ch == '+' || ch == '-' || ch == '*' || ch == '/') ||
            (text[i + 1] != '\0' && text[i + 1] != ' ')) {
            *error_token = number;
            return E_TOKEN;
        }
        if (queue_push(&tokens, ch) != DS_OK) {
            *error_token = number;
            return E_CAPACITY;
        }
        number++;
    }
    ArrayStack values;
    stack_init(&values);
    size_t index = 0;
    int token = 0;
    while (queue_pop(&tokens, &token) == DS_OK) {
        if (token >= '0' && token <= '9') {
            if (stack_push(&values, token - '0') != DS_OK) {
                *error_token = index;
                return E_CAPACITY;
            }
        } else {
            int right = 0, left = 0;
            if (stack_pop(&values, &right) != DS_OK || stack_pop(&values, &left) != DS_OK) {
                *error_token = index;
                return E_ARITY;
            }
            long result = 0;
            switch (token) {
            case '+': result = (long)left + right; break;
            case '-': result = (long)left - right; break;
            case '*': result = (long)left * right; break;
            case '/':
                if (right == 0) {
                    *error_token = index;
                    return E_DIVZERO;
                }
                result = (long)left / right;
                break;
            default: return E_INVALID;
            }
            if (result < -9999 || result > 9999) {
                *error_token = index;
                return E_RANGE;
            }
            if (stack_push(&values, (int)result) != DS_OK) {
                *error_token = index;
                return E_CAPACITY;
            }
        }
        index++;
    }
    int final = 0;
    if (stack_pop(&values, &final) != DS_OK || values.count != 0) {
        *error_token = number;
        return E_ARITY;
    }
    *out = final;
    return E_OK;
}

const char *expression_status_name(ExprStatus status)
{
    switch (status) {
    case E_OK: return "ok";
    case E_TOKEN: return "token";
    case E_CAPACITY: return "capacity";
    case E_ARITY: return "arity";
    case E_DIVZERO: return "division-by-zero";
    case E_RANGE: return "range";
    case E_LENGTH: return "length";
    default: return "invalid";
    }
}
```

完整入口main.c及复用模块都在 [源码附录](示例代码/stage4-common/完整源码.md)。复制到同一练习目录后，按练习页的四个.c文件命令构建；不要混入栈演示或队列演示的其他main。

## 四、为什么先排队再求值

本版先扫描完整字符串，按单字符token检查、忽略ASCII空格、逐个入队。发现坏token或第17个token就返回，不在半个词法输入上继续算。只有队列准备成功，才开始数值操作。

这使输入格式与计算职责分开，也让FIFO有具体用途。正式计算器可以边扫描边求值，未必需要缓存全部token；这里是教学组合，不宣称队列是后缀求值的必要条件。

扫描最长127字节，队列最多16项，顺序值栈16格。当前token预算下，值栈不会需要超过16个数字，但仍检查push状态，以保留接口约定。空或纯空格得到空token流，最终没有结果，返回arity。

## 五、左右操作数与数值范围

遇运算符先pop right，再pop left，计算left op right。对2 8 -，先取8再取2，正确值为-6；交换后会得到6，普通加法样例无法暴露这个错误。

每个已接受中间值在[-9999,9999]。乘法先把left转long再运算，最大绝对乘积9999×9999=99980001，在标准C保证的long范围内；之后检查结果是否仍在业务范围。不能先做int乘法再把可能已溢出的结果转long。

除零在除法之前检查；允许的值范围也避开最小有符号整数除以-1的额外边界。整数除法向0截断，因此-7/2为-3，不是数学下取整-4。输出只在所有token处理后且栈中恰好一个值时写回，失败保留777。

## 六、诊断的含义

arity表示操作数不足或结束时剩余值不为1；token表示协议不接受该token；capacity是符号队列预算；division-by-zero与range是计算错误；length先于词法检查，错误token按约定0占位。

先词法后求值意味着一个很后面的坏token，可能优先于较早运算符的语义错误报告。这是本协议的验证顺序，不是声称找到了任意表达式语言全局最早的错误。

出错消息向stderr，退出1；正常result向stdout，退出0。输入通过单个引号参数提供，Shell不会把里面的*当文件通配符展开。程序不支持多位或负数字面量、变量、中缀括号、浮点或通用语言解析。

## 七、资源与复杂度

当前表达式项目只使用固定数组栈和循环队列，没有堆节点；局部对象随函数返回结束，不需要free。编译进来的链栈/链队列函数并未因此自动执行或分配。

推广到文本长度L与token数k的模型，扫描O(L)，每token入出队一次、值栈常数次操作，求值O(k)；如果缓存全部token，额外存储O(k)。当前固定上限带来明确预算，不把它说成无限容量服务。

链结构的其他演示仍要clear，动态数组仍要释放，不能因为表达式项目没有malloc就忘记本阶段整体资源责任。真实验证与限制见 [第四阶段验证记录](验证/第四阶段验证记录.md)。
