# 第三阶段练习：查找对照实验台

## 一、范围与投入

先完成17—20章，建议5—7小时。先手算再写程序，答案另见 [第三阶段参考答案](第三阶段-参考答案.md)。本阶段不修改第二阶段资料目录，不提前加入排序或散列；使用独立的有序整数序列，集中检查算法约定、正确性和工作量。

## 二、闭卷解释

1. 为“最大值最早位置”写前置条件、成功结果与失败保证。
2. 求和循环开始时i表示准备处理的位置，已处理前缀是什么？终止依据是什么？
3. 两个先后执行的n次循环与两层n次嵌套的量级分别是什么？
4. O、Ω、Θ能否分别直接翻译为最坏、最好、平均？说明原因。
5. 顺序查找平均(n+1)/2次比较依赖什么概率假设？
6. 递归求和的总调用数和最大活跃层数是多少？汉诺塔又有什么区别？
7. 对[2,4,4,9]找5，下界与第一个相等结果分别是什么？
8. 为什么二分查询前每次重新验证整个输入，会改变完整流程的复杂度？

## 三、先画表，再编码

对序列[2,4,4,9]分别查找0、2、4、5、9、10，画每轮lo、hi、mid、访问值与新范围。单独记下下界比较次数，精确匹配再判断是否需要额外==。找到重复4时，必须返回第一次出现的位置1。

然后写出以下测试的期望：空序列、一个数、全相等、目标比全部值小、比全部值大。空输入不创建0容量数组，不读取哨兵count位置。

## 四、实现独立查找实验台

在自己的`~/dsa-labs/stage3`目录准备main.c、search.h、search.c。先自行实现三个查询接口，再参考第20章；从空文件写，不把二分循环当无法解释的模板。

输入协议：

- 命令行一个目标整数，范围0—9999，只接受一个或多个十进制数字，允许前导零。
- 标准输入第一行是数量0—128，接着count行，每行一个0—9999的值。
- 输入必须非递减；失败时不自动排序，向stderr报告。
- 空行、符号、空格、小数、过长数值或缺失元素都拒绝；最后一行可没有换行。
- 读取约定数量后不再检查额外行；本工具是受限文本协议，不是任意二进制输入和完整I/O故障诊断工具。

正常时输出count、target、lower位置、顺序查询位置和比较次数、二分查询位置和比较次数，并显示found=0或1。不存在时位置为count；下界仍是合法插入边界，不能直接把它当相等匹配。

编译运行在 **UCRT64 Bash、自己的stage3目录**：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic main.c search.c -o search_lab.exe
printf '6\n1\n3\n3\n3\n8\n12\n' | ./search_lab.exe 3
```

预期：

```text
count=6 target=3
lower=1
linear=1 comparisons=2 found=1
binary=1 comparisons=4 found=1
```

这里binary计数包含下界的3次<，再加一次==。顺序方法的2次更少，不能把小样例强行写成“二分一定更快”。

## 五、验收矩阵

| 输入 | 目标 | 关键结果 |
| --- | --- | --- |
| 空 | 3 | lower=0，两种查找index=0且found=0，比较0 |
| [3] | 3 | lower=0，两种找到0 |
| [3] | 2 | lower=0，但两种都未找到、哨兵1 |
| [3] | 4 | lower=1，未找到 |
| [3,3,3] | 3 | 两种都找到0 |
| [1,3,3,3,8,12] | 4 | lower=4，未找到、哨兵6 |
| 同上 | 12 | 找到5 |
| 同上 | 13 | lower=6，未找到 |
| [5,1,4] | 1 | 拒绝无序输入，不报告伪造查询结果 |
| 数量129或值10000 | 任意合法目标 | 范围错误，状态1 |
| 缺元素、12x、空行 | 任意合法目标 | 输入错误，状态1 |

再增加一次有较大规模的有序输入，比如0—127，找127：顺序需要128次比较；二分精确查找的次数按你的跟踪表推导，不用墙上秒表猜复杂度。
