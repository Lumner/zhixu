# 25 栈与括号匹配

## 25.1 目标与先修

先掌握顺序表、单链表与第19章调用栈。建议5—7小时。本章把操作限制在同一端，分别实现顺序栈和链栈，再写一个能报告位置的括号检查器。先理解后进先出，再看代码如何实现它。

叠放的盘子只能从顶部取。先放10，再放20，先取出的应是20。这种规则叫**后进先出**，LIFO。栈顶是允许插入和删除的一端，不是数值最大的元素。

## 25.2 栈的ADT与两种表示

push压入、pop取出并移除、peek只观察栈顶，空时pop/peek返回DS_EMPTY，不把0当空标志。本阶段输出地址沿用第21章的独立变量约定，失败不改输出。

顺序栈data[0..count)有效，栈顶在count-1。push先查满，再写data[count]、count++；pop先查空，再取data[count-1]、count--。顺序栈固定16格，不能先减count再检查空，否则无符号数量会下溢。

链栈top指最上方节点，新节点next指旧top；弹出时保存旧top的值与next，再改top、释放旧节点。count为0时top必须NULL。链栈有64项实验预算，并可能分配失败，不等于永远不会满或失败。

## 25.3 接口、完整实现与基本实验

把 [stack.h](示例代码/25-stack/stack.h)、[stack.c](示例代码/25-stack/stack.c)、[main.c](示例代码/25-stack/main.c) 与 [共享头](示例代码/stage4-common/ds_status.h) 复制到自己的`~/dsa-labs/ch25`。

完整文件stack.h：

```c
#ifndef DSA_STACK_H
#define DSA_STACK_H
#include "ds_status.h"

#define STACK_CAPACITY 16
typedef struct { int data[STACK_CAPACITY]; size_t count; } ArrayStack;
typedef struct StackNode { int value; struct StackNode *next; } StackNode;
typedef struct { StackNode *top; size_t count; } LinkedStack;
void stack_init(ArrayStack *stack);
DsStatus stack_push(ArrayStack *stack, int value);
DsStatus stack_pop(ArrayStack *stack, int *out);
DsStatus stack_peek(const ArrayStack *stack, int *out);
void lstack_init(LinkedStack *stack);
void lstack_clear(LinkedStack *stack);
DsStatus lstack_push(LinkedStack *stack, int value);
DsStatus lstack_pop(LinkedStack *stack, int *out);
DsStatus lstack_peek(const LinkedStack *stack, int *out);
#endif
```

完整文件stack.c：

```c
#include "stack.h"
#include <stdlib.h>

void stack_init(ArrayStack *stack) {
    stack->count = 0;
}
DsStatus stack_push(ArrayStack *stack, int value)
{
    if (stack->count == STACK_CAPACITY) {
        return DS_FULL;
    }
    stack->data[stack->count] = value;
    stack->count++;
    return DS_OK;
}
DsStatus stack_pop(ArrayStack *stack, int *out)
{
    if (out == NULL) {
        return DS_INVALID;
    }
    if (stack->count == 0) {
        return DS_EMPTY;
    }
    *out = stack->data[stack->count - 1];
    stack->count--;
    return DS_OK;
}
DsStatus stack_peek(const ArrayStack *stack, int *out)
{
    if (out == NULL) {
        return DS_INVALID;
    }
    if (stack->count == 0) {
        return DS_EMPTY;
    }
    *out = stack->data[stack->count - 1];
    return DS_OK;
}
void lstack_init(LinkedStack *stack) {
    stack->top = NULL;
    stack->count = 0;
}
void lstack_clear(LinkedStack *stack)
{
    StackNode *node = stack->top;
    while (node != NULL) {
        StackNode *next = node->next;
        free(node);
        node = next;
    }
    lstack_init(stack);
}
DsStatus lstack_push(LinkedStack *stack, int value)
{
    if (stack->count == DS_MAX_ITEMS) {
        return DS_FULL;
    }
    StackNode *node = malloc(sizeof *node);
    if (node == NULL) {
        return DS_MEMORY;
    }
    node->value = value;
    node->next = stack->top;
    stack->top = node;
    stack->count++;
    return DS_OK;
}
DsStatus lstack_pop(LinkedStack *stack, int *out)
{
    if (out == NULL) {
        return DS_INVALID;
    }
    if (stack->count == 0) {
        return DS_EMPTY;
    }
    StackNode *node = stack->top;
    int saved = node->value;
    stack->top = node->next;
    free(node);
    stack->count--;
    *out = saved;
    return DS_OK;
}
DsStatus lstack_peek(const LinkedStack *stack, int *out)
{
    if (out == NULL) {
        return DS_INVALID;
    }
    if (stack->count == 0) {
        return DS_EMPTY;
    }
    *out = stack->top->value;
    return DS_OK;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch25`目录**：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic main.c stack.c -o stack.exe
./stack.exe
```

预期`array_pop=20 linked_pop=20`。两种表示都遵守同一LIFO行为，但一份使用内嵌数组，另一份拥有需释放的节点。入口在退出前clear链栈；顺序栈没有堆资源。

push/pop/peek的结构修改在本模型下为Θ(1)，链栈分配器本身的时间另论；clear链栈需Θ(n)。存储按容量或节点数计算。它们与第19章的语言调用栈是同类后进先出思想，但这里是我们自己实现、自己维护的容器，不是直接控制编译器调用栈。

## 25.4 为什么括号需要“最近的未完成任务”

看`([x])`：遇到左圆括号，记下它；遇到左方括号，再记下；右方括号应先匹配最近的左方括号，之后右圆括号匹配更早的左圆括号。

若按最早进入的左括号先处理，就会把右方括号与左圆括号比较，得到错误判断。这里需要的正是栈，而不是下一章的先进先出队列。

栈里保存左括号的原文**字节下标**，不只保存括号字符。这样可以回查种类，也能报告未闭合的位置。本例输入最多256字节，下标转int最多255，在int保证范围内。

## 25.5 先明确检查器的诊断规则

检查器处理()、[]、{}，其他字符忽略。它不是C语法解析器，不识别引号或注释，所以引号中的括号也按普通括号字符处理。

在长度与深度预算内，扫描时第一次遇到无可匹配或种类不符的右括号，就报告该右括号位置；若一直没有这种错误，最后还有左括号，报告**最早仍未闭合的左括号**位置。

| 输入 | 结果 | 原因 |
| --- | --- | --- |
| 空文本、abc、([]) | ok | 没有未解决括号 |
| ) | mismatch，0 | 没有可匹配的左括号 |
| ([)] | mismatch，2 | 最近左括号是[，不能配) |
| [( | unclosed，0 | 到末尾才发现，两枚中最早剩余位置0 |
| 17个连续左括号 | depth，16 | 超过顺序栈16层预算 |
| 257字节 | length，256 | 先检查长度，尚未做括号判断 |

“最早”要连同规则理解：对([)]不是报告位置0，而是首次无法合法匹配的右括号2。长度错误优先于扫描错误；深度超限是资源预算，不等同于括号种类不符。

## 25.6 完整检查器的执行步骤

额外复制 [brackets.h](示例代码/25-stack/brackets.h)、[brackets.c](示例代码/25-stack/brackets.c)、[brackets_main.c](示例代码/25-stack/brackets_main.c) 到同一练习目录。它是另一份完整程序，不与前一份main.c同时链接。

完整文件brackets.c：

```c
#include "brackets.h"
#include "stack.h"
#include <string.h>

BracketStatus brackets_check(const char *text, size_t *error_position)
{
    if (text == NULL || error_position == NULL) {
        return B_INVALID;
    }
    size_t length = strlen(text);
    if (length > 256) {
        *error_position = 256;
        return B_LENGTH;
    }
    ArrayStack pending;
    stack_init(&pending);
    for (size_t i = 0; i < length; i++) {
        char ch = text[i];
        if (ch == '(' || ch == '[' || ch == '{') {
            if (stack_push(&pending, (int)i) != DS_OK) {
                *error_position = i;
                return B_DEPTH;
            }
        } else if (ch == ')' || ch == ']' || ch == '}') {
            int opening = 0;
            if (stack_peek(&pending, &opening) != DS_OK ||
                !((text[opening] == '(' && ch == ')') ||
                  (text[opening] == '[' && ch == ']') ||
                  (text[opening] == '{' && ch == '}'))) {
                *error_position = i;
                return B_MISMATCH;
            }
            if (stack_pop(&pending, &opening) != DS_OK) {
                return B_INVALID;
            }
        }
    }
    if (pending.count > 0) {
        int earliest = 0;
        while (stack_pop(&pending, &earliest) == DS_OK) {
        }
        *error_position = (size_t)earliest;
        return B_UNCLOSED;
    }
    return B_OK;
}

const char *brackets_status_name(BracketStatus status)
{
    switch (status) {
    case B_OK: return "ok";
    case B_MISMATCH: return "mismatch";
    case B_UNCLOSED: return "unclosed";
    case B_DEPTH: return "depth";
    case B_LENGTH: return "length";
    default: return "invalid";
    }
}
```

遇左括号push位置；遇右括号先peek，空或种类不符就失败，相配才pop。`||`短路确保peek失败时不会继续用opening访问错误位置。

末尾仍有待配左括号时，逐个pop直到空，最后弹出的是栈底，也就是最早未闭合位置。这只是诊断时用现有ADT取信息，没有改变正常LIFO规则。

成功时error_position不改；有具体诊断时写位置；NULL文本或NULL输出返回B_INVALID。所有文本参数必须指向正确终止且仍有效的字符串。

## 25.7 运行与逐轮跟踪

在 **UCRT64 Bash、ch25目录**：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic brackets_main.c brackets.c stack.c -o brackets.exe
./brackets.exe '([])'
./brackets.exe '([)]'
```

第一条输出ok，状态0；第二条向stderr输出`mismatch position=2`，状态1。使用引号把整个文本交给一个argv参数。旧MinGW的%zu兼容选项沿用第09章。

对([])跟踪：位置0压入0，位置1压入1，位置2匹配[并弹出1，位置3匹配(并弹出0；最后栈空。每个括号至多压入、弹出一次，推广到长度L和允许深度D的模型，时间O(L)，额外栈空间O(D)。当前固定16格使实际存储有明确上限。

## 25.8 常见错误

- 用FIFO匹配左括号，破坏最近嵌套关系。
- 只数左右数量相等就判正确，([)]数量相等但种类次序错误。
- 空栈先count--，再读栈顶。
- 未闭合时直接报栈顶，得到最后而非约定的最早剩余位置。
- 认为所有非ok都是语法错误，忽略长度或深度预算。
- 链栈压入失败后仍改top或count，丢掉原内容。

## 25.9 练习与参考答案

练习一：依次push 1、2，peek一次再pop两次，输出顺序是什么？

答案：peek为2但不删除，随后pop为2、1，再pop返回DS_EMPTY且输出变量不变。

练习二：`((]`按本规则报告哪个位置？

答案：位置2的]，为第一次无法匹配的右括号；不等到末尾再报左括号。

练习三：`[(]`与`[(`为什么诊断类型不同？

答案：前者的]不能匹配最近的(，位置2 mismatch；后者没有错误右括号，到末尾为unclosed位置0。
