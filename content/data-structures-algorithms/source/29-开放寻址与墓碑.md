# 29 开放寻址、墓碑与重散列

## 29.1 目标与先修

先完成第28章键值协议、第22章分配失败保留与容量增长。建议6—9小时。目标是手推探测和绕回，解释EMPTY与DELETED为什么不同，分别计算有效负载和占用负载，并实现先建新表再提交的重散列。

拉链法把同桶项放到外部节点。**开放寻址open addressing**把所有键值保存在表的槽位数组中；碰撞时按确定顺序寻找别的槽。这里的“开放”不表示可以随意跳到任何位置，插入、查找、删除必须使用同一探测规则。

## 29.2 线性探测：沿着车位逐格走

初始槽位h(key)=key%capacity。第step次访问`(h(key)+step)%capacity`，step从0到capacity-1。这叫**线性探测linear probing**，一圈恰好访问所有槽位一次。容量8，键7、15、23依次去7、0、1，体现下标绕回。

```text
容量8，加入0、8、16：
下标       0        1        2       3 ... 7
状态     LIVE     LIVE     LIVE    EMPTY
键         0        8       16
```

key=0是正常键；value=0也可以。不能拿某个键值代替空状态。每槽有独立枚举state，键值仅在LIVE时有意义。探测至少要有循环上界；协议出问题或表真满时，不能让while永远转圈。

## 29.3 删除为什么不能写成EMPTY

若删除8后直接把槽1设EMPTY，查16会先见0，再见EMPTY，于是错误地认为后面不会有16。过去插入时，槽1曾占用，16才被挤到槽2。删除不能抹掉这条历史证据。

**墓碑tombstone**记作SLOT_DELETED：此格没有有效记录，但探测必须继续。三种状态的行为如下：

| 状态 | 查找 | 已确认键不存在后的插入 | 是否计入count / used |
| --- | --- | --- | --- |
| EMPTY 从未占用或刚重建的空格 | 可停止并报告缺失 | 可用 | 否 / 否 |
| LIVE 有效记录 | 比较完整键，不同则继续 | 不可覆盖 | 是 / 是 |
| DELETED 墓碑 | 继续，不能当结果 | 可复用 | 否 / 是 |

先查完整条有效探测路径，确认没有重复键，才选择空位。本版把这分成locate和place两步：locate跳过墓碑查重，place才可在遇到的第一个非LIVE槽落下。若一见墓碑就直接插入，后面可能已存在同键，破坏唯一性。

## 29.4 count、used与清墓碑

count是LIVE数量；used是LIVE加DELETED数量，即尚未被清理的占用痕迹数。始终0<=count<=used<=capacity。删除使count减1，used不变；复用墓碑使count加1，used不变；使用EMPTY使二者都加1。重建只搬LIVE，所以新used=count。

有效负载α=count/capacity；占用负载β=used/capacity。α很低但β很高时，失败查询仍可能经过很长的墓碑段。因此仅凭“有效项少”不能证明探测短。

本版容量只能8、16、32、64，初始0表示尚未申请数组；最多48项。新增前：若count+1超过容量的3/4就翻倍；否则，若used+1超过3/4就同容量重建，清墓碑。容量0第一次新增申请8格。超过48项直接H_FULL，不申请128格。

`used+1`按“下一项可能用EMPTY”作保守判断，即使本次本可复用墓碑，也可能先清理。它让规则简单、used不超过3/4，但不是最少分配次数的优化。清理也可能分配失败，此时即使物理上还有墓碑可用，本接口仍返回H_MEMORY并保留旧表。

手推：容量8，加入0—5，count=used=6；删0—4后count=1、used=6；再加6，count+1=2不需扩容，但used+1=7>6，先同容量清理，再加6，得到count=used=2。

## 29.5 重散列不是直接复制数组

8取模与16取模结果可能不同，例如键8原起点0，新起点8。**重散列rehash**是按新容量重新计算位置并重新放入所有有效键，不能memcpy旧槽布局后只改capacity。

open_rehash允许调用者指定合法容量，只要count<=新容量*3/4；可主动清理或缩小，但不会自动缩容。先calloc新槽数组；HSlot只含枚举和int，全零使state等于枚举首项SLOT_EMPTY。这里不依赖“全零字节必定能表示任意类型的空指针”。

把LIVE项放入临时OpenMap next；这期间不修改旧表。新表足够空，place不分配、不失败。全部搬好后才free旧数组，再以结构体赋值转移新数组所有权。成功后旧内部地址全部失效；失败旧slots、capacity、count、used和值保持。

重建后新增也必有空位：已有count低于目标阈值，并已预留下一项空间。因此私有place无需返回“满”；它只在这些已证明前提下调用，不能单独当通用公开插入函数。

## 29.6 完整接口与C实现

下载 [共享状态头](示例代码/stage5-common/hash_status.h)、[open_map.h](示例代码/29-open-addressing/open_map.h)、[open_map.c](示例代码/29-open-addressing/open_map.c)、[main.c](示例代码/29-open-addressing/main.c) 到自己的`~/dsa-labs/ch29`，放同一目录。

沿用上一章0—9999键、任意int值、重复拒绝、set只更新已有键。get的out必须是独立变量，失败不写；对象地址必须有效且已初始化。init不释放已有数组，重复init会漏资源，要用clear。clear后可继续使用。不得复制拥有数组的OpenMap后让两份分别clear。

完整文件open_map.h：

```c
#ifndef DSA_OPEN_MAP_H
#define DSA_OPEN_MAP_H
#include "hash_status.h"
typedef enum { SLOT_EMPTY, SLOT_LIVE, SLOT_DELETED } SlotState;
typedef struct { SlotState state; int key; int value; } HSlot;
typedef struct { HSlot *slots; size_t capacity; size_t count; size_t used; } OpenMap;
void open_init(OpenMap *map);
void open_clear(OpenMap *map);
HStatus open_rehash(OpenMap *map, size_t capacity);
HStatus open_put(OpenMap *map, int key, int value);
HStatus open_get(const OpenMap *map, int key, int *out);
HStatus open_set(OpenMap *map, int key, int value);
HStatus open_erase(OpenMap *map, int key);
#endif
```

完整文件open_map.c：

```c
#include "open_map.h"
#include <stdlib.h>

static size_t locate(const OpenMap *map, int key)
{
    if (map->capacity == 0) {
        return 0;
    }
    size_t start = (size_t)key % map->capacity;
    for (size_t step = 0; step < map->capacity; step++) {
        size_t i = (start + step) % map->capacity;
        if (map->slots[i].state == SLOT_EMPTY) {
            break;
        }
        if (map->slots[i].state == SLOT_LIVE && map->slots[i].key == key) {
            return i;
        }
    }
    return map->capacity;
}
static void place(OpenMap *map, int key, int value)
{
    size_t start = (size_t)key % map->capacity;
    for (size_t step = 0; step < map->capacity; step++) {
        size_t i = (start + step) % map->capacity;
        if (map->slots[i].state != SLOT_LIVE) {
            if (map->slots[i].state == SLOT_EMPTY) {
                map->used++;
            }
            map->slots[i].state = SLOT_LIVE;
            map->slots[i].key = key;
            map->slots[i].value = value;
            map->count++;
            return;
        }
    }
}
void open_init(OpenMap *map)
{
    map->slots = NULL;
    map->capacity = map->count = map->used = 0;
}
void open_clear(OpenMap *map)
{
    free(map->slots);
    open_init(map);
}
HStatus open_rehash(OpenMap *map, size_t capacity)
{
    if ((capacity != 8 && capacity != 16 && capacity != 32 && capacity != 64) ||
        map->count > capacity * 3 / 4) {
        return H_INVALID;
    }
    HSlot *slots = calloc(capacity, sizeof *slots);
    if (slots == NULL) {
        return H_MEMORY;
    }
    OpenMap next = {slots, capacity, 0, 0};
    for (size_t i = 0; i < map->capacity; i++) {
        if (map->slots[i].state == SLOT_LIVE) {
            place(&next, map->slots[i].key, map->slots[i].value);
        }
    }
    free(map->slots);
    *map = next;
    return H_OK;
}
HStatus open_put(OpenMap *map, int key, int value)
{
    if (key < 0 || key > H_KEY_MAX) {
        return H_INVALID;
    }
    if (locate(map, key) != map->capacity) {
        return H_DUPLICATE;
    }
    if (map->count == H_MAX_ITEMS) {
        return H_FULL;
    }
    size_t target = map->capacity;
    if (target == 0) {
        target = 8;
    }
    else if (map->count + 1 > target * 3 / 4) {
        target *= 2;
    }
    if (target != map->capacity || map->used + 1 > target * 3 / 4) {
        HStatus status = open_rehash(map, target);
        if (status != H_OK) {
            return status;
        }
    }
    place(map, key, value);
    return H_OK;
}
HStatus open_get(const OpenMap *map, int key, int *out)
{
    if (key < 0 || key > H_KEY_MAX || out == NULL) {
        return H_INVALID;
    }
    size_t i = locate(map, key);
    if (i == map->capacity) {
        return H_MISSING;
    }
    *out = map->slots[i].value;
    return H_OK;
}
HStatus open_set(OpenMap *map, int key, int value)
{
    if (key < 0 || key > H_KEY_MAX) {
        return H_INVALID;
    }
    size_t i = locate(map, key);
    if (i == map->capacity) {
        return H_MISSING;
    }
    map->slots[i].value = value;
    return H_OK;
}
HStatus open_erase(OpenMap *map, int key)
{
    if (key < 0 || key > H_KEY_MAX) {
        return H_INVALID;
    }
    size_t i = locate(map, key);
    if (i == map->capacity) {
        return H_MISSING;
    }
    map->slots[i].state = SLOT_DELETED;
    map->count--;
    return H_OK;
}
```

locate返回capacity表示缺失。初始capacity=0时返回0，不取余也不访问NULL数组。所有用到key取余的路径都在公开接口先检查键。最大容量64，start+step至多126；这个预算内没有加法溢出。推广到巨大表时仍须重新检查容量乘法和取余前求和，不能认为`%`能修复先前溢出。

预期：

```text
after_delete key16=160 count=2 used=3 capacity=8
duplicate=1
after_rehash count=3 used=3 capacity=16
```

删8后查询16跨过墓碑；重复插16被拒绝，旧160保留。加入24会复用墓碑，然后主动按16格重建；新used恰好等于有效数3。把演示改为加入7、15、23，画出7→0→1的探测；删除7后仍应查到23。

自动增长点：第7项从8到16格，第13项到32，第25项到64。第49个新键报告H_FULL，既有48项不变；满表中put已有键仍先报告H_DUPLICATE。本版公开操作始终保留EMPTY槽，因此资源“满”是48项预算到达，并不是64格全LIVE。不要为了测试物理全满而手工破坏内部状态，再把结果算作合法API验收。

## 29.8 探测成本与聚集

连续LIVE或墓碑形成长段，新碰撞更容易挤入这段，叫**聚集clustering**。线性探测容易出现这种现象，单次查找/新增/删除最坏O(capacity)。负载受控且散列分布良好时，才适合讨论短探测的平均或期望行为。本版简单取余没有随机化，不保证任意输入下的期望常数。

重建需要初始化新capacity格，再为n个有效项找位置。良好分散时可接近O(capacity+n)；最坏全部碰撞，逐次放置可能比较1+2+…+n格，严格上界O(capacity+n²)。不要把第22章连续数组扩容的线性搬运结论直接套到带探测的重散列。

扩容过程中旧表与新表同时存在，额外申请新capacity*sizeof(HSlot)字节；成功后只保留新数组。固定小预算不是无限大词典。二次探测、双重散列、Robin Hood等属于不同策略；步长不当可能走不满全表，本章只实现步长1的线性探测。

## 29.9 常见错误

删键写EMPTY截断探测；墓碑后面的重复键漏查；用key=0表示空；把used随删除一起减；复制旧槽布局后改模数；先free旧表再申请新表；忽略同容量清理的失败；无循环上界；把48项预算满误写成64格全占；声称所有重建必定线性。

## 29.10 练习与参考答案

练习一：容量8，7、15、23分别落在哪？删除15后23还能查到吗？答案：7、0、1；槽0为DELETED，查23跳过它，仍到槽1。

练习二：count=2、used=6、capacity=8，α与β分别是多少？答案：1/4与3/4。新键加入前本策略会做同容量清理，若分配失败则不加入。

练习三：新容量16，把旧key8留在槽0是否总正确？答案：不正确；查找从8开始，若槽8是EMPTY会立即判缺失，应重新按新探测序列放置。
