# 42 哈夫曼树与前缀编解码

## 42.1 目标与先修

先完成树、路径和最小项选择，建议8—11小时。目标是手工合并权重，从根到叶生成前缀码，完成按字节编码/解码，处理空和单符号，并说明最优性范围及真实压缩文件还缺哪些部分。

若A很常见、B很少见，可让常见符号用短码、少见者用长码，减少总编码位数。但必须能无歧义解码，不能随便给A码0、B码01后直接串在一起。

## 42.2 固定长度与前缀码

四种符号固定长度可各用2位。**前缀码prefix code**要求任何一个符号完整码字都不是另一个码字的开头。码字放在二叉树的叶上，向左记0、向右记1；到叶即一个符号，所以叶不会再向下延伸成另一符号的完整码。

如D=0、C=10、A=110、B=111，从根走到叶立即输出并回根，无需在符号间插分隔符。码字可以变长，但不能在输入结束时还停在内部节点，否则是截断编码。

## 42.3 用最小两棵树反复合并

**权重weight**在本例表示符号频数。每个符号先是一棵单叶树，反复选权重最小的两棵，以新根连接，新权重为两者之和，直到只剩一棵。

| 当前权重 | 合并 | 新集合 |
| --- | --- | --- |
| A5,B7,C10,D15 | 5+7=12 | C10,12,D15 |
| C10,12,D15 | 10+12=22 | D15,22 |
| D15,22 | 15+22=37 | 根37 |

第一棵较小者放左、第二棵放右，得到D=0、C=10、A=110、B=111。相同权重可能产生多个同样最优码表；本版按创建下标较小者先选来确定结果，同一输入顺序可复现，不要求所有教材码字完全一致。

## 42.4 为什么选择最小两项有依据

加权编码成本为Σ频数×码长。最优前缀树可以取为每个内部节点都有两孩子：只有一个孩子的内部节点可以缩短路径而不损失可区分性。

在一棵最优树的最深兄弟叶位置，可以通过交换符号把两个最小权重放进去而不增加成本：让较小权重走更长路径不会比相反安排更贵。将这对兄弟合为权重之和的一个叶，得到更小的同类问题；展开时只增加这两权重之和的成本。反复应用便得到哈夫曼合并。

这是当前“每个符号一个码字、二进制前缀码、已知正权重”模型的最优性，不意味着对任意文件都比所有压缩方式更小。第49章会进一步练习这种局部选择的交换论证，不能把“每次选最小”泛化为任何问题都对。

## 42.5 本课有界数组表示

最多8种不同字节，权重每种1—1000；没出现的符号应省略，不用0权重混进来。符号可为0或255，不只限可打印英文；相同字节重复定义T_DUPLICATE，非法权重T_INVALID，超过8种T_FULL，建表失败旧对象保持。

s>0时共2s-1个节点，最多15格。叶先放0到s-1，新内部节点随后创建，left/right/parent保存数组下标，-1代表无链接；不把symbol=0当空。根是最后创建节点；空表root=-1。

本实现扫描active数组找最小项，构建O(s²)，空间O(s)。第41章的优先队列可以启发更大码表的实现，但其Job与本节点类型/预算不同，本版不强转指针或偷偷改旧堆。堆优化可使最小项选择合计O(s log s)，这里明确尚未实现。

## 42.6 从叶沿parent反向收集码字

叶往父走，若自己是父的left，记录0，否则记录1；得到的是反向路径，最后逆序写回。8叶树路径最长7边；局部9字节code空间能装码字和结尾零。本版code只由ASCII字符'0'/'1'组成。

空码表无符号码字；单符号树根就是叶，数学路径长0，但空码字无法仅凭位串还原重复次数。因此本协议明确给唯一符号码`0`，每个0解出一个字节，1非法；编码成本按1位计，不把它与零边路径成本混淆。

## 42.7 编解码接口的容量与失败约定

接口见 [huffman.h](示例代码/42-huffman/huffman.h)。对象先huff_init或成功build；不含堆指针，可以按值复制，无需free。每个输入/输出缓冲区和数量变量独立，不与对象或彼此重叠；任意坏地址不能由函数验证。

| 操作 | 成功输出 | 边界 |
| --- | --- | --- |
| code | 零终止的0/1码字 | out不可NULL；容量含结尾零，缺符号T_MISSING |
| encode | 零终止0/1文本，另写有效位数 | 消息0—64字节，正长度text非NULL；输出/位数非NULL，容量至少bits+1 |
| decode | 原始字节及有效数量，不加零终止 | 输入0—448位；输出最多64字节；out可NULL仅capacity=0，数量变量必需 |

未知消息字节或非法/截断位串T_INVALID，预算超出T_FULL，输出空间不足T_SPACE。所有失败保留输出和数量。先在局部候选缓冲完成校验，再复制到调用者空间，不边输出边遇错。空表只接受空消息/空位串；空encode仍需要一格结尾零，空decode可NULL/0。

## 42.8 完整实现

完整文件huffman.c：

```c
#include "huffman.h"
#include <string.h>
void huff_init(Huffman *tree) { *tree = (Huffman){0}; tree->root = -1; }
static int minimum(const Huffman *tree, const int *active)
{
    int best = -1;
    for (size_t i = 0; i < tree->count; i++) {
        if (active[i] && (best < 0 || tree->nodes[i].weight < tree->nodes[best].weight)) { best = (int)i; }
    }
    return best;
}
TStatus huff_build(Huffman *tree, const HuffSymbol *symbols, size_t n)
{
    if (n != 0 && symbols == NULL) { return T_INVALID; }
    if (n > HUFF_SYMBOLS) { return T_FULL; }
    for (size_t i = 0; i < n; i++) {
        if (symbols[i].weight == 0 || symbols[i].weight > 1000) { return T_INVALID; }
        for (size_t j = 0; j < i; j++) { if (symbols[j].symbol == symbols[i].symbol) { return T_DUPLICATE; } }
    }
    Huffman next; huff_init(&next); int active[HUFF_NODES] = {0};
    next.symbols = next.count = n;
    for (size_t i = 0; i < n; i++) { next.nodes[i] = (HuffNode){symbols[i].weight,-1,-1,-1,symbols[i].symbol}; active[i] = 1; }
    for (size_t remaining = n; remaining > 1; remaining--) {
        int left = minimum(&next, active); active[left] = 0;
        int right = minimum(&next, active); active[right] = 0;
        int parent = (int)next.count++;
        next.nodes[parent] = (HuffNode){next.nodes[left].weight + next.nodes[right].weight,left,right,-1,0};
        next.nodes[left].parent = next.nodes[right].parent = parent; active[parent] = 1;
    }
    next.root = n == 0 ? -1 : (int)next.count - 1;
    *tree = next; return T_OK;
}
static size_t code_at(const Huffman *tree, int leaf, char *code)
{
    if (tree->symbols == 1) { code[0] = '0'; code[1] = '\0'; return 1; }
    char reverse[HUFF_SYMBOLS]; size_t n = 0;
    while (tree->nodes[leaf].parent >= 0) {
        int parent = tree->nodes[leaf].parent;
        reverse[n++] = tree->nodes[parent].left == leaf ? '0' : '1'; leaf = parent;
    }
    for (size_t i = 0; i < n; i++) { code[i] = reverse[n - 1 - i]; }
    code[n] = '\0'; return n;
}
TStatus huff_code(const Huffman *tree, unsigned char symbol, char *out, size_t capacity)
{
    if (out == NULL) { return T_INVALID; }
    for (size_t i = 0; i < tree->symbols; i++) {
        if (tree->nodes[i].symbol == symbol) {
            char code[HUFF_SYMBOLS + 1]; size_t n = code_at(tree, (int)i, code);
            if (capacity <= n) { return T_SPACE; }
            memcpy(out, code, n + 1); return T_OK;
        }
    }
    return T_MISSING;
}
TStatus huff_encode(const Huffman *tree, const unsigned char *text, size_t n, char *out, size_t capacity, size_t *bits)
{
    if (out == NULL || bits == NULL || (n != 0 && text == NULL)) { return T_INVALID; }
    if (n > HUFF_TEXT_MAX) { return T_FULL; }
    char candidate[HUFF_BITS_MAX + 1]; size_t used = 0;
    for (size_t i = 0; i < n; i++) {
        char code[HUFF_SYMBOLS + 1];
        if (huff_code(tree, text[i], code, sizeof code) != T_OK) { return T_INVALID; }
        for (size_t j = 0; code[j] != '\0'; j++) { candidate[used++] = code[j]; }
    }
    if (capacity <= used) { return T_SPACE; }
    candidate[used] = '\0'; memcpy(out, candidate, used + 1); *bits = used; return T_OK;
}
TStatus huff_decode(const Huffman *tree, const char *bits, size_t n, unsigned char *out, size_t capacity, size_t *bytes)
{
    if (bytes == NULL || (n != 0 && bits == NULL) || (capacity != 0 && out == NULL)) { return T_INVALID; }
    if (n > HUFF_BITS_MAX) { return T_FULL; }
    unsigned char candidate[HUFF_TEXT_MAX]; size_t used = 0;
    if (tree->root < 0) { if (n != 0) { return T_INVALID; } }
    else {
        int cursor = tree->root;
        for (size_t i = 0; i < n; i++) {
            if (bits[i] != '0' && bits[i] != '1') { return T_INVALID; }
            if (tree->symbols == 1) { if (bits[i] != '0') { return T_INVALID; } }
            else { cursor = bits[i] == '0' ? tree->nodes[cursor].left : tree->nodes[cursor].right; }
            if (tree->nodes[cursor].left < 0) {
                if (used == HUFF_TEXT_MAX) { return T_FULL; }
                candidate[used++] = tree->nodes[cursor].symbol; cursor = tree->root;
            }
        }
        if (cursor != tree->root) { return T_INVALID; }
    }
    if (capacity < used) { return T_SPACE; }
    if (used != 0) { memcpy(out, candidate, used); }
    *bytes = used; return T_OK;
}
unsigned long huff_cost(const Huffman *tree)
{
    unsigned long total = 0;
    for (size_t i = 0; i < tree->symbols; i++) {
        char code[HUFF_SYMBOLS + 1]; size_t n = code_at(tree, (int)i, code);
        total += (unsigned long)tree->nodes[i].weight * n;
    }
    return total;
}
```

minimum相等时保留先扫描到的下标。active只保留尚未并入父树的根，每次拿掉两个、加入一个，数量严格减少，构造会结束。总权重至多8000，合并和在本预算内不会溢出unsigned int；码成本上界56000，可放unsigned long。

decode遇叶后重置cursor=root；最后必须再次位于根。单符号单独解释0，不假装根有两个孩子。decode返回的是二进制字节，不应直接用%s打印；入口用fwrite并明确bytes，因消息中可能包含零。

把 [huffman.h](示例代码/42-huffman/huffman.h)、[huffman.c](示例代码/42-huffman/huffman.c)、[main.c](示例代码/42-huffman/main.c)、[共享头](示例代码/stage7-common/tree_status.h) 放自己的`~/dsa-labs/ch42`。在 **UCRT64 Bash、该目录**：

```bash

./huffman.exe
```

预期：

```text
A=110
B=111
C=10
D=0
bits=1101111000110 cost=71
decoded=ABCDDA bytes=6
```

71=5*3+7*3+10*2+15*1，是按四种频数加权的成本；固定2位为37*2=74。输出消息ABCDDA自身只有13位，不是71位，因为其出现次数不是上述权重分布。

编码每个字节扫描s叶再沿高度h取码，时间O(L(s+h))；解码沿每个输入位走一次，O(位数)，本版使用固定候选缓冲。这里展示的bits是每位用一个字符字节存放，没有真正按8位打包，不能拿文本文件字节数宣称已经压缩。真实文件还需保存/传递码表、消息长度或有效位数、打包及格式校验；当前不是通用文件压缩器。

## 42.10 常见错误

任意短码却不检查前缀；选最大权重合并；相同权重码表不同就判错；用symbol=0当内部节点；遗漏单符号约定；解码未回根也成功；decode结果用%s读越界；容量忘留encode终止零；输入有未知字节仍忽略；将加权成本与一条样本位数混比；把0/1文本当真实打包文件；忽略码表开销。

## 42.11 练习与参考答案

练习一：5、7、10、15三次合并和是多少？答案：12+22+37=71，等于对应叶频数×路径长之和。

练习二：上表位串`11`能完整解码吗？答案：不能，停在A/B共同内部节点，T_INVALID且输出保持。

练习三：仅一种零字节、消息连续三个零字节，编码与解码长度？答案：码为000，共3位；解出3字节0，不能靠strlen判断原消息长度。
