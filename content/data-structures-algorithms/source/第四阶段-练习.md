## 三、实现与逐步记录

先自己做固定顺序表、动态数组、单链表、循环双向表中至少两种，实现get/set/insert/erase。对相同命令序列每步记录逻辑值、count、容量或链的形状。

执行：空插10，末尾插30，中间插20；改位置1为25；删除头，再删除尾，最后删唯一节点；继续删除应失败，输出变量999应保持。再尝试insert(count)、insert(count+1)、NULL输出、容量上限。

动态分配失败使用测试替身，不耗尽真实内存。成功扩容后重新取地址，不继续使用旧借用；测试循环双向表不得复制结构体快照，改为单独保存数量与逻辑值。

## 四、栈与队列验收

栈分别用数组与链实现：push10、20，peek为20，pop为20、10，再pop为空。检查空或满失败不改变结构。

循环队列分别用容量1、3、16：入10、20（容量1时交替入出），出10，再入30、40，得到20、30、40。反复操作超过物理容量多次，检查head绕回与逻辑顺序。

链队列做“入一条、出到空、再入新一条”，检查head/tail同时归空又能重新使用。清空后重复清空，不应重复释放节点。

括号检查测试空、()、([])、([)]、[(、17层与257字节；先写约定诊断位置，不把超预算混作普通括号语法错。

## 五、阶段项目规格

写受限**后缀表达式**求值器，不实现中缀转换。用队列保存输入token顺序，用栈处理数值。

- 输入是一个命令行字符串，最多127字节。
- token之间用一个或多个ASCII空格分隔；可有首尾空格。
- 数字字面量只支持一位0—9，运算符为二元+、-、*、/。
- 不接受多位字面量、负数字面量、括号、变量、制表符或小数。
- 最多16个token；先完成词法与队列预算检查，再求值。
- 中间和最终值都限制-9999—9999，整数除法向0截断，先检查除数非0。
- 正常结束必须恰好一个结果；失败不改调用者结果变量。
- 诊断token从0编号；结束时多余/缺结果用总token数表示，长度超限用0占位。

这些限制是实验协议，不是后缀表达式天然限制。token长度、队列容量、值范围是三种不同预算。

## 六、构建与样例

把expression.h、expression.c、main.c、stack.h、stack.c、queue.h、queue.c、ds_status.h放到同一自己的stage4目录。在 **UCRT64 Bash、该目录**：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic main.c expression.c stack.c queue.c -o expression.exe
./expression.exe '2 3 + 4 *'
```

预期result=20。至少覆盖：

| 输入 | 预期 |
| --- | --- |
| 8 3 - 2 * | result=10 |
| 2 8 - | result=-6 |
| 7 2 / | result=3 |
| 0 7 - 2 / | result=-3 |
| 2 + | arity，token=1 |
| 2 3 | arity，token=2，表示结束处 |
| 8 0 / | division-by-zero，token=2 |
| 12 3 + | token错误，token=0 |
| 9 9 * 9 * 9 * 9 * | range，token=8 |
| 17个1，空格分隔 | capacity，token=16，在求值前拒绝 |
| 空或纯空格 | arity，token=0 |

把result预先设777，错误后仍应777。不要为了测试范围而先做可能溢出的int乘法，再看结果是否小于9999。
