# 51 动态规划：状态、计算顺序与恢复

## 51.1 目标与先修

先完成递归、数组、图的依赖顺序，以及第49—50章。建议10—14小时，含两个独立入口、手填表格和改造。本章要能自己写出状态含义、转移、边界、求值顺序；从递归走到记忆化与表格；恢复一份答案；解释滚动数组为何必须按指定方向更新。

**子问题**是原问题的一小部分；**状态**用足够的信息准确标识一个子问题；**转移**表达状态与更小子问题之间的关系。**动态规划DP**把可复用的子问题答案保存下来，按依赖关系计算，避免重复工作。

它不是“看到数组就套公式”，也不是所有回溯都能轻易去掉一个维度。若两个历史在未来可选项、目标或限制上不同，就不能因眼前数值相同而当同一状态。

## 51.2 从零钱的重复递归开始

回到面额4、3、1，目标6，每种无限使用，求最少枚数。定义F(a)为恰好凑a所需的最少枚数；不可达另作标记。若最后一枚为c，前面必须最优地凑出a-c，所以候选为F(a-c)+1。

F(6)会询问F(2)、F(3)、F(5)；F(5)又询问F(1)、F(2)、F(4)。F(2)被多次问到。朴素递归会重复展开这些分支；题目虽不同路径，问的却是同一个剩余金额问题。

**最优子结构**在这里指：某个最优解去掉最后一枚后，余下必须是对应金额的最优解。否则可用更少硬币替换它，使整体更优，产生矛盾。**重叠子问题**指不同推导分支会反复询问相同状态；这解释了保存答案为何有用。

“金额a”足够作为状态，是因为面额系统固定、每种可无限使用。若每种只能用一次，还必须知道哪些物品已经可用/已处理；后面0/1背包正需要这个信息。

## 51.3 状态、边界、转移逐句写清

| 项目 | 本题定义 |
| --- | --- |
| 状态F(a) | 恰好凑a的最少硬币枚数，不是方案数 |
| 基例 | F(0)=0，空方案不需硬币 |
| 候选 | 对每个c≤a且F(a-c)可达，取F(a-c)+1 |
| 转移 | 所有合法候选中的最小值 |
| 无候选 | a不可达 |
| 答案 | F(amount)，另恢复每种用了多少枚 |

面额必须为正，所以a-c<a，依赖严格向小金额走，形成有向无环关系。这是递归能终止、从小到大能填表的原因。允许0面额会出现F(a)依赖自身，并造成除以零或循环，输入必须拒绝。

本批金额上限60，有限解最多60枚。因此用61作内部NO_CHANGE，不会与真实有限最优值混淆。它只在模块内部作标记：加1前先检查child不是61，不拿“无穷”参与算术。对外用possible区分，possible=0时total=0只是占位。

若金额范围变大，标记值与数组容量、整数边界都须一起重审，不能只把宏扩大若干倍就当通用大整数方案。

## 51.4 手填一张小表

按金额从0到6计算，面额按4、3、1尝试。同值候选不覆盖旧选择，因此先出现的较大面额作为最后一步被保留。

| a | 合法候选枚数 | F(a) | 记录最后一步 |
| --- | --- | --- | --- |
| 0 | 基例 | 0 | 无 |
| 1 | F(0)+1=1 | 1 | 1 |
| 2 | F(1)+1=2 | 2 | 1 |
| 3 | F(0)+1=1；F(2)+1=3 | 1 | 3 |
| 4 | F(0)+1=1；F(1)+1=2；F(3)+1=2 | 1 | 4 |
| 5 | F(1)+1=2；F(2)+1=3；F(4)+1=2 | 2 | 4 |
| 6 | F(2)+1=3；F(3)+1=2；F(5)+1=3 | 2 | 3 |

第49章的贪心只尝试固定路径4→1→1；DP对每个金额比较所有合法的最后一步，得到3→3。它没有把任意“看起来好”的局部规则假定成最优。

## 51.5 记忆化：仍递归，但一个状态只展开一次

**记忆化memoization**为每个状态保存“算过没有”与“答案”。已知状态直接返回；未知状态才展开依赖。这里known[a]与best[a]分开，因为0是合法答案，61是已确认不可达，而两者都不同于“尚未计算”。

本程序在solve入口标记known，再递归更小金额。由于依赖严格下降，不会回到尚在计算的祖先；若将这种写法搬去含环的依赖图，仅用一个known标记就不够，不能假定任意循环都可用记忆化解决。

工作对象是本次调用的局部CoinWork，没有静态全局缓存。换一套面额再次调用时不会误用上一套结果。工作对象中的coins指针只在同步调用期间借用，函数不保存到返回值或释放调用者的数组。

## 51.6 表格法：按依赖顺序直接计算

**表格法tabulation**事先安排状态顺序，再逐个计算。本题先best[0]=0，然后a从1递增，每次需要的a-c都在前面，直接查表即可。

两种方法算的是同一转移：记忆化从目标往下追所需状态；表格法从小到大把0..amount全算完。稀疏可达关系下前者可能少算一些状态，但仍有递归栈；后者没有这份调用栈。不能据此断言某一种在所有电脑、所有数据上更快。

evaluations只统计状态首次求值的次数（表格含基例0），不统计缓存命中、每个候选比较、初始化或I/O，所以它不是完整工作量。4、3、1凑6，两者都算7个状态；4、2凑3，记忆化不必访问所有金额，表格仍填0..3。

## 51.7 保存选择并恢复零钱方案

**恢复**是从最优值构造实际选项。choice[a]保存使F(a)改进的面额位置i，而不是硬币数。若目标可达，从remaining=amount开始：给counts[i]加1，令remaining减coins[i]，直到0。

每步都减正数，最多60步；choice仅在对应状态已获得有限候选时读取，所以不会把初始化的越界哨兵D_COINS当有效下标。无解时直接输出possible=0，不能进入恢复循环。

同样的最少枚数可能有多份方案，本程序按严格改进和降序面额确定一份；不是枚举全部最优组合。零金额恢复0步，possible=1、total=0，是有效的空方案。

接口沿用 [coins.h](示例代码/49-change/coins.h)，含`min_change_memo`与`min_change_table`。下面是两者及私有辅助函数所在的**完整模块coins.c**，入口另见 [coin_main.c](示例代码/51-dp/coin_main.c)：

```c
#include "coins.h"
#define NO_CHANGE (D_LIMIT + 1u)
typedef struct {
    const unsigned *coins;
    size_t n, choice[D_LIMIT + 1];
    unsigned best[D_LIMIT + 1];
    unsigned char known[D_LIMIT + 1];
    unsigned long evaluations;
} CoinWork;
static DStatus validate(const unsigned *coins, size_t n, unsigned amount, Change *out)
{
    if (out == NULL || (n != 0 && coins == NULL)) { return D_INVALID; }
    if (n > D_COINS || amount > D_LIMIT) { return D_RANGE; }
    for (size_t i = 0; i < n; i++) {
        if (coins[i] == 0 || coins[i] > D_DENOM) { return D_RANGE; }
        if (i > 0 && coins[i - 1] <= coins[i]) { return D_INVALID; }
    }
    return D_OK;
}
static CoinWork begin(const unsigned *coins, size_t n)
{
    CoinWork work = {0};
    work.coins = coins; work.n = n;
    for (unsigned a = 0; a <= D_LIMIT; a++) {
        work.best[a] = NO_CHANGE; work.choice[a] = D_COINS;
    }
    return work;
}
static unsigned solve(CoinWork *work, unsigned amount)
{
    if (work->known[amount]) { return work->best[amount]; }
    work->known[amount] = 1;
    work->evaluations++;
    if (amount == 0) { work->best[0] = 0; return 0; }
    for (size_t i = 0; i < work->n; i++) {
        if (work->coins[i] > amount) { continue; }
        unsigned child = solve(work, amount - work->coins[i]);
        if (child != NO_CHANGE && child + 1 < work->best[amount]) {
            work->best[amount] = child + 1;
            work->choice[amount] = i;
        }
    }
    return work->best[amount];
}
static Change finish(const CoinWork *work, unsigned amount)
{
    Change next = {0};
    next.evaluations = work->evaluations;
    if (work->best[amount] == NO_CHANGE) { return next; }
    next.possible = 1; next.total = work->best[amount];
    unsigned remaining = amount;
    while (remaining != 0) {
        size_t coin = work->choice[remaining];
        next.counts[coin]++;
        remaining -= work->coins[coin];
    }
    return next;
}
DStatus min_change_memo(const unsigned *coins, size_t n, unsigned amount, Change *out)
{
    DStatus status = validate(coins, n, amount, out);
    if (status != D_OK) { return status; }
    CoinWork work = begin(coins, n);
    (void)solve(&work, amount);
    *out = finish(&work, amount);
    return D_OK;
}
DStatus min_change_table(const unsigned *coins, size_t n, unsigned amount, Change *out)
{
    DStatus status = validate(coins, n, amount, out);
    if (status != D_OK) { return status; }
    CoinWork work = begin(coins, n);
    work.best[0] = 0; work.evaluations = 1;
    for (unsigned a = 1; a <= amount; a++) {
        work.evaluations++;
        for (size_t i = 0; i < n; i++) {
            if (coins[i] > a) { continue; }
            unsigned child = work.best[a - coins[i]];
            if (child != NO_CHANGE && child + 1 < work.best[a]) {
                work.best[a] = child + 1; work.choice[a] = i;
            }
        }
    }
    *out = finish(&work, amount);
    return D_OK;
}
```

`(void)solve(...)`表示确实执行函数，但此处不使用返回表达式值，答案已经写在work里；不等于没有调用它。begin返回含数组的结构体值，这种普通值对象可以复制；它不拥有动态内存。


`-I49-change`找接口头，`-Istage9-common`找公共状态；二者不会自动链接greedy.c。本入口不调用贪心函数，因此不需要它，也不要误把两个main都加入链接。

预期：

```text
memo total=2 states=7
table total=2 counts=0,2,0 states=7
amount3 possible=0
```

最后的系统是4、2凑3，两者皆偶数，不可能凑奇数；DP返回D_OK、possible=0，而不是第49章某条贪心路径的D_STUCK。参数非法时仍返回错误码且旧out保持，调用者必须区分这两个层面。

设面额种数k、目标A、编译预算L=60。状态处理上界O((k+1)(A+1))，begin另初始化O(L)个槽；恢复O(A)。工作数组按L预留，记忆化另有至多A+1层调用，表格没有递归栈。若按目标规模配置L，通常概括为O(kA)量级（含必要边界项）、O(A)辅助空间；当前程序的实际预算不因A=1就自动缩成2格。

## 51.9 0/1背包：为什么必须多一个维度

现在每份学习材料都有费用cost和价值value；每份最多选一次，预算内使总价值最大。这里价值是人为设定的练习分数，不表示真实学习效果。三份材料：

| 位置 | 费用 | 价值 | 价值/费用 |
| --- | --- | --- | --- |
| 0 | 3 | 5 | 约1.67 |
| 1 | 4 | 6 | 1.5 |
| 2 | 2 | 3 | 1.5 |

预算6。按比值先取位置0，再取2，总价值8；取1和2总费用6、价值9，更好。材料不能切成分数，故不能把“可分割背包”的规则照搬到0/1问题。

只记剩余预算不够：同样剩3，在“物品0还未处理”和“物品0已处理”的历史下，可选物品集合不同。定义best[i][b]为**只允许前i件物品、总费用不超过b的最大价值**。i是数量，因此本轮新物品下标为i-1。

“不超过”允许留预算、允许空集；如果改成“必须恰好用满预算”，边界与不可达表示要重写，不能仍将所有格子初始化为0。

## 51.10 从选择推导转移与基例

面对第i件（下标i-1），只有两种情况：不选，价值best[i-1][b]；选一次，前提cost≤b，价值best[i-1][b-cost]+value。取较大者。

两项都从**前i-1件**取答案，保证当前物品不会重复使用。基例best[0][b]=0：没有物品时，只能取空集；预算0也为0，因为本程序费用必须≥1。

按i从1到n填行，每行b从0到budget。所有依赖都在上一行，已算完，所以这一顺序合法。i递增代表允许的物品变多，不代表把当前预算花掉后覆盖整张表。

手算预算0..6：

| 允许物品 | b=0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 无 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 仅0 | 0 | 0 | 0 | 5 | 5 | 5 | 5 |
| 0、1 | 0 | 0 | 0 | 5 | 6 | 6 | 6 |
| 0、1、2 | 0 | 0 | 3 | 5 | 6 | 8 | 9 |

例如最后一格比较“不选2得6”和“选2，上一行预算4得6，加3得9”。不是拿本行预算4再加3，从而多次使用2。

## 51.11 二维表恢复：从最后一行退回

从i=n、b=budget开始。如果best[i][b]等于best[i-1][b]，本程序选择不取当前物品；若不同，说明严格改进来自选当前物品，记录位置i-1，b减它的费用。无论选不选，i都减1。

同价值时固定不选当前较后物品，只承诺确定性，不额外优化“费用最少”“物品最少”。例如费用2价值3与费用3价值3两件，预算3时，会保留前者；交换输入位置后同价值策略也随位置变化，不能称作一条独立的最小费用承诺。

结果PackResult含value、cost和位置集合mask。示例mask6选1、2，cost6、value9。mask仍不是业务ID；最终项目需要另外映射，不能直接输出位置当课程编号。

## 51.12 滚动数组：覆盖历史前先看依赖

二维表每行只读上一行，可把价值压成best[b]一行。为了让读取的best[b-cost]仍代表上一轮，**预算从大到小更新**。

只一件费用2、价值3，预算4，初始全0。倒序时先更新best[4]=旧best[2]+3=3，然后best[3]=3、best[2]=3，仍只取一次。若正序：先best[2]=3，再best[4]=本轮best[2]+3=6，同一物品取了两次，题目已变成允许重复使用。

代码中cap为unsigned，循环条件`cap >= cost`之所以安全，是验证cost≥1；当cap降到cost后，再减到cost-1就退出，不会从0继续减。不要照搬成`cap >= 0`，它对无符号数永远成立。

滚动版本**只返回最优价值**，没有保留可恢复的历史表。简单给每个容量挂一个会继续变化的旧父指针，可能恢复出重复物品。需要方案时本课使用二维版本；可以再研究完整决策位表或分治恢复，但本批没有实现这些扩展。

## 51.13 完整背包模块与运行

[knapsack.h](示例代码/51-dp/knapsack.h)定义PackItem、PackResult与两个函数。输入最多8件，费用1—60、价值0—100、预算0—60；相同费用/价值的不同位置仍是不同物品。0价值允许，0费用被本协议拒绝。

**完整模块knapsack.c**，需公共头和[入口pack_main.c](示例代码/51-dp/pack_main.c)：

```c
#include "knapsack.h"
static DStatus validate(const PackItem *items, size_t n, unsigned budget, const void *out)
{
    if (out == NULL || (n != 0 && items == NULL)) { return D_INVALID; }
    if (n > D_ITEMS || budget > D_LIMIT) { return D_RANGE; }
    for (size_t i = 0; i < n; i++) {
        if (items[i].cost == 0 || items[i].cost > D_LIMIT || items[i].value > D_VALUE) {
            return D_RANGE;
        }
    }
    return D_OK;
}
DStatus pack01_table(const PackItem *items, size_t n, unsigned budget, PackResult *out)
{
    DStatus status = validate(items, n, budget, out);
    if (status != D_OK) { return status; }
    unsigned best[D_ITEMS + 1][D_LIMIT + 1] = {{0}};
    for (size_t i = 1; i <= n; i++) {
        PackItem item = items[i - 1];
        for (unsigned cap = 0; cap <= budget; cap++) {
            best[i][cap] = best[i - 1][cap];
            if (item.cost <= cap) {
                unsigned candidate = best[i - 1][cap - item.cost] + item.value;
                if (candidate > best[i][cap]) { best[i][cap] = candidate; }
            }
        }
    }
    PackResult next = {0};
    next.value = best[n][budget];
    unsigned cap = budget;
    for (size_t i = n; i > 0; i--) {
        if (best[i][cap] != best[i - 1][cap]) {
            next.mask |= 1u << (i - 1);
            next.cost += items[i - 1].cost;
            cap -= items[i - 1].cost;
        }
    }
    *out = next;
    return D_OK;
}
DStatus pack01_rolling(const PackItem *items, size_t n, unsigned budget, unsigned *out)
{
    DStatus status = validate(items, n, budget, out);
    if (status != D_OK) { return status; }
    unsigned best[D_LIMIT + 1] = {0};
    for (size_t i = 0; i < n; i++) {
        for (unsigned cap = budget; cap >= items[i].cost; cap--) {
            unsigned candidate = best[cap - items[i].cost] + items[i].value;
            if (candidate > best[cap]) { best[cap] = candidate; }
        }
    }
    *out = best[budget];
    return D_OK;
}
```

私有validate里的`const void *out`只用于统一检查两种输出指针是否为空，不解引用或修改未知类型的数据；公共接口仍分别用PackResult*和unsigned*。这是已有void*知识的一次局部使用，不是让调用者随意传错类型。

在 **UCRT64 Bash、`source/示例代码`目录**：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -Istage9-common \
  51-dp/pack_main.c 51-dp/knapsack.c -o pack01.exe
./pack01.exe
```

预期：

```text
value=9 cost=6 mask=6 rolling=9
ratio greedy on this sample: value=8, optimum=9
```

最后一行是入口对已手算样例的说明，不是程序又实现了一套比值贪心。二维与滚动的一致性是检查之一，正式验证还枚举全部子集独立求最优，避免两个版本一起出错。

## 51.14 成本、数值边界与适用范围

若随问题规模配置数组，二维背包的转移O(n(B+1))、表空间O((n+1)(B+1))、恢复O(n)；滚动的工作O(nB+n)、空间O(B+1)。当前二维数组按9×61清零、滚动按61清零；这份预算初始化即使小输入也存在。最大总价值8×100=800，费用不超过60，unsigned足以容纳，不执行越界整数相加。

**伪多项式**在这里指时间依赖预算数值B，而不是只依赖写出B用了多少位；例如二进制写很大的预算可能只需几十位，按所有金额建表却非常大。因此不能只看O(nB)就认为任意数值输入都轻松。当前60预算是教学边界，不是通用大规模解法。

这套背包假定物品彼此独立。若材料B必须先选A，不能先跑独立背包再把结果拓扑排序，就宣称得到依赖约束下最优计划；被漏掉的先修、已学状态与预算都需加入新的模型。最终工程会明确选择哪种业务语义。

## 51.15 常见错误

| 错误 | 原因与修正 |
| --- | --- |
| F(0)=1 | 空方案被多算一枚，正确基例是0 |
| 用0兼任未算与不可达 | 混淆合法值、未知、无解，分别存标记 |
| 无解也读choice恢复 | 可能把哨兵当下标；先判断possible |
| 换面额还复用旧缓存 | 状态的上下文改变，缓存必须属于本次调用 |
| 背包只记预算而忘物品范围 | 未来选择不同，状态信息不足 |
| 二维选物品时读本行 | 可能重复取当前物品，应读上一行 |
| 0/1滚动预算正序 | 复用了本轮值，同一物品可能多次取 |
| 只返回价值就声称恢复路径 | 价值与方案是两类输出，恢复需要额外信息 |
| 预算不超过与恰好花满混用 | 合法空状态与不可达边界不同 |

## 51.16 练习与参考答案

练习一：面额5、2凑3，F(0)、F(1)、F(2)、F(3)分别是什么？答案：0、不可达、1、不可达；不能把不可达当0再加1。

练习二：只有一件费用2价值3，预算4，二维与倒序滚动的最优值？错误正序是多少？答案：正确3，错误6。解释后者读到了本轮更新的best[2]。

练习三：面额4、3、1凑6的choice恢复走哪些金额？答案：6→3→0，各取一枚3；不需要保留整棵递归树。

练习四：两件均费用1、价值1，预算1，同值不取较后物品时mask是多少？答案：1，取位置0；不代表它有更高业务优先级。

练习五：给背包加上“材料1依赖材料0”是否只需输出时排序？答案：不够，原最优子集可能根本没选0，需要把先修约束加入可行性与状态设计。独立物品证明不可直接搬用。
