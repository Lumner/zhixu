# 20 顺序查找与二分边界

## 20.1 目标与先修

先掌握数组与长度、size_t、函数结果结构体、不变量和复杂度。建议5—7小时。本章实现三件事：顺序找第一个相等值；找到第一个不小于目标的位置；在有序数组中找第一个相等值。用同一套边界说明空数组、重复值、未找到和比较次数。

本章不要求先会排序算法。示例数组已经按非递减顺序提供；阶段实验会先验证顺序。以后排序章节完成后，再讨论从无序资料建立查询视图的完整成本。

## 20.2 先区分三个问题

示例是`[1,3,3,3,8,12]`，目标3。

| 接口 | 问的是什么 | 正常结果 | 没有符合元素时 |
| --- | --- | --- | --- |
| linear_find | 从左到右第一个相等值 | 下标1 | 返回count |
| lower_bound_int | 第一个大于或等于目标的位置 | 下标1 | 返回count这个末尾边界 |
| binary_find_first | 用二分规则找第一个相等值 | 下标1 | 返回count |

lower_bound称下界位置，它不是“必须相等”。目标4的下界是下标4，因为那里8是第一个≥4的元素，但数组里没有4；目标13的下界为6，表示可放在末尾，不表示values[6]能读。

接口用size_t表示位置，缺失时选count做哨兵，不再使用-1。判断存在应先看index<count。空数组count=0时，返回0表示缺失或空插入边界，不意味着存在第一个元素。

## 20.3 各自前提必须写清

所有函数要求：count>0时，values指向至少count个有效int；count=0允许NULL，不读取元素。它们不分配、不修改输入，不替调用者识别坏地址。

顺序查找允许无序数组。下界和二分查找则要求**非递减**：从左到右不会变小，重复值允许。is_nondecreasing用相邻比较单独检查这个条件，它不是每次二分内自动运行的步骤。

假如数组是`[5,1,4]`，目标1，二分可能把候选范围缩到下标0，最后说没找到，虽然1确实存在。这里的问题是前提不满足，不能把无序数组上偶然成功的例子当正确证据。阶段工具会明确拒绝这种输入。

## 20.4 顺序查找的推理

开始从下标0扫描，每轮开始，`[0,i)`已经确认没有目标。当前元素相等就返回i；因为前面没有，所以它是第一次。否则i加1，已排除前缀扩大一格。

扫描完n个都没相等，返回count。目标在首位只比较1次；在最后或未找到比较n次；空输入不比较。额外空间只有几个变量，Θ(1)。

这是一个简单而重要的参考实现：后面复杂方法可以与它对照。顺序查找不是“过时的错误算法”，对小数据、无序数据或很少查询，它常有合理用途。

## 20.5 半开区间究竟包含什么

二分用lo和hi表示尚未排除的**元素范围**`[lo,hi)`，包含lo，不包含hi。初始lo=0、hi=count，恰好覆盖全部元素；空数组自然是[0,0)，不需要计算count-1。

我们要找的下界是一个**分界位置**，可能恰好等于hi，所以候选分界位置在闭区间`[lo,hi]`。元素范围与分界位置不是同一个集合：位置n合法地表示数组末尾，却不是可访问元素。

始终保持：

1. `0 <= lo <= hi <= count`。
2. `[0,lo)`中的元素都小于target。
3. `[hi,count)`中的元素都大于或等于target。

中间元素尚未确定属于哪侧。这里比较的是有序值与目标，不只是机械移动两个数字。

## 20.6 每次怎样排除一半

只在lo<hi时取`mid = lo + (hi-lo)/2`。此时mid落在[lo,hi)内，所以可以读values[mid]。写成(lo+hi)/2可能先加法溢出；本写法用已知非负的间距计算，避免那项风险。

- 若values[mid]<target，有序性说明从lo到mid都小于目标，可以把lo设为mid+1。
- 否则values[mid]≥target，mid已经属于右侧已知区域，把hi设为mid。

不是hi=mid-1：mid也可能正是第一个≥target的位置，必须保留为右侧分界。这里保留的是“边界可以在mid”，并不要求下次还访问这个元素。

每次新间距hi-lo严格减小，最多变成原间距向下取半，最终lo=hi。此时中间空了，左边全<target，右边全≥target，lo就是所需下界。

## 20.7 重复值手推表

对`[1,3,3,3,8,12]`找3：

| 轮次前lo | hi | mid | values[mid] | 决策 | 新范围 |
| --- | --- | --- | --- | --- | --- |
| 0 | 6 | 3 | 3 | 不小于目标，hi=3 | [0,3) |
| 0 | 3 | 1 | 3 | 不小于目标，hi=1 | [0,1) |
| 0 | 1 | 0 | 1 | 小于目标，lo=1 | [1,1) |

即使中间遇到相等值，也继续往左确定边界，所以不会随便返回下标3。结束位置为1，再检查values[1]==3，才得到“第一个相等值”。

找4时，依次访问3、12、8，最后边界4；再检查8!=4，应报告没找到，而不能把插入位置4当成相等位置。找13时会返回末尾6，这时短路检查避免读取values[6]。

## 20.8 一组完整程序与接口

把 [search.h](示例代码/20-search/search.h)、[search.c](示例代码/20-search/search.c)、[search_demo.c](示例代码/20-search/search_demo.c) 放到自己的`~/dsa-labs/ch20`。以下三份共同组成完整程序。

完整文件search.h：

```c
#ifndef DSA_SEARCH_H
#define DSA_SEARCH_H

#include <stddef.h>

typedef struct {
    size_t index;
    size_t comparisons;
} SearchResult;

int is_nondecreasing(const int *values, size_t count);
SearchResult linear_find(const int *values, size_t count, int target);
SearchResult lower_bound_int(const int *values, size_t count, int target);
SearchResult binary_find_first(const int *values, size_t count, int target);

#endif
```

完整文件search.c：

```c
#include "search.h"

int is_nondecreasing(const int *values, size_t count)
{
    for (size_t i = 1; i < count; i++) {
        if (values[i] < values[i - 1]) {
            return 0;
        }
    }
    return 1;
}

SearchResult linear_find(const int *values, size_t count, int target)
{
    SearchResult result = {count, 0};
    for (size_t i = 0; i < count; i++) {
        result.comparisons++;
        if (values[i] == target) {
            result.index = i;
            break;
        }
    }
    return result;
}

SearchResult lower_bound_int(const int *values, size_t count, int target)
{
    size_t lo = 0;
    size_t hi = count;
    SearchResult result = {count, 0};
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        result.comparisons++;
        if (values[mid] < target) {
            lo = mid + 1;
        } else {
            hi = mid;
        }
    }
    result.index = lo;
    return result;
}

SearchResult binary_find_first(const int *values, size_t count, int target)
{
    SearchResult result = lower_bound_int(values, count, target);
    if (result.index < count) {
        result.comparisons++;
        if (values[result.index] == target) {
            return result;
        }
    }
    result.index = count;
    return result;
}
```

完整文件search_demo.c：

```c
#include "search.h"
#include <stdio.h>

int main(void)
{
    int values[] = {1, 3, 3, 3, 8, 12};
    size_t count = sizeof values / sizeof values[0];
    int target = 3;
    if (!is_nondecreasing(values, count)) {
        fputs("array is not sorted\n", stderr);
        return 1;
    }
    SearchResult linear = linear_find(values, count, target);
    SearchResult lower = lower_bound_int(values, count, target);
    SearchResult binary = binary_find_first(values, count, target);
    printf("linear index=%zu comparisons=%zu\n", linear.index, linear.comparisons);
    printf("lower index=%zu comparisons=%zu\n", lower.index, lower.comparisons);
    printf("binary index=%zu comparisons=%zu\n", binary.index, binary.comparisons);
    return 0;
}
```

## 20.9 先定义比较次数，再读报告

本例comparisons只数“一个数组元素与target之间的比较”：顺序扫描每轮一次==；下界每轮一次<；binary_find_first复用下界计数，在返回位置<count时再加一次==。

它**不计**循环边界判断、索引算术、顺序验证、参数解析与打印。这里顺序方法2次、二分精确方法4次，说明很靠前的目标在小数组中未必适合二分；不能只背“log比n小就总更快”。

main为了展示接口，独立调用了lower_bound与binary_find_first，后者内部又求一次下界。每行给的是该函数自身计数，不是整个main累积计数。这是一份教学报告，不是经过优化的完整查询服务性能基准。

若固定数组长度为n>0，下界循环最多`floor(log2(n))+1`轮；精确查找可能再加1次等值比较。最坏查询时间Θ(log n)，额外空间Θ(1)。n=0为常数处理，元素比较0次。

## 20.10 查询成本与完整流程分开

is_nondecreasing最坏检查n-1对相邻元素，耗时Θ(n)。因此“每次都从文件读入并验证，然后做一次二分”的完整流程仍可能是线性的，不能因其中一次二分就整体宣称Θ(log n)。

若数据保持不变，可以先一次读入验证，再对同一有序数组做m次查询，算法部分可写成O(n + m log n)。如果输入无序还需排序，应再计排序成本；后续排序章节会讨论。修改数据后是否仍有序，也要重新保证。

数组可按下标常数时间访问中间元素；链表没有这个访问特性，不能把“比较次数少”直接等同于总访问成本少。这一点在线性结构阶段再做实验。

## 20.11 边界实验与安全检查

在练习副本中依次改数组和target，每次保持声明容量与count一致：

| 输入与目标 | 下界位置 | 第一个相等值 |
| --- | --- | --- |
| 空，找3 | 0 | 未找到，哨兵0 |
| [3]，找3 | 0 | 0 |
| [3]，找2 | 0 | 未找到，哨兵1 |
| [3]，找4 | 1 | 未找到，哨兵1 |
| [3,3,3]，找3 | 0 | 0 |
| [1,3,3,3,8,12]，找4 | 4 | 未找到，哨兵6 |
| 同上，找12 | 5 | 5 |
| 同上，找13 | 6 | 未找到，哨兵6 |

标准C不创建0容量数组。空测试可以用一个已有数组配count=0，或在有效函数调用中用NULL配0，不做NULL配正count的读元素实验。

作者验证会穷举小规模有序序列，并与独立参考结果比较。不是只把二分和顺序互相比一遍：两者如果都犯同一个规格错误仍可能一致，所以还直接检查下界两侧性质、最早位置与比较次数上界。

## 20.12 常见错误

- 输入无序却调用二分，偶然命中就认为正确。
- count为0还计算count-1，无符号下溢。
- 把半开元素范围误读为末尾可访问：下标count不能解引用。
- 更新lo=mid，在只剩1个元素时可能不进展。
- 把相等就立即返回套进“第一次出现”需求，得到任意匹配。
- 下界位置直接当精确匹配，不再检查相等。
- 把返回count转成int的-1约定，混淆接口类型。
- 查询内核是对数，就忽略每次的线性验证与读入。

## 20.13 练习与参考答案

练习一：对[2,4,4,9]找4，依次写lo、hi、mid。

答案：开始(0,4)，mid=2，值4，所以hi=2；(0,2)，mid=1，值4，所以hi=1；(0,1)，mid=0，值2，所以lo=1，结束下界1。再检查相等，精确位置1。

练习二：为什么hi=mid不会导致保留同一个区间一直循环？

答案：仅在lo<hi时进入，mid<旧hi，因此新hi严格减小；lo=mid+1分支也严格增大lo。

练习三：下界返回count时能不能读values[count]再判断？

答案：不能。先判断index<count，只有成立才读取元素；这正是代码中分开的边界检查。

练习四：每次查询前重新读n条并验证，整体为什么不能只写对数？

答案：前置流程已需要线性处理，查询本身的改进不会消除它。
