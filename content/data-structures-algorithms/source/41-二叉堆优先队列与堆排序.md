# 41 二叉堆、优先队列与堆排序

## 41.1 目标与先修

先完成完全二叉树、数组下标和第六阶段排序。建议7—10小时。目标是分清堆与BST，用数组画出完全树，实现上浮、下沉、线性建堆和优先取项，再用大根堆完成升序堆排序。

普通队列先来先出；有些待办工作应先处理更紧急者。**优先队列priority queue**按约定的优先级选择下一项，是操作行为；二叉堆是实现它的一种数据结构，不等于任意队列都会自动按优先级工作。

## 41.2 形状和顺序是两个不变量

**小根二叉堆**要求形状为完全二叉树，并且每个父项不大于孩子，因此根是最小项。它不要求左子树所有项小于根、右子树大于根；那是BST的另一种顺序。

```text
小根堆可以是：       1
                  /   \
                 3     2
                / \
               7   4
数组顺序：1,3,2,7,4
```

数组并没有整体排好序，中序也不保证有序。只检查根是最小不够，所有父子都必须满足堆序。数据结构的“堆”也不同于第13章申请动态内存的“堆区”，这里的实现甚至不需要malloc。

## 41.3 完全树为何适合紧密数组

从0编号，节点i的左孩子2i+1、右孩子2i+2；存在孩子须下标<count。非根父下标(i-1)/2；i=0时不能先做无符号i-1。完全形状保证有效项正好占[0,count)，不需要为中间缺口存NULL。

最后一个非叶下标为count/2-1，空/单项单独通过循环条件跳过，不直接让无符号数减成巨大值。当前优先队列最多63项，公式在预算内安全；推广巨大容量仍须核对乘加边界。

## 41.4 明确谁先处理，允许哪些重复

Job有priority与id。本版数字越小越优先；priority相等时id较小者先。两字段都允许所有int，比较不使用相减；允许重复ID，也允许完全相同Job，不提供按ID唯一索引。

这不是相同优先级的FIFO；若需要FIFO，要另外保存递增入队序号并约定溢出。本版只有push、peek、pop、build，没有任意ID删除/改优先级或decrease-key接口。

peek/pop的out是独立Job变量，不能为空，失败保持；空为T_EMPTY、满为T_FULL、NULL参数T_INVALID。数组对象不拥有堆内存，可以按值复制形成独立堆；这与拥有节点的BST/AVL不能浅拷贝不同。仍不把内部数组格当作输出变量。

## 41.5 加入上浮，取出下沉

push把新项放数组末尾，完全形状保持，唯一可能破坏的关系在新项与祖先之间。若新项比父小，就交换并继续向上；遇到父<=当前或到根停止。

pop保存根，把末尾有效项移到根、数量减1。此时只有从根向下的路径可能违规；选左右孩子中更小者，若当前不大于它则停止，否则交换后继续。必须选较小孩子，否则另一个孩子可能仍比新父小。

删最后一项时数量变0，不再下沉；先检查空再读取data[0]。保存要返回的Job直到操作结束，再写*out，输出不受内部搬动影响。

## 41.6 自底向上建堆

叶天然是小堆。从最后非叶向根依次down，处理当前节点时孩子子树已成堆，下沉即可把整棵当前子树修好。

不是每个节点都走log n层：约一半是叶，不下沉；更少节点才有较大高度。按各高度节点数求和可得Θ(n)建堆。逐条push最坏O(n log n)，两种构造方式不能混称相同工作量。

build先检查n<=63和指针，再在局部next复制输入、建堆，最后整体赋给heap，错误保留旧堆。它不申请内存；不需要把不存在的内存失败演成T_MEMORY。

## 41.7 完整优先队列实现与运行

完整文件heap.c，接口见 [heap.h](示例代码/41-heap/heap.h)：

```c
#include "heap.h"
static int compare(Job a, Job b)
{
    if (a.priority != b.priority) { return a.priority < b.priority ? -1 : 1; }
    if (a.id != b.id) { return a.id < b.id ? -1 : 1; }
    return 0;
}
static void swap(Job *a, Job *b) { Job saved = *a; *a = *b; *b = saved; }
static void down(MinHeap *heap, size_t root)
{
    while (root < heap->count / 2) {
        size_t child = root * 2 + 1;
        if (child + 1 < heap->count && compare(heap->data[child + 1], heap->data[child]) < 0) { child++; }
        if (compare(heap->data[root], heap->data[child]) <= 0) { break; }
        swap(&heap->data[root], &heap->data[child]); root = child;
    }
}
void heap_init(MinHeap *heap) { *heap = (MinHeap){0}; }
TStatus heap_build(MinHeap *heap, const Job *values, size_t n)
{
    if (n != 0 && values == NULL) { return T_INVALID; }
    if (n > TREE_LIMIT) { return T_FULL; }
    MinHeap next = {0}; next.count = n;
    for (size_t i = 0; i < n; i++) { next.data[i] = values[i]; }
    for (size_t i = n / 2; i > 0; i--) { down(&next, i - 1); }
    *heap = next; return T_OK;
}
TStatus heap_push(MinHeap *heap, Job job)
{
    if (heap->count == TREE_LIMIT) { return T_FULL; }
    size_t child = heap->count++; heap->data[child] = job;
    while (child > 0) {
        size_t parent = (child - 1) / 2;
        if (compare(heap->data[parent], heap->data[child]) <= 0) { break; }
        swap(&heap->data[parent], &heap->data[child]); child = parent;
    }
    return T_OK;
}
TStatus heap_peek(const MinHeap *heap, Job *out)
{
    if (out == NULL) { return T_INVALID; }
    if (heap->count == 0) { return T_EMPTY; }
    *out = heap->data[0]; return T_OK;
}
TStatus heap_pop(MinHeap *heap, Job *out)
{
    if (out == NULL) { return T_INVALID; }
    if (heap->count == 0) { return T_EMPTY; }
    Job saved = heap->data[0]; heap->count--;
    if (heap->count != 0) { heap->data[0] = heap->data[heap->count]; down(heap, 0); }
    *out = saved; return T_OK;
}
```

将heap.h/c、[main.c](示例代码/41-heap/main.c)、[共享头](示例代码/stage7-common/tree_status.h) 放自己的`~/dsa-labs/ch41-heap`。在 **UCRT64 Bash、该目录**：

```bash

./heap.exe
```

预期：

```text
priority=1 id=10
priority=1 id=20
priority=2 id=40
priority=3 id=30
```

先处理priority1，再按ID10/20分先后。peek是O(1)，push/pop最坏O(log n)，build Θ(n)，存储O(n)预算。本版固定63格，额外工作仅局部变量，不承诺按当前n动态缩减实际对象大小。

## 41.8 升序排序为什么改用大根堆

把最大项放根，与当前末尾交换，就能把最大值安放在最终位置。把末尾排除在堆之外，对剩余前缀修大根堆，再重复。这样已完成后缀逐渐从右往左增长。

不变量：前缀是大根堆，后缀已非递减且其中键不小于前缀。最大值搬到末尾后关系仍成立，堆长度不断缩短，最终全局有序。

本排序使用第六阶段SItem与统一计数，仅比较key，tag随记录移动；与优先队列的priority/id双字段规则不同。它是新增独立函数，没有修改前批九算法实验台，完整课程现在再补上堆排序。

## 41.9 完整堆排序与可复现反例

完整文件heapsort.c：

```c
#include "heapsort.h"
#include "sort_internal.h"
static void down_max(SItem *a, size_t root, size_t n, SortStats *stats)
{
    while (root < n / 2) {
        size_t child = root * 2 + 1;
        if (child + 1 < n && sort_compare(a[child + 1].key, a[child].key, stats) > 0) { child++; }
        if (sort_compare(a[root].key, a[child].key, stats) >= 0) { break; }
        sort_swap(a, root, child, stats); root = child;
    }
}
SortStatus heap_sort(SItem *a, size_t n, SortStats *out)
{
    SortStatus status = sort_validate(a, n, out);
    if (status != S_OK) { return status; }
    SortStats stats = {0, 0};
    for (size_t i = n / 2; i > 0; i--) { down_max(a, i - 1, n, &stats); }
    for (size_t end = n; end > 1; end--) {
        sort_swap(a, 0, end - 1, &stats); down_max(a, 0, end - 1, &stats);
    }
    *out = stats; return S_OK;
}
```

取 [heapsort.h](示例代码/41-heap/heapsort.h)、heapsort.c、[sort_main.c](示例代码/41-heap/sort_main.c) 和 [第六阶段公共5文件](示例代码/stage6-common/README.md) 到独立`~/dsa-labs/ch41-sort`。在 **UCRT64 Bash、该目录**：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic sort_main.c heapsort.c sort_common.c demo.c -o heap-sort.exe
./heap-sort.exe
```

输出：

```text
heap-sort comparisons=3 writes=6
1:12 2:11 2:10
```

同键2的标记10/11颠倒，堆排序不稳定。先线性建堆，再反复下沉，最坏Θ(n log n)，额外空间Θ(1)，无递归或辅助记录数组。全相等时本版下沉很快停止，不能把最坏上界当成所有样本精确计数。

输入与失败统计沿用SortStatus、n<=128和第六阶段约定，所有int键合法；不要把优先队列63项限制移来覆盖排序128项预算。完整文件组合见 [本阶段说明](示例代码/stage7-common/README.md)。

## 41.10 常见错误

把堆当BST或完整排序数组；parent在i=0时仍先算i-1；下沉只选左孩子；pop数量更新后读错末项；空时先读根；优先级相同默认FIFO；按ID查询认为一定O(log n)；自底建堆也写成n次完整上浮；升序用小根堆直接换末尾却不改流程；混用两组比较/容量协议。

## 41.11 练习与参考答案

练习一：数组下标5的父与孩子下标？答案：父2，孩子11、12；是否存在还需与count比较。

练习二：priority1/id20先入，priority1/id10后入，谁先出？答案：id10，本版相同优先级按ID，不按时间。

练习三：小根堆能快速查任意ID吗？答案：本接口没有按ID组织的搜索性质，通常需扫描或另加索引，不因树高对数就自动能二分。
