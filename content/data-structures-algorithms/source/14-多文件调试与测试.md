# 14 多文件、调试与测试

## 14.1 目标与先修

先完成函数、指针与动态内存。建议4—6小时。本章把一个程序分成头文件、实现文件和入口，理解编译链接，使用断言和调试器观察状态，写出有判据的测试。重点是“出错时怎样找到原因”，不是记住某个编辑器按钮。

## 14.2 头文件是接口，不是另一份程序入口

程序可由多个翻译单元组合。一个`.c`文件经预处理和编译产生对应目标代码，再由链接器把所需定义组合起来。头文件提供共享声明，避免main与实现对函数参数有不同理解。

本例三份文件放在同一`~/dsa-labs/ch14`目录：`totals.h`给出声明，`totals.c`实现计算，`main.c`调用。只需要一个main。`#include "totals.h"`查找本项目头文件；标准头文件用尖括号。

头文件防重复包含的`#ifndef`表示“若此宏尚未定义”，随后#define标记，#endif结束条件；同一翻译单元重复包含时不会重复处理其中内容。宏名选择本项目独有的DSA_TOTALS_H。

## 14.3 一组完整程序的三个文件

**完整程序由以下三文件共同组成**，不是三个分别运行的程序。下载 [totals.h](示例代码/14-modules/totals.h)、[totals.c](示例代码/14-modules/totals.c)、[main.c](示例代码/14-modules/main.c)。

totals.h：

```c
#ifndef DSA_TOTALS_H
#define DSA_TOTALS_H

int add_minutes(int a, int b);

#endif
```

totals.c：

```c
#include "totals.h"
#include <assert.h>

int add_minutes(int a, int b)
{
    assert(a >= 0 && a <= 1440 && b >= 0 && b <= 1440);
    int result = a + b;
    return result;
}
```

main.c：

```c
#include "totals.h"
#include <stdio.h>

int main(void)
{
    int total = add_minutes(30, 15);
    printf("total=%d\n", total);
    return 0;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch14`目录**：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -g -O0 main.c totals.c -o totals.exe
./totals.exe
```

应输出`total=45`。`-g`生成调试信息，`-O0`在本教学实验关闭优化，便于按源码跟踪；实际工程也可按GCC文档选择适合调试的优化级别。选项依据[官方说明](https://gcc.gnu.org/onlinedocs/gcc/Debugging-Options.html)，核验日期2026-11-11。

## 14.4 编译成功与链接成功是两件事

仍在同一目录，可分步执行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -g -O0 -c main.c -o main.o
gcc -std=c17 -Wall -Wextra -Wpedantic -g -O0 -c totals.c -o totals.o
gcc main.o totals.o -o totals.exe
```

`-c`表示生成目标文件，暂不链接。main.o知道要调用add_minutes，但真正定义来自totals.o。如果只运行`gcc main.c -o incomplete.exe`，通常会出现未定义符号的链接错误；不要靠把函数体复制进每个文件解决。

在实现文件中也包含自己的头文件，可以让编译器检查声明与定义一致。共享头文件里优先放声明和类型，不在这里定义一个每次包含就重复产生的普通函数或全局变量。函数前的`static`用于把实现内部辅助函数限制在当前翻译单元，阶段项目的read_line就采用此做法。

## 14.5 assert检查程序员约定

assert来自`<assert.h>`，表达式为假时终止程序并给诊断。本例断言两个输入都在0—1440，这是内部计算函数的前提。测试违反前提时终止是预期行为，不意味着用户输入已经得到友好处理。

可通过NDEBUG配置禁用断言，因此不能把必要业务校验只写在assert里，也不能让assert中的表达式负责真正的赋值、读取或资源释放。用户文件是否合法，要用普通判断返回可处理的错误。

第16章的公开接口会返回枚举结果；断言、错误返回、编译警告各自覆盖不同层面，不能互相替代。

## 14.6 用GDB看见一次计算

已有可用GDB可执行`gdb --version`确认。新装MSYS2的UCRT64用户可按[官方包页面](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-gdb)安装对应gdb包；不要求已装其他环境的读者重新安装。下列GDB步骤是终端交互命令，不写进C源码。

在 **UCRT64 Bash、ch14目录**，先运行上面的带-g编译，再执行`gdb ./totals.exe`。进入`(gdb)`提示符后逐行输入：

```text
break totals.c:7
run
print a
print b
next
print result
continue
quit
```

当前源码第7行是`int result = a + b;`。断点停在这一行执行之前，所以a应30、b应15，result尚未完成初始化；先next执行该行，再print result，得到45。continue继续到程序正常结束。GDB打印值前可能带`$1`等历史编号，不是变量值的一部分。

step可进入函数，next通常把当前行中的函数调用作为一步执行，具体行为依据[官方单步说明](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Continuing-and-Stepping.html)。源码行号改变就按自己的文件调整断点，不要照抄旧行号后认为变量一定初始化了。

## 14.7 测试必须先定义判据

正常用例30、15应45；边界0、0应0，1440、1440应2880；相同参数的多次调用应独立一致。用函数测试检查计算值，用命令行测试检查输出和状态，用后续项目测试检查多个模块协作。

故意漏掉实现文件的实验，判据是“应链接失败”；故意修改const的实验，判据是“应编译失败”。把这些失败写成“测试没通过”会混淆期待的行为与真正缺陷。

动态内存测试还要覆盖分配失败、旧数据保留与释放；文件测试要覆盖截断与读写错误。本课程验证脚本与记录独立保留，不能只截图普通样例。

## 14.8 常见错误

- 修改了头文件但没有重编译相关.c：旧目标文件仍保留旧约定。
- 同时链接两份含main的独立例程：把不同章节当成一个程序了。
- 只编译main却漏掉实现：声明不能代替定义。
- 没有-g就希望看到完整变量信息：重新生成调试版本。
- 在赋值执行前观察局部值：先确认断点时刻与行号。
- 用assert检查用户输入后还宣称错误可恢复：断言失败通常直接终止，应改普通校验。

## 14.9 练习与参考答案

练习一：totals.h能不能单独替代totals.c参与链接？

答案：不能。声明告诉调用方式，定义才提供实际操作。

练习二：计算结果写在assert表达式内有什么问题？

答案：禁用断言后必要操作可能消失，程序行为依赖调试配置。

练习三：GDB停在初始化语句行时，可以把此变量的当前显示值当成计算结果吗？

答案：不可以。先执行相应语句，再观察；调试也必须理解执行顺序。
