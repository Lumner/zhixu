# 35 计数、桶与基数排序

## 35.1 目标与先修

先完成数组、前缀累计、稳定性与辅助内存。建议7—10小时，分三次学习也可以。目标是分别解释计数、分桶、按位分配的依据，手算起始位置，正确映射负数，说明值域、位数和分布对成本的影响。

比较排序反复问“甲比乙大吗”。如果键是范围不大的整数，还可以利用数字本身决定位置。这样的办法需要额外前提，并非把比较删掉就自动更快。

## 35.2 本版先限定值域

三种函数都沿用n<=128，但键只允许-999—999。先验证全部键，再做任何数据变动或申请；发现超界返回S_RANGE，原记录和统计保留。单项也要验证键，不能因“无需排序”就绕过协议。

取偏移u=key-SORT_LOW=key+999，范围0—1998，共R=1999种值。加同一个常数保持顺序：key1<key2等价于u1<u2。因此可以按u排序，再保留原记录中的key，不必改写键本身。

不能对任意int直接key+999，也不能用abs(INT_MIN)作负数处理；它们可能溢出。本版先限制范围，使之后的加减、取余和数组下标都有依据。若键是1000000或目录分钟1440，改用归并等通用比较排序，不能截断、取余后冒充原顺序。

## 35.3 计数：先知道每个键占多少位置

**频数counts[u]**表示偏移值u出现几次。**起始位置next[u]**表示比u小的记录总数，也就是这组记录在输出中的第一格。由前向后累加频数即可得到所有起始位置，这是不包含当前项的前缀累计。

以`-9:A,4:B,-9:C,0:D,12:E`为例，未列出的频数全为0：

| key | 偏移u | counts[u] | 最初next[u] |
| --- | --- | --- | --- |
| -9 | 990 | 2 | 0 |
| 0 | 999 | 1 | 2 |
| 4 | 1003 | 1 | 3 |
| 12 | 1011 | 1 | 4 |

从输入左到右分配：A去0，B去3，C去1，D去2，E去4；每放一条，对应next加1。于是输出A,C,D,B,E，同键-9的A仍先于C。

## 35.4 为什么不只输出重复的键

若只是按counts循环打印整数，tag、标题等负载就丢了。本课把完整SItem放入辅助数组work，随后复制回a，保留所有字段与出现次数。

forward扫描配合递增的组内next保证稳定。另一些教材用累计结束位置、反向扫描，那也是可行方案，但不能把两套位置定义和方向拼在一起；否则可能颠倒相等项或写错格。

每条记录最后恰好分到某个组中唯一位置，counts总和为n，所有组范围连续且互不重叠，所以不会遗漏或覆盖另一条输出记录。

## 35.5 桶：一个范围一组，再在组内排序

**桶排序bucket sort**先按键所在范围分组，桶内再排序，最后按桶范围顺序拼接。本版用10桶，桶号为u/200：桶0代表-999—-800，桶1代表-799—-600，……，桶4代表-199—0，桶5代表1—200，最后桶9代表801—999。

注意0属于桶4、1属于桶5，这是偏移999后的结果，不要按另一种偏移公式凭感觉填桶号。任意较小桶里的key都小于较大桶里的key，所以只需桶内有序，再串起来就全局有序。

本实现先统计每桶大小，以前缀累计计算连续存放区间，将记录稳定分配到同一个work数组中；不是每个桶都额外开n格。每桶内用第32章严格>右移的插入排序。相同键必在同桶，分配和桶内排序都稳定，因此整个版本稳定。

样本的-9、-9、0进桶4，4、12进桶5；两个桶内本来已有序。它仍要做桶内插入的比较和写回，不能把分桶完成当作整个过程零成本。

## 35.6 基数：逐位稳定整理

**基数radix**在这里指每位有多少种数字，十进制为10。LSD表示从最低位开始：先个位，再十位、百位、千位，每一趟都稳定分配。

下面仅是解释位次的正数概念演算，不是改动本版偏移协议：输入`21:A,13:B,11:C,21:D`，个位一趟得到`21:A,11:C,21:D,13:B`；十位稳定分配后得到`11:C,13:B,21:A,21:D`。

处理到十位时，同十位组保留上一趟个位顺序，才使低位结果继续有效。若每趟任意打乱同位记录，低位信息会被破坏。归纳地，完成第d趟后按已处理的低d位有序。

本程序实际处理u=key+999，用`(u/factor)%10`取某位，factor固定1、10、100、1000共四趟，因为最大u=1998。即使某批数据只需较少位，也按四趟执行，便于计数；不声称实现了自适应跳过。

## 35.7 完整实现与内存失败

完整文件distribution.c：

```c
#include "sort_internal.h"
#include <stdlib.h>
#define KEY_RANGE (SORT_HIGH - SORT_LOW + 1)
#define BUCKET_COUNT 10
#define BUCKET_WIDTH 200
static void positions(const size_t *counts, size_t *next, size_t k)
{
    size_t total = 0;
    for (size_t i = 0; i < k; i++) { next[i] = total; total += counts[i]; }
}
static SortStatus prepare(const SItem *a, size_t n, const SortStats *out)
{
    SortStatus status = sort_validate(a, n, out);
    return status == S_OK ? sort_domain(a, n) : status;
}
SortStatus counting_sort(SItem *a, size_t n, SortStats *out)
{
    SortStatus status = prepare(a, n, out);
    if (status != S_OK) { return status; }
    SortStats stats = {0, 0};
    if (n > 1) {
        SItem *work = malloc(n * sizeof *work);
        if (work == NULL) { return S_MEMORY; }
        size_t counts[KEY_RANGE] = {0}, next[KEY_RANGE];
        for (size_t i = 0; i < n; i++) { counts[a[i].key - SORT_LOW]++; }
        positions(counts, next, KEY_RANGE);
        for (size_t i = 0; i < n; i++) {
            size_t key = (size_t)(a[i].key - SORT_LOW);
            sort_write(work, next[key]++, a[i], &stats);
        }
        for (size_t i = 0; i < n; i++) { sort_write(a, i, work[i], &stats); }
        free(work);
    }
    *out = stats;
    return S_OK;
}
SortStatus bucket_sort(SItem *a, size_t n, SortStats *out)
{
    SortStatus status = prepare(a, n, out);
    if (status != S_OK) { return status; }
    SortStats stats = {0, 0};
    if (n > 1) {
        SItem *work = malloc(n * sizeof *work);
        if (work == NULL) { return S_MEMORY; }
        size_t counts[BUCKET_COUNT] = {0}, starts[BUCKET_COUNT], next[BUCKET_COUNT];
        for (size_t i = 0; i < n; i++) { counts[(a[i].key - SORT_LOW) / BUCKET_WIDTH]++; }
        positions(counts, starts, BUCKET_COUNT);
        for (size_t b = 0; b < BUCKET_COUNT; b++) { next[b] = starts[b]; }
        for (size_t i = 0; i < n; i++) {
            size_t b = (size_t)((a[i].key - SORT_LOW) / BUCKET_WIDTH);
            sort_write(work, next[b]++, a[i], &stats);
        }
        for (size_t b = 0; b < BUCKET_COUNT; b++) {
            size_t lo = starts[b], hi = lo + counts[b];
            for (size_t i = lo + 1; i < hi; i++) {
                SItem saved = work[i]; size_t j = i;
                while (j > lo && sort_compare(work[j - 1].key, saved.key, &stats) > 0) {
                    sort_write(work, j, work[j - 1], &stats); j--;
                }
                sort_write(work, j, saved, &stats);
            }
        }
        for (size_t i = 0; i < n; i++) { sort_write(a, i, work[i], &stats); }
        free(work);
    }
    *out = stats;
    return S_OK;
}
SortStatus radix_sort(SItem *a, size_t n, SortStats *out)
{
    SortStatus status = prepare(a, n, out);
    if (status != S_OK) { return status; }
    SortStats stats = {0, 0};
    if (n > 1) {
        SItem *work = malloc(n * sizeof *work);
        if (work == NULL) { return S_MEMORY; }
        for (int factor = 1; factor <= 1000; factor *= 10) {
            size_t counts[10] = {0}, next[10];
            for (size_t i = 0; i < n; i++) { counts[((a[i].key - SORT_LOW) / factor) % 10]++; }
            positions(counts, next, 10);
            for (size_t i = 0; i < n; i++) {
                size_t digit = (size_t)(((a[i].key - SORT_LOW) / factor) % 10);
                sort_write(work, next[digit]++, a[i], &stats);
            }
            for (size_t i = 0; i < n; i++) { sort_write(a, i, work[i], &stats); }
        }
        free(work);
    }
    *out = stats;
    return S_OK;
}
```

positions在读counts后写独立next，不覆盖频数；桶还保留starts供之后界定区间。每次next后自增都只在预先分配给该组的范围内前进。

每个算法n>1时只申请一次n项辅助空间，申请失败前尚未修改输入；之后只执行有界分配/排序，不再申请。n=0或1验证通过后直接写零统计。统计与频数数组是不同对象，不能把它们混为一个“counts”。

## 35.8 复杂度必须把参数写全

计数排序时间Θ(n+R)、额外空间Θ(n+R)，本版R=1999；频数清零与累计即使没有记录写入计数也真实发生。n很小而R很大时，它可能比简单插入浪费更多工作与内存。

桶排序用B桶，各桶数量n₀、n₁……，本版桶内插入，总时间可用O(n+B+Σnᵢ²)描述，最坏全挤一桶为O(n²+B)，额外空间O(n+B)。固定10桶不保证随n增大仍线性；好的平均结论需要相应分布和桶数策略，不能只写“桶排序O(n)”。

基数排序d趟、每位b种值，时间Θ(d(n+b))，额外空间Θ(n+b)；当前d=4、b=10。若推广到更多位或变长字符串，位数成本要重新计入。

比较排序的一般Ω(n log n)下界是在只靠键比较、处理一般不同键顺序的模型下讨论的；这里额外利用有限整数值域或位结构，因此并不矛盾。comparisons=0只是没有调用本课键比较器，不是没有运算。


预期：

```text
counting comparisons=0 writes=10
-9:0 -9:2 0:3 4:1 12:4
bucket comparisons=3 writes=13
-9:0 -9:2 0:3 4:1 12:4
radix comparisons=0 writes=40
-9:0 -9:2 0:3 4:1 12:4
```

计数每项写work、再写回，共2n=10；桶还做3次组内插入填回，共13；基数四趟，每趟2n，总40。三个结果都保留-9的标记0、2先后。

## 35.10 常见错误

未验证就负数作下标或做偏移；只重建键丢掉tag；混用累计起点/终点与扫描方向；桶内没排序就连接；基数每趟不稳定；有负数就直接取带负号的余数当桶号；忽略R/d/B，只按n宣传线性；用comparisons=0宣称最快；分配失败时先清输入或清统计。

## 35.11 练习与参考答案

练习一：-999和999映射为几？答案：0与1998，1999格覆盖两端。

练习二：为什么目录分钟1440不能直接用本版计数？答案：超出其键域，必须S_RANGE；目录视图选通用归并，不能默默改变本章协议。

练习三：LSD完成个位后再按十位不稳定排序是否一定正确？答案：不一定；同十位记录的个位顺序可能被颠倒，破坏已建立的低位有序。
