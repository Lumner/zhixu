# 09 字符串与整行输入

## 9.1 目标与先修

先完成第08章与第一阶段练习，能解释数组下标和循环。建议4—6小时。本章让资料有一个标题，学会字符数组、字符串结束标记、长度、比较，以及“缓冲区装满不等于整行读完”。

本次输入约定：一行非空文字，最多15字节，不包含内嵌零字节；最后可以没有换行。它是文本输入协议，不是任意二进制数据协议。中文UTF-8的字节数与汉字个数不同，限制按字节计算。

## 9.2 字符串多了一个结束标记

第03章用`char`保存一个简单字符。C字符串则是一段以`'\0'`结束的字符序列，通常保存在字符数组中。`'\0'`叫空字符或终止零，数值为0；它不是数字字符`'0'`，也不是空指针。

**上下文片段：main内部。**

```c
char title[4] = "C17";
```

| 下标 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| 内容 | C | 1 | 7 | 终止零 |

文字有3字节，数组需要至少4格。`char title[] = "C17";`会根据初始化文字分配4格。若手写`{'C','1','7'}`但没有终止零，它只是3个字符，不是可安全传给字符串函数的字符串。

终止零告诉字符串函数在哪里停下。`printf("%s", title)`遇到它停止；没有有效终止标记就可能越界读取。不要把“碰巧打印了正确文字”当作存储正确的证明。

## 9.3 长度、容量、sizeof与strlen

`sizeof title`得到数组对象所占字节数；`strlen(title)`从开头数到第一个终止零之前，得到当前字符串长度，不包含终止零。对`char title[16] = "C";`，二者分别为16与1。

`strlen`声明在`<string.h>`。它只适用于已经正确终止的字符串，不能用来检查一块来历不明的内存是否安全。`sizeof`是语言运算符，不是普通函数；这里的`sizeof title`不会遍历文字。

长度的类型用`size_t`表示，它是一种用于对象大小和计数的无符号整数类型，配`%zu`显示。本例包含的标准头文件提供其定义。第11章会专门讨论无符号边界和数组参数；现在不要把size_t随意改成int来消除警告。

UTF-8中的“算法”通常占6字节，`strlen`得到6，不是2。终端显示几列、用户看见几个字符、程序保存多少字节，是三个不同问题。本课不在这一章实现Unicode字符切分。

如果保留的是旧版MinGW工具链，编译器可能把%zu按旧微软运行库格式诊断为不支持。确认属于这种环境时，可在本章及后续编译命令的gcc后添加`-D__USE_MINGW_ANSI_STDIO=1`，启用该工具链提供的标准格式实现；不要简单删掉格式警告。本课推荐的MSYS2 UCRT64主线无需为了旧工具链改变标准C源码，实际验证选项单独记录。

## 9.4 文字比较与复制不是数字赋值

`strcmp(a,b)`比较两个正确终止的字符串；返回0表示内容相同，小于或大于0表示一种按字节比较的顺序。不要假定它恰好返回-1或1，也不要把这种顺序当作中文拼音顺序。

`a == b`比较数组用于表达式后所代表的位置，不比较文字。数组与地址的关系在第10、11章讲。现在检查内容相同应写`strcmp(title, "C basics") == 0`。

已经创建的字符数组不能用`title = "new"`整体改写。复制需要确认目的容量足够，包括终止零。本批不使用不检查容量的输入或复制函数；第12章会看到，结构体内部的字符数组随结构体赋值可以整体复制，这和单独数组赋值不同。

## 9.5 fgets到底读了什么

`fgets(title, sizeof title, stdin)`最多向16格中放15个输入字符，再补终止零。若在容量耗尽前读到换行，换行也会存进数组；若立刻遇到输入结束且一个字符也没有读到，则返回`NULL`。

这里先把`NULL`理解为“没有成功结果”的空值标记：只用它检查成功与否，下一章会解释它作为空指针的含义。`stdin`是标准输入流；fgets接收数组的机制也在第11章展开。使用标准函数前先理解其输入输出约定，不要求此刻自己实现库函数。

输入`C17`加Enter后，数组是C、1、7、换行、终止零。想要不含换行的标题，就把最后的换行替换成终止零，长度随之减1。

输入恰好15字节时，fgets已经装满，换行还可能留在输入流中。不能仅凭“数组里没有换行”就宣布太长：需要再读取一个字符；若正好是换行或EOF，15字节仍合法；若是普通字符，才说明这一行超限。

## 9.6 完整实验与逐步解释

**完整程序：strings.c。** 下载 [源码](示例代码/09-strings/strings.c)，保存到自己的`~/dsa-labs/ch09`。

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
    char title[16];
    if (fgets(title, sizeof title, stdin) == NULL) {
        puts("missing input");
        return 1;
    }
    size_t length = strlen(title);
    if (length > 0 && title[length - 1] == '\n') {
        title[--length] = '\0';
    } else if (length == sizeof title - 1) {
        int ch = getchar();
        if (ch != '\n' && ch != EOF) {
            while (ch != '\n' && ch != EOF) {
                ch = getchar();
            }
            puts("too long");
            return 1;
        }
    }
    if (length == 0) {
        puts("empty title");
        return 1;
    }
    printf("title=%s\nbytes=%zu\n", title, length);
    printf("same=%d\n", strcmp(title, "C basics") == 0);
    return 0;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch09`目录**执行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic strings.c -o strings.exe
printf 'C basics\n' | ./strings.exe
```

结果为：

```text
title=C basics
bytes=8
same=1
```

程序先处理缺失输入，再取得长度；非空且最后为换行时，`title[--length] = '\0'`先把length减1，再写终止零，相当于先单独写`length--;`再用新下标。若满15字节仍无换行，就做一次向前读取；确实超长时继续读到本行结束后报错，不把半个标题当完整标题。

最后检查空标题。空行读到了换行，去掉之后length为0；完全没有输入则在fgets处失败，这两种情况有不同消息。这里只读一行，不处理后面的其他行；若用于循环录入，保留“消耗完超长行”的约定会很重要。

## 9.7 必做边界实验

| 输入 | 预期 | 原因 |
| --- | --- | --- |
| 空输入立即EOF | missing input，状态1 | 没有读到一行 |
| 只有Enter | empty title，状态1 | 读到一行，但去掉换行后为空 |
| C basics | bytes=8，same=1 | 空格也是一个字节 |
| 15个英文字母 | 接受，bytes=15 | 第16格留给终止零 |
| 16个英文字母 | too long，状态1 | 不是静默截断 |
| 15字节后直接EOF | 接受 | 不要求最后必须有换行 |

在同一Bash目录可用`printf '123456789012345\n' | ./strings.exe`核对15字节边界，再多加一个6测试16字节。正常返回0，三种错误返回1。中文输入实验记录实际字节数，不按显示宽度推算容量。

## 9.8 常见错误

- 忘记为终止零留一格：15字节标题需要16格。
- 把`'0'`写成结束标记：那会添加可见数字0，不能终止字符串。
- 用sizeof当文字长度：容量不随当前标题改变。
- 用strlen检查未终止数组：检查本身就可能越界。
- 认为没有换行就是超长：恰好装满的行还需向前看一个字符。
- 用`==`比较文字或用`%d`显示size_t：改用strcmp和%zu。

## 9.9 练习与参考答案

练习一：`char x[8] = "cat";`的容量、strlen和最后一位正文下标分别是多少？

答案：8字节、3字节、下标2；终止零在下标3，剩余格子也被初始化为0。

练习二：15字节读满后，下一个getchar读到换行，应接受还是拒绝？

答案：接受。正文恰好符合上限，换行属于行结束，不属于标题。

练习三：只改数组容量为8，最多允许多少正文字节？测试哪些值？

答案：最多7；测试0、1、6、7、8字节，特别检查7后换行、7后EOF和8后换行。程序中的sizeof会跟随容量变化。
