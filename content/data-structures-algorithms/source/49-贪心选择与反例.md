# 49 贪心选择与反例

## 49.1 目标与先修

先完成排序、循环不变量和第48章最小生成森林。建议6—8小时，含手推、重写和改错。本章要做到：写清优化目标；区分“现在最好”与“最后最好”；用交换论证解释活动选择；用小反例否定不可靠的规则。

**可行解**是满足全部限制的答案；**最优解**是可行解中目标最好的答案。最优解可能有多份，不要求某一份唯一。

**贪心算法**在每一步按某条规则选一个当前最合适的选项，并固定这个选择。关键不是“排序后遍历”，而是：为什么固定后仍至少保留一个最优解？前章Kruskal的安全选边就是已证明适用的例子。本章会遇到适用与失效两种情况。

## 49.2 先写问题，再选择规则

一间教室同一时刻只能安排一个活动。活动有ID、开始时间start、结束时间end，目标是**安排活动数量最多**，不是总时长最长，也不是收益最大。

本章用半开区间`[start,end)`表示占用时间：包括开始、不包括结束。因此`[1,3)`和`[3,5)`不冲突，判断应是下一项`start >= last_end`。要求start<end，排除零时长的特殊语义。

**问题规格**：输入最多8个活动，时间0—60，ID唯一，原数组不变；输出一个不冲突且数量最多的ID序列。空输入输出0项。活动可以有相同的开始/结束时间，只要ID不同；它们是不同候选，不代表能同时安排。

如果改成“每个活动收益不同，求总收益最大”，这里的证明就不够了。先确认目标，是判断算法能否复用的第一步。

## 49.3 三个看起来合理的规则

考虑以下活动，先别看后面的选择：

| ID | 区间 | 意义 |
| --- | --- | --- |
| 10 | [0,6) | 开始最早，但占用很久 |
| 20 | [1,3) | 结束最早 |
| 30 | [3,5) | 可紧接20 |
| 40 | [5,7) | 可紧接30 |
| 50 | [7,8) | 可紧接40 |

“开始最早”会先取10，随后只能再取50，共2个；20→30→40→50能取4个。所以开始最早不可靠。

“时长最短”也不保证。例如`[0,3)、[3,6)、[2,4)`，最短的是`[2,4)`，却同时挡住另外两个。一次能反驳规则的输入叫**反例**；找出一个反例，便足以否定“对所有合法输入都最优”，但若干成功样例不能证明这个全称命题。

本题采用：在仍可安排的活动里，取**结束最早**的一个。直觉是尽量给后面留空间；接下来必须把直觉变成证明。

## 49.4 交换论证：把最优解的第一项换过来

令g为所有活动中结束最早者。设某个最优安排O的第一项为a。

1. 因g结束最早，g.end≤a.end。
2. O里a后面的每个活动，都从不早于a.end的时刻开始。
3. 用g替换a，后面的活动仍能接上，活动数量不变。

因此至少存在一个最优安排以g开头。这里没有声称每个最优安排都必须包含g，也没有声称g开始更早。

固定g以后，只保留start≥g.end的活动；剩下的仍是同一种问题。对剩余问题重复上述交换，就能逐项构成一个最优安排。**交换论证**的作用，是把任意最优解改造成包含当前选择的最优解，而不让目标变差。

结束时间相同的候选，任取一个都不影响数量最优；本程序额外按start、id排序，只为输出确定。这不是对所有最优解的完整枚举。

## 49.5 排序后怎样扫描

将活动按end非递减排列。扫描不变量是：已选序列互不冲突，last_end是最后一项的结束时间；当前扫描位置以前的候选已被考虑。

| 扫到 | 判断 | 选后结果 |
| --- | --- | --- |
| 20：[1,3) | 还没选过 | 20；last_end=3 |
| 30：[3,5) | 3≥3 | 20,30；last_end=5 |
| 10：[0,6) | 0<5 | 跳过，结果保持 |
| 40：[5,7) | 5≥5 | 20,30,40；last_end=7 |
| 50：[7,8) | 7≥7 | 20,30,40,50 |

排序改变的是局部副本sorted，输出记录ID，不能把排序后的数组位置当业务ID。原输入保持原来的顺序。

## 49.6 完整活动选择模块

公共常量/状态见 [design.h](示例代码/stage9-common/design.h)，结构体与接口见 [interval.h](示例代码/49-interval/interval.h)。Activity为`{id,start,end}`，Schedule含最多8个ID及实际count。

下面是**完整模块文件interval.c**，需要上述头文件和[入口main.c](示例代码/49-interval/main.c)共同编译，不是单文件独立程序：

```c
#include "interval.h"
static int earlier(Activity a, Activity b)
{
    if (a.end != b.end) { return a.end < b.end; }
    if (a.start != b.start) { return a.start < b.start; }
    return a.id < b.id;
}
DStatus activity_select(const Activity *items, size_t n, Schedule *out)
{
    if (out == NULL || (n != 0 && items == NULL)) { return D_INVALID; }
    if (n > D_ITEMS) { return D_RANGE; }
    Activity sorted[D_ITEMS];
    for (size_t i = 0; i < n; i++) {
        if (items[i].start > D_LIMIT || items[i].end > D_LIMIT) { return D_RANGE; }
        if (items[i].start >= items[i].end) { return D_INVALID; }
        for (size_t j = 0; j < i; j++) {
            if (items[j].id == items[i].id) { return D_INVALID; }
        }
        sorted[i] = items[i];
    }
    for (size_t i = 1; i < n; i++) {
        Activity saved = sorted[i];
        size_t j = i;
        while (j > 0 && earlier(saved, sorted[j - 1])) {
            sorted[j] = sorted[j - 1]; j--;
        }
        sorted[j] = saved;
    }
    Schedule next = {0};
    unsigned last_end = 0;
    for (size_t i = 0; i < n; i++) {
        if (next.count == 0 || sorted[i].start >= last_end) {
            next.ids[next.count++] = sorted[i].id;
            last_end = sorted[i].end;
        }
    }
    *out = next;
    return D_OK;
}
```

`earlier`返回前者是否应排在前面；这是普通C函数，不是C++比较器对象。插入排序先保存一整条记录，搬动时不能只动end，否则ID与时间会错配。

函数先验证参数，再在局部next中生成答案，成功后一次赋给*out。D_INVALID表示空指针/无效区间/重复ID等结构错误，D_RANGE表示超出容量或时间范围。输入数组与输出对象须独立；n=0时items可为NULL，out仍须有效。

本实现为了沿用已学的插入排序，验证重复ID与排序都为O(n²)，扫描O(n)，局部副本O(n)。不能把使用更快排序时的O(n log n)直接写成本程序的成本。数组按8项上限预留；没有malloc，也就没有分配失败分支。

## 49.8 零钱问题：相同直觉不代表相同证明

给定可无限使用的硬币面额，要求**恰好凑出金额，枚数最少**。面额不是活动区间，前面的交换不能直接套用。

面额4、3、1，金额6。每次取不超过剩余金额的最大硬币，得到4+1+1，共3枚；3+3只需2枚。把最优解中的一枚3替换成4，并不能保证剩余金额仍能以同样枚数凑出；交换论证断在这里。

再去掉面额1，只剩4、3，金额仍为6。该规则先取4，剩余2卡住，然而3+3确实可行。**某条贪心路径走不通，不等于整个问题无解。** 程序用D_STUCK表达前者；第51章用完整状态计算判断后者。

这些是自造的算法例子，不是现实货币建议。含面额1只能保证有解，不能保证这种贪心总是最优。

## 49.9 完整零钱贪心与运行

本批协议：最多8种面额，1—20，必须严格降序（因此也无重复）；金额0—60。`counts[i]`对应输入的第i种面额；total为枚数；possible仅在成功结果中为1。空面额加金额0成功，空面额加正金额返回D_STUCK。

完整接口见 [coins.h](示例代码/49-change/coins.h)。其中另有第51章才实现的两个DP函数声明；编译本入口只用greedy.c即可。**完整模块文件greedy.c**：

```c
#include "coins.h"
DStatus greedy_change(const unsigned *coins, size_t n, unsigned amount, Change *out)
{
    if (out == NULL || (n != 0 && coins == NULL)) { return D_INVALID; }
    if (n > D_COINS || amount > D_LIMIT) { return D_RANGE; }
    for (size_t i = 0; i < n; i++) {
        if (coins[i] == 0 || coins[i] > D_DENOM) { return D_RANGE; }
        if (i > 0 && coins[i - 1] <= coins[i]) { return D_INVALID; }
    }
    Change next = {0};
    unsigned remaining = amount;
    for (size_t i = 0; i < n; i++) {
        next.evaluations++;
        next.counts[i] = remaining / coins[i];
        remaining %= coins[i];
        next.total += next.counts[i];
    }
    if (remaining != 0) { return D_STUCK; }
    next.possible = 1;
    *out = next;
    return D_OK;
}
```

对每种面额用除法一次算出取几枚，用余数更新剩余金额，不需要一枚枚循环。`remaining %= coins[i]`使用前已验证面额非零；不能通过实际除以零来学习错误结果。

仍在 **UCRT64 Bash、`source/示例代码`目录**：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -Istage9-common \
  49-change/main.c 49-change/greedy.c -o greedy-change.exe
./greedy-change.exe
```

预期：

```text
greedy total=3 counts=1,0,2
manual better: 3+3 uses 2 coins
stuck=1 old_total=99
```

最后一行的99是入口预先放入的旧值。它证明失败时输出保持，不能把旧值当这次计算结果；调用方必须先判断返回码。evaluations统计处理了多少种面额，不是墙上时钟时间，也不与后面的DP状态数直接当同一种工作量比较。

本实现验证O(k)、取硬币O(k)，k为面额种数；固定结果数组按8项清零。不对任意面额承诺最优，只准确运行这条规则。

## 49.10 怎样审查一个新的贪心规则

先写四件事：输入限制、可行性、目标函数、选择规则。接着问当前选择固定后，为什么还能找到一个全局最优解；可以尝试交换论证、安全边论证，或构造一个小反例。

例如活动有收益后，`[0,1)`收益1、`[0,2)`收益100，结束最早会取收益1，却非收益最大。算法名称没变，目标变了，结论就要重新审查。背包按“价值/费用比”从高到低也会在第51章出现反例。

不要把“随机试了很多次没失败”写成数学证明；也不要因一类贪心失效，就断言所有贪心都不可靠。前八阶段的哈夫曼、非负Dijkstra、最小生成树分别有自己的适用条件与证明。

## 49.11 常见错误

| 错误 | 原因与修正 |
| --- | --- |
| 用start>last_end | 把相邻的半开区间误判冲突，应使用≥ |
| 只按开始时间排 | 没有对应交换依据，长活动可能挡住多项 |
| 搬时间但不搬ID | 记录关系被破坏，必须搬整条Activity |
| 输入收益却仍说数量最优等于收益最优 | 两个目标不同，重新建模 |
| 面额有1就认定贪心最优 | 4、3、1凑6已有反例 |
| D_STUCK后读取旧total | 返回失败，输出有意保留旧值，先检查状态 |

## 49.12 练习与参考答案

练习一：`[0,2)、[2,4)、[1,3)`最多取几个？写出本算法顺序。答案：2个；按结束时间先取[0,2)，跳过[1,3)，再取[2,4)。

练习二：交换论证中，g.start≤a.start是否必要？答案：不必要。首项替换只需g.end≤a.end，后续活动就仍能接上；g自身是合法活动。

练习三：8、5、1凑10，最大面额优先得到几枚？更好的方案？答案：8+1+1为3枚，5+5为2枚。

练习四：为何本章不直接复用第35章限制-999—999的排序键，强行把所有未来业务时间塞进去？答案：输入范围/记录类型是接口契约。当前局部实现只排序本章Activity，不改旧接口来满足新例子。

独立任务和更完整答案见 [第九阶段上练习](第九阶段上-练习.md) 与 [参考答案](第九阶段上-参考答案.md)。
