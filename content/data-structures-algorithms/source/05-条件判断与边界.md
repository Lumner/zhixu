# 05 条件判断与边界

## 5.1 目标与先修

先完成第04章的输入检查。建议3—4小时。本章把“如果满足某条件就执行某操作”讲完整，重点是条件覆盖范围、先后顺序与门槛附近的测试。

业务问题：输入0—9个学习块，每块10分钟。达到8块显示`excellent`，达到5块但不到8块显示`keep-going`，不足5块显示`start-small`。文字只是练习反馈，不评价学习者本人；重要的是程序的区间规则。

## 5.2 条件的结果是成立还是不成立

C把0当作假，非0当作真。比较运算产生int类型的0或1，可以直接用在if的括号内。

| 写法 | 含义 | blocks为5时 |
| --- | --- | --- |
| `blocks > 5` | 大于5 | 假 |
| `blocks >= 5` | 大于或等于5 | 真 |
| `blocks < 5` | 小于5 | 假 |
| `blocks <= 5` | 小于或等于5 | 真 |
| `blocks == 5` | 等于5 | 真 |
| `blocks != 5` | 不等于5 | 假 |

`=`用于赋值，`==`用于判断相等。把`if (blocks == 5)`误写成`if (blocks = 5)`会修改变量；赋值结果5又被当成真。编译器常会警告，但根本解决方法是明确你在“改变值”还是“提出问题”。

## 5.3 多个条件怎样组合

`&&`表示都成立，`||`表示至少一个成立，`!`表示取反。合法范围0—9可写成`blocks >= 0 && blocks <= 9`；不合法可写成`blocks < 0 || blocks > 9`。

不要写`0 <= blocks <= 9`。C会先算`0 <= blocks`，得到0或1，再拿这个结果与9比较，无法表达数学中的连写区间。

`&&`和`||`还有短路规则：左边已经决定结果，就不计算右边。例如`count != 0 && total / count > 10`在count为0时不会除以0。不要用单个`&`、`|`替代，它们是另一类运算，后面再讲。对混合条件加括号使意思清楚，不靠猜优先级。

## 5.4 if、else if与else怎样选择

**上下文片段：main内，blocks已是0—9的合法整数。**

```c
if (blocks >= 8) {
    puts("excellent");
} else if (blocks >= 5) {
    puts("keep-going");
} else {
    puts("start-small");
}
```

整个链从上到下检查，第一个成立的分支执行后，不再检查后面的分支。到达第二个判断时，已经知道blocks小于8，所以只写`>= 5`就表达5—7；最后剩下0—4。

如果把`>= 5`放在最前，8和9也会先被它接住，`excellent`永远无法执行。这不是编译错误，而是分支顺序破坏了业务规则。

如果写两个独立的if，输入9可能同时显示两条消息。独立if适合多个动作可同时发生的情况；互斥的分类应使用一个清晰的分支链。

## 5.5 完整实验：学习块反馈

**完整程序：branches.c。** 保存到 `~/dsa-labs/ch05`，或下载 [源码](示例代码/05-branches/branches.c)。前半段输入检查沿用第04章，后半段才是新增业务。

```c
#include <stdio.h>

int main(void)
{
    int digit = getchar();
    int ending = getchar();

    if (digit < '0' || digit > '9') {
        puts("invalid input");
        return 1;
    }
    if (ending != '\n' && ending != EOF) {
        puts("invalid input");
        return 1;
    }

    int blocks = digit - '0';
    if (blocks >= 8) {
        puts("excellent");
    } else if (blocks >= 5) {
        puts("keep-going");
    } else {
        puts("start-small");
    }
    return 0;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch05`目录**执行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic branches.c -o branches.exe
printf '8\n' | ./branches.exe
```

输出`excellent`。接着分别输入0、4、5、7、8、9；再输入a和10。预测表如下：

| 输入 | 预期输出 | 检查目的 |
| --- | --- | --- |
| 0 | start-small | 最小值 |
| 4 | start-small | 5的前一位 |
| 5 | keep-going | 恰好达到门槛 |
| 7 | keep-going | 8的前一位 |
| 8、9 | excellent | 门槛与最大值 |
| a、10 | invalid input，状态1 | 字符及长度检查 |

只测6无法区分`>= 5`和`> 5`，所以门槛本身特别重要。后面数据结构的空/满、首/尾，也用同样方法选测试点。

## 5.6 花括号、分号与嵌套

本课即使分支只有一条语句，也写花括号。这样后来多加一条输出时，不会误以为它也受if控制。

`if (condition);`末尾那个分号是一个空语句，意味着if控制的是“什么也不做”，后面的块可能无条件执行。不要在条件右括号与左花括号之间加分号。

一个if内可以再有if，这叫嵌套。先验证输入、错误时尽早return，再处理正常情况，往往比层层嵌套容易读。else默认关联最近尚未匹配的if；成对花括号能明确关联。

## 5.7 switch适合离散选项

if适合大小区间，switch常用于几个明确整数或字符选项。下面是**上下文片段：放在main内，替代其他业务片段**，不是完整程序：

```c
int option = 2;
switch (option) {
case 1:
    puts("add");
    break;
case 2:
    puts("list");
    break;
default:
    puts("unknown");
    break;
}
```

`case 2`匹配值2；`break`跳出这个switch；`default`处理没有任何case匹配的情况。此例只显示list。若漏掉case 1后的break，选1时会继续执行后面语句，这叫贯穿。先掌握有明确break的版本，不依赖贯穿技巧。

switch的case不是随意范围，也不能直接用字符串作为本例这样的选择值。学习块的5—7区间继续使用if更直接。

## 5.8 常见错误

- 把“至少5”写成`> 5`：漏掉端点5。
- 用`&&`连接两个不可能同时满足的非法范围条件，如`x < 0 && x > 9`：永远不成立。
- 在if后加空分号：分支失去作用。
- 先写较宽条件：后面的窄条件被挡住。
- 两个独立if重复输出：先判断动作是否应互斥。
- 修改分支后只测中间值：还要重新测门槛前、门槛、门槛后。

## 5.9 练习与参考答案

练习一：学习分钟0—1440是否合法，写条件。非法条件又是什么？

答案：合法为`minutes >= 0 && minutes <= 1440`；非法为`minutes < 0 || minutes > 1440`。

练习二：为`>= 8`改成`> 8`的错误找一个能暴露它的输入。

答案：8。正确规则显示excellent，错误规则显示keep-going。

练习三：switch例子中option为1，若删掉第一个break，输出什么？

答案：先add，再list，然后在第二个break处离开。不需要重新匹配case 2才执行那里的语句。
