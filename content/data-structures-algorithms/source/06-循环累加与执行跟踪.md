# 06 循环、累加与执行跟踪

## 6.1 目标与先修

先掌握条件判断。建议3—5小时。循环让同一套操作重复作用于不同数据，但也会带来漏一次、多一次、一直停不下来的问题。本章要求你画出每轮变化，再运行核对。

小问题：求1+2+3+4+5。直接写五个加数不难；如果上限由输入决定，不能每次改写一条很长的表达式。我们要表达“从1到n，逐个累加”。

## 6.2 for的三个部分

**上下文片段：main内，n和total已声明并初始化。**

```c
for (int i = 1; i <= n; i++) {
    total = total + i;
}
```

读法是：先创建i并设为1；每轮开始前判断`i <= n`；成立就执行循环体；循环体结束后执行`i++`，再回到条件。

`i++`在这里表示把i增加1。现在只把它当单独的一次更新，不把它嵌入复杂表达式。循环头中的两个分号分隔初始化、条件和更新，最后的右括号后不加空分号。

for的初始化只做一次，条件可能检查多次，更新在每轮循环体之后做一次。n为5时，循环体执行5次，条件检查6次，最后一次是i为6而条件为假。这一差别是后面计数分析的起点。

## 6.3 完整实验：看见每一轮

**完整程序：sum.c。** 保存到 `~/dsa-labs/ch06`，或下载 [源码](示例代码/06-loops/sum.c)。

```c
#include <stdio.h>

int main(void)
{
    int n = 5;
    int total = 0;

    for (int i = 1; i <= n; i++) {
        total = total + i;
        printf("i=%d total=%d\n", i, total);
    }
    printf("sum=%d\n", total);
    return 0;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch06`目录**编译运行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic sum.c -o sum.exe
./sum.exe
```

预期输出：

```text
i=1 total=1
i=2 total=3
i=3 total=6
i=4 total=10
i=5 total=15
sum=15
```

调试输出位于加法之后，所以显示的是“这一轮处理完成”的总和。移到加法之前，第一行total会是0。状态跟踪必须说明观察时刻。

| 轮次开始i | 条件成立吗 | 本轮之前total | 本轮之后total | 更新后i |
| --- | --- | --- | --- | --- |
| 1 | 是 | 0 | 1 | 2 |
| 2 | 是 | 1 | 3 | 3 |
| 3 | 是 | 3 | 6 | 4 |
| 4 | 是 | 6 | 10 | 5 |
| 5 | 是 | 10 | 15 | 6 |
| 6 | 否 | 15 | 不执行 | 不更新 |

开始前total是空和0；每轮加入当前i，循环结束时已加入1到n的全部整数。这比“电脑算出来就是15”更能说明原因。现在先用语言解释，第17章再正式写正确性论证。

## 6.4 边界不是额外的小事

将n依次改成0、1、5并重新编译：n为0时一次都不进入循环，只输出sum=0；n为1时一次；n为5时五次。如果改成`i < n`，n为1时就漏掉唯一的数，n为5时只得到10。

本程序的业务前提是n为非负的小整数。练习时限制0—100，避免总和或计数器超出int范围。不要直接把n改为极大整数来“测性能”；整数类型有上限，重复运算也可能溢出。

`total = total + i`可简写为`total += i`。但`total = i`只是覆盖旧值，最后得到5而非15。若写成`int total = 0;`放在循环体内，每轮又从0开始，也没有跨轮累积。

## 6.5 while：条件为真就继续

下面是**替换main中计算部分的上下文片段**，不要和已有同名变量重复放置：

```c
int remaining = 3;
while (remaining > 0) {
    printf("%d\n", remaining);
    remaining--;
}
```

它依次显示3、2、1。`remaining--`减1；减到0后条件为假，结束。while也可能执行0次，例如初值为0。

如果漏掉减1，remaining一直是3，条件永远成立，程序不断输出；这叫死循环。调试时用Ctrl+C结束这个自己的练习程序，再修复状态更新。对一个循环总要问：初始状态是什么，何时继续，谁让它接近停止条件？

有时状态来自输入，例如每轮读取下一个字符，遇到换行停止。阶段项目会用这种while循环，不需要预先知道这一行有几位。

## 6.6 do while：至少先做一次

**上下文片段：main内，独立替换其他练习部分。**

```c
int remaining = 0;
do {
    printf("%d\n", remaining);
    remaining--;
} while (remaining > 0);
```

它仍输出一次0，因为先执行循环体，再检查条件。结尾的分号是do while语法的一部分，不是for或while头后误加的空语句。改为普通while，则初始条件为假，一次也不输出。

选择依据是问题：明确次数常用for；条件决定是否继续常用while；必须先执行一次才检查可用do while。三者不是速度排名。

## 6.7 break与continue不是一回事

**上下文片段：main内。**

```c
for (int i = 1; i <= 5; i++) {
    if (i == 2) {
        continue;
    }
    if (i == 4) {
        break;
    }
    printf("%d\n", i);
}
```

输出1和3。continue跳过本轮剩余部分；在for中随后仍执行更新i++。break立即离开最近的一层循环或switch，4不打印，5也不会再处理。

while中使用continue时，不会自动帮你更新自定义计数器。若把减1放在continue之后，某个分支可能永远碰不到它。初学时把所有状态更新路径画清楚。

查找目标时找到就break很自然；求整组数据总和时遇到目标却break，会漏掉后续值。控制语句是否正确取决于整个任务，而不是它的名字。

## 6.8 嵌套循环怎样数

**概念演算：** 外层重复3次，内层每次重复2次，并且内层每轮重新初始化，则内层工作总共做3×2=6次；如果内层上限随外层变化，就不能直接用同一个常数相乘。

本阶段先数具体次数。到第18章再把3和2替换为输入规模n，推导增长速度。不要看见两个for就直接背一个复杂度结论，需要检查它们各自的范围和依赖。

## 6.9 常见错误

- 从1到n写`< n`：漏掉n，先列出最小输入n=1。
- 从0开始遍历n条数据却用`<= n`：多处理一次；数组章节会看到它的危险。
- 在循环内反复初始化累加器：不能保留前面结果。
- 条件变量不变化：无法接近终止状态。
- 不区分循环体与循环外输出：最终汇总放循环外，每轮跟踪放循环内。
- 把break理解成“跳过这一次”：它会结束整个最近循环，跳过本轮用continue。

## 6.10 练习与参考答案

练习一：for中i从1开始，条件`i <= 3`，更新i++，循环体和条件各执行几次？

答案：循环体3次，条件4次。最后i为4时检查失败。

练习二：求1至5的奇数之和，如何在本章完整程序中改造？

答案：在加法与跟踪输出外加 `if (i % 2 != 0) { ... }`，或在循环开始处对偶数continue；最终为1+3+5=9。`% 2`在整数中检查奇偶。

练习三：计算0次时，为什么总和是0而不是“没有初始化”？

答案：total在进入循环前已经设为0，即使循环不执行也有确定结果。
