# 38 二叉树遍历、显式栈与层序

## 38.1 目标与先修

先完成第37章、栈、队列与递归。建议5—7小时。目标是手推前/中/后序与层序，区分访问时机，理解显式栈保存的待办工作，运行三种递归、三种迭代和一种层序。

**遍历traversal**是按某种规则把每个节点访问一次。本章“访问”具体指把value复制到输出数组，不改变树、不释放节点。树形相同，只换访问时机，输出就会不同。

## 38.2 三种深度优先顺序

先固定左子树在右子树之前。前序preorder为“当前、左、右”；中序inorder为“左、当前、右”；后序postorder为“左、右、当前”。这里的前中后指当前节点在左右任务中的位置，不是指数组下标或键大小。

对第37章样本：

```text
      4
     / \
    2   6
   / \
  1   3
前序：4,2,1,3,6
中序：1,2,3,4,6
后序：1,3,2,6,4
```

样本中序碰巧递增，是因为这个样本也符合搜索树关系；普通二叉树的中序不保证有序，把4和6的值换掉就能看见区别。

## 38.3 递归调用究竟在等什么

处理节点2时，前序先访问2再递归1；中序先等左子树1返回再访问2；后序要等1和3都返回才访问2。空指针直接返回，不输出一个“空节点值”。

递归每次只处理当前子树，对左右子树使用同一规则。两个子树不共享节点且不含当前根，因而每个真实节点恰被访问一次。第37章释放也采用后序思想，但这里的遍历仅复制值，不能把两种操作随便混在一起。

## 38.4 前序显式栈：待办项后进先出

不使用递归时，自己保存尚待处理的节点地址。开始把root压栈；每次弹出并访问，先压右，再压左。由于栈后进先出，左边下一步先处理。

| 动作 | 栈底→栈顶 | 已输出 |
| --- | --- | --- |
| 压4 | 4 | 空 |
| 弹4，压6再2 | 6,2 | 4 |
| 弹2，压3再1 | 6,3,1 | 4,2 |
| 弹1 | 6,3 | 4,2,1 |
| 弹3、再6 | 空 | 4,2,1,3,6 |

不能照“先左再右”的阅读顺序直接压左再压右，否则访问顺序变成右在先。数组元素是const TreeNode*，不是把地址强转成int塞到前批整数栈；那样可能截断地址。

## 38.5 中序栈：一路向左，回来再转右

中序的栈保存“左边处理完后还要回来访问”的祖先。当前node非空就压它并走left；走到空，弹出一个祖先，访问它，再从它的right继续。

样本先压4、2、1，弹1访问；再弹2访问，然后进入3；3完成才轮到4与6。循环必须在node非空**或**栈非空时继续，否则某个条件先空就会漏祖先或漏右子树。

## 38.6 后序栈：显式记录返回阶段

后序需要区分“刚遇到节点”和“孩子已处理完”。本版Frame含node和expanded标记。弹出未展开帧时，依次压“稍后访问当前”、右、左；弹出expanded帧时才真正输出。

每个真实节点最多产生一次展开工作和一次访问工作，共不超过2n个帧事件。因此设置2*63格的保守栈预算。它保存的是待办控制状态，不是每个节点值输出两次。其他后序算法可以用最近访问指针等办法，本章只用这一套阶段规则。

## 38.7 层序队列：先来先处理

**层序level order**按深度从小到大，同层从左到右。root先入队，每次出队访问，再把左、右孩子依次入队。样本队列变化：`[4]→[2,6]→[6,1,3]→[1,3]→[3]→[]`，输出4,2,6,1,3。

这里head、tail单调前进，不绕回：整次遍历每节点只入队一次，总入队<=63，所以63格足够。它是单次有界遍历的工作队列，不是把第26章通用循环队列的空满公式改掉。

## 38.8 完整实现与输出协议

完整文件traversal.c：

```c
#include "traversal.h"
static void recursive(const TreeNode *node, WalkOrder order, int *out, size_t *n)
{
    if (node == NULL) { return; }
    if (order == WALK_PRE) { out[(*n)++] = node->value; }
    recursive(node->left, order, out, n);
    if (order == WALK_IN) { out[(*n)++] = node->value; }
    recursive(node->right, order, out, n);
    if (order == WALK_POST) { out[(*n)++] = node->value; }
}
TStatus tree_walk(const BinaryTree *tree, WalkOrder order, int *out, size_t capacity, size_t *out_count)
{
    if (out_count == NULL || (tree->count != 0 && out == NULL) || order < WALK_PRE || order > WALK_POST_STACK) { return T_INVALID; }
    if (capacity < tree->count) { return T_SPACE; }
    size_t n = 0;
    if (order <= WALK_POST) { recursive(tree->root, order, out, &n); }
    else if (order == WALK_LEVEL) {
        const TreeNode *queue[TREE_LIMIT]; size_t head = 0, tail = 0;
        if (tree->root != NULL) { queue[tail++] = tree->root; }
        while (head < tail) {
            const TreeNode *node = queue[head++]; out[n++] = node->value;
            if (node->left != NULL) { queue[tail++] = node->left; }
            if (node->right != NULL) { queue[tail++] = node->right; }
        }
    }
    else if (order == WALK_PRE_STACK) {
        const TreeNode *stack[TREE_LIMIT]; size_t top = 0;
        if (tree->root != NULL) { stack[top++] = tree->root; }
        while (top != 0) {
            const TreeNode *node = stack[--top]; out[n++] = node->value;
            if (node->right != NULL) { stack[top++] = node->right; }
            if (node->left != NULL) { stack[top++] = node->left; }
        }
    }
    else if (order == WALK_IN_STACK) {
        const TreeNode *stack[TREE_LIMIT], *node = tree->root; size_t top = 0;
        while (node != NULL || top != 0) {
            while (node != NULL) { stack[top++] = node; node = node->left; }
            node = stack[--top]; out[n++] = node->value; node = node->right;
        }
    }
    else {
        typedef struct { const TreeNode *node; int expanded; } Frame;
        Frame stack[2 * TREE_LIMIT]; size_t top = 0;
        if (tree->root != NULL) { stack[top++] = (Frame){tree->root, 0}; }
        while (top != 0) {
            Frame frame = stack[--top];
            if (frame.expanded) { out[n++] = frame.node->value; }
            else {
                stack[top++] = (Frame){frame.node, 1};
                if (frame.node->right != NULL) { stack[top++] = (Frame){frame.node->right, 0}; }
                if (frame.node->left != NULL) { stack[top++] = (Frame){frame.node->left, 0}; }
            }
        }
    }
    *out_count = n;
    return T_OK;
}
```

接口见 [traversal.h](示例代码/38-traversal/traversal.h)。输入为已初始化且不变量成立的BinaryTree；输出数组与out_count为独立有效空间，不与树重叠。容量至少count；不足T_SPACE，无写入；NULL等参数或非法order为T_INVALID；空树可out=NULL，但out_count仍需有效。

先验证参数和容量，之后遍历不申请堆内存，也无业务失败分支，最后写真实数量。因此错误时输出与数量保持。函数不为任意损坏的图检测环；用户不能手改root/count后仍期待安全遍历。

## 38.10 常见错误

把前中后序理解成键递增顺序；前序压左再压右；中序只用node非空作循环条件；后序展开时立即输出导致变前序；把expanded帧再展开；层序用栈替队列；给指针强转int；输出空间不足还边写边报错；遍历过程中释放/改链；忽略空树。

## 38.11 练习与参考答案

练习一：前序先压哪边？答案：先右后左，使左先弹。

练习二：一条只有右孩子的链，中序怎样？答案：根、右、再右逐个输出；不能把左链样本背成唯一过程。

练习三：为什么后序有两种帧却只输出n个值？答案：未展开帧只安排工作，expanded帧才访问，每节点恰有一次访问帧。
