# 31 排序规格、稳定性与基础排序

## 31.1 目标与先修

先完成数组、结构体、复杂度和第30章索引一致性，建议5—7小时。目标是写出排序的正确性条件，分清键与整条记录，观察稳定性，并实现选择、冒泡两种排序。

你把学习资料按预计分钟从少到多排。分钟相同的两份资料，是否还要保持原来的加入顺序？排序不仅是让数字看起来递增，也涉及记录内容、相同键的先后和原来数据的用途。

## 31.2 两条正确性条件缺一不可

排序用来决定顺序的字段叫**排序键key**。本阶段用SItem{key,tag}表示小记录；tag是随记录移动的身份标记，不参与大小比较。输出`2:10`表示键2、标记10，不是小数或除法。

本课按key非递减排列，即允许相等：对每个相邻位置，前一个key<=后一个key。还要求输出与输入包含完全相同的记录及出现次数，这叫保持**多重集**。比如输入3、1、2，输出1、1、1虽然有序，却丢了数据；只检查相邻顺序抓不住它。

空数组与单项数组已经有序。键可重复，标记可以是任意int；不能偷用tag作次排序键来掩盖算法本身是否稳定。交换、移动都必须搬整条SItem，只搬key会让分钟与资料身份错配。

## 31.3 稳定性究竟保持什么

**稳定排序**保证：输入中键相同的记录，输出中仍保持原来的相对顺序。`2:A,2:B,1:C`稳定结果应为`1:C,2:A,2:B`。A/B只是人的记号，程序用10/11/12；不是按字母或tag数值另排。

不稳定表示“对某些输入可能改变相等键的顺序”，不是每次必然改变，也不代表键序错误。某一例恰好保留顺序，不能证明算法稳定；一个合法反例就可以证明不稳定。

第36章会稳定地按分钟生成目录视图：相同分钟保留主记录中的先后，不直接重排主数组，因此不破坏ID→位置索引。

## 31.4 统一接口、预算与失败约定

本阶段每种排序都接受SItem*a、size_t n、SortStats*out。n最多128；n>0时a指向至少n条可写记录，n=0可传NULL。out指向独立有效统计对象，不与a重叠。比较排序允许所有int键；第35章的分配式排序另限-999—999。

S_OK=0表示成功，S_INVALID表示NULL等协议错误，S_RANGE表示数量/键域超预算，S_MEMORY表示辅助数组申请失败。失败不改输入与统计；成功覆盖统计，而不是在调用者旧统计上累加。函数不能识别任意无效地址，调用者仍需提供真实有效空间。

完整公共头sort.h（后续函数将在对应章解释，当前只调用前两种）：

```c
#ifndef DSA_SORT_H
#define DSA_SORT_H
#include <stddef.h>
#define SORT_MAX 128
#define SORT_LOW (-999)
#define SORT_HIGH 999
typedef struct { int key; int tag; } SItem;
typedef struct { size_t comparisons; size_t writes; } SortStats;
typedef enum { S_OK, S_INVALID, S_RANGE, S_MEMORY } SortStatus;
SortStatus selection_sort(SItem *a, size_t n, SortStats *out);
SortStatus bubble_sort(SItem *a, size_t n, SortStats *out);
SortStatus insertion_sort(SItem *a, size_t n, SortStats *out);
SortStatus shell_sort(SItem *a, size_t n, SortStats *out);
SortStatus merge_sort(SItem *a, size_t n, SortStats *out);
SortStatus quick_sort(SItem *a, size_t n, SortStats *out);
SortStatus counting_sort(SItem *a, size_t n, SortStats *out);
SortStatus bucket_sort(SItem *a, size_t n, SortStats *out);
SortStatus radix_sort(SItem *a, size_t n, SortStats *out);
#endif
```

## 31.5 怎样公平地数操作

comparisons计**调用一次三路键比较函数**；函数返回负、零、正表示小于、相等、大于。一次调用即一次计数，即使函数内部最多用了两个C关系表达式。比较时直接用<和>，不用left-right，避免INT_MIN与INT_MAX相减溢出。

writes计向输入或辅助SItem数组写入一条完整记录；写同样的内容也计一次。存入局部saved、pivot等标量不计；交换两个不同位置计2次数组写，自交换跳过计0。频数数组、下标、循环条件、输入验证、测试检查和打印不计入这两栏。

因此它们是明确的成本模型，不是CPU指令数、总工作量或运行时间。第35章即便comparisons=0，仍有统计、遍历和内存成本。

完整公共实现sort_common.c：

```c
#include "sort_internal.h"
SortStatus sort_validate(const SItem *a, size_t n, const SortStats *out)
{
    if (out == NULL || (n != 0 && a == NULL)) { return S_INVALID; }
    return n > SORT_MAX ? S_RANGE : S_OK;
}
SortStatus sort_domain(const SItem *a, size_t n)
{
    for (size_t i = 0; i < n; i++) {
        if (a[i].key < SORT_LOW || a[i].key > SORT_HIGH) { return S_RANGE; }
    }
    return S_OK;
}
int sort_compare(int left, int right, SortStats *stats)
{
    stats->comparisons++;
    if (left < right) { return -1; }
    if (left > right) { return 1; }
    return 0;
}
void sort_write(SItem *a, size_t i, SItem value, SortStats *stats)
{
    a[i] = value;
    stats->writes++;
}
void sort_swap(SItem *a, size_t i, size_t j, SortStats *stats)
{
    if (i != j) {
        SItem saved = a[i];
        sort_write(a, i, a[j], stats);
        sort_write(a, j, saved, stats);
    }
}
```

它的声明放在 [sort_internal.h](示例代码/stage6-common/sort_internal.h)，只为实现文件共享辅助函数；public/internal两个头的区别是用途，不是C自动提供了访问控制。`sort_write`按值接收SItem，整条复制；`sort_swap`先保存旧项，再写两处。

## 31.6 选择排序：为当前位置挑最小项

外循环i表示当前要填写的位置。先令best=i，向右扫描，遇严格更小的key才更新best，最后交换a[i]与a[best]。之后前缀[0,i+1)已放好最小的若干项，任何前缀键都不大于剩余键。

```text
输入：2:A 2:B 1:C
i=0：最小在2，交换0和2 -> 1:C 2:B 2:A
i=1：两项键相等，best仍1 -> 不交换
```

相同键2的A/B被远距离交换颠倒，所以本实现不稳定。即使查最小时遇相等不更新，也无法防止另一个被交换项跨越同键记录。

第i趟比较n-i-1次，总数(n-1)+(n-2)+…+1=n(n-1)/2；已排好也照样扫描，所以最好、最坏均Θ(n²)。至多n-1次非自交换，记录写入O(n)，额外空间Θ(1)。

## 31.7 冒泡排序：让大项逐步向右

从左到右比较相邻项，仅在左键严格大于右键时交换。一趟后，当前未完成区间的最大项到达最右端；下一趟不再碰这个位置。

```text
输入：2:A 2:B 1:C
第一趟：A/B不换，B/C换 -> 2:A 1:C 2:B
第二趟：A/C换          -> 1:C 2:A 2:B
```

相等键不交换，且每次只跨越相邻记录，因此它们不能互相越过，本实现稳定。若某趟没有交换，所有相邻项都已满足非递减，直接结束；没有必要凑满n-1趟。

本版已排序时只比较n-1次，最好Θ(n)；逆序时比较Θ(n²)，最坏写入Θ(n²)，额外空间Θ(1)。不要给所有冒泡变体套同一个“最好”结论，提前停止条件是实现的一部分。

## 31.8 完整核心代码

完整文件basic.c：

```c
#include "sort_internal.h"
SortStatus selection_sort(SItem *a, size_t n, SortStats *out)
{
    SortStatus status = sort_validate(a, n, out);
    if (status != S_OK) { return status; }
    SortStats stats = {0, 0};
    for (size_t i = 0; i + 1 < n; i++) {
        size_t best = i;
        for (size_t j = i + 1; j < n; j++) {
            if (sort_compare(a[j].key, a[best].key, &stats) < 0) { best = j; }
        }
        sort_swap(a, i, best, &stats);
    }
    *out = stats;
    return S_OK;
}
SortStatus bubble_sort(SItem *a, size_t n, SortStats *out)
{
    SortStatus status = sort_validate(a, n, out);
    if (status != S_OK) { return status; }
    SortStats stats = {0, 0};
    for (size_t end = n; end > 1; end--) {
        int changed = 0;
        for (size_t j = 1; j < end; j++) {
            if (sort_compare(a[j - 1].key, a[j].key, &stats) > 0) {
                sort_swap(a, j - 1, j, &stats);
                changed = 1;
            }
        }
        if (!changed) { break; }
    }
    *out = stats;
    return S_OK;
}
```

selection使用`i+1<n`而非先算n-1，避免空数组无符号减法。bubble的end是右端**不含**的位置，j从1开始比较j-1与j；end>1时才需要一趟。

## 31.10 常见错误

只检查有序、不查记录丢失；只交换key；把稳定理解为结果永远一样或运行不报错；用tag参与比较却宣称原算法天然稳定；相等时也做冒泡交换；将交换算3次数组写却和本课2次口径混比；以无符号n-1写空数组循环；用相减比较极端整数。

## 31.11 练习与参考答案

练习一：4项选择排序比较多少次？答案：3+2+1=6，不随原顺序变化。

练习二：冒泡把>改为>=会怎样？答案：键序仍可能正确，但相等项会交换，稳定性保证失去；全相等输入也无法及时停止。

练习三：输出有序且长度相同，能证明没丢记录吗？答案：不能，比如把3、1、2都改为1，长度仍3。应核对完整记录及出现次数。
