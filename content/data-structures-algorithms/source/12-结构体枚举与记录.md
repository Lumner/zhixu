# 12 结构体、枚举与记录

## 12.1 目标与先修

先掌握数组、字符串和指针。建议3—4小时。本章把资料编号、标题、时长、学习状态组合成一条记录，分清结构体对象、对象副本和对象指针。后面的链表节点、树节点、图的边都建立在这里的语法上。

如果用四个独立数组保存编号、标题、时长、状态，第i个位置必须永远对应同一资料。插入删除时漏改一个数组，数据就会错位。结构体让“属于同一条记录”的字段放在一个类型中。

## 12.2 struct定义一组有名字的字段

`struct`定义结构体类型；字段也叫成员，每个成员有自己的类型。一个Record可以同时含int、字符数组和状态，不再要求整条记录内所有数据同类型。

`typedef struct { ... } Record;`为这个结构体类型取别名Record。typedef不创建对象，也不分配一条记录；真正的对象声明是`Record original = ...;`。结构体定义右花括号后需要分号。

本例title是内嵌的16字节数组，不是指向别处文字的指针。每个Record对象自己拥有这16格，所以一组Record数组中的各条记录不会因为用了同一个成员名就共享标题。

## 12.3 enum表达几个明确状态

`typedef enum { PLANNED, DONE } State;`给状态取名。没有显式指定时，PLANNED为0、DONE为1。用DONE比直接写1更能表达含义，仍应按接口约定保持在允许状态集合中。

枚举不是一套自动验证用户输入的系统；任意整数不能因为转成State就一定成为合法业务状态。读取文件时仍要检查允许值。最终项目会用枚举表示操作结果，这样“重复编号”和“内存不足”可以区分。

## 12.4 点号与箭头访问不同的东西

`original.minutes`通过结构体对象访问字段。若有`Record *p = &original;`，则`p->minutes`访问它所指对象的字段，与`(*p).minutes`等价。

括号不可省略成`*p.minutes`，因为点号与解引用的组合含义不同。使用箭头前必须确保p指向仍有效的Record；NULL检查只覆盖空指针。

输入只读可用`const Record *`，需要修改状态用`Record *`。不要因为结构体比整数大，就以为所有函数都会自动按引用传递；普通结构体参数仍是值传递。

## 12.5 完整实验：副本与原件

**完整程序：records.c。** 下载 [源码](示例代码/12-records/records.c)，放到`~/dsa-labs/ch12`。

```c
#include <stdio.h>

typedef enum { PLANNED, DONE } State;

typedef struct {
    int id;
    char title[16];
    int minutes;
    State state;
} Record;

void mark_done(Record *record)
{
    if (record != NULL) {
        record->state = DONE;
    }
}

int main(void)
{
    Record original = {1, "C basics", 30, PLANNED};
    Record copy = original;
    copy.title[0] = 'X';
    mark_done(&copy);
    printf("original=%s,%d\n", original.title, original.state);
    printf("copy=%s,%d\n", copy.title, copy.state);
    return 0;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch12`目录**：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic records.c -o records.exe
./records.exe
```

结果：

```text
original=C basics,0
copy=X basics,1
```

`Record copy = original;`复制所有成员值，包括内嵌字符数组。随后修改copy.title[0]只影响副本。虽然不能单独给一个已经创建的数组整体赋另一个数组，但结构体赋值会复制其数组成员，二者规则不同。

`mark_done(&copy)`接收副本的地址，通过箭头修改它的state，原件仍为PLANNED。函数声明为void，因为这一版本只执行状态修改，不返回业务结果。

## 12.6 结构体中如果装的是指针呢

现在先做概念对照：如果title不是`char title[16]`，而是`char *title`，结构体赋值只复制指针值，不复制它指向的整段文字。两个副本可能共享同一段存储。

这一点叫浅拷贝问题。内嵌数组随对象复制，指针所指资源不自动复制。第13章和第16章中的Catalog含动态数组指针，不能简单复制后让两个对象各自free同一块内存。

也不要用memcmp直接判断两条Record业务相等：结构体可能有填充字节，相同字段不意味着整块对象的所有字节必须完全相同。按字段比较id、minutes、state，标题用strcmp。

## 12.7 一组记录与初始化

**上下文片段：放在已有Record类型定义之后的main内。**

```c
Record records[2] = {
    {1, "C basics", 30, PLANNED},
    {2, "Pointers", 45, PLANNED}
};
records[1].minutes = 60;
```

先下标取一条Record，再点号取字段。数组容量2、实际数量也为2；若以后容量大于数量，仍需单独count。字段顺序与初始化顺序要一致，也可用C的指定成员初始化如`.id = 1`，但先保持一种清楚写法。

`Record empty = {0};`将数值字段置0、数组成员置0；若0不代表合法记录，它只是初始化状态，仍需后续赋值和验证，不能直接收录进目录。

## 12.8 改造与结果原因

把copy.minutes改为90，再显示两者分钟：original仍30，copy为90。然后把`mark_done(&copy)`换为`mark_done(&original)`，状态变化转移到原件，文字副本关系不变。

尝试把函数参数改为普通`Record record`并在函数内部设DONE，main中的对象不会变化。这个版本可在练习副本中编译对照；正确方法取决于你想返回新副本还是修改原对象，不是“参数都加星号”。

## 12.9 常见错误

- 把类型别名当成已经创建的对象：还需要声明Record变量。
- 忘记结构体定义后的分号：它是完整声明的一部分。
- 对指针用点号，或对对象直接用箭头：先确认手中是对象还是地址。
- 以为普通结构体参数能自动改原件：值传递仍然成立。
- 以为指针成员也复制了整块资源：只复制地址值。
- 直接把结构体原始字节写文件：字段布局、填充和平台表示未约定，不能当通用文本格式。

## 12.10 练习与参考答案

练习一：copy=original之后改copy.title[0]，原件变化吗？若字段是指针，结论还能照搬吗？

答案：本例内嵌数组独立，原件不变；若是指向共享字符区的指针，复制后可能仍访问同一字符区，需要另行说明所有权。

练习二：要修改某条Record的minutes，函数参数应怎样表达？

答案：可以接收`Record *record`并验证分钟范围后写`record->minutes`；如果只读则用`const Record *`。

练习三：设计一条Record的有效性约定。

答案方向：id范围、唯一性、分钟范围、标题非空与容量上限、状态允许集合。唯一性依赖整个目录，单条记录的字段检查不足以判定。
