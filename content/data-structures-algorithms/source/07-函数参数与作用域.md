# 07 函数、参数与作用域

## 7.1 目标与先修

先掌握变量、判断和循环。建议2—3小时。本章把一个计算步骤封装成函数，弄清参数、返回值、声明、定义、作用域和值传递。暂不使用指针，也不要求一次学完多文件工程。

当程序越来越长，“读取、计算、显示”全挤进main会难以检查。函数让我们为一个职责命名，例如“把新增分钟加到已有分钟上”，并约定输入和结果。

## 7.2 函数像一个有约定的小任务

下面是**函数定义片段，放在main之外**：

```c
int add_minutes(int current, int extra)
{
    current = current + extra;
    return current;
}
```

开头`int`表示返回一个整数，`add_minutes`是函数名，括号里声明两个参数。参数是这个函数接收输入时使用的局部名字。花括号包含函数体，`return current;`把结果交给调用者，并立刻结束这次调用。

本函数前提是current与extra为非负的小整数，而且和能放进int；本批使用的值不超过几千。不因为写成函数就自动获得范围检查，前提也应在说明中保留。

调用写成`add_minutes(minutes, 15)`，把两个实参按位置交给两个形参。实参是调用处的表达式，形参是函数定义中的接收名字；可以先把这两个词理解为“交出去的值”和“接收值的局部名字”。参数之间用逗号隔开，顺序与类型应符合声明。

## 7.3 返回值与显示内容不同

`return 45;`把整数45交给调用者，不负责打印；`printf`负责显示内容，不代表函数一定把同一个数作为计算结果返回。把计算函数写成返回值，调用者可以选择显示、比较或继续运算。

**上下文片段：main内部，已经有函数声明。**

```c
int minutes = 30;
int result = add_minutes(minutes, 15);
printf("%d\n", result);
```

先求调用结果45，再用它初始化result，最后显示45。单独写`add_minutes(minutes, 15);`也会执行调用，但没有保存返回值，main里的minutes并不会因此改变。若希望更新，明确写`minutes = add_minutes(minutes, 15);`。

## 7.4 值传递：函数收到的是副本

普通C函数参数按值传递。调用时，形参current得到minutes当前值的副本30；给current重新赋值，不会直接改main里的minutes。

| 时刻 | main的minutes | 函数的current | extra | result |
| --- | --- | --- | --- | --- |
| 调用之前 | 30 | 尚不存在 | 尚不存在 | 尚未初始化完成 |
| 进入函数 | 30 | 30 | 15 | 等待返回 |
| 加法之后 | 30 | 45 | 15 | 等待返回 |
| 返回之后 | 30 | 本次局部对象生命周期结束 | 同左 | 45 |

参数名不用与调用者名字相同。函数中的局部变量在本次调用中存在，不会自动保留给下一次调用。第10章学指针后，会解释如何显式访问调用者对象；现在先把副本模型学牢。

## 7.5 声明告诉编译器怎么调用

`int add_minutes(int current, int extra);`是函数声明，也叫原型。它没有函数体，末尾有分号，告诉编译器参数和返回类型。定义则包含真正执行的函数体。

本章先在main前放声明、main后放定义，方便阅读入口。也可以先定义函数，再写main；但不能在没有合适声明的情况下随意调用一个未知函数。`#include <stdio.h>`正是为printf等标准函数提供声明入口。

`void print_goal(void);`中，前面的void表示不返回可用的结果值，括号中的void表示不接收参数。它仍然可以产生显示效果。主函数`int main(void)`返回整数状态，含义与“没有返回值”不同。

## 7.6 完整实验：计算与显示分开

**完整程序：functions.c。** 保存到 `~/dsa-labs/ch07`，或下载 [源码](示例代码/07-functions/functions.c)。

```c
#include <stdio.h>

int add_minutes(int current, int extra);
void print_goal(void);

int main(void)
{
    int minutes = 30;
    int result = add_minutes(minutes, 15);
    printf("minutes=%d\nresult=%d\n", minutes, result);
    print_goal();
    return 0;
}

int add_minutes(int current, int extra)
{
    current = current + extra;
    return current;
}

void print_goal(void)
{
    puts("goal=60");
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch07`目录**执行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic functions.c -o functions.exe
./functions.exe
```

结果：

```text
minutes=30
result=45
goal=60
```

执行顺序从main开始，不是从文件最下面开始；调用add_minutes时暂时进入它的函数体，返回后继续main；再调用print_goal，最后main返回0。函数定义在文件中出现，不代表程序启动时就逐个执行它们。

## 7.7 作用域：名字在哪里有效

作用域描述一个名字可以在源代码的哪些范围中使用。这里main的minutes只在它所属块中有效，add_minutes的current只在其函数体内有效；循环头里声明的i在对应for范围内有效，离开后不能直接使用。

内层块也可有局部变量。不要为“让所有地方都能看到”就把所有变量搬到全局。优先通过参数传入必要信息，通过返回值交出结果，依赖会更清楚。

一个函数不能在函数体内再定义普通C函数。把新函数写在main外面，函数调用语句才写在main内部。第14章会把声明放头文件、定义放实现文件；那时仍遵守同一套约定。

## 7.8 改造实验

第一步，把调用中的30改为0、extra保持15，结果应15，minutes仍0。第二步保留30但extra改0，结果应30。第三步在main里用返回值明确覆盖minutes，再显示它，应为45。

再写一个`int larger(int a, int b)`函数：如果a大于b则返回a，否则返回b。先自己写声明、定义、调用，再试相等情况。返回int的函数在这些普通调用路径中都应返回确定值，不能只写if的一边就漏掉另一边。

函数名和局部变量名也可以帮助发现职责混杂：一个叫add_minutes的函数不应暗中读取键盘或打印一整份报告。本阶段输入函数、计算和输出分开，便于分别核对。

## 7.9 常见错误

- 以为改形参就能改调用者：当前只改了副本，想更新需接住返回值。
- 声明和定义参数不同：编译器无法给出一致的调用约定，检查类型与数量。
- 把函数定义写在main内部：移到main之外。
- 对void函数的结果做赋值：它没有可用的结果值。
- 把return当break：return会结束整个当前函数，不只是循环。
- 在循环外打印只在循环头定义的i：名字已超出作用域，按职责重新安排变量。

## 7.10 练习与参考答案

练习一：main中x=10，调用函数把其普通int参数改为20，不接收返回值，x是多少？

答案：仍为10。参数是值副本，不是调用者对象本身。

练习二：larger函数怎样覆盖相等的情况？

答案：**函数定义片段，放main外并配声明使用：**

```c
int larger(int a, int b)
{
    if (a > b) {
        return a;
    }
    return b;
}
```

相等时返回b的值，与a相同，符合“返回较大值”的约定。如果还要返回最早位置，则是另一个需明确的问题。

练习三：给“读取0—limit之间整数”的函数设计结果约定，失败怎样区分？

答案：正常返回0—limit，失败返回-1。因为合法范围不含-1，不会混淆。阶段项目会实现这一约定；前提是limit非负。
