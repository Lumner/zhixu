# 02 环境与第一个C程序

## 2.1 目标与先修

先完成第01章。建议3—5小时，目标是自己保存一个 `.c` 文件，编译、运行、修改后再次编译，并能区分源文件、编译器和生成的程序。第一次不急着配置“一键运行”，先理解每一步。

**编辑器**用于修改文字；**终端**是显示输入输出的窗口；**Shell**解释你输入的命令；**编译器**把源代码翻译成程序构建所需的机器代码；**可执行文件**是本系统能启动的程序。VS Code等编辑器并不自动等于已经装好 C 编译器。

## 2.2 选择一条环境路线

本课新手主线为 **Windows x64 + MSYS2 UCRT64 + GCC**。MSYS2提供工具环境，UCRT64是其中一种配置，GCC是编译器。已经能用 GCC 编译 C17 的读者可以保留原环境，不需要先卸载或重装。Linux/macOS读者见本章末的命令对应关系。

安装步骤依据2026-11-10核验的 [MSYS2官方入门](https://www.msys2.org/)、[环境说明](https://www.msys2.org/docs/environments/) 和 [更新说明](https://www.msys2.org/docs/updating/)。官方安装器当前要求64位Windows 10（1809或更新）等受支持系统；这里针对x64写步骤，ARM64读者应按官方对应环境操作。

1. 从官方入门页选择x64安装器，使用默认安装目录或自己记录的目录。
2. 打开开始菜单中的 **MSYS2 UCRT64**。不要把PowerShell、命令提示符或MSYS环境当成同一个终端。
3. 在这个UCRT64窗口更新工具。下面命令在哪个目录都可以执行：

```bash
pacman -Suy
```

`pacman`是管理工具软件的命令。若更新明确要求关闭终端，按提示完成，重新打开UCRT64，再运行同一命令完成剩余更新。不要在更新中途直接安装一部分新包。

4. 仍在UCRT64终端，安装GCC：

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-gcc
gcc --version
```

看到GCC版本文字表示这个终端能够找到并启动编译器。版本号不必与教材验证机一致。若显示 `command not found`，先检查终端标题是否含UCRT64、安装是否成功，不要随意往系统PATH拼接多个编译器目录。

本课选择C17是为了固定语法基线，并不声称它是最新标准。GCC选项的含义见 [GCC标准说明](https://gcc.gnu.org/onlinedocs/gcc/Standards.html)。

## 2.3 先建立自己的练习目录

下面所有命令都在 **UCRT64的Bash终端**执行，不在 C 文件中输入。提示符里常见的 `$` 不是命令的一部分，不要复制。

```bash
mkdir -p ~/dsa-labs/ch02
cd ~/dsa-labs/ch02
pwd
ls
```

`mkdir`创建目录，`-p`允许中间目录一起建立；`~`表示这个Shell中的用户主目录；`cd`改变当前位置；`pwd`显示当前位置；`ls`列出当前位置内容。这里通常对应MSYS2安装目录下的 `home/你的用户名/dsa-labs/ch02`，不一定是Windows的“文档”。以 `pwd` 的结果为准。

**当前目录**决定相对文件名从哪里找。例如 `hello.c` 表示当前目录里的文件；`../`表示上一级。文件存在但编译器找不到时，先 `pwd` 和 `ls`，不要立刻重装工具。

可在UCRT64中运行 `explorer.exe .` 打开当前目录，再用已有编辑器创建 `hello.c`。Windows文件资源管理器中打开“显示文件扩展名”，确认它不是 `hello.c.txt`。用英文标点输入代码，保存为UTF-8纯文本；不要用会生成富文本的排版软件。

没有代码编辑器也可以先用Windows自带记事本：粘贴下一节的程序，选择“另存为”，定位到刚打开的练习目录；文件名填`hello.c`，保存类型选“所有文件”，编码选UTF-8，然后保存。回到终端用`ls`确认实际文件名。之后可再选用具备行号、语法高亮的编辑器，第一份程序不依赖任何编辑器扩展。

## 2.4 写第一份完整程序

**完整程序：hello.c。** 在刚才的 `ch02` 目录保存以下内容；也可下载 [同名源码](示例代码/02-hello/hello.c)。

```c
#include <stdio.h>

int main(void)
{
    puts("Hello, algorithms!");
    return 0;
}
```

逐行理解：

- `#include <stdio.h>`让标准输入输出相关的声明可供编译器使用。头文件可以先理解为函数使用约定的说明入口；这一行末尾没有分号。
- `int main(void)`定义程序主函数。函数是有名字的一组操作；`main`是本课普通程序的入口，`int`说明它返回整数，`void`说明这里不接收参数。函数细节在第07章展开。
- `{`和`}`圈定函数体，必须成对。缩进帮助人看结构，不替代花括号。
- `puts(...)`调用输出函数；双引号包住要显示的文字，括号表示调用，分号结束语句。`puts`会在文字后再输出一个换行。
- `return 0;`结束主函数并报告成功状态。它不会在屏幕打印0。其他非零返回值可表示失败，具体约定由程序和环境共同使用。

空行和普通空格有助于阅读。名字区分大小写，`Main`不是这里的`main`；中文的`“”`不能代替英文双引号。

## 2.5 编译与运行是两条命令

在 **UCRT64终端、`~/dsa-labs/ch02`目录**执行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic hello.c -o hello.exe
./hello.exe
```

正常输出：

```text
Hello, algorithms!
```

| 命令部分 | 含义 |
| --- | --- |
| `gcc` | 启动编译器驱动，完成本例需要的编译和链接 |
| `-std=c17` | 固定采用C17语言模式 |
| `-Wall -Wextra -Wpedantic` | 打开常见及标准相关警告；不是数学上的“所有错误都能发现” |
| `hello.c` | 输入的源码文件 |
| `-o hello.exe` | 指定生成文件名，别把输出写成源码名 |
| `./hello.exe` | 启动当前目录里的程序，`./`明确当前位置 |

成功编译通常没有消息。运行 `ls` 应同时看到 `.c` 与 `.exe`。前者是可修改的源码，后者是本次生成的程序；不在编辑器里把 `.exe` 当文本修改。其他系统生成的可执行文件也不能保证直接在Windows启动。

可以紧接着在Bash运行 `echo $?` 查看刚才命令的退出状态，本例为0。它读的是**上一条命令**的状态；中间执行别的命令后再查看，就不是程序原来的状态了。

## 2.6 必做实验：改了代码为什么还是旧结果

把文字改为 `I can rebuild C programs.`，保存文件。先只运行 `./hello.exe`，你会看到旧输出，因为磁盘上的可执行文件尚未更新。

再运行编译命令，确认没有错误，然后运行程序，输出才改变。这说明“编辑、保存、编译、运行”是四个环节。编辑器里的内容没保存，编译器也读不到最新修改。

接着临时去掉 `puts` 那行末尾的分号，再编译。编译器应拒绝这个程序。诊断中常包含文件、行号、列号和 `error`；它指出的是发现问题的位置，根因也可能在上一行。补回分号再编译。**编译失败后旧的 `.exe` 仍可能存在**，不要把旧程序能运行当作刚才错误代码可用的证据。

## 2.7 常见错误：先分清三种类别

语法错误如缺分号，通常在编译时发现；链接错误如调用了只有声明、没有实现的函数，会在组合程序时发现；逻辑错误如把应加的数相减，可能编译运行都正常却得到错误结果。第14章再细分构建和调试过程。

遇到错误时按顺序检查：当前目录、实际文件名、是否保存、第一条有效诊断、是否重新编译。不要连续改十处再看结果，每次修一个原因。

## 2.8 其他终端的对应关系

有可用GCC的Linux终端可以使用相同源码与警告选项，输出文件名换成 `hello`，用 `./hello` 运行；已有Clang的macOS也可用 `clang` 替换命令中的 `gcc`。这里不提供这些系统的安装验收。

PowerShell不是Bash，启动当前目录程序通常写 `.\hello.exe`；`echo $?`在PowerShell中的含义也不同，原生程序的数字退出码用 `$LASTEXITCODE` 查看。后续主线统一使用Bash，先不要混用两套语法。源码目录可以保存在任意位置，不需要修改本网站的课程文件来做练习。

## 2.9 练习与参考答案

练习一：让程序输出两行文字，第二行为 `Step by step.`。

答案：在原来 `puts` 后、`return` 前再写 `puts("Step by step.");`。这是**放在main内部的片段**，不能单独当完整文件编译。

练习二：把 `return 0;`改成 `return 7;`，显示文字是否变成7？

答案：文字不变；在Bash紧接着查状态会得到7。退出状态与显示内容是两条不同的信息通道。练习后改回0。

练习三：运行时报“找不到文件”，你应先执行哪两条检查命令？

答案：`pwd`和`ls`。确认当前位置、源文件与生成文件都在，再核对编译是否成功。
