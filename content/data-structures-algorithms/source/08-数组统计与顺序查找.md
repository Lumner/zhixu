# 08 数组、统计与顺序查找

## 8.1 目标与先修

先完成循环与函数。建议2—4小时。本章把第01章的纸面表格变成C数组，用同一次遍历求总和、最值、有效记录数和第一次匹配位置。之后还需6—8小时完成独立阶段练习。

## 8.2 数组是一组同类型元素

**上下文片段：main内部。**

```c
int minutes[5] = {30, 0, 45, 15, 60};
printf("%d\n", minutes[0]);
minutes[1] = 20;
```

第一行创建5个int元素的数组。方括号声明容量，花括号给出初始值；使用时方括号里的整数是下标。下标从0开始，5个元素的合法下标为0—4。`minutes[0]`是第1个元素30，`minutes[1]`原为0，最后一行把它改为20。

数组在内存中按元素连续排列。现在把它看作一排等大小的格子即可，地址和指针在第二阶段再讲。数组名后不能直接跟`= 新的一组值`来整体重新赋值；初始化与逐个修改是不同操作。

## 8.3 容量不等于实际记录数量

容量是准备了多少个格子，数量是目前有多少条真实记录。本例准备7格，只记录5天。循环应处理前5格，不把剩余格子当作真实日期。

本章用`#define CAPACITY 7`给固定数字起名。它是预处理指令，在编译前替换后面出现的这个名字；这一行不写等号、也不加分号。这里仅用来表达固定数组容量，不用它封装复杂计算。

`int minutes[CAPACITY] = {30, 0, 45, 15, 60};`在容量7时，剩余两个元素也初始化为0。**这些0的存在仍不代表记录过两天。** count明确为5；第2天的0则是真实记录，会进入分母。

需要保持的关系是 `0 <= count && count <= CAPACITY`。本章count写在源码中，由编写者保证；阶段项目会检查用户输入。合法内存下标还不够，访问的数据也应在实际记录范围内。

## 8.4 遍历：依次处理每条记录

从0开始，条件写`i < count`，最后一次i为count-1。若用`<= count`，会多处理一个位置；count等于容量时，就会访问数组外部。C通常不会替你检查每次下标是否合法，越界访问属于未定义行为，不能靠“我这里没有崩溃”证明安全。

总和从0开始；最小最大值从第一条真实记录开始；第一次匹配位置从-1开始，表示还未找到。读`minutes[0]`前必须确认count大于0。若没有记录，最值没有定义，应该提前走空结果分支。

## 8.5 完整实验：统计与查找

**完整程序：arrays.c。** 保存到 `~/dsa-labs/ch08`，或下载 [源码](示例代码/08-arrays/arrays.c)。

```c
#include <stdio.h>

#define CAPACITY 7

int main(void)
{
    int minutes[CAPACITY] = {30, 0, 45, 15, 60};
    int count = 5;
    int target = 45;

    if (count == 0) {
        puts("empty");
        return 0;
    }

    int total = 0;
    int minimum = minutes[0];
    int maximum = minutes[0];
    int active = 0;
    int first = -1;

    for (int i = 0; i < count; i++) {
        int value = minutes[i];
        total += value;
        if (value < minimum) {
            minimum = value;
        }
        if (value > maximum) {
            maximum = value;
        }
        if (value > 0) {
            active++;
        }
        if (value == target && first == -1) {
            first = i;
        }
    }

    printf("count=%d total=%d min=%d max=%d\n", count, total, minimum, maximum);
    printf("average=%.2f active=%d first=%d\n", (double)total / count, active, first);
    return 0;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch08`目录**运行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic arrays.c -o arrays.exe
./arrays.exe
```

预期输出：

```text
count=5 total=150 min=0 max=60
average=30.00 active=4 first=2
```

count为5，所以平均值150/5为30；active只数值大于0的条目，因此为4。第一次45在下标2，不是下标3；人说“第3天”才是3。

## 8.6 每个状态为什么这样更新

| 已处理到的位置 | total | minimum | maximum | active | first |
| --- | --- | --- | --- | --- | --- |
| 0 | 30 | 30 | 30 | 1 | -1 |
| 1 | 30 | 0 | 30 | 1 | -1 |
| 2 | 75 | 0 | 45 | 2 | 2 |
| 3 | 90 | 0 | 45 | 3 | 2 |
| 4 | 150 | 0 | 60 | 4 | 2 |

每处理一个value，总和增加该值；比minimum小才替换，比maximum大才替换；value大于0才增加active；目标相等且first仍为-1才记录位置。后面再遇到45时，first已不是-1，所以不会覆盖最早位置。

这里的查找方式叫顺序查找：按照位置逐条比较。若唯一任务是找目标，可以找到后立即返回；本程序还要算完整统计，必须继续遍历。第20章会独立实现并比较查找策略。

五条数据，每条访问一次，做固定数量的判断；第一阶段先理解这个具体工作量。不要现在就跳去背复杂度公式。

## 8.7 改造时怎样覆盖边界

每次只改一组初始化数据和count，保持count不超过7，数据限定0—1440：

| 数据与数量 | 关键预期 | 检查什么 |
| --- | --- | --- |
| count=0 | 只显示empty | 在读第一条与除法之前退出 |
| `{45}`，count=1 | 和45，最小最大45，first=0 | 只有一个元素 |
| `{0,0,0}`，count=3 | 和0，最值0，active=0 | 全零是合法记录 |
| `{45,15,45}`，count=3 | first=0 | 重复目标保留最早位置 |
| `{10,20,45}`，count=3 | first=2 | 最后一个位置 |
| `{10,20,30}`，count=3 | first=-1 | 没有找到 |

不要故意把count改为8去看会输出什么；那是在违反容量约定，不是有意义的功能实验。第13章会处理真正的动态扩容。

## 8.8 为什么本章没有把数组直接传给函数

前章普通int参数是值副本，但数组用作函数参数时有特殊规则，不能简单理解为整个数组复制给函数。为了不制造错误模型，本章先在main中遍历，第11章学完指针后，再把它拆成带长度参数的函数。

同样，`sizeof`能得到对象所占的字节数，并不自动知道数组中哪些位置是“真实记录”。即使以后计算出容量，实际数量仍需单独记录。不要把容量查询当成业务数据计数。

## 8.9 常见错误

- 循环从1开始：漏掉下标0。
- 把`<= count`当成“包含最后一个”：最后一个下标实际是count-1。
- 最小值初始化0：全为正数时最小值错误地保留0。使用第一条真实数据。
- 平均值除以CAPACITY：把未记录天数也放进了分母。
- 找到后无条件改first：结果变成最后位置。
- 找到目标就结束整个统计：后面数据未统计。
- 空数组仍读取第一条或做除法：先走空结果分支。

## 8.10 练习与参考答案

练习一：容量7、count=3，合法的真实记录下标有哪些？还有哪些格子虽在数组内，却不是记录？

答案：真实记录为0、1、2；3—6仍在数组内，但不属于已记录数据。下标7在数组外。

练习二：数据20、0、40，全部平均和有学习天平均分别是多少？

答案：全部平均60/3=20，有学习天平均60/2=30。若全零，有学习天数为0，该平均值应显示不存在，不能除0。

练习三：让查找结果变成“最后出现位置”，改哪一处？

答案：保留`value == target`，移除`&& first == -1`，每次匹配都更新位置，同时把变量名改为last以免误导。
