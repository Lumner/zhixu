# 10 地址、指针与生命周期

## 10.1 目标与先修

先会数组、函数的值传递和字符串。建议5—7小时。本章用两个整数说明地址、指针、取址、解引用、重绑、空指针和生命周期；目标是能画出关系，而不是只背星号。

第07章函数改普通int形参，main中的变量没有变。如果希望函数交换main中的两个对象，需要告诉函数“操作的是哪两个对象”，地址提供这种联系。

## 10.2 对象、值、地址、指针分开看

对象是程序中用于保存值的一块存储，例如`int a = 10;`中的a。地址用于定位对象。指针变量则保存指向某对象的位置关系，它本身也是一个有类型、有当前值的对象。

**概念模型：下面的格子编号只是画图编号，不是真实机器地址。**

```text
a格子：10         b格子：20
p格子：指向a  ──→ a格子
```

**上下文片段：main内部。**

```c
int a = 10;
int *p = &a;
*p = 15;
```

`&a`是取址：取得a的位置。声明中的`int *p`表示p是指向int的指针。表达式中的`*p`是解引用：访问p所指的那个int对象；给`*p`赋15，就是把a改为15。

声明里的星号和表达式里的星号作用不同，二者都不是乘法；乘法需要左右两个操作数。初学每行只声明一个指针，避免`int *p, q;`中误把q也当指针。

## 10.3 改指针本身与改所指对象

执行`p = &b;`改变的是p保存的位置，让它从此指向b，a的值不会自动搬到b。此后`*p = 30;`修改b，a保留原值。这叫重新绑定指向关系，可以想成把箭头移到另一个格子。

“两个指针指向同一对象”则叫别名：通过其中一个改值，另一个再读取时会看到同一对象的新值。不是两个整数副本在自动同步，而是两个访问路径通向同一处。

如果想显示地址，使用`printf("%p\n", (void *)&a);`。这是**main内的可选片段**；%p需要void指针参数，所以显式转换。真实地址会随运行环境变化，不把某一串十六进制数字作为预期答案。

## 10.4 函数仍然按值传递

交换函数参数`int *left`收到的是地址值的副本，函数并没有获得修改main里某个指针变量本身的特殊能力。但这个地址副本仍然指向main的a，所以`*left`能访问a。

`swap(&a, &b)`中传的是a和b的位置，不是直接传10和20。函数内临时保存左值，写右值到左对象，再写保存值到右对象。若只写`*left = *right; *right = *left;`，原左值已丢失，两个值都会变成原右值。

## 10.5 完整实验：交换与重绑

**完整程序：pointers.c。** 下载 [源码](示例代码/10-pointers/pointers.c)，保存到`~/dsa-labs/ch10`。

```c
#include <stdio.h>

void swap(int *left, int *right)
{
    if (left == NULL || right == NULL) {
        return;
    }
    int saved = *left;
    *left = *right;
    *right = saved;
}

int main(void)
{
    int a = 10;
    int b = 20;
    int *p = &a;
    *p = 15;
    printf("before=%d,%d\n", a, b);
    swap(&a, &b);
    printf("after=%d,%d\n", a, b);
    p = &b;
    *p = 30;
    printf("rebound=%d,%d\n", a, b);
    swap(NULL, &b);
    printf("null_call=%d,%d\n", a, b);
    return 0;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch10`目录**执行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic pointers.c -o pointers.exe
./pointers.exe
```

结果：

```text
before=15,20
after=20,15
rebound=20,30
null_call=20,30
```

| 操作后 | a | b | main里的p指向谁 |
| --- | --- | --- | --- |
| 初始化 | 10 | 20 | a |
| *p=15 | 15 | 20 | a |
| swap返回 | 20 | 15 | 仍为a |
| p=&b，*p=30 | 20 | 30 | b |
| 空参数调用返回 | 20 | 30 | b |

交换函数没修改p；它只操作收到的两个地址所指对象。每一行输出都应能用表格解释。

## 10.6 NULL不是一个可访问的空格子

NULL用于表示“不指向对象”的空指针值。本例swap约定：有任一参数为空就直接返回，不进行交换。调用者传NULL因而不会导致解引用。

空检查只能识别空指针，不能证明任意非空指针都有效。未初始化的指针、指向已结束对象的指针、越界指针，也可能非空，却不能读写。

指针的类型决定应怎样访问对象。`int *`用于指向合适的int对象，不要强行把一个随意整数变成地址再解引用。取址也不等于拥有释放权；本章的a、b是自动存储期对象，不能交给free。

## 10.7 生命周期：对象什么时候还存在

普通局部对象在执行进入其块时开始相应生命周期，离开时结束。本函数返回后，局部变量saved不再是可继续访问的对象；因此不能把“局部变量地址”返回给调用者，期待它永久存在。

本例left指向main的a。swap执行期间main尚未结束，a仍存在，所以访问有效。函数形参left本身会在调用结束后消失，这不影响main的a继续存在。

常说的“栈上变量”是一种实现解释；C语言更直接的规则是存储期和生命周期。不要用“内存好像还没被覆盖”作为访问已结束对象的理由。第13章的动态分配对象有另一套显式释放规则。

## 10.8 改造与排错

把初值改为a=0、b=0，再试不同值、相等值；交换后应满足“新a等于旧b，新b等于旧a”。再在练习副本调用`swap(&a, &a)`，临时保存法仍正确，值不变。

把重绑后的`*p = 30`改成`p = &a`，先画箭头再预测输出。不要为了理解错误而实际运行空解引用、返回局部地址后读取等未定义行为；可在纸上指出它违反的前提。

## 10.9 常见错误

- 把`p = &b`理解成把b的值写给a：它只移动箭头。
- 以为指针参数不是值传递：收到的仍是地址副本。
- 把`p`与`*p`混为一谈：前者是位置，后者是所指对象。
- 认为非NULL就安全：对象必须还存在，类型和访问范围也要正确。
- 用%d显示地址：%d不是指针格式，使用%p和对应转换。
- 用局部地址保存跨函数的长期数据：生命周期不满足要求。

## 10.10 练习与参考答案

练习一：`p=&a; q=&a; *q=7;`之后，通过p读到什么？

答案：7。两个指针指向同一个a，并不是两个int副本。

练习二：一个函数内写`left = NULL;`，main的a会变成0吗？

答案：不会。只修改了函数的指针形参副本，既没写a，也没有修改调用者的指针变量。

练习三：为什么swap需要saved？

答案：第一次覆盖左对象前必须保存旧值，否则第二次赋值无法恢复原左值。
