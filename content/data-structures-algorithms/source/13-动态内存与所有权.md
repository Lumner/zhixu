# 13 动态内存与所有权

## 13.1 目标与先修

先掌握生命周期、数组长度和结构体。建议5—7小时。本章学习malloc、calloc、realloc与free，理解分配失败、初始化、扩容后指针失效、所有者与借用者。不要把“申请成功”与“内容已经正确初始化”混为一谈。

固定数组适合数量上限很小的练习；资料增加时，可能希望按需要准备更多空间。动态分配让程序显式申请一段存储，它一直存在到相应释放，不因创建它的普通函数返回而自动消失。

## 13.2 先建立资源生命周期

```text
请求存储 → 检查成功 → 初始化元素 → 使用 → 释放
                  ↘ 失败：保留已有状态并报告
```

**所有者**负责最终释放，**借用者**只在约定时间内访问，不擅自释放。本例values持有的分配由main负责；传给计算函数的const指针可以只借用。

C不会自动记录所有权，也不会在指针变量离开作用域时自动free动态对象。只记住“最后free一下”不够：每个提前return也要考虑已取得哪些资源。

## 13.3 malloc分配字节，不分配已知的业务值

`malloc(2 * sizeof *values)`申请可容纳2个int的字节数，返回指针，失败为NULL。`sizeof *values`取得所指int类型大小，这里不会真的读取一个尚未分配的元素。

包含`<stdlib.h>`后，C允许malloc返回的void指针转换成适当对象指针，不需要在本课额外写强制转换。先检查NULL，再通过下标初始化。malloc内容没有你可依赖的初值，不能先累加后初始化。

不要把“2个元素”误写成`malloc(2)`；字节数与元素数不同。一般的`count * sizeof element`可能先发生无符号乘法溢出，所以计算之前检查`count > SIZE_MAX / sizeof element`。SIZE_MAX来自标准头文件，表示size_t上限。

## 13.4 realloc成功与失败是两条不同路径

`realloc(values, new_count * sizeof *values)`调整分配大小，成功时保留新旧大小较小范围内的旧字节。新增区域没有自动初始化，需要写入。它可能搬到新位置，也可能看起来仍在原处。

始终先接到临时指针grown。如果失败返回NULL，原分配仍属于values，仍可使用或释放；若直接`values = realloc(...)`，就可能丢掉原地址，造成泄漏。

一旦成功，应以后只使用新的返回指针，原来的指针与指向旧区域内部的借用地址都不能继续依赖。即使打印出来地址数值好像没变，也不要用旧指针做后续访问或比较来“验证是否搬家”。需要的元素位置用下标重新取得。

本章只请求正大小，不研究0大小realloc在不同规范和实现中的差异。空集合用指针NULL、数量0、容量0表示，不分配后又解引用0个元素。

## 13.5 完整实验：从2格扩到4格

**完整程序：memory.c。** 下载 [源码](示例代码/13-memory/memory.c)，放到`~/dsa-labs/ch13`。

```c
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *values = malloc(2 * sizeof *values);
    if (values == NULL) {
        fputs("allocation failed\n", stderr);
        return 1;
    }
    values[0] = 10;
    values[1] = 20;

    size_t new_count = 4;
    if (new_count > SIZE_MAX / sizeof *values) {
        free(values);
        return 1;
    }
    int *grown = realloc(values, new_count * sizeof *values);
    if (grown == NULL) {
        fputs("growth failed\n", stderr);
        free(values);
        return 1;
    }
    values = grown;
    values[2] = 30;
    values[3] = 40;
    printf("sum=%d\n", values[0] + values[1] + values[2] + values[3]);
    free(values);
    values = NULL;

    int *zeros = calloc(3, sizeof *zeros);
    if (zeros == NULL) {
        fputs("zero allocation failed\n", stderr);
        return 1;
    }
    printf("zeros=%d,%d,%d\n", zeros[0], zeros[1], zeros[2]);
    free(zeros);
    return 0;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch13`目录**：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic memory.c -o memory.exe
./memory.exe
```

正常结果：

```text
sum=100
zeros=0,0,0
```

先初始化10、20；成功扩容后再写30、40，所以总和100。free之后不再访问元素，将values置NULL只是防止这一个名字继续保存失效地址，不能让其他别名自动变安全。

calloc接收“元素数、每个元素大小”两个参数，并将分配字节置零。对这里的int数组，得到0、0、0。不要将此推广为任意指针或浮点表示一定可以靠全零字节获得所需值；包含指针的复杂对象仍应按类型明确初始化。

## 13.6 free的前提与常见资源错误

free可以接收NULL，效果是什么也不做。对非空值，只释放尚未释放的、由对应分配函数返回的起始地址，不能传局部变量地址、数组中间地址或已经释放的旧地址。

**内存泄漏**：所有者失去最后一个可用访问路径，资源却没释放。**释放后访问**：对象生命周期已结束，却通过旧地址读取或写入。**重复释放**：同一分配被释放两次。它们不是每次都会立即崩溃，但都不能接受。

本例第一次malloc失败时还没有资源；扩容失败时必须释放原values；第二次calloc失败时values已经释放，不需要再释放它。请按每条return逐一标出当前资源，而不是只看正常路径末尾。

## 13.7 容量、数量和借用的失效

扩容只改变可用格子数capacity，不代表新增元素已经成为业务记录。下一章项目里，只有新记录成功写入后才增加count；分配失败时count、capacity和旧数据都应保持不变。

如果某函数返回动态数组内的一条记录地址，这只是借用。下一次扩容、释放或整体替换目录后，地址可能失效。需要长期标识某资料，应保存稳定id，使用时重新查找，不把借用地址当永久编号。

结构体中含指针时，简单赋值只复制地址。若两个Catalog都以为自己是所有者并各自free，会重复释放。第16章会实现一次明确的所有权移交：成功后把临时目录交给目标，临时对象不再释放那块资源。

## 13.8 如何验证分配失败

不要为了实验耗尽整台电脑内存，也不要依靠“很大请求肯定失败”的猜测。本课验证脚本使用专用测试替身，让指定第几次分配返回NULL，检查原数据未改变且最后资源归零。

这是受控失败路径测试，不是声称实际耗尽物理内存。正常运行程序只会打印前述结果；作者实际运行哪些失败测试和工具，见独立验证记录。没有运行的检查器不能写成已通过。

## 13.9 练习与参考答案

练习一：为什么新增两格不能直接参与求和？

答案：realloc只保证旧范围内容保留，新增区域尚未初始化，也没有自动成为有效记录。

练习二：分配2个int失败，应该先写values[0]=10还是先检查NULL？

答案：先检查，失败时不能解引用。

练习三：free(values)之后把values设NULL，另一个曾指向同一对象的p还能用吗？

答案：不能。资源已结束，改一个变量不改变其他别名。

## 13.10 常见错误与完成条件

常见错误：按元素数当字节数；先乘法后检查溢出；直接覆盖唯一分配地址；扩容成功后继续用旧借用地址；把capacity当count；漏掉错误返回路径的释放；释放局部变量或重复释放。

完成条件：能逐条追踪所有return处的资源，独立写出临时指针扩容模板，说明新区域初始化和借用失效规则，画出本例完整生命周期。下一章进入 [多文件、调试与测试](14-多文件调试与测试.md)。
