# 04 输入输出与合法数据

## 4.1 目标与先修

先掌握第03章的类型和输出。建议3—4小时。本章让程序读取键盘输入，区分“字符3”和“整数3”，并在计算前检查数据。你会提前接触最小的条件语句，下一章再系统练习分支。

本次需求刻意很小：**一行只允许一位数字0—9，表示小时数，输出对应分钟数。** 不接受空格、正负号、小数或两位数字。这不是最终输入方案，而是让每一个字符都能解释清楚的第一步。多位整数在阶段项目中完成。

## 4.2 输入、输出是信息通道

普通终端程序启动时，有标准输入、标准输出、标准错误三个常用通道。输入通常连接键盘，输出通常显示在终端，也可以被Shell连接到文件或其他程序。

本章用`getchar()`从标准输入取下一个字符，用`printf`、`puts`写标准输出。为了先聚焦字符处理，本批教学程序也把输入错误消息写到标准输出，并用非零退出码表示失败。后续工具程序会专门组织错误通道。

运行程序后，键盘输入通常要按Enter才交给程序读取。程序等待输入时没有重新出现Shell提示符，不表示崩溃；不要在它等待的时候继续输入编译命令。可用Ctrl+C结束这次运行，再重新开始。

## 4.3 getchar为什么返回int

`getchar()`的返回值需要表示所有正常字节值，还需要额外表示结束或读取失败的标记`EOF`。因此应使用`int`接收，不能先缩窄到`char`再判断EOF。

EOF不是你要输入的三个字母，也不是普通字符；它是头文件定义的特殊整数标记，不要硬编码为某个数字。初学时用文件或下面的管道实验观察输入结束最稳定。需要区分正常结束与实际I/O错误时还要进一步检查流状态，后续文件章节再展开。

键盘输入`3`并按Enter，通常带来字符`'3'`和换行`'\n'`。它们不等于整数3和字母n。在本章主线环境中，C标准文本输入会处理Windows文本换行；程序判断的是读到的换行字符。

C保证`'0'`至`'9'`的编码连续，所以通过检查后，`digit - '0'`可以得到0—9。这里不要求背ASCII码表，也不能假定所有字母间都存在相同规律。

## 4.4 先学习一个条件句

**上下文片段：用于完整程序的main内，digit已由getchar初始化。**

```c
if (digit < '0' || digit > '9') {
    puts("invalid input");
    return 1;
}
```

`if`表示“如果”，括号里是条件，条件成立才执行花括号里的语句。`<`和`>`是大小比较，`||`表示逻辑“或者”。这段读成“如果小于字符0，或者大于字符9，就报错并退出”。EOF也不属于合法数字字符，会被拒绝。

`return 1;`使main立即结束，后面的换算不再执行。这样程序先确认输入满足前提，再进行计算。不要先转换和计算，最后才决定刚才是否合法。

结尾的检查是另一句：`ending != '\n' && ending != EOF`。`!=`表示不相等，`&&`表示“而且”。结尾既不是换行也不是输入结束，就说明第一行不只含一位数字，应拒绝。条件内的`'\n'`使用单引号，因为比较的是一个字符值。

## 4.5 完整实验：一位小时数换算

**完整程序：input.c。** 保存到自己的 `~/dsa-labs/ch04`，或下载 [源码](示例代码/04-input/input.c)。

```c
#include <stdio.h>

int main(void)
{
    int digit = getchar();
    int ending = getchar();

    if (digit < '0' || digit > '9') {
        puts("invalid input");
        return 1;
    }
    if (ending != '\n' && ending != EOF) {
        puts("invalid input");
        return 1;
    }

    int hours = digit - '0';
    printf("hours=%d\nminutes=%d\n", hours, hours * 60);
    return 0;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch04`目录**运行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic input.c -o input.exe
./input.exe
```

输入`3`后按Enter，程序显示：

```text
hours=3
minutes=180
```

终端里你敲出的3可能也会显示，那是终端回显，不是程序额外打印的输出。程序没有提示语是为了让输入输出格式保持简单；不代表它没有在等输入。

两次`getchar`不是让你输入两次数字。第一次取3，第二次取紧随其后的换行。输入12加Enter时，第二次取到2，因此拒绝；此程序随后结束，不再处理剩余字符。第二行及更后面的输入不在它的单行任务范围内。

## 4.6 用固定输入重复验证

在 **同一Bash终端与ch04目录**执行以下命令：

```bash
printf '3\n' | ./input.exe
printf '9' | ./input.exe
printf '12\n' | ./input.exe
echo $?
```

这里`printf`是Shell提供的命令，不是源码中的C函数；单引号保护输入文字，`\n`产生换行，`|`把左边的输出连接给右边程序的输入。第一条与手输3相同；第二条没有末尾换行，但数字后马上是EOF，仍合法；第三条应输出`invalid input`，随后查退出状态为1。

这既是复现方法，也说明程序读的是输入通道，不是只能从真人键盘读取。状态应在目标命令后立刻查看。

| 输入第一行 | 是否接受 | 原因 |
| --- | --- | --- |
| `0` | 是，分钟0 | 范围包含0 |
| `9` | 是，分钟540 | 上端点也是合法值 |
| 空行 | 否 | 第一个字符就是换行 |
| `a` | 否 | 不是十进制数字字符 |
| `12` | 否 | 第二个字符不是行尾 |
| ` 3`、`3 ` | 否 | 本协议不允许空格 |
| 无任何输入即结束 | 否 | 没有数字 |

请至少实际运行0、9、空行、12四组，再核对你的输出。

## 4.7 为什么这一步不先使用scanf

你会在其他教材见到`scanf("%d", &x)`。它牵涉变量地址、转换结果、未消费字符和数值范围；若只记住模板，容易以为返回成功就代表整行都合法。超出目标整数范围的转换也不能靠“先读进int再判断”保证安全。

本课先处理单个字符，等第06、07章讲完循环和函数，再写“每读一位，先查范围，再累积”的读取器；学完数组与指针后，再比较标准库转换方案。不需要现在背`&x`，也不要用不明白的输入模板来绕开错误。

## 4.8 常见错误

- 用`char`保存getchar结果：可能无法可靠保留EOF信息，改用int。
- 输入字母却仍做减`'0'`：先验证，再转换。
- 把换行写成`'/n'`或`'n'`：转义使用反斜线`\n`。
- 把两位数当作本例支持的输入：先遵守协议，阶段项目再扩展。
- 输入后没按Enter，以为程序死掉：先确认终端输入行为。
- 想用`fflush(stdin)`清空键盘：本课不使用这种非可移植做法，后面会显式读取至行尾。

## 4.9 练习与参考答案

练习一：输入`7`后按Enter，两次getchar分别得到什么？最后显示几分钟？

答案：字符`'7'`与`'\n'`，转换后7，分钟420。

练习二：输入`3x`为什么失败，即使第一个字符正确？

答案：结尾读到`'x'`，整行不符合“一位数字”的协议。有效前缀不等于整条输入有效。

练习三：若要把输入改为0—9个十分钟学习块，只改哪一处业务计算？

答案：把乘60改为乘10，并把变量与输出标签改成块数，输入检查不变。别让输出仍写hours却实际表示块数。
