# 17 问题规格与循环不变量

## 17.1 目标与先修

先完成01—16章，尤其是数组长度、输出参数、失败不写结果和资源归属。建议4—5小时。本章不增加很多C语法，而是训练另一项能力：在程序运行之前，说清它应该做什么，并解释循环为什么不会漏算或重复算。

到目前为止，你已经能编译程序、输入数据、管理记录。接下来的数据结构代码更长，不能只依靠“几个样例没问题”。我们先从熟悉的学习分钟统计开始，为以后写顺序表、链表和树建立统一的思考方法。

## 17.2 从一句需求写成问题规格

需求是“求总时长和最大值”。**规格**就是把输入、输出、前提与失败行为写到没有歧义。它是判断实现对不对的依据，不是把代码再翻译一遍。

| 项目 | 本次约定 |
| --- | --- |
| 输入 | values指向count个仍有效的int，表示按日期排列的分钟数 |
| 数据范围 | 每个值0—1440；成功结果的总和必须可由long表示 |
| 输出 | 总和、最大值、最大值最早出现的下标 |
| 正常结果 | 返回1，把完整结果写入调用者提供的PrefixStats对象 |
| 空序列 | 没有最大值，返回0，不写输出对象 |
| 可检查错误 | 空输出指针、空输入指针、非法分钟、总和超范围，都返回0 |
| 调用者责任 | 指针实际指向合适对象、输入区域足够长、生命周期有效 |
| 失败保证 | 输出对象原有字段保持；输入不修改 |

为什么这次空输入失败，而第11章空求和成功？“求空和”可以定义为0；“同时返回最大值”还需要一个不存在的最大值。本函数选择返回失败状态，调用者若需要空报告，可先检查count并展示“无记录”。这两种接口回答的问题不同，并不矛盾。

为什么用long累计？第16章最多32条，每条1440，总和可能46080，已经超出标准C所保证的最小int正范围；long至少能表示到2147483647。本函数还允许更长输入，因此在加法前检查LONG_MAX，不能假定换成long就永远不溢出。

## 17.3 前置条件与后置条件

**前置条件**是调用前需要成立的事，例如指针确实指向count个int。**后置条件**是函数完成后承诺成立的事，例如成功时total等于所有值之和。

空检查不能验证实际分配长度，也不能识别悬空地址。把错误指针传给函数，再期待它逐一“试读验证”，不是可行的接口设计。可检查的数据错误在函数中处理，内存对象有效性仍由调用者保证。

成功后的条件可拆成三句：

1. total等于每条分钟数相加，没有漏项或重复。
2. maximum不小于任何输入值，而且确实来自输入。
3. first_max指向maximum的第一次出现，不只是随便一个最大值位置。

第三句正是重复值容易漏掉的要求。实现中`>`与`>=`只有一个符号差别，却可能对应不同规格。

## 17.4 伪代码先表达思路

下面是**伪代码，不是可编译C程序**。先忽略C类型和格式符，只看逻辑：

```text
拒绝没有元素的输入
检查第一条分钟数
把第一条作为当前总和、最大值，最大位置记0
从位置1到最后依次处理：
    检查当前分钟数与总和范围
    加入总和
    若当前值严格更大，更新最大值与位置
全部成功后，一次写回完整结果
```

先写伪代码的价值是让“步骤”和“语言标点”分开检查。它也必须明确：第一条在哪里处理、剩余从哪里开始、何时写回；不能只写“适当更新一下”。

## 17.5 什么是循环不变量

循环不变量是：**在约定的循环观察时刻，每次都成立的性质**。“变量”是会变化的数据，“不变量”是变化过程中始终成立的关系，不代表某个变量永远不变。

我们选“每轮循环开始、准备处理下标i之前”作为观察时刻。此时已经处理的范围是`[0,i)`，即包含0、不包含i，也就是0—i-1。叫作已处理前缀。

本例的不变量：

- result.total等于前缀`[0,i)`的总和。
- result.maximum是这个前缀的最大值。
- result.first_max是这个前缀中最大值第一次出现的下标。
- 原输入未修改，调用者输出对象还没有被写入。

选择从第1条剩余记录开始循环，能让前缀始终非空，最大值不需要凭空初始化成0。初始化已经处理了下标0，因此循环开始i=1。

## 17.6 用三步说明正确性，再补终止性

**初始化。** 进入循环前，前缀只有values[0]。总和就是它，最大值也是它，最早位置为0，因此不变量成立。

**保持。** 假设某轮之前成立，处理values[i]：加到总和，恰好把新元素加入一次；比原最大值大就替换最大值和位置，否则保留。相等时不替换，最早位置就仍然保留。随后i加1，新前缀变成`[0,i+1)`，性质继续成立。

**结束时的结论。** 正常退出时i=count，前缀就是整个输入，所以局部结果满足规格。此时才写回输出对象。

**为什么能结束。** 每轮处理前还有`count-i`个未处理元素，这是非负整数；每个正常迭代后减少1，最终变0。出错时直接返回，也会结束。只说“不变量一直成立”不能证明程序必定停止，需要这项进展依据。

在算法术语中，若程序终止则结果正确，称部分正确性；再证明终止，才得到完整的终止与正确保证。现在能用自己的话解释这四段，比记住术语名称更重要。

## 17.7 手算一次，确认观察时刻

输入30、0、45、15、45：

| 循环开始i | 已处理前缀 | total | maximum | first_max |
| --- | --- | --- | --- | --- |
| 1 | 30 | 30 | 30 | 0 |
| 2 | 30、0 | 30 | 30 | 0 |
| 3 | 30、0、45 | 75 | 45 | 2 |
| 4 | 30、0、45、15 | 90 | 45 | 2 |
| 5，循环结束 | 全部5条 | 135 | 45 | 2 |

最后一个45不会把位置改为4，因为它没有严格超过当前最大值。若调试输出放在循环体更新之后，表格标签就要写“本轮处理后”，不能拿两个时刻混着比。

## 17.8 一组完整C程序

把以下三文件放在自己的`~/dsa-labs/ch17`。它们共同构成一个程序，下载入口为 [prefix_stats.h](示例代码/17-specifications/prefix_stats.h)、[prefix_stats.c](示例代码/17-specifications/prefix_stats.c)、[main.c](示例代码/17-specifications/main.c)。

完整文件prefix_stats.h：

```c
#ifndef DSA_PREFIX_STATS_H
#define DSA_PREFIX_STATS_H

#include <stddef.h>

typedef struct {
    long total;
    int maximum;
    size_t first_max;
} PrefixStats;

int prefix_stats(const int *values, size_t count, PrefixStats *out);

#endif
```

完整文件prefix_stats.c：

```c
#include "prefix_stats.h"
#include <limits.h>

int prefix_stats(const int *values, size_t count, PrefixStats *out)
{
    if (out == NULL || count == 0 || values == NULL) {
        return 0;
    }
    if (values[0] < 0 || values[0] > 1440) {
        return 0;
    }
    PrefixStats result = {values[0], values[0], 0};
    for (size_t i = 1; i < count; i++) {
        int value = values[i];
        if (value < 0 || value > 1440 || result.total > LONG_MAX - value) {
            return 0;
        }
        result.total += value;
        if (value > result.maximum) {
            result.maximum = value;
            result.first_max = i;
        }
    }
    *out = result;
    return 1;
}
```

完整文件main.c：

```c
#include "prefix_stats.h"
#include <stdio.h>

int main(void)
{
    int values[] = {30, 0, 45, 15, 45};
    size_t count = sizeof values / sizeof values[0];
    PrefixStats stats = {0, 0, 0};
    if (!prefix_stats(values, count, &stats)) {
        fputs("invalid statistics input\n", stderr);
        return 1;
    }
    printf("total=%ld maximum=%d first_max=%zu\n",
           stats.total, stats.maximum, stats.first_max);
    return 0;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch17`目录**执行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic main.c prefix_stats.c -o prefix_stats.exe
./prefix_stats.exe
```

预期：`total=135 maximum=45 first_max=2`。旧MinGW环境若需要第09章的标准格式兼容选项，仍在gcc之后加`-D__USE_MINGW_ANSI_STDIO=1`。

result是局部临时结果，正常结束才`*out = result`。范围错误在任何位置出现，都不向调用者写半个统计。`LONG_MAX - value`只有在value已确认0—1440后才检查，依赖`||`从左到右的短路规则，随后加法才安全。

## 17.9 反例、测试与证明各做什么

把更新条件改为`value >= result.maximum`，程序仍能编译，但上述输入会得到first_max=4。这个反例足以证明它不满足“最早位置”的规格。反例常用来推翻错误方案，不需要准备上千个样例。

反过来，很多测试通过仍不能单独证明所有合法输入都正确；推理检查循环结构，测试检查实现是否真的对应推理。二者配合：先写不变量，再用边界测试找实现与说明之间的差别。

至少检查单元素、全零、最大值在首尾、重复最大值，以及空输入和非法分钟。给输出字段先设为999，失败后检查仍为999；不能只确认返回0而忽略输出已被提前改坏。

## 17.10 常见错误

- 把“不变量”写成最后答案：循环进行一半时，最后答案通常尚不存在。
- 忘记观察时刻：i表示已处理数还是正处理位置，必须先约定。
- 初始化最大值为0却声称支持任意负整数：规格和实现不一致。
- 相等时覆盖位置，却承诺最早位置：需要严格大于。
- 只证明正常路径，不管失败输出：后置条件也包含失败保证。
- 没有状态进展却声称必然停止：正确性与终止性分别解释。

## 17.11 练习与参考答案

练习一：若需求改为“最后一次出现的最大值位置”，该改什么？

答案：更新条件改成>=，把字段名和不变量中的“最早”同步改为“最后”。只改代码不改约定，会让读者误用。

练习二：一个n条数据的求和循环，开始时i=0,total=0，不变量怎样写？

答案：每轮开始total等于`[0,i)`之和。空前缀和为0，因此初始化成立；每轮加values[i]后前缀扩大一格；i=n时得到全和。

练习三：为什么本程序输出对象必须等到最后再写？

答案：若后面出现坏值或总和超范围，提前写入的字段会违反“失败不改变旧结果”的约定。
