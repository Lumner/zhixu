## 四、资料目录核心实现

照第16章的格式约定，自己实现Record与Catalog，至少提供init、free、add、find、set_minutes。保持count≤capacity≤32，重复编号拒绝；追加成功复制记录，失败不改旧内容。find结果只是借用，不能跨扩容继续使用。

按顺序加入5条记录，触发容量4到8的变化；记录每次count/capacity。标题先用固定英文字串，让注意力集中在所有权与结构，而不是输入细节。

不要直接复制整个catalog.c。先写一项、编译一项，再加入验证。复杂度推导将在下一阶段正式进行，本阶段先能说清每次查找实际访问哪些记录。

## 五、导入导出与回归矩阵

增加文件头、整行读取、数字校验和临时目录提交。读取器必须消耗完超长行，拒绝内嵌零与ASCII控制字节。导出只向数据通道写可重新导入的内容，错误走stderr。

| 用例 | 预期 |
| --- | --- |
| 只有正确文件头 | 空目录成功 |
| 0分钟、1440分钟 | 合法 |
| 标题63字节、64字节 | 前者成功，后者拒绝 |
| 字段缺失、空标题、未知版本 | 失败，不提交临时目录 |
| 编号1与0001 | 按数值重复，拒绝 |
| 非法数字12x、-1、1.5、超长9串 | 拒绝，无数值累积溢出 |
| 32条、33条 | 前者成功，后者record limit |
| 最后一条标题后无换行 | 成功 |
| 保存后重新读取 | 记录值与顺序相同 |
| 改存在编号、改不存在编号 | 前者成功，后者not found |

再准备一个非空的原目录，导入坏文件后确认它还在。只在空目录上测试不够。分配失败应用测试替身，不尝试耗尽真实内存；可以参考作者验证脚本的专用测试方法，业务代码不要加入随机失败。
