# 28 散列、冲突与拉链法

## 28.1 目标与先修

先完成单链表、数组与余数运算，建议5—7小时。目标是解释键、值、散列函数、桶、冲突、负载因子；手工构造冲突，完成增查改删与释放，说明为什么“散列查找总是O(1)”不成立。

资料ID是17，不表示它在数组第17格。ID用来辨认资料，这叫**键key**；关联的分钟数或记录位置叫**值value**。把不同键关联到值的结构叫映射，也常叫字典。本章用整数键和整数值，先不把整份标题塞进节点。

## 28.2 从直接寻址到散列

键范围0—9999，如果直接开10000格并配存在标记，就可以用键当下标，叫直接寻址。查询简单，但只有几十条资料时会预留很多格；推广到很大的键空间会更明显。

**散列函数hash function**把键变成较小数组的下标。这里用h(key)=key%8。数组中的一个入口叫**桶bucket**，编号0—7。1、9、17都映射到桶1，这叫**冲突collision**。冲突只是不同键碰巧同桶，不表示它们是同一个键。

查到桶之后仍必须比较完整key。只比较余数会把资料9误当资料17。好的散列函数应让实际键分布较均匀，并且计算成本合理；本课特意用易手算的余数来暴露冲突，不把它推荐为生产系统的通用安全散列。

## 28.3 拉链法怎样保存碰撞项

**拉链法separate chaining**让每个桶指向一条链。本章每个真实节点有key、value、next，桶中无头哨兵；桶指针为NULL表示该桶空。

```text
加入 (1,10)、(9,90)、(17,170)，每次在链头插入：
bucket[1] -> [17,170] -> [9,90] -> [1,10] -> NULL
其他桶为空
```

同桶节点的顺序不影响映射结果；本接口不保证按键排序或按加入先后遍历。链上每个键必须不同。全表count等于所有链长之和，每个节点恰好由一个桶拥有，不形成环或共享节点。

## 28.4 先定义完整接口协议

键限0—9999，值允许任意int，最多48项；8桶是表示选择，48项是教学资源预算。它们不是“桶数一定等于最多项数”。本版桶数固定，不自动扩容，便于集中学习链式碰撞。

| 操作 | 成功行为 | 主要失败 |
| --- | --- | --- |
| init / clear | 初始化空表 / 释放后回空表 | 对象必须是有效地址；clear前已初始化 |
| put(key,value) | 新增唯一键 | 非法键、重复、48项已满、申请失败 |
| get(key,&out) | 将值复制到独立变量 | 非法键/NULL输出、查无此键 |
| set(key,value) | 修改已有键的值 | 非法键、查无此键；不自动新增 |
| erase(key) | 删除已有键并释放节点 | 非法键、查无此键 |

返回枚举H_OK、H_DUPLICATE、H_MISSING、H_FULL、H_MEMORY、H_INVALID；H_OK的数值为0，要显式比较名字，不能沿用以前bool接口的“非零成功”。put先判非法，再判重复，再判满，再分配：满表里插入原键仍报告重复。失败保留旧表；get失败不写out。

对象参数必须是已初始化的有效对象；不能复制拥有节点的ChainMap后分别clear。头文件展示内部结构用于学习，业务调用不自行改buckets或count。输出必须指向独立int变量，不指向节点内部，也不能与对象存储重叠。

## 28.5 查找、新增与修改的顺序

查找先验证键非负，再将其转为size_t取余。负数先转换可能变成很大的无符号数；即便取余能落在数组里，也已违反键协议，所以必须先拒绝。

从对应桶头依次比较完整键。走到NULL才证明不存在。put复用这次查找来拒绝重复；确认可加后malloc一个节点，填完key/value/next，最后接入桶头并增加count。若malloc失败，原桶头仍没有变。

set定位到节点后只改value，键与链接保持，因此不改变桶位置或数量。本版的内部find_node返回节点指针供实现使用，公开get只复制值，不把内部地址交给调用者长期保存。

## 28.6 删除为什么要记录前驱

删9时，previous指17，node指9，让17.next改为9.next，再free(9)。删头17时没有前驱，改bucket[1]本身。删最后节点或唯一节点，同样先接回后继，再释放，数量只减一次。

```text
删除9之前：17 -> 9 -> 1 -> NULL
保存9.next后接链：17 ------> 1 -> NULL
最后释放9；以后不再读取9的任何字段
```

clear对每个桶重复“保存next、free当前、前进”，最后把所有桶设NULL、count归0。不能在free后再用node->next；也不能只清桶指针而不释放真实节点。

完整文件chaining.h：

```c
#ifndef DSA_CHAINING_H
#define DSA_CHAINING_H
#include "hash_status.h"
#define CHAIN_BUCKETS 8
typedef struct HNode { int key; int value; struct HNode *next; } HNode;
typedef struct { HNode *buckets[CHAIN_BUCKETS]; size_t count; } ChainMap;
void chain_init(ChainMap *map);
void chain_clear(ChainMap *map);
HStatus chain_put(ChainMap *map, int key, int value);
HStatus chain_get(const ChainMap *map, int key, int *out);
HStatus chain_set(ChainMap *map, int key, int value);
HStatus chain_erase(ChainMap *map, int key);
#endif
```

完整文件chaining.c：

```c
#include "chaining.h"
#include <stdlib.h>

static HNode *find_node(const ChainMap *map, int key)
{
    HNode *node = map->buckets[(size_t)key % CHAIN_BUCKETS];
    while (node != NULL && node->key != key) {
        node = node->next;
    }
    return node;
}
void chain_init(ChainMap *map)
{
    for (size_t i = 0; i < CHAIN_BUCKETS; i++) {
        map->buckets[i] = NULL;
    }
    map->count = 0;
}
void chain_clear(ChainMap *map)
{
    for (size_t i = 0; i < CHAIN_BUCKETS; i++) {
        HNode *node = map->buckets[i];
        while (node != NULL) {
            HNode *next = node->next;
            free(node);
            node = next;
        }
    }
    chain_init(map);
}
HStatus chain_put(ChainMap *map, int key, int value)
{
    if (key < 0 || key > H_KEY_MAX) {
        return H_INVALID;
    }
    if (find_node(map, key) != NULL) {
        return H_DUPLICATE;
    }
    if (map->count == H_MAX_ITEMS) {
        return H_FULL;
    }
    HNode *node = malloc(sizeof *node);
    if (node == NULL) {
        return H_MEMORY;
    }
    size_t bucket = (size_t)key % CHAIN_BUCKETS;
    node->key = key;
    node->value = value;
    node->next = map->buckets[bucket];
    map->buckets[bucket] = node;
    map->count++;
    return H_OK;
}
HStatus chain_get(const ChainMap *map, int key, int *out)
{
    if (key < 0 || key > H_KEY_MAX || out == NULL) {
        return H_INVALID;
    }
    const HNode *node = find_node(map, key);
    if (node == NULL) {
        return H_MISSING;
    }
    *out = node->value;
    return H_OK;
}
HStatus chain_set(ChainMap *map, int key, int value)
{
    if (key < 0 || key > H_KEY_MAX) {
        return H_INVALID;
    }
    HNode *node = find_node(map, key);
    if (node == NULL) {
        return H_MISSING;
    }
    node->value = value;
    return H_OK;
}
HStatus chain_erase(ChainMap *map, int key)
{
    if (key < 0 || key > H_KEY_MAX) {
        return H_INVALID;
    }
    size_t bucket = (size_t)key % CHAIN_BUCKETS;
    HNode *previous = NULL, *node = map->buckets[bucket];
    while (node != NULL && node->key != key) {
        previous = node;
        node = node->next;
    }
    if (node == NULL) {
        return H_MISSING;
    }
    if (previous == NULL) {
        map->buckets[bucket] = node->next;
    }
    else {
        previous->next = node->next;
    }
    free(node);
    map->count--;
    return H_OK;
}
```

## 28.8 负载因子与复杂度的条件

**负载因子α**是有效项数n除以桶数b，即n/b。3项8桶α=0.375；48项8桶α=6。拉链法一桶可有多个节点，α可以大于1。平均每桶n/b项，不代表每一桶都正好这么长。

若键被良好地分散，查找的期望链长随α变化，通常写期望O(1+α)。固定负载并采用合适散列策略时才可讨论期望常数；本版固定取余没有随机化，不提供对任意键分布的这种保证。刻意选择0、8、16……就能把所有项放在同一桶，最坏查找、put的查重、set、erase均O(n)。

真正接链是O(1)，但put先查重，不能把整个put说成无条件O(1)。clear扫描b个桶及n个节点，为Θ(b+n)；空间Θ(b+n)。本版预算很小，复杂度讨论将n、b视为可扩展量。

扩桶时也不能只把旧桶数组变大：h(key)的模数改变，旧节点可能属于新桶，必须重散列。下一章用数组内的另一种冲突表示，具体实现重散列和失败保留。

## 28.9 相等、散列与常见错误

如果以后用字符串作键，字符串内容相等才算相同，不能只比较两个char*地址；相等的键必须具有相同散列结果，散列相同却不保证键相等。长字符串求散列本身需要读字符，不能忽略键长度再说查询总是常数。

常见错误：同桶就当重复；用负数余数作下标；重复插入偷偷覆盖；set缺失时偷偷新增；先改桶头再判断分配成功；漏处理删头；释放后读取next；只统计接链不统计查重；把α>1误判为数组必然越界。

## 28.10 练习与参考答案

练习一：2、10、18分别进哪个桶？答案：都进桶2，插入后链头为18，链序18→10→2。

练习二：48项8桶时α为多少？是不是每条链6项？答案：6；仅为平均，极端时某桶48项，其余0项。

练习三：满表中put已有键和新键分别报什么？答案：已有键H_DUPLICATE，新键H_FULL，原值与count不变。判断顺序是接口的一部分。
