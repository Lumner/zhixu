## 18.1 目标与先修

要回答的问题是：同样解决一个问题，当数据增加，哪种方法会越来越难以承受？比较一台机器上某次运行的毫秒数很有用，却不是全部答案。

## 18.2 先说规模n是什么

n通常表示输入规模，例如数组中实际有n条记录，不是数组容量，也不是某个元素恰好等于n。其他问题可能有两个规模：图有V个点和E条边，文字比较还可能取决于标题长度L。

必须先固定分析对象：是一次查询，还是读文件、验证顺序、做查询并打印的整个程序？后者可能被读入的线性成本主导。第20章会实际展示这种区别。

本阶段采用简单的**单位成本模型**：一个固定大小整数的比较、赋值、下标访问视为常数成本。长字符串比较不一定是一次常数工作；任意精度大整数也不能直接沿用这个假设。每个结论都依赖模型，而不是算法名字自动决定。

## 18.3 从一个循环数到两个循环

处理n条记录，循环体每条一次，就是n次；若把循环条件也算进去，通常检查n+1次。只要约定计数口径，就能解释差别。

两个顺序执行的n次循环，总计2n，增长仍是线性的。两层嵌套、内层每次都跑n次，则n×n，也就是n²。

如果只枚举下标i<j的两条记录，次数不是n²，而是：

```text
(n-1) + (n-2) + ... + 1 + 0 = n(n-1)/2
```

可以把正序、逆序两排相加，每列都为n-1，共n列，再除2得到。n=4时是3+2+1+0=6；用四条记录在纸上列出六对即可核对。空输入n=0时次数为0；公式是数学表达式，C中无符号n-1不能在n=0时不加判断就照抄。

两层循环也可能总共只有n级工作：例如内层在整个运行中共享一个只前进不后退的下标，总前进次数受n限制。先看范围与状态，不要靠数for的个数判断。

## 18.4 对数：要减半多少次

从8反复除以2：8→4→2→1，共3次。反过来，2×2×2=8，记为`log2(8)=3`。log2(n)回答“2的几次方得到n”。

整数除法向下取整时，9→4→2→1也做3次，所以这样的循环次数是`floor(log2(n))`（n≥1）；floor表示向下取整。n=0单独规定不执行，不能说log2(0)=0。

后面二分查找每轮缩小候选范围，但它还要处理剩最后一个元素的情况，因此精确比较次数不一定等于这里的halves。相同增长量级不意味着每一行计数相同。

对任意固定大于1的底，换底只差常数倍，所以复杂度常写log n，不特意写2。手算精确次数时仍要明确底数和循环停止条件。

## 18.5 完整实验：四把工作量标尺

**完整程序：growth.c。** 下载 [源码](示例代码/18-growth/growth.c)，放到`~/dsa-labs/ch18`。参数n只允许0—128，既避免演示长时间占用，也使所有计数保持很小。

演示上限不是渐近分析中的阈值。量级分析考虑同一组步骤推广到更大规模时怎样增长；真实C实现仍受类型范围、对象容量和运行资源约束，不能把数学规模无限扩大后原样运行。

```c
#include <stdio.h>

int parse_size(const char *text, size_t *out)
{
    size_t value = 0;
    if (text[0] == '\0') {
        return 0;
    }
    for (size_t i = 0; text[i] != '\0'; i++) {
        if (text[i] < '0' || text[i] > '9') {
            return 0;
        }
        size_t digit = (size_t)(text[i] - '0');
        if (value > 128 / 10 || (value == 128 / 10 && digit > 128 % 10)) {
            return 0;
        }
        value = value * 10 + digit;
    }
    *out = value;
    return 1;
}

int main(int argc, char *argv[])
{
    size_t n = 0;
    if (argc != 2 || !parse_size(argv[1], &n)) {
        fputs("usage: growth n (0..128)\n", stderr);
        return 1;
    }
    size_t linear = 0;
    size_t square = 0;
    size_t pairs = 0;
    size_t halves = 0;
    for (size_t i = 0; i < n; i++) {
        linear++;
    }
    for (size_t i = 0; i < n; i++) {
        for (size_t j = 0; j < n; j++) {
            square++;
        }
    }
    for (size_t i = 0; i < n; i++) {
        for (size_t j = i + 1; j < n; j++) {
            pairs++;
        }
    }
    for (size_t remaining = n; remaining > 1; remaining /= 2) {
        halves++;
    }
    printf("n=%zu linear=%zu square=%zu pairs=%zu halves=%zu\n",
           n, linear, square, pairs, halves);
    return 0;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch18`目录**：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic growth.c -o growth.exe
./growth.exe 8
```

结果：`n=8 linear=8 square=64 pairs=28 halves=3`。

四个计数器各记录对应循环体做一次标记的次数，不是整个程序的CPU指令数。整个演示程序依次执行了四种任务，它的总体工作由平方部分主导；不能拿halves列当整个程序只做了3次工作。编译优化也可能改写循环，所以这里是源级计数模型，不是机器性能基准。

## 18.6 大O不是精确秒数

如果某种工作量是`T(n)=5n+7`，n增大时它大致随n成比例增加。我们关心增长关系，而不是把5和7当成所有机器共同的指令成本。

**O(g(n))表示渐近上界**：存在固定正数c和阈值n0，使所有n≥n0时，`0 <= T(n) <= c*g(n)`。固定的意思是不能为了每个n再临时换一个c；否则任何曲线都能“被包住”，定义就没有意义。

对5n+7，当n≥1时，5n+7≤12n，所以取c=12、n0=1，得到O(n)。它也满足O(n²)，但那个上界比较松，不能据此把实际线性工作说成“必定平方增长”。

**Ω(g(n))表示渐近下界**：足够大的n下，工作量至少为某个正常数倍的g(n)。5n+7≥5n，因此是Ω(n)。

**Θ(g(n))表示上下界同时成立**：即增长量级被两边夹住。5n+7同时为O(n)与Ω(n)，所以是Θ(n)。Θ不是“某次运行刚好等于n”，仍然忽略固定倍数和低阶项。

这一组定义只比较函数增长，不自动说明输入是哪种情况。先确定你在分析最坏、平均还是其他函数，再给它加O或Θ。

## 18.7 常见增长放在一起看

| 规模n | log2 n | n | n log2 n | n² | 2的n次方 |
| --- | --- | --- | --- | --- | --- |
| 4 | 2 | 4 | 8 | 16 | 16 |
| 8 | 3 | 8 | 24 | 64 | 256 |
| 16 | 4 | 16 | 64 | 256 | 65536 |
| 32 | 5 | 32 | 160 | 1024 | 4294967296 |

这张表比较数学数量，不宣称每一种算法在n=4时都会恰好执行对应数次。平方n²是n乘自己；指数2^n是把2连续相乘n次，二者不是同一类增长。第19章的汉诺塔会让指数增长变得可见。

忽略常数不是说常数永远不重要。在实际规模很小时，初始化、缓存、函数调用都可能让较好量级的方法暂时更慢。复杂度帮你理解规模趋势，具体性能仍需在真实工作负载上测量。

## 18.8 最好、最坏与平均分别是什么

在n个互不相同的值里顺序查找：目标就在第一个位置，比较1次，是最好情况；目标在最后或没有找到，比较n次，是最坏情况。

若明确假设“查找必定成功，并且每个位置成为目标的概率相同”，平均比较次数是`(1+2+...+n)/n = (n+1)/2`。这是特定概率模型下的平均，不代表任何随机输入都符合，也不等于“最好与最坏随便取平均”。有重复值或大量查找失败，分布就要重新定义。

所以可以分别说：最好时间Θ(1)，最坏Θ(n)，在上述模型下平均Θ(n)。**O不等于最坏，Ω不等于最好。** 例如一个平均时间函数也能讨论其O上界；符号和情况是两个维度。

## 18.9 摊还不是随机平均

回忆第16章的容量4、8、16、32：某次追加可能触发扩容，代价比普通追加大。即使完全不假设输入概率，仍可以把一串追加的总成本分摊到每次操作。

**概念成本模型**：每次普通新记录写入记1次；假设扩容都搬家，并复制已有的全部记录，不使用“碰巧原地扩展”来论证。

这里单独统计元素复制与新写入，不测量真实内存分配器内部的时间。

| 第几次追加 | 新记录写入 | 搬动旧记录 | 当次合计 |
| --- | --- | --- | --- |
| 1 | 1 | 0 | 1 |
| 4 | 1 | 0 | 1 |
| 5 | 1 | 4 | 5 |
| 9 | 1 | 8 | 9 |
| 17 | 1 | 16 | 17 |

前17次中复制旧记录4+8+16=28次，加新记录17次，总计45次。某次很贵，但整串总和仍与操作数同级。

把倍增思想推广到不限32的概念模型，复制量4+8+...小于2m，加上m次新写入，少于3m，所以容量管理的追加摊还为Θ(1)。第22章会正式实现与推导。

**不能直接宣布当前catalog_add整体摊还Θ(1)。** 它每次还顺序扫描已有记录检查重复ID，m次可能累计平方级比较；分摊解决的是扩容部分，不会神奇消除查重成本。这是分清分析对象的重要例子。

## 18.10 额外空间与递归栈

输入数组本身有n个元素，占Θ(n)存储。求和只需要一个total和下标，额外空间Θ(1)；如果另建n个元素的副本，额外空间Θ(n)。报告时说明是否包含输入和输出。

循环做n轮，不代表每轮的局部对象都同时存活；它们可以反复使用同一份存储。递归则可能同时保留多层未完成调用，没有malloc也可能需要随深度增长的调用存储，第19章具体画图。

不要把“申请总次数”与“峰值同时占用”混为一谈。很多次分配后立即释放，峰值不一定大；一次巨大副本却可能立即占满内存。

## 18.11 常见错误

- 把容量当n：规模应对应实际问题大小。
- 两个顺序循环误乘成n²：顺序相加，嵌套才根据各层范围累计。
- 见到除2就忽略终止条件：精确次数可能差一次，量级与精确值分开。
- 把O当等号、把O当最坏：分别说明上界与输入情况。
- 没有分布假设却给平均结论：先声明概率模型。
- 把扩容摊还结论套到含线性查重的整个操作：遗漏其他工作。
- 只数malloc判断空间：递归调用与副本也占存储。

## 18.12 练习与参考答案

练习一：先遍历n条，再遍历n条；与对每条再完整遍历n条，有什么区别？

答案：前者2n、Θ(n)，后者n²、Θ(n²)，前提是每次循环体为常数工作且各内层确实跑n次。

练习二：T(n)=7n+2是否属于O(n²)？为什么通常仍说Θ(n)？

答案：属于，但上界不紧。Θ(n)还给出了线性下界，更准确表达增长级别。

练习三：n为16时不断整数除2直到≤1，做几次？n=0呢？

答案：16→8→4→2→1，共4次；0不进入循环，单独处理，不取log2(0)。

练习四：某数组每次追加都线性查重，再倍增扩容，能说整个追加摊还常数吗？

答案：不能。扩容部分可摊还常数，但查重仍每次可能扫描当前全部条目。
