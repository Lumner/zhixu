# 34 三路快排与递归控制

## 34.1 目标与先修

先完成递归、区间与第33章分治。建议6—8小时。目标是跟踪三路分区不变量，区分基准位置与基准值，处理重复键，说明最坏二次时间，并用“只递归小边”限制调用栈。

归并先把左右排好，再花力气合并。快速排序先选一个**基准pivot**，把项分到比它小、等于它、比它大的区域，再分别整理小区和大区；等值区已经无需递归。

## 34.2 本章只采用一套明确的分区方案

快速排序有许多基准和分区变体。本版对[lo,hi)取中间位置的key作为pivot，使用三路分区。中间**位置**并不保证取到数值的中位数，不能据此承诺每次均分。

pivot存为独立int值，不是指向a[mid]的指针。分区过程中原中间记录可能被交换；若一直读取那个槽的当前key，就会让比较标准中途变化。

比较只调用第31章三路键比较函数，不做key-pivot或pivot±1，所以INT_MIN/INT_MAX也不引入算术溢出问题。

## 34.3 四段不变量与三个下标

设置lt=lo、i=lo、gt=hi，始终维持：

```text
[lo,lt)   key < pivot
[lt,i)    key == pivot
[i,gt)    尚未处理
[gt,hi)   key > pivot
```

开始三个已处理区都空，未知区是整个区间。循环条件i<gt，查看a[i]：

- 小于：交换a[lt]与a[i]，lt和i都加1；若二者重合就是自交换，公共函数跳过写入。
- 等于：i加1，把该项并入等值区。
- 大于：gt先减1，交换a[i]与a[gt]，i暂不动，因为换进来的项还没检查。

每次未知区长度gt-i都减少1，循环必终止。终止时未知区空，三个完成区的大小关系已建立。

## 34.4 手推一次分区

输入`3,1,2,3,0`，中间基准值2：

| 当前项/动作 | 数组 | lt | i | gt |
| --- | --- | --- | --- | --- |
| 初始 | 3,1,2,3,0 | 0 | 0 | 5 |
| 3大于，和末端0换 | 0,1,2,3,3 | 0 | 0 | 4 |
| 0小于，自交换 | 0,1,2,3,3 | 1 | 1 | 4 |
| 1小于，自交换 | 0,1,2,3,3 | 2 | 2 | 4 |
| 2相等 | 0,1,2,3,3 | 2 | 3 | 4 |
| 3大于，gt退到3 | 0,1,2,3,3 | 2 | 3 | 3 |

得到小区[0,2)、等值[2,3)、大区[3,5)。一般分区只保证大小关系，不保证小区内部和大区内部已排序；上例内部恰好有序，不能据此删除递归步骤。

## 34.5 三路为什么适合重复值

若所有key都5，一次扫描把整个区间变为等值区，小区和大区都空，立即完成；本版比较n次、写入0，不再递归n-1条重复项。

但三路不保证稳定。例如`2:A,2:B,1:C`，基准2，把最后1:C交换到最前时，2:A被换到末尾，变成`1:C,2:B,2:A`。全相等样本没有交换，只能说明那一例保持顺序，不能推翻这个不稳定反例。

## 34.6 不让坏分区拖出很深的栈

最直观写法对小区、大区都递归，极不均分时调用栈可能Θ(n)。本版比较两边长度，只递归较短的一边；较长的一边更新lo或hi，用当前while继续处理。

因为等值区至少含一条原基准记录，较短边长度不超过当前长度的一半。沿着真正嵌套的递归，每层规模至少折半，所以调用栈O(log n)。较长边仍要做工作，只是不用多压一层调用栈，不会因此把最坏时间也改成O(n log n)。

“原地”在不同教材中可能允许递归栈。精确说，本版不分配辅助记录数组，分区局部记录空间Θ(1)，仍需O(log n)调用栈；不能把全部额外空间写成Θ(1)。

## 34.7 完整实现

完整文件quick.c：

```c
#include "sort_internal.h"
static void quick_range(SItem *a, size_t lo, size_t hi, SortStats *stats)
{
    while (hi - lo > 1) {
        int pivot = a[lo + (hi - lo) / 2].key;
        size_t lt = lo, i = lo, gt = hi;
        while (i < gt) {
            int order = sort_compare(a[i].key, pivot, stats);
            if (order < 0) { sort_swap(a, lt, i, stats); lt++; i++; }
            else if (order > 0) { gt--; sort_swap(a, i, gt, stats); }
            else { i++; }
        }
        if (lt - lo < hi - gt) {
            quick_range(a, lo, lt, stats);
            lo = gt;
        }
        else {
            quick_range(a, gt, hi, stats);
            hi = lt;
        }
    }
}
SortStatus quick_sort(SItem *a, size_t n, SortStats *out)
{
    SortStatus status = sort_validate(a, n, out);
    if (status != S_OK) { return status; }
    SortStats stats = {0, 0};
    quick_range(a, 0, n, &stats);
    *out = stats;
    return S_OK;
}
```

hi-lo<2时不取pivot，空/单项不会读无效位置。分区后只处理[lo,lt)与[gt,hi)，不把已完成的等值区再次放进范围。每个继续处理的区间严格更短，因此while也会结束。

## 34.8 最好、平衡与最坏分别怎样分析

一次长度k分区调用比较器k次。各层较均分时，一层总量Θ(n)，约log n层，得到Θ(n log n)；全相等因三路仅一层，Θ(n)。若反复极不均分，工作量可能n+(n-1)+…，最坏Θ(n²)。

本版中间位置取基准是确定策略，没有随机抽样，不对任意输入承诺期望O(n log n)。已排序输入不必然是这个变体最坏；“首项基准在有序输入退化”的例子不能不加修改就当成本版实测结论。

更强最坏时间保证需要别的策略，例如深度受限后改用其他排序；堆排序要到第41章先讲堆再实现，本章不在代码里悄悄加入未学的数据结构。

## 34.10 常见错误

把基准指向会移动的槽；大于分支交换后也i++，跳过新项；gt先后顺序写错；把等值区再次递归导致重复工作或不终止；认为分区完两侧各自有序；中间位置当成数值中位数；只递归小边就宣称最坏时间线性对数；全相等例子误判为稳定。

## 34.11 练习与参考答案

练习一：大于分支为什么不推进i？答案：a[gt]换来的记录原在未知区，仍需按pivot分类。

练习二：128项全相等，本版比较与写入多少？答案：比较128，写入0；不计验证与打印。

练习三：较长区由while处理，是否跳过了排序？答案：没有，只是复用当前调用；lo/hi改成那一侧后再做分区，逻辑任务仍在。
