# 第九阶段下：参考结果与验收解释

## 一、使用说明

先完成 [独立练习](第九阶段下-练习.md)。全部代码和命令在 [项目运行说明](示例代码/stage9-planner/README.md)，以下是结果与理由，不是你的运行记录。实际作者覆盖以 [本批验证](验证/第九阶段下验证记录.md) 为准。

## 二、构建与记录顺序

17个.c中只有stage9-planner/main.c是入口，其他都是模块。两个catalog.c分别处理文件目录与内存索引，外部函数名不同，各自先包含本目录头；适配头明确写相对路径，所以不会因文件基本名相同自动冲突。

check为records=4 categories=3 study=4 places=4。原主顺序0、17、9、9999，稳定分钟视图9999、9、0、17。排序的是副本，索引仍对应原位置。

## 三、映射与分类

类别内部顺序7、0、42；父关系为7→父0、0为根、42→父0。展示前序0、7、42，深度0、1、1；这与声明顺序/类别ID升序都不是同一概念。

学习ID9999在位置0，地点ID9999在位置2。学习ID0在位置2，地点ID0在位置1。反向映射不可遗漏，不能把两个位置表互换。

父项可在后面定义，因为引用验证在记录收齐后进行。缺父返回missing reference or item，环返回cycle。分类非空须一根，多个根为invalid argument；空类别42仍展示。

## 五、路线结果

0→202成本5，路径0,101,202；反向202,101,0成本5；0→0成本0、单点路径；0→9999为unreachable、退出0；0→44为missing reference or item、退出1。

零权0→101存在，has与weight分开。无向反向重复道路为duplicate item，负数字段-1不符合非负语法，返回bad format；超过1000则limit exceeded。来源于不同检查层的错误如实报告，不假装所有“数值不合法”都属于同一状态。

## 六、分钟修改与重载

minutes 0 20输出协议头DSA-CATALOG-1，主记录仍按0、17、9、9999写出，只有0的分钟变20；重载后list为9999、0、9、17，两个20中0先于9。

list是人读行，不能给旧加载器当三行记录；export/minutes是可重载协议。把输出重定向回同一输入路径会在程序读取前截断，这是shell行为，程序的候选保证无法补救它。使用新路径、再重载核对。

## 七、错误与资源

空配置有效；重复资料/S/边拒绝；缺M或未知端点拒绝；分类/依赖环拒绝；标签空/过长、数字和文件错误分别返回约定状态。正常业务无结果退出0，输入或I/O错误退出1，错误文本去stderr。

planner_load借用流，不关闭、不回滚读位置；planner_load_files自行打开流，读入中间候选后，连关闭都成功再提交。候选与旧App索引各有唯一拥有者，交换后清理旧资源；不是对任意结构体浅拷贝的许可。

导出先构造旧格式临时目录，准备失败不写出；写入开始后的错误可能留下部分字节。受控申请/读写/关闭模拟验证了实际分支，但不能称为真实磁盘耗尽、设备移除或全进程无分配证明。

## 八、选择报告示例

散列索引减少某些查找的逐项比较，但依赖键/负载并增加申请与重建；小规模线性扫描更简单，最坏O(R)。稳定副本付出O(R)辅助空间，保留主顺序和位置索引；直接重排需同时重建所有位置关系。

最多8点选矩阵，存在与权重分开易检查；成本按V²，不能写成邻接表V+E。分类父表省去节点所有权与申请，扫描孩子O(C²)；大树则应重新评估表示和遍历成本。

真实SortStats计数在机器结果stableSampleComparisons/stableSampleWrites中，样本为30、20、20三条。只计排序比较与SItem写入，不包含全部CPU/I/O工作。选择报告要同时写正确性、资源和失败保证，不把一项“更快”当成所有场景通用结论。
