# 15 文件、命令行与错误处理

## 15.1 目标与先修

先完成指针、结构体和多文件。建议4—6小时。本章让数据跨程序运行保留，理解文件流、打开关闭、EOF与错误、命令行参数、文本与二进制模式，以及输出失败的处理。先用简单计数程序，再为资料目录准备格式。

变量在进程结束后不会自动留到下次启动；想长期保存，需要把数据按明确格式写出，再读取和验证。文件中有数据不意味着它一定符合我们的记录约定。

## 15.2 FILE指针是一种资源句柄

`FILE *in = fopen(path, "rb");`尝试打开一个字节读取流。成功得到可供stdio使用的流指针，失败返回NULL。FILE内部由标准库管理，程序不自行创建其内部字段，也不对它调用free；对应释放操作是fclose。

stdin、stdout、stderr也是流。`fgetc(in)`与getchar相似，但指定从哪个流读；返回int以保留EOF。fputs、fprintf把内容写到指定流；例如`fputs("open failed\n", stderr)`写错误消息，不混入正常数据输出。

| 模式 | 主要含义 | 要先明确的行为 |
| --- | --- | --- |
| r | 读文本 | 文件不存在时不能正常打开 |
| rb | 读二进制字节 | 避免文本换行等转换影响字节计数 |
| w | 写文本 | 成功打开时可截断已有文件内容 |
| a | 追加文本 | 写入定位在文件末尾，不自动符合记录格式 |

本章写文件只在自己的练习目录，对明确的新输出名操作。不要把“打开成功”当成“已经安全保存全部内容”。

## 15.3 结束与读取失败要区分

fgetc返回EOF，可能到达正常末尾，也可能发生读取错误。循环退出后检查ferror，才能区分是否有错误；feof可查询结束标志，但它通常是在读取尝试遇到末尾后才设置。

不要写“while还没到EOF就读一次并处理”，那样最后一次读取失败也可能被当成数据处理。以每次读取的返回值控制循环，退出后检查流状态。

fclose也有返回值，失败不能报告完整成功。流一旦经过fclose调用，就不再使用，即使关闭报告失败。多个资源要按取得顺序和失败路径管理，不能看到一个return就忘记当前还开着文件。

## 15.4 main的参数怎样来自Shell

本章首次使用`int main(int argc, char *argv[])`。argc是参数条目数，argv是指向参数字符串的数组；通常argv[0]是程序启动名，argv[1]是第一个用户参数。

`./file_count.exe notes.txt`通常有2项：程序名与文件名。argv字符串不保证就是合法数字，数字参数仍需验证。访问argv[1]前先检查argc，路径含空格时由Shell引号将它组成一个参数。

这是本阶段见到的二级间接关系：argv先定位一个字符串指针，再定位该字符串的字符。二维int数组是连续的行，不能因此把它当成argv式指针数组，二者布局不同。

## 15.5 完整实验：文件有多少字节

**完整程序：file_count.c。** 下载 [源码](示例代码/15-files/file_count.c)，放到`~/dsa-labs/ch15`。

```c
#include <stdint.h>
#include <stdio.h>

int main(int argc, char *argv[])
{
    if (argc != 2) {
        fputs("usage: file_count input-file\n", stderr);
        return 1;
    }
    FILE *in = fopen(argv[1], "rb");
    if (in == NULL) {
        fputs("open failed\n", stderr);
        return 1;
    }
    size_t count = 0;
    int ch;
    while ((ch = fgetc(in)) != EOF) {
        if (count == SIZE_MAX) {
            fclose(in);
            fputs("file too large\n", stderr);
            return 1;
        }
        count++;
    }
    int failed = ferror(in) != 0;
    if (fclose(in) != 0) {
        failed = 1;
    }
    if (failed) {
        fputs("read or close failed\n", stderr);
        return 1;
    }
    printf("bytes=%zu\n", count);
    return 0;
}
```

在 **UCRT64 Bash、`~/dsa-labs/ch15`目录**执行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic file_count.c -o file_count.exe
printf 'abc\n' > sample.txt
./file_count.exe sample.txt
```

这个Bash printf生成a、b、c、LF四个字节，预期`bytes=4`。若用别的编辑器保存，编码标记或换行方式可能增加实际字节数，不能硬把所有文件都解释成4。

再运行`./file_count.exe missing.txt`（确认该名字不存在）应在标准错误显示open failed、状态1；不传文件名显示usage、状态1。空文件应为bytes=0，不是错误。读取过程中用size_t计数，并在增加前检查上限；极大文件的上限路径本课不靠创建巨型文件来验证。

## 15.6 写入、刷新、关闭各意味着什么

**上下文片段：main内独立练习，已包含stdio，当前目录是自己的ch15。** 它会写名为new-note.txt的文件，若已有同名文件会截断，所以先选择自己的新输出名。

```c
FILE *out = fopen("new-note.txt", "w");
if (out == NULL) {
    return 1;
}
int failed = fprintf(out, "C basics\n30\n") < 0;
if (fclose(out) != 0) {
    failed = 1;
}
if (failed) {
    return 1;
}
```

stdio可能先把内容存在缓冲区，fprintf成功不一定意味着磁盘最终保存成功。fclose会处理刷新和关闭，仍需检查结果。如果流由调用者提供、当前函数不负责关闭，可用fflush请求刷新并检查；第16章save函数就这样对stdout处理。

fflush成功不等于已保证突然断电后持久保存，原子替换、持久化同步和崩溃恢复属于更深入的系统主题。本阶段明确提供文本导入导出，不声称实现了抗崩溃数据库。

## 15.7 文件格式也需要输入协议

资料目录选择第一行为版本标记`DSA-CATALOG-1`，每条记录三行：编号、预计分钟、标题。编号0—9999，分钟0—1440，标题非空且最多63字节，不含控制字符；最多32条，编号唯一。最后一行可无换行，记录中途EOF则是坏文件。

为什么加版本行？未来改变字段时，读取器能明确拒绝未知格式，而不是把标题错当编号。为什么不用直接fwrite整个Record？结构体的填充、类型大小和字节表示没有跨平台文件协议，文字字段也需单独验证。

文件输入采用UTF-8文本约定，本项目按字节限制标题，不实现Unicode合法性校验。下一章的严格读取器选择rb逐字节读取，再自行识别LF/CRLF，拒绝其他控制字节；这里也说明文本格式与打开模式不是同一个概念。不自动猜测所有外部编码或任意二进制文件。

## 15.8 常见错误

- 用char接fgetc：可能丢失EOF信息。
- 只查feof就处理上次结果：重复或错误处理最后一次读取。
- 忽略ferror、fprintf和fclose返回值：失败时仍报告成功。
- 提前return忘记关文件：为每条路径列出资源。
- 对FILE指针调用free：资源释放接口用错。
- 把argv[1]当总会存在：先验证argc。
- 把w当无副作用的“创建或打开”：它可以截断已有内容。

## 15.9 练习与参考答案

练习一：空文件与不存在文件的区别是什么？

答案：空文件可打开，读取立刻正常结束，计数0；不存在文件在fopen处失败。

练习二：为什么记录只有编号和分钟、缺标题时应拒绝？

答案：EOF落在记录内部，格式被截断；不能把不存在标题补为空并宣布成功。

练习三：`argv[2]`为`"12x"`，能只取前面的12吗？

答案：本课数字协议要求整串都是数字，必须拒绝，不能把合法前缀当整个参数合法。
