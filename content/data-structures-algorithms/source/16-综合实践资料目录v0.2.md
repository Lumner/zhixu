# 16 综合实践：资料目录v0.2

## 16.1 目标与先修

先完成09—15章，能解释数组长度、指针借用、结构体、动态内存、多文件和流。建议2—3小时阅读与跟踪，再花8—11小时做第二阶段练习。不要一次抄完项目后才看输出；先运行样例，再沿一次成功和一次失败路径逐步阅读。

本项目管理一个小资料目录：资料有唯一编号、预计学习分钟和标题；支持导入、按编号查找、修改分钟、导出并再次读取。界面采用文本命令行，暂不做交互菜单、删除、排序或散列索引；当前查找仍逐条比较，后续数据结构阶段再改进。

## 16.2 先写清协议与容量

| 项目 | 约定 |
| --- | --- |
| 文件头 | 第一行恰好DSA-CATALOG-1，不含UTF-8 BOM |
| 每条记录 | 三行：编号、分钟、标题；无空白分隔行 |
| 编号 | 十进制0—9999，整行数字；允许前导零，但数值不能重复 |
| 分钟 | 十进制0—1440；不接受符号、空格、小数或数字后杂字 |
| 标题 | 非空，最多63字节；不含ASCII控制字节0—31、127；空格允许 |
| 数量 | 最多32条；只有文件头表示空目录 |
| 文件结尾 | 最后一条标题后可无换行；缺失一条记录中的任一字段则拒绝 |
| 编码 | 约定UTF-8文本，限制按字节；本版不验证Unicode编码合法性 |

项目用二进制模式读取，再由read_line明确识别LF与CRLF两种行尾，避免平台文本模式把某些控制字节提前解释为结束。它不自动识别所有外部编码，不接受BOM或孤立控制字节。标题中的数字不会被误作分钟，因为字段顺序固定。

## 16.3 数据结构与所有权

Record中有`int id`、`int minutes`和`char title[64]`，标题内嵌。Catalog中有`Record *items`、`size_t count`和capacity。items拥有动态数组，count是有效条目数，capacity是已分配格子数。

必须始终保持：`0 <= count <= capacity <= 32`；每条已收录记录合法、编号不重复；capacity为0时items为NULL；释放后恢复空状态。只处理count之前的元素，不读取备用格子。

| 接口 | 主要职责 | 资源约定 |
| --- | --- | --- |
| catalog_init | 初始化为空 | 不释放旧资源，只用于未初始化对象 |
| catalog_free | 释放并恢复为空 | 可对已初始化的空目录重复调用 |
| catalog_add | 校验、查重、按需扩容、追加 | 成功复制Record，失败不改旧内容 |
| catalog_find | 按编号返回只读记录地址或NULL | 地址为借用，扩容/释放/整体替换后不得继续用 |
| catalog_set_minutes | 校验范围并修改指定记录 | 找不到与非法分钟分别返回状态 |
| catalog_load | 验证整个文件，成功才替换目录 | 借用FILE，不负责fclose |
| catalog_save | 向指定流导出并检查刷新 | 借用流，不负责关闭 |

这些函数的Catalog参数必须指向已初始化的有效对象，Record参数必须有效；它们不尝试识别任意悬空地址。外部代码不能随意破坏count/capacity后又期待模块自行修复。

## 16.4 三个源文件怎样组织

完整文件为 [catalog.h](示例代码/stage2-catalog/catalog.h)、[catalog.c](示例代码/stage2-catalog/catalog.c)、[main.c](示例代码/stage2-catalog/main.c)，输入为 [sample.txt](示例代码/stage2-catalog/sample.txt)。可逐文件阅读 [完整源码附录](示例代码/stage2-catalog/完整源码.md)，它是同一程序的源码展示，不是额外主线章节。

头文件定义类型和接口；catalog.c实现数据规则、行读取与保存；main.c负责参数、打开关闭文件和报告状态。实现辅助函数前加static，限制为本实现文件使用。

下面是**完整程序中的入口文件main.c**，不能只编译它而漏掉catalog.c：

```c
#include "catalog.h"
#include <stdio.h>

int main(int argc, char *argv[])
{
    if (argc != 2 && argc != 4) {
        fputs("usage: catalog input-file [id minutes]\n", stderr);
        return 1;
    }
    int id = 0;
    int minutes = 0;
    if (argc == 4 && (!parse_number(argv[2], 9999, &id) ||
                      !parse_number(argv[3], 1440, &minutes))) {
        fputs("invalid arguments\n", stderr);
        return 1;
    }
    FILE *in = fopen(argv[1], "rb");
    if (in == NULL) {
        fputs("open failed\n", stderr);
        return 1;
    }
    Catalog catalog;
    catalog_init(&catalog);
    CatStatus status = catalog_load(in, &catalog);
    if (fclose(in) != 0 && status == CAT_OK) {
        status = CAT_IO;
    }
    if (status == CAT_OK && argc == 4) {
        status = catalog_set_minutes(&catalog, id, minutes);
    }
    if (status == CAT_OK) {
        status = catalog_save(stdout, &catalog);
    }
    catalog_free(&catalog);
    if (status != CAT_OK) {
        fprintf(stderr, "catalog: %s\n", catalog_status_name(status));
        return 1;
    }
    return 0;
}
```

main先验证参数，打开输入，初始化目录，调用load，关闭输入；成功且给了修改参数时更新；成功后导出；无论业务状态成功与否，最后都释放已初始化目录。正常数据写stdout，错误写stderr，返回1。

`const char *catalog_status_name(...)`返回只读状态文字，不需要调用者释放，也不能修改字符串字面量。条件运算符`condition ? a : b`表示根据条件选择一个表达式的值，代码中用于选择结果状态和初始扩容容量。

## 16.5 编译与正常运行

将三份源文件和sample.txt复制到自己的`~/dsa-labs/ch16`。在 **UCRT64 Bash、这个目录**：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -g -O0 main.c catalog.c -o catalog.exe
./catalog.exe sample.txt
```

输出保持相同的三行一记录格式：

```text
DSA-CATALOG-1
1
30
C basics
2
45
Pointers
3
20
Arrays
```

这不是“程序没有做事”：它确实读入、验证、存入动态数组，再按统一格式导出。输入中的前导零会规范化成普通十进制，输出最后有换行。比较时关注记录值和顺序，不要求所有合法输入与输出字节完全相同。

## 16.6 修改、保存与重载

同一目录运行：

```bash
./catalog.exe sample.txt 2 60 > exported.txt
./catalog.exe exported.txt
```

编号2的分钟变成60，其他字段和次序不变。参数2和60经parse_number整串验证；它不会把`60x`当60，也不会把编号不存在当成功。第一次命令的`>`由Shell建立输出文件，不是C的比较运算。

**不要把输出重定向到同一个输入文件。** Shell可能在程序打开输入之前就截断输出目标，因此`sample.txt > sample.txt`并不是安全原地更新。本版本使用不同的新输出名；不提供自动备份、原子替换和掉电恢复。失败时新输出文件仍可能存在，保存成功以退出状态和再次读取为准。

stdout刷新失败时，catalog_save返回CAT_IO，main也返回失败。已经写出的部分输出不能回收，这与“导入失败保留内存旧目录”是两件事，不能把后者的保证推广到导出文件。

## 16.7 把一条记录加进去发生什么

catalog_add先做一个Record局部副本，检查字段，再查编号是否存在，检查32条上限。若count等于capacity，申请4、8、16、32格的下一容量；本课程数量上限很小，仍在计算字节前检查乘法上界。

realloc失败立即返回CAT_MEMORY，旧items/count/capacity不改。成功后写入新Record，最后才count++。capacity变化不等于count变化。

为什么先复制Record？避免在扩容之后才去读取一个可能来自旧数组的记录地址。追加时完整复制内嵌标题，调用者随后改自己的Record不会自动改目录内那条记录。目录查找返回的借用地址则可能在下一次扩容后失效，需按id重新查。

## 16.8 读取整行与验证数字

read_line逐字节读取，最多保存capacity-1个，末尾补零；超长或含控制字节时标记坏行，但仍继续消耗至行尾。读到CR时再取一个字节，只有紧随LF才作为正常行尾，否则标坏行。容量前提是大于0，本项目只用64格数组调用。EOF在新记录边界表示正常结束，在分钟或标题处表示截断。

parse_number接收已经终止的字符串，沿字符逐个验证，使用第一阶段相同的“先查范围再乘加”规则；结果通过out参数写回，失败时不改原结果。这次输入函数与数值转换分开，所以来自文件与argv的字符串可以复用同一规则。

字符串内遇到零会停止，因此读取层必须先拒绝文件中的内嵌零字节，不能只依赖strlen或数字转换函数发现所有坏输入。标题校验也在上限64格内查找终止零，不对未终止数组无限调用strlen。

## 16.9 为什么导入用临时目录

```text
目标目录保留 → 建立空incoming → 逐条校验并追加
                                  ↓
                     任一步失败：释放incoming，返回错误
                                  ↓ 全部成功
                     释放目标旧内容 → 移交incoming的所有权
```

成功时`*catalog = incoming`复制指针、数量和容量，这是一次约定好的所有权移交；此后不能再对incoming执行catalog_free，因为目标已成为同一块分配的所有者。局部incoming离开函数并不会自动free，所以目标可以继续使用。

这不是随意复制一个拥有资源的结构体。先释放目标旧资源、随后只保留一个所有者，必须作为接口约定整体理解。单次失败时临时目录的所有分配都释放，原目标保持原记录和数量。

CLI通常以空目录开始；验证脚本还会先准备非空目录，再用坏输入和分配失败测试，才能真正证明“旧目录保留”，不能仅凭空目录上的失败推断。

## 16.10 边界实验与常见错误

在自己的样例副本中分别构造：仅文件头、标题63/64字节、重复编号、0/1440/1441分钟、记录缺标题、未知版本、超过32条、无匹配修改编号。每次先写预期状态，再运行并查看Bash的`echo $?`。

常见错误包括：一边读取一边清空原目录；先count++再检查分配；同一借用地址跨扩容继续使用；关闭由别人拥有的流；stdout混入提示语破坏导出格式；忽略Shell重定向先于程序运行的顺序。

## 16.11 练习与参考答案

练习一：导入两条记录后，第3条编号重复，原先非空的目标目录应剩什么？

答案：原目录不变；前两条位于临时incoming中，应与其分配一并释放，不提交任何半成品。

练习二：load成功后再free(incoming)为什么错误？

答案：目标已拥有incoming那块数组，这会释放目标仍要使用的存储，造成失效访问或后续重复释放。

练习三：导出失败能否保证输出文件完全未改？

答案：不能。可能已经写出部分数据；本版只报告失败，不提供原子文件替换。
