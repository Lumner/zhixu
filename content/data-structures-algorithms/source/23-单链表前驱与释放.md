# 23 单链表、前驱与释放

## 23.1 目标与先修

先完成顺序表、动态数组，能画指针与所有权。建议5—7小时。本章把整数分别放在动态节点中，通过next连接次序，实现与顺序表相同的按位置操作，并逐步说明插入、删除、清空的安全顺序。

桌上每张卡片写一个值和“下一张在哪里”，卡片不必挨着摆。这样改变相邻关系可能不需要搬动整排卡片，但要找第p张，就不能凭数组下标一步到达。

## 23.2 一个节点装什么

SNode包含int value和指向下一个SNode的next。结构体中的`struct SNode *next`是自引用指针，不是在一个节点里无限内嵌另一个完整节点，所以结构大小仍然有限。

```text
head哨兵 → [10 | next] → [20 | next] → [30 | NULL]
```

箭头表示访问关系，不代表两个节点物理相邻。NULL表示没有下一个。逻辑先后由next决定，不能通过对节点地址做+1来找到下一项。

## 23.3 为什么加一个不存数据的头哨兵

SList内嵌一个head节点，head.value不使用；head.next指向第一条真实数据，count只数真实节点。空表head.next=NULL、count=0。

有了哨兵，插入最前面也有统一的前驱：head本身。没有哨兵时，改头指针通常需要额外分支。哨兵减少分支，不是给真实数据偷偷增加一条0。

head是SList对象的一部分，不是malloc出来的节点，清空时不能free(&list.head)。所有真实节点由list拥有，调用者不复制这个拥有节点指针的结构体来制造第二个释放者。

## 23.4 前驱怎样找

插在位置p前面，需要先找到其前驱。从head出发走p步：p=0前驱head；p=1前驱第0个真实节点；p=count时前驱最后节点。只有先确认p≤count，这段走法才满足约定。

删除位置p也先找前驱，但要求p<count，前驱的next才必定是真实节点。按位置get/set要先走链，最坏Θ(n)，不能沿用数组的Θ(1)下标成本。

## 23.5 插入的两次连线有先后

在10与30之间插20，previous指向10，原previous.next指向30。先申请节点并写值，再：

```text
node.next = previous.next     新20先记住原来的30
previous.next = node          再让10连到20
最后count加1
```

这段是**概念步骤**，对应完整实现中的指针赋值。若先把previous.next改成node，再让node.next=previous.next，就可能把node连回自己，丢掉后面的链。

所有可能失败的校验与malloc都在改链之前。malloc失败返回DS_MEMORY，原连接、数量和数据不变。查找前驱的成本仍存在，不能只看两次赋值说按位置插入总是常数。

## 23.6 删除要先接好后面的链

previous.next为待删node，先保存node.value，再令previous.next=node.next，随后free(node)，count减1，最后把值写给调用者的独立变量。

不能先free(node)再读node.next，那时对象已经结束。也不能让previous继续指向已释放节点。最后一个节点删除后，前驱next自然变NULL；唯一节点删除后，head.next自然变NULL。

这解释了“已知前驱的摘链Θ(1)”与“按位置删除最坏Θ(n)”的区别。只知道待删节点地址，通常还不能在单链表中直接修改它前面的next；不要把某些特殊技巧当通用删除语义。

```c
#ifndef DSA_SINGLY_H
#define DSA_SINGLY_H
#include "ds_status.h"

typedef struct SNode { int value; struct SNode *next; } SNode;
typedef struct { SNode head; size_t count; } SList;
void slist_init(SList *list);
void slist_clear(SList *list);
DsStatus slist_get(const SList *list, size_t position, int *out);
DsStatus slist_set(SList *list, size_t position, int value);

```

完整文件singly.c：

```c
#include "singly.h"
#include <stdlib.h>

void slist_init(SList *list) {
    list->head.next = NULL;
    list->count = 0;
}

void slist_clear(SList *list)
{
    SNode *node = list->head.next;
    while (node != NULL) {
        SNode *next = node->next;
        free(node);
        node = next;
    }
    slist_init(list);
}

static SNode *before(SList *list, size_t position)
{
    SNode *previous = &list->head;
    for (size_t i = 0; i < position; i++) {
        previous = previous->next;
    }
    return previous;
}

DsStatus slist_get(const SList *list, size_t position, int *out)
{
    if (out == NULL) {
        return DS_INVALID;
    }
    if (position >= list->count) {
        return DS_RANGE;
    }
    const SNode *node = list->head.next;
    for (size_t i = 0; i < position; i++) {
        node = node->next;
    }
    *out = node->value;
    return DS_OK;
}

DsStatus slist_set(SList *list, size_t position, int value)
{
    if (position >= list->count) {
        return DS_RANGE;
    }
    before(list, position)->next->value = value;
    return DS_OK;
}

DsStatus slist_insert(SList *list, size_t position, int value)
{
    if (position > list->count) {
        return DS_RANGE;
    }
    if (list->count == DS_MAX_ITEMS) {
        return DS_FULL;
    }
    SNode *previous = before(list, position);
    SNode *node = malloc(sizeof *node);
    if (node == NULL) {
        return DS_MEMORY;
    }
    node->value = value;
    node->next = previous->next;
    previous->next = node;
    list->count++;
    return DS_OK;
}

DsStatus slist_erase(SList *list, size_t position, int *out)
{
    if (out == NULL) {
        return DS_INVALID;
    }
    if (position >= list->count) {
        return DS_RANGE;
    }
    SNode *previous = before(list, position);
    SNode *node = previous->next;
    int saved = node->value;
    previous->next = node->next;
    free(node);
    list->count--;
    *out = saved;
    return DS_OK;
}
```

## 23.8 清空为什么需要保存next

clear从head.next开始，每次先把node.next存到一个临时变量，再free(node)，然后node=next。循环不变量是：前面所有节点已释放，node及其后仍是一条尚未释放的链。

如果把node=node.next放在free之后，又没有保存next，就在访问已结束对象。清空结束再把head.next设NULL、count=0，便可重复clear。不要保留旧节点地址期待“清空后还能看一眼”。

真实节点共n个时，clear为Θ(n)，每个释放一次；额外辅助变量Θ(1)。存储是n个节点，每个比一个int多一个next及可能填充，不能只按数据值大小估计占用。

## 23.9 不变量与边界实验

本实现限制最多64个真实节点。对象不变量：从head.next恰好走count个真实节点，最后为NULL；不存在绕回；每个节点归本表拥有，不与另一个表共享释放责任。

验证应不仅看输出值，还看链是否能按count走完，是否多节点或少节点。先试空表插0，再删唯一节点；再试头、中、尾插删，位置count和count+1，重复清空，分配失败。

地址非NULL不能证明节点仍有效。教材测试通过跟踪专用分配器检查拥有关系，不让学习者用“读取一个可能已free的节点试试看”代替检查。

## 23.10 常见错误

- 把头哨兵的value计入真实数据，数量多1。
- 把新节点连线顺序写反，形成自环并丢链。
- 先free再取next，释放后访问。
- 忘记改前驱next，保留悬空链。
- 删到空后count不归零，或head.next未变NULL。
- 只说插删Θ(1)，遗漏寻找前驱的遍历。
- init覆盖已有链，或复制拥有者后重复释放。

## 23.11 练习与参考答案

练习一：有头哨兵时，在空表位置0插入，前驱与原后继分别是谁？

答案：前驱为head，原后继NULL；新节点next=NULL，head.next改为新节点。

练习二：删除唯一节点需要特殊地free哨兵吗？

答案：不需要。改head.next为NULL、只free真实节点，count减到0。

练习三：按位置p插入的前驱查找要走几步？为什么末尾追加不一定常数？

答案：从head走p步；本表示不缓存尾节点，p=count时要走整条链。
