# 最终项目：第52章实现前契约

> 这是第52章实现前保存的设计基线，下文保留原拟定措辞。最终v1.0现已实现，实际接口/协议/命令以 [第52章](52-综合项目资料检索与路线规划.md)、[运行说明](示例代码/stage9-planner/README.md) 和 [真实验证](验证/第九阶段下验证记录.md) 为准；本页不重复计为正文或程序。

## 一、目标与范围

将资料检索、树形分类、学习先后、就绪推荐和地点路线放到一个可构建的C17命令行工具。复用已有模块，通过适配层统一接口；保留v0.3及所有旧例程，不修改旧容量、文件格式或所有权规则。

第52章暂估16—24小时，包含手打、工程拆分、跨模块回归与报告。若实现范围改变，应更新路线预算与本契约，不把未完成的命令列为功能。

首版以可复现文本命令为主，不要求交互菜单。资料的费用/预计分钟不等于路线距离；依赖拓扑不等于最短路；就绪推荐不宣称依赖约束下预算最优。独立背包仍是第51章算法实验，不强行用于有先修关系的选课。

## 二、对象和ID映射

| 对象 | 计划预算与语义 | 复用/适配策略 |
| --- | --- | --- |
| 资料目录 | 文件32条，ID0—9999，分钟0—1440，标题1—63字节 | 复用stage6-catalog加载、索引和稳定视图；内存48项上限不改 |
| 分类树 | 最多8类，ID0—9999，父ID或-1根，标签1—31字节 | 父关系数组表示一般树，解释遍历与环检查；不把一般分类树冒充BST |
| 分类归属 | 每条资料恰好归属一个已定义类别 | 映射以业务ID保存，验证完整后绑定记录 |
| 学习网络 | 最多8个显式参与资料ID，含孤立点 | 建立ID↔Graph位置0..n-1表，所有依赖端点必须参与 |
| 地点网络 | 最多8个地点，独立ID0—9999及标签 | 另建位置表，绝不把地点ID、资料ID和数组位置混为一谈 |
| 就绪队列 | 未完成且全部先修已完成的网络资料 | 复用小根堆，priority=分钟、id=资料ID，同分钟按ID升序，非FIFO |
| 路线 | 无向，权重0—1000 | 复用Graph与Dijkstra/恢复，拒绝负权，区分不可达 |

资料有32条但学习图最多8点；没有绑定进学习网络的资料仍可检索/分类，不虚构成图的隐含节点。所有映射都有实际数量，ID0合法，不能用0表示缺失；查找必须返回独立状态或数量哨兵。

分类非空时有一个根，父节点必须存在，禁止自父、环和重复类别；每条资料归属恰好一次。空目录可以有空分类，具体是否允许保留空分类在实现测试中明确。分类树不是二叉搜索树，勿为了使用某个名字强行改变业务关系。

## 三、保留资料文件，新增关系侧文件

资料文件保持现有DSA-CATALOG-1协议，仍按原来的LF/CRLF、无BOM、UTF-8字节约定；不声称验证了全部Unicode。原目录文件不加入新字段，避免破坏旧例程。

另以`DSA-RELATIONS-1`为关系文件头，后续拟采用竖线分隔记录。以下是**协议设计样例，不是C代码或已运行输入**：

```text
DSA-RELATIONS-1
C|0|-1|基础
C|1|0|算法
M|17|0
M|1|1
S|17
S|1
D|17|1
P|101|书桌
P|202|图书馆
R|101|202|5
```

C定义分类/父类/标签；M绑定资料与分类；S声明学习网络资料（按出现顺序建位置表）；D表示先修资料→后继资料；P定义地点与标签；R表示无向道路。样例必须搭配含资料17和1的目录，其余M应覆盖真实目录全部记录。

关系文件中标签禁止分隔符及ASCII控制字符，限制字节长度；未知记录类型、缺字段、多字段、空数字、符号错误、超长行、重复项、无效引用和超过容量均拒绝。-1仅用于分类根父项；其他ID非负。明确数字逐位检查上界，不先发生溢出再判断。

首版记录类型按C、M、S、D、P、R的区块顺序，重复依赖和无向反向重复道路拒绝；不静默忽略坏行。道路零权合法，has与weight分开。学习图在整体语义检查时运行拓扑，环导致配置加载失败并保留旧应用状态。

## 四、模块边界与失败保证

建议独立新目录`stage9-planner/`，不直接往旧main继续堆命令。分为配置解析、业务ID映射、目录适配、分类、学习网络、路线、CLI；共享算法文件按明确路径链接，避免多个catalog.h/main.c互相覆盖。

调用关系概念为：CLI解析命令→构造候选应用→加载目录和侧文件→验证跨文件引用/分类树/依赖环→提交→执行只读查询或目录副本更新。尚未提交的候选失败后完整释放；旧App保持。配置FILE流由谁打开谁关闭，语法失败不承诺流位置回滚。

目录索引含动态资源，App作为单一所有者统一清理；禁止把拥有者普通赋值复制后分别clear。提交需要明确的交换/所有权转移函数，核对内部引用后实现；不能把“结构体赋值”当成通用事务。图、位置表、堆和小分类表为值数组，不拥有外部节点。

API按结果区分参数错误、格式错误、重复、范围/容量、缺失引用、环、内存错误、I/O错误。路线不可达和空查询是成功计算的业务结果；没有结果时不输出未初始化的路径。错误信息去stderr，正常结果去stdout，退出状态约定成功0/错误1。

更新分钟时先构造候选并重建派生视图/队列，不沿用旧视图副本。写出文件仍可能在I/O失败后留下部分内容，首版不承诺原子覆盖；示例重定向必须输出到不同文件名，避免shell提前截断输入。

## 五、计划命令与可审查输出

拟采用`planner 目录文件 关系文件 命令 [参数]`。确切usage应以第52章实现为准：

| 命令 | 输出与验收 |
| --- | --- |
| check | 两文件、全部引用、分类树和依赖DAG合法；失败明确原因 |
| list / find ID / title 模式 | 稳定分钟视图、ID索引查询、标题字节匹配；不改主序列 |
| categories | 树形类别及资料归属，空类/空目录有明确定义 |
| order | 只输出显式学习网络节点的完整合法先修顺序，映射回业务ID |
| ready [已完成ID…] | 检查参数及学习网络身份，按分钟/ID输出当前就绪资料；已完成集合的闭包条件明确验证 |
| route 起点ID 终点ID | 地点业务ID路径与总权，或明确不可达；自身路线成本0 |
| minutes ID 新分钟 | 验证后输出更新的原目录协议，重定向到新文件并重新加载核对 |
| export | 输出保持主顺序的原目录协议，不把人读列表当可导入文件 |

首版不新增/删除关系或写关系文件，不做图形地图、联网账户或压缩文件。旧v0.3的删除命令独立保留，不冒充新工具已有功能。若实现时扩展，应增加相应引用一致性与失败测试。

## 六、最终验收矩阵

从干净副本构建；测试空/单/边界目录、ID0与稀疏ID、重复资料/类别/边、过长标题/标签/行、非法数字、引用缺失、分类环、依赖环、不连通地点、零权、自身路径、文件不存在、格式错误、保存重载与稳定同键顺序。

为目录/索引实际分配位置做可控失败注入，验证旧App与资源存活数；不虚构图数组malloc失败。I/O错误模拟与真实设备故障分别报告；借用流、关闭/刷新、候选释放与提交的每条错误路径都要追踪。若某项未运行，须在第52章验证记录中列出限制。

独立参考核对ID映射、先修顺序的每条边、就绪资格、路线成本与有效边、目录主数据/索引/分类一致性。比较至少两种算法或结构选择，并报告真实工作量口径，不凭一次毫秒数证明复杂度。

全部功能、完整源码、协议样例、故障矩阵和真实结果准备后，才注册第52章，课程才能判断是否达到完成条件。当前第九阶段上与最终工程分别验收，不提前把课程状态改成complete。


## 七、2026-11-12实际落地说明

六份新C/H、17个链接源文件、一个main组成v1.0。原资料协议保持，关系记录按本设计C/M/S/D/P/R落地；支持空类别树或一棵合法无资料树，父声明顺序可变。就绪完成集合须先修闭合，分类一般树采用父关系表。

分钟修改采用先验证后单个标量提交；不缓存稳定视图/就绪堆，每查询按当前记录重建，因此省去设计草案中的整份修改候选。加载仍完整候选提交，自有流关闭成功后才换旧App；受控交换核对无内部自指。导出失败不回滚已经成功的内存分钟修改，也不承诺文件原子覆盖。

命令落地为check/list/find/title/categories/order/ready/route/minutes/export，无交互菜单。设计中的资料/类别/学习/地点容量保持，新增/删除关系及原子保存仍不在本版范围。原拟定例子的ID1不是默认最终样例的一部分，不应把设计片段直接当可运行配置；实际完整样本已随工程提供。
